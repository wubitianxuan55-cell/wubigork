# 首页 v10「天玄」卡片工作台重设计（2026-09-30）

> 用户指令（原文）：「重新设计首页，现在的风格不喜欢，我喜欢卡片式的」→「重新设计整个首页」→
> 「使用技能重新设计整个首页，主题定为天玄」。
> 技能：`redesign-existing-projects`（既有界面重设计·审计先行）+ `high-end-visual-design`
> （双层工艺/弹性动效/一枚强调色）+ `ui-ux-pro-max`（风格与配色检索：Bento Grids 形态 +
> Modern Dark / OLED midnight-blue 配色）。
> 范围：ModuleLauncher 三态首页（书斋 classic / 闲庭 classic / 任务优先 tasks）+ 新增
> `tianXuan` 主题预设（含亮暗两档、三语主题文案）。零功能删除。

## 1. 背景与冲突声明

v6 曾因「等大圆角卡片 + 描边铺满」被用户判「低级」，v7–v9 遂走「去卡片化」路线（仪表条 /
账页 / 案牌 / 脉息面板）。本轮用户明确要求**卡片式**——按其本轮指令覆盖旧判据，但把 v6 的
廉价根因写成避坑清单（§3.1），卡片必须**异质、有工艺、有母题**，否则回退到 v6 观感。

## 2. v9 诊断（落地前快照）

1. **没有卡片层级**：全页只有「开放排印 + hairline 行 + 单张面板」，命令条、文档、能力、
   状态四类信息的视觉权重靠字号微差区分，扫视时无法按块跳读。
2. **右舷挤压**：304px 窄栏里五节纵排（写作/内核/会话/记忆/任务），信息被压成清单。
3. **可点目标不明确**：账页行与案牌都是「文字 + 末端箭头」，点击热区小、悬停反馈弱。
4. **主题与首页无关系**：首页完全跟随全局预设，没有任何「属于自己的」母题。

### 7.7 v11 四轮：一屏自适应（2026-10-01，用户指令「全屏时整个窗口显示全部内容，不用下拉」）

- **机制**：`.w-board`/`.p-board` 高度定界化（`flex: 1 0 0` + `min-height: min-content`）——
  fr 行按确定高度分配：富余给文档行/海报墙（内部消化），不足时 min-content 兜底、
  `.ml` 回退滚动。此前 `flex: 1 0 auto` 在内容超高时 fr 行失准膨胀（不确定高度下 fr→max-content）。
- **纵向压缩一档**：页底 padding 22→8、board gap 14→12、hero 34→30px/cmd 60→52/模块卡
  86→72/旗舰 124→100/仪表带 cell 14→10 + 环 72→64、海报行 200→178、展厅卡/会客厅横幅同步。
- **高度档 `@media (max-height: 1060px)`**（与宽度档正交）：文档/海报行下限 150、模块 64、
  cmd 48、环 56、空态紧凑、`w-voice-status` 闲置隐藏（`.w-cmd.is-* ~ .w-voice-status` 恢复）、
  strip/seal/卡图标再收一档。
- **闲庭设置横条移出海报墙**（JSX）：原在墙内被 `minmax(178px,1fr)` 行高撑成 178px 空洞。
- **实测**：1920×1080 书斋/闲庭 over=0；1600×1000 书斋/闲庭/任务三态 over=0（零滚动一屏呈现）；
  1280×950/640 宽度塌缩档回退滚动（单列堆叠物理不可一屏，设计行为）。测试 81/81 绿 + tsc 0 错。

### 7.8 v11 五轮：真机数据下的一屏根修（2026-10-01，用户反馈「书斋全屏不是全屏」）

- **根因（真机 CDP 9333 只读实测）**：`min-height: min-content` 把行内容高灌回 board——
  真实数据（5 条文档）下文档行 min-content 306 > 视口余量，board 被撑到 1046 > 925；
  且 board 缺 `min-height:0`，flex 自动最小尺寸顶住不肯缩（12px 级残差）。
- **修**：①删 min-content + 补 `min-height: 0`（w/p 两 board）——board 恒等于可用高度，
  fr 行分配、auto 行超限才回退滚动；②高度档文档行藏路径副行（`w-docs-path`）+
  行 padding 4px + 行允许收缩（`flex: 1 1 auto`）。
- **验证**：dev 注入 5 条文档（`gaea.atRecentFiles`）1080/1600×1000 over=0；
  重建 exe 后 CDP 附着真机（真实数据）模拟 1920×1009/1080、1600×1000 三档全屏 over=0。
  exe SHA256 `48f6b0dc7da7cd2f`（51,768,320B），已替换桌面并重启；低窗（761 高）回退滚动=设计行为。

### 7.13 v11 十轮：闲庭矮窗重叠根修（2026-10-01，用户反馈「非全屏时闲庭大量卡片重叠」）

- **复现（1600×760 dev）**：墙容器被压到 119px、海报溢出墙 193px、设置横条/仪表带被

  矮窗负剩余空间下 fr 轨被压瘪到任意小，墙内容（行下限 178×2）溢出可见容器；轨道
  总和恰好填满 board → scrollHeight 不涨 → 不触发滚动回退。
- **修**：墙轨道显式下限 `minmax(var(--p-wall-floor),1fr)`，四档断点变量：
  基础 368px（4 列 2 行）/ 高度档 312px / ≤1400 430px（3 列含 hero 行 240）/
  ≤900 640px（2 列 3 行）/ ≤640 980px（1 列 5 行）——不足即正常滚动回退。

  全屏 over=0；测试 15/15 绿 + tsc 0 错；exe 重建替换（SHA `fd64a0637d87827a`）并重启。
- **教训**：一屏自适应的 grid fr 轨道必须显式下限——item 的 min-height:0 会把
  auto min 归零，fr 在负空间下压瘪轨道且不涨 scrollHeight，表现为重叠而非滚动。
