## 3 单位、间隔、比例的映射关系

### 3.1 单位编码

```
1 = 年-月        2 = 月-天        6 = 工程月（fov=6 分支，与 4 同族）
3 = 工程周       4 = 工程月       8..10 = 月-天内的 10 日 / 15 日 / 月
```

界面上下拉的实际内容（`FUN_140698d60` +0x148 / +0x88 / +0x118 处 `tr()` 三/二项）：

| 下拉 | 项 |
|---|---|
| 工程标尺·上方刻度 | 年-月 / 月-天 / 日-时 |
| 工程标尺·下方刻度 | 工程周 / 工程月 |
| 进度标尺·上方刻度 | 工程周 / 工程月 |
| 进度标尺·下方刻度 | 工程周 / 工程月 |
| 时标刻度局部缩放·单位 | 由资源池 5 串全部可选项驱动（含"年-月/月-天/日-时/工程周/工程月"） |

> 资源池里 5 个串（`0x140d16e60/68/70/78/88`）**都被 `tr()` 引用**，
> 但工程标尺上方行只用前 3 个、其余行只用后 2 个 —— 不是"6 个下拉各取一值"，
> 而是**同一套串按行裁剪**。

### 3.2 间隔索引钳位（预设回填时）

```c
fov==1: sel = 0;                       if (step < 5)  sel = step - 1;
fov==2: sel = 1;  step < 8 ? sel=step-1 : (step==10 ? sel=8 : sel=7);
fov==6: sel = 2;  step < 4 ? sel=step-1 : sel=3;
```

注意 `6b7e20`（网络图版）对 `fov==1` 的写法有原始缺陷：`iVar6` 未赋值即参与
`*(int*)(this+0x2dc) = iVar6`（条件内赋值），实际表现取决于寄存器残留 —— 复刻时按"取 0/step-1"实现即可。

### 3.3 工作信息卡的"时间单位"是同一套编码

`zpbdata` 的 `groupby_setting` 里有 `time_unit / interval_type / interval_start / interval_step`，
与本节编码同族（`time_unit` 取值 0/6 已见于示例视图 JSON）。

## 4 自动联动算法（核心，`FUN_14069a4d0`）

### 4.1 输入输出

```
in : ZoomTime{fov, step, min_step, width} + fv[6]
out: this+0x300 = scale（随后 FUN_1402c4b40 重算全部像素坐标）
gate: this+0x2e0 == 0 直接 return（"未改动"短路）
```

### 4.2 常量表（`.rdata` 直读）

| 地址 | 值 | 含义 |
|---|---|---|
| `1408bd210` | 0.08 | 密度下限（≈1.92 工作小时/像素） |
| `1408bd218` | 0.10 | 1 分钟档基准 |
| `1408bd220` | 0.12 | ≈2.88 工作小时 |
| `1408bd228` | 0.24 | ≈5.76 工作小时 |
| `1408bd230` | 0.40 | ≈9.6 工作小时 |
| `1408bd238` | 2.4 | **每日工作小时** |
| `1408bd240` | 5 | 一年 ≈ 5 个 10 日 |
| `1408bd248` | 7 | 一周 7 天 |
| `1408bd250` | 15 | 半月 15 天 |
| `140818460` | 1 | — |
| `140818470` | 10 | 旬 |
| `1407f8ba0` | 0.5 | 统一收尾系数 |
| `140d16ea0` | -0.08 | 负向钳位基准 |
| `140d16eb0` | 1000000 | 微秒/秒换算 |

### 4.3 分支

```c
work_days = |视图跨度(秒)| / 3600.0 / 2.4;      // 每工作日折算的自然日数

fov==1 : scale = (step<4 ? 0.10/2.4/(step+1) : 0.10/2.4/5) + 2.4/15;
fov==2 : switch(stepIdx){
           0: scale = 1 - (2.4/15)/0.08;
           1: scale = (2.4/15)/0.12 + (2.4/15)/0.08;
           2: scale = (2.4/15)/0.24 + (2.4/15)/0.12;
           3: scale = (2.4/15)/0.24 + (2.4/15)/0.40;
           <7: scale = (int)((2.4/15)/(stepIdx+1)) + 1;
           7: scale = (2.4/15)/7  + (2.4/15)/10;
           >7: scale = (2.4/15)/15 + (2.4/15)/10;
         }
fov==6 : d = 2.4/15;
         d<=0.08 → 步长 1;  d<=0.12 → 2;  d<=0.24 → 3;  d>0.24 → 6;
         step = max(step, min_step);
fov==4/5: scale = 1 - (2.4/15)/0.08;
scale *= 0.5;                                  // 统一收尾
```

**语义**：`scale` 是"1 像素代表多少个工作日当量"，六档就是把同一个量
按 分钟/小时/工作日/工作周/工程月/自然日 六个量纲各自换一次。
`1 刻度像素宽 = scale × 2.4`（工作日），这正是「按日期 / 按周 / 按月 / 按年」四档粒度的分界。

## 8 对 gaea 复刻的口径（可直接落地）

1. **`TimeScaleConfig`** 一条记录：
   ```ts
   type Fov = 1|2|3|4|5|6;             // 分钟/小时/工作日/自然日/工作周/工程月
   type Unit = 1|2|3|4|6|8|9|10;       // 年-月/月-天/工程周/工程月/工程月/10日/15日/月
   interface TimeScaleConfig {
     fov: Fov; step: number; minStep: number; scale: number; fv: number[];  // fv.length===6
     showProjectRuler: boolean; showPeriodRow: boolean; showCalendarLine: boolean;
     lineDensity: 'small'|'big'|'project'|'none';
     topUnit: Unit; topStep: number; bottomUnit: Unit; bottomStep: number;
     localZoom: {unit: Unit; step: 1|2|3|4|5}[];
   }
   ```
2. **间隔集映射表**照 §2/§3.1 硬编码，改单位时先 `step = null` 再按集合重选（斑马就是"归零 + 重填 + 首项"）。
3. **自动联动**照 §4.3 实现；`0.5` 收尾系数别漏，否则 1 刻度像素宽整体翻倍。
4. **像素换算单一出口**：所有视图（横道/双代号/单代号/时标/逻辑）共用
   `pos[i] = Σ step[k] × scale × 2.4`（工作日当量 → 像素），与斑马保持一致，避免各视图漂移。
5. **双语标尺名**按"日期/周/月/年"四档做资源键，不要按 6 档各写一套文案。
6. **持久化**：两套布局（横道/网络图）互斥，落盘时按 `display_mode == 网络图族` 选槽位，读时同判。

## 9 六档时标的真正载体：时标分段表（本轮收口）

前面 §2 的 `fov 1..6` 是**自动档位选择器**的内部枚举；真正让用户看到"六个时标"的，
是对话框里那张可增删排序的**时标分段表**（`ZTimeZoomGrid` + `TimeScaleDataSource`）。

### 9.1 类型枚举 = 日 + 一~六（硬证据）

`0x1400b94a0` 初始化一张 **7 项 QString 表**（`0x1410f12e0`，步长 0x20），
每项都是**单个汉字**，字面量取自连续短串池：

| 索引 | 值 | 字面量地址 |
|---|---|---|
| 0 | **日** | `0x1407d7d78` |
| 1 | **一** | `0x1407d7c8c` |
| 2 | **二** | `0x1407d7c90` |
| 3 | **三** | `0x1407d7c94` |
| 4 | **四** | `0x1407d7c98` |
| 5 | **五** | `0x1407d7c9c` |
| 6 | **六** | `0x1407d7ca0` |

→ **「6 个时标」就是 一 / 二 / 三 / 四 / 五 / 六 这六档，`日` 是基础档（第 0 档）**。
消费点在 `FUN_14069a840` 的 `case 1:`：`idx = row[+0x20]`，越界（<0 或 >6）强制归 0。

### 9.2 分段表记录布局（0x68 = 104 字节/行）

向量在 `ZoomTime+0x128`（begin）/`+0x130`（end），步长 `0x68`：

| 偏移 | 类型 | 列 | 列数据类型码 |
|---|---|---|---|
| +0x00 | QString(0x20) | **名称** | 1（文本） |
| +0x20 | int | **类型**（0..6 → 日/一~六） | 2（枚举） |
| +0x28 | qword | **开始**（编码值） | 8（日期） |
| +0x30 | qword | **完成**（编码值） | 8（日期） |
| +0x39 | byte | **生效** | 3（布尔） |
| +0x3c | uint | **刻度比例(%)** | 2（整数） |
| +0x48 | 容器 | 析构器 `FUN_1401e42b0` 单独释放（备注/编辑缓存） | — |

列头由 `vtable[9]`=`FUN_14069b0c0` 返回 `dataSource+0x98+col*0x20`：
`名称 / 类型 / 开始 / 完成 / 刻度比例(%) / 生效`（6 个 QString，析构按 6 项）。
列数据类型由 `vtable[10]`=`FUN_14069b100` 返回 `*(int*)(dataSource+0x158+col*4)` = **`{1,2,8,8,2,3}`**。

### 9.3 开始/完成 是"紧凑周期码"，不是时间戳

`FUN_14069a840` 的 `case 2/3` 用魔数除法（`-0x5c28f5c28f5c28f5` = 1/100）拆两位十进制：

```c
q = v / 100;  r = v % 100;
// 类型=年-月口径： swprintf(L"%02I64d-%02I64d", q, r)   → "2026-11"
// 类型=月-日口径： swprintf(L"%02d-%02d",      q, r)    → "11-14"
```

即 **开始/完成 存的是 `年*100+月` 或 `月*100+日` 的整数**，显示时才展开。
这解释了为什么一个"时标分段"能跨年（`2026-11 → 2027-03` 就是 202611..202703）。

### 9.4 增删排序 = 分段管理层

对话框底部的 插入 / 删除 / 上移 / 下移 四个按钮（moc 名表里同簇）
就是分段表的行操作；确定时 `FUN_14069cb80` 先清空 `dialog+0x428/+0x430` 向量
（逐行 `FUN_1401e42b0(row+0x48)` + `FUN_1400debd0(row)`，步长 0x68），
再由 `FUN_140261180(doc+off, dialog+0x2e8)` 整体写回。

→ **"时标刻度局部缩放"的语义**：不是给全局设一个比例，而是
**在一张「时间段 → 时标档位 + 刻度比例」的分段表里，为不同时间段分别指定档位与比例**，
段与段之间可插入/删除/排序。这正是"局部"二字的来源。

### 9.5 与 §2 的 `fov` 的关系

| 层 | 枚举 | 作用 |
|---|---|---|
| 段表（用户可见） | 类型 = 日/一~六 | 该时间段用第几档时标 |
| 自动档位选择器（内部） | `fov = 1..6` | 依据视图宽度与跨度**自动推荐**档位与间隔 |
| 像素换算（几何） | `scale ∈ [0.04,0.4]` | 六档比例 → `pos[i] = Σ step×scale` |

三者串联：**用户填段表 → 选中段的类型映射到 `fov` → 自动选择器按跨度调 `scale` → 像素表**。
`FUN_14069a4d0` 就是"改比例 → 反算 scale"的那一环。

### 9.6 段表的 4 个粒度大类

`TimeScaleDataSource` 另有一组 **4 项 QString**（`+0x18`，步长 0x20）：
`按日期 / 按周 / 按月 / 按年`，析构按 4 项。
这是段表**按粒度分组的四个大类**（不是列头），用于把 日/一~六 归到四类显示。
