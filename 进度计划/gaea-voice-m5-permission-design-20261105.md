## 2. 工具分级模型（提案）

| Tier | 定义 | 例 | 语音执行策略（提案） |
|---|---|---|---|
| **T0 只读/可逆导航** | 零副作用或即时可逆 | status 查询、板块导航 | **免确认自动执行**（现 P2 确认卡的减摩擦细化，待拍板 §7-1） |
| **T1 写本机** | 落盘本机状态、可撤销 | 提醒、存任务 | 预览+确认（现状） |
| **T2 外发/不可逆** | 出网、发消息、生成产物 | 生图（出产）、发文件、微信发送 | **可预览不可执行**（现状；未来逐项立项） |
| **T3 隐私敏感** | 读屏、OCR、麦克风外数据 | 读屏 OCR | **永久禁语音执行**（现状） |

## 3. 确认交互设计（语音特有约束）

**约束**：确认必须在「一键」或「一句话」内完成——语音场景没有稳定的键盘焦点，不能要求打字。

**主通道 = 按钮（现状已就位）**：bar/浮层的预览卡带「执行」钮。论证：点按零歧义、TTL 内随时可按、误触率最低。

**增强通道 = 语音确认词（提案：默认关，待拍板 §7-2）**：TTL 内 sidecar 仍在听，说「确认」即执行。**风险论证**：①STT 误识别「确认」（回声自打断史+同音词）→ 不可逆动作误执行；②旁人一句话即可确认——T1 以上动作不可接受。落地形态（若立项）：仅 T1 动作开启+要求完整短语「确认执行」+说话人非 AI 回声校验（EC 链已有）+每预览仅接受一次语音确认。

**反馈闭环**：执行回执走 TTS 朗读一句（现回执只上屏）——「已设好提醒，明天下午三点叫你」。避免「说了确认但不知道成没成」。

## 4. M5 模型工具的权限流（统一到 P2 台账）

```text
模型在语音对话中发起工具调用（function call）
  → 网关截获（不再透传给 4B——对话/动作平面分离，同 e211ff9e 剥 tools 的反面：识别而非剥除）
  → dry-run 评估（参数校验+Tier 判级）→ T2/T3 直接拒绝并让模型改口
  → T0 自动执行；T1 入 P2 台账 → 预览卡（bar）→ 确认 → 执行
  → 回执朗读 + 对话文本落库
```

- 台账复用：`voiceV2ActionPreview` 增 `source` 字段（user-intent | model-tool），执行层按 action 分派不变。
- **频控**：同 action 每分钟 ≤N 次（N=3 起）——防模型循环发起（tianxuan 线的循环调用教训）。
- **工具清单**：M5 首批建议只开 T0+T1 各一项（status、save_task）验证全链，再扩。

## 5. 与 Agent 工具面的边界（防越权蔓延）

- 语音工具面=**独立白名单**（本设计 §2），不读 agent 的工具注册表。
- Approver=nil 洞（agent 子代理审批全放行）未修复前，语音侧永不接 agent 执行面——两权限面互不借道。

## 6. 落地切分（拍板后）

1. **刀一（纯减摩擦）**：T0 免确认自动执行 + 执行回执 TTS 朗读。
2. **刀二（M5 通道）**：网关截获模型工具调用 + dry-run 台账接入 + 首批两工具。
3. **刀三（可选，拍板后）**：语音确认词增强通道。
