# 投标技术方案工程图件

## Overview

这套技能解决"图画出来"之后的质量问题。工程图件的核心不是装饰，而是
**用途单一、数字可追溯、示意边界诚实、程序化排版合格**。先建图件台账，
再生成，再做确定性几何体检，最后才用视觉模型核对语义。

## 强制工作流

1. **先建台账**：为每个配图位记录 `图号`、`用途`、`数据来源`、`图注`、
   `输出路径`、`状态`。不要先画后猜它服务哪一段正文。
2. **锁定用途**：一张图只承担一个主用途。深度关系、点位关系、平面关系
   不得混画；需要联合表达时拆成组图并在图注说明先后关系。
3. **核数字**：图上的面积、体积、浓度、控制量、距离、台数都必须能追到
   正文、表格、检测报告或明确的计算式。只在图上出现、正文无处核对的具体值
   一律不画。
4. **区分示意与实测**：示意边界、非比例尺、预测范围、现状照片必须写进
   图注。不得让示意线看起来像批准红线或实测边界。
5. **选确定性生成器**：统计图用 `chart_gen`；框架/流程/分层图用
   `diagram_gen`。两者回执带 `layout` 体检结果，有问题先改再交付。
6. **自绘图加体检**：matplotlib 自绘图在保存前调用本技能
   `scripts/mpl_layout_check.py` 的 `check_figure_layout(fig, boxed_labels)`。
   检查文本重叠、文本出界、节点框内溢出、字号过小；文本与表格线交叉不报。
7. **语义核图**：几何体检通过后，才用 `vision` 核对图注、数字口径、错别字、
   要素是否齐全。不得用 `vision` 的"看起来没问题"替代几何检测。
8. **交付回执**：给出图号到文件路径的清单；有版本迭代时保留最终版，不把
   `_v1/_v2/_bak` 混进交付目录。

## 图注模板

示意类：

> 图 x-y ×××示意图。本图为工艺关系示意，不按比例尺绘制；工程边界与最终
> 实施位置以进场复核放线及批准的施工图为准。

实测/调查类：

> 图 x-y ×××分布图。数据来源：《××报告》表 x / 检测报告编号××；图上数值
> 与正文口径一致。

对照类：

> 图 x-y ×××对照图。图中 a 值仅用于××对照，不作为本项目判定阈值。

## 数据纪律

- 不写未核实的窑名、运距、筛孔尺寸、含水率控制值、掺入百分比、车辆台数。
- 不出现本方案未采用的工艺路线。若必须作否定说明，放在正文，不在图上画成
  一条容易被误读为实施路线的流程。
- "约""预计""控制上限"必须说明口径；不能把估算写成实测。
- 图上编号、图例、正文引用使用同一套名称，避免同物多名。

## 图面验收口径

- 文本-文本交叠面积达到较小文本框面积的 18% 即报硬问题。
- 文本超出画布、节点文字超出节点框，报硬问题。
- 字号小于 6pt 报硬问题。
- 字体没有 bold 变体时，必须改用有 700 字重的字体，或用字号/颜色承担层级；
  不允许只留下 `findfont` warning。
- 文本穿过线条、表格分隔线贴近字底边，默认不报；这些可能是有意的排版关系。

## 工具与边界

- `chart_gen`：统计图，自带 `layout` 报告。
- `diagram_gen`：框架图/流程图，自带 `layout` 报告与节点框溢出检查。
- `scripts/mpl_layout_check.py`：自定义 matplotlib 图的可导入检查器。
- `vision`：只做 OCR、内容识别、图注语义核对；不提供几何合格证明。

## 交付前检查单

- [ ] 每个配图位都有图号、用途、数据来源、图注、文件路径。
- [ ] 图上具体数字均能在正文/表格/检测资料中追溯。
- [ ] 示意图已声明"示意、不按比例尺、边界以复核放线为准"。
- [ ] 自动排版报告为 `ok`，或所有 `warn` 已解释并修复。
- [ ] 图注与正文口径一致，错别字和未核实值已清除。
- [ ] 最终目录只保留交付版本，不混入临时稿和废弃版本。
