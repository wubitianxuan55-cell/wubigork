# 造价组价校验判定口径（cost-compose）

## Overview

组价校验引擎是 gaea 内核的**通用机制**（`CheckComposeComponents` 金额自洽 +
`CheckContentBaseline` 含量对照，确定性纯函数，结论随证据链展示与留痕）；**判定
参数是行业经验值 = 数据资产**——默认表随构建内置，本目录 `params.json` 可部分
覆盖，改口径不改代码。

## 判定规则与默认参数

### 金额自洽（R1-R3，逐行 + 全局）

| 规则 | 判定 | 默认参数 | JSON 字段 |
|------|------|----------|-----------|
| R2 非正值 | 含量≤0 或单价≤0 → warn「含量/单价须为正」，该行非法（跳过 R1、不计入合计） | 固定语义，不可调 | — |
| R1 金额一致性 | \|amount−含量×单价\| > max(0.01, \|amount\|×1%) → warn | 绝对下限 0.01；相对容差 1% | `amountAbsFloor` / `amountRelTol` |
| R3 超推荐价 | Σ(合法行 amount) > 推荐价×1.05 → warn | 超出比 1.05 | `totalOverRatio` |
| R3 低于推荐价 | Σ < 推荐价×0.5 → info「注意管理费/利润/税金口径」 | 低于比 0.5 | `totalUnderRatio` |

### 含量分位带对照（同类条目池）

| 判定 | 口径 | 默认参数 | JSON 字段 |
|------|------|----------|-----------|
| 最少样本 | 同标题同单位样本不足 → 静默不比对（宁缺勿误） | 3 例 | `minContentSamples` |
| 带外判定 | q>P75 偏高 warn；q<P25 偏低 warn；P25==P75 时按 ±5% 容差 | 容差 5% | `degenerateBandTol` |

匹配键=标题归一精确相等+单位归一相等（双方都空视为可比）；一方缺失一律不比。
基线源=用户自己的成本库（私人记忆哲学），外部行业区间数据源不引入。

## 如何改判定口径（覆盖文件）

在当前工作区建 `.gaea/skills/cost-compose/params.json`（部分字段即可）：

```json
{ "amountRelTol": 0.03, "minContentSamples": 5 }
```

- **部分覆盖**：只写要改的字段，其余用内置默认（0.01/0.01/1.05/0.5/3/0.05）。
- 非法值（≤0）字段被忽略、保持当前值；JSON 坏损显式报错，不带病运行。
- 保存后下一次组价会话生效（每进程懒加载一次）。
- 也接受 `.agents` / `.agent` / `.claude` 惯例目录（`.gaea` 优先）。

## 判定纪律

- warn=数据可疑需人工修正；info=口径提醒，不阻断确认。
- 结论随 CostComposeView.Checks 展示并随 Apply 留痕——改参数只影响**之后**的
  组价会话，已留痕结论不受影响。
- 带内静默降噪：没有把握时不开口。
