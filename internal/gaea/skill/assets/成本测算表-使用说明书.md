# 成本测算表 使用说明书

> **适用**：测算样表（`cost_library action=template` 取到的那份 .xlsx，内嵌种子 v5.5）以及任何由它填出的项目测算簿。
> **本页与样表绑定发放**，并取代《三级树表测算模版-结构说明与适配规范》v5.6——那是 2026-11-26 的版本，已按现行程序修正并入（修正处见附录 B）。
> **做测算的顺序**：读本文 → 取样表 → 查库定价 → 填表 → 两道门 → **交用户检查，同意后入库**。
> 行数多时按标题只读需要的节（`read_file` 的 `section`）。

# 第一部分 用法

## 一、30 秒总则

- **样表里的内容全是示例。** 每组「2 个定额块、每块 4 行工料机明细」只是占位，**不是数量限制**。一条清单实际由几道工序组成就挂几个定额块，一条定额实际消耗几种工料机就写几行明细——1 块合法，5 块也合法；每块 3 行、12 行都可以。
- **不要迁就槽位**：槽位不够就按第三节加行；不要为了塞进 4 行而删工序、把一条定额硬拆成两块，更不要只写 4 行就停（实测因此整块定额丢失、合计静默偏低十几万）。
- **只有「综合单价」表是导入造价库的硬契约**；其余五张表是参考，可按项目改版式。
- **这份表要经用户检查同意才能入库**（见第十二节）。草稿、没过门、用户没看过的表一律不入库。

## 二、编制流程

| 步 | 做什么 | 用什么 |
|---|---|---|
| 1 | 对齐口径：范围、计价方式、地区（省）、计价期 | 问用户；缺项先问，不猜 |
| 2 | 取样表 + 本说明书 | `cost_library action=template` |
| 3 | 摸库：本专业有哪些定额、工料机什么价 | `cost_project action=quotas / resources`（带 specialty） |
| 4 | 填工料机价格表 | 库里有就引用库内码与价；库里没有的询价后填 |
| 5 | 在综合单价表上编制（清单 → 定额 → 明细） | `xlsx_apply`；行数多用脚本（写 `.gaea/work/`，样式照样表原型行复制） |
| 6 | 两道门 | `xlsx_recalc` → `cost_library import_project dry_run=true` |
| 7 | **交用户检查**：给出工作簿路径 + 关键勾稽结论 | 用户明确同意后才去掉 dry_run 正式入库 |

清单怎么列：范围、工艺、工程量以**设计文件**（技术方案、图纸）为准；询价 / 报价文件只取价格；以往测算表只做价格参考。清单行优先用可计量的物理单位（m³ / t / m² / 点次）；「以项包干」的大项拆成工程量 × 定额单价；水、电、燃气等投入要素进定额含量行，不单设清单行。

歧义指令先确认再动手：用户说「按模板编制 / 在模板上做」时，先确认是**在模板原件上填**还是**按模板的结构口径重建**——两种理解会差一整轮返工。

用户提修改意见返工时，在交付说明里维护一行式修订记录（轮次 / 改了什么 / 依据），交付时逐条对应。

## 三、槽位不够 / 用不完怎么办

固定骨架下第 n 组的行号：清单行 L = 4 + 11×(n−1)；第 1 块定额行 L+1、明细 L+2 ~ L+5；第 2 块定额行 L+6、明细 L+7 ~ L+10。

**清单条数少于 30：先把末尾未用的组删掉再填**（交付时不能留空骨架；从末尾删不挪动任何引用）。N 条清单：综合单价从第 4+11×N 行起删 11×(30−N) 行；清单与工程量计算从第 4+N 行起删 30−N 行；再把两处合计改到第 3+N 行。15 条清单的写法（`xlsx_apply` 一次提交）：

```json
[{"type":"delete_rows","sheet":"综合单价","row":169,"count":165},
 {"type":"delete_rows","sheet":"清单","row":19,"count":15},
 {"type":"delete_rows","sheet":"工程量计算","row":19,"count":15},
 {"type":"set_formula","sheet":"清单","target":"I1","formula":"=SUM(I4:I18)"},
 {"type":"set_formula","sheet":"费用汇总","target":"E16","formula":"=SUM(清单!I4:I18)"}]
```

**只用 1 块**：第 2 块整块留空（编码、名称都不填），导回自动跳过。不要删中间的块或行。

**一块超过 4 行明细**（第 1 块加 k 行）：
1. `{"type":"insert_rows","sheet":"综合单价","row":L+6,"count":k}`——在第 2 块定额行之前插。后面的行自动下移，清单表对综合单价的引用会自动跟着改（实测）。
2. 新行照明细行补齐：B 层级（人工 / 材料 / 机械 / 外委）、C 工料机编码、F 含量；D / E / G / H 四个公式格按 5.5 的模板把行号换成新行号。**新插入的行是默认样式**，要从上一行明细复制样式（脚本里 `new_cell._style = copy(prototype._style)` 最省事；`xlsx_apply` 的 `copy_range` 只复制值，不带公式和样式）。
3. 第 1 块定额行 H：`=ROUND(SUM(H<L+2>:H<L+5+k>),2)`。
4. 清单行 H / K / L / M 里**第 1 块**的区间扩到新行（第 2 块的区间插入时已自动下移）。

**要第 3 块及以上**：在下一组的清单行之前 insert（1 条定额行 + 明细行数），照第 2 块的定额行与明细行填；清单行 H 续一段 `+IF(F<定额行>="",1,F<定额行>)*SUM(H<明细起>:H<明细止>)`，K / M 各续一段同结构的 `SUMIF`（条件「人工」「机械」），L 续 `SUMIF(…,"材料",…)+SUMIF(…,"外委",…)`。清单行这四个公式只认写进去的块，不续写新块 = 金额与三费为 0。

**不要把同一条定额拆成两块来凑槽位**：同码重复挂接，库里只取第一块。库内定额的含量行实测最多 7 条——槽位只有 4 个，所以要会插行。

**行数多、结构不一：用紧凑布局 + 脚本**（见 5.3）。脚本要点：
- 样式只从样表三个原型行复制：清单行（第 4 行）、定额行（第 5 行）、明细行（第 6 行）；
- 先建「组号 → 清单行 / 各块定额行 / 明细区间」映射，再按映射写公式，不要按 4+11×(n−1) 推；
- 清单表 H 列引该组的清单行（第 4 行走反推公式）；综合单价 I 列引**清单表**对应行；
- 清单超过 30 条：清单表与工程量计算表末尾加行，费用汇总的 `SUMIF` 区间（`清单!$B$4:$B$33`、`$I$4:$I$33`）、清单 I1 与费用汇总 E16 的 `SUM` 区间同步扩到新末行。

## 五、综合单价表（核心）

### 5.1 列布局（14 列，A–N）

| 列 | 表头 | 清单行 | 定额行 | 人材机明细行 |
|---|---|---|---|---|
| A | 序号 | `1` / `2`…（组号） | `1.1` / `1.2`（组.块） | 空 |
| B | **层级**（唯一判别键） | 清单 | 定额 | 人工 / 材料 / 机械 / 外委 |
| C | 编码（三列共用） | 清单编码 | 定额编码 | 工料机编码（工料机价格表 A 列的值，不是「自有码」） |
| D | 名称 | 项目名称 | 定额名称 | `=VLOOKUP(C,工料机价格!$A$4:$G$9999,4,FALSE)` |
| E | 单位 | 清单单位 | 定额单位 | 同 VLOOKUP 第 6 列 |
| F | **工程量** | **1** | **换算系数**（每清单单位含几个定额单位，默认 1，留空按 1） | **含量**（每定额单位消耗量） |
| G | 单价 | `=ROUND(H/F,2)`（= 综合单价，**不含管利税**） | `=ROUND(H/F,2)` | VLOOKUP 第 7 列（不含税价） |
| H | 金额 | `=ROUND(Σ(块金额 × 块系数),2)` | `=ROUND(SUM(本块明细 H),2)` | `=ROUND(F×G,2)` |
| I | 清单工程量 | `=IF(清单!G<M>="",0,清单!G<M>)`（M = 清单表对应行号） | — | — |
| J | 合价 | `=ROUND(H×I,2)` | — | — |
| K / L / M | 人工 / 材料 / 机械 | 按块系数加权的 SUMIF 拆分（**外委并入 L 材料桶**） | — | — |
| N | 备注 | 自由文本 | 自由文本 | 自由文本 |

手填的只有：B 层级、C 编码、清单行与定额行的 D 名称 / E 单位、明细行的 F 含量、定额行的 F 换算系数。其余是公式格，不要用数值覆盖。

### 5.2 行型判别

**唯一可靠判据 = B 列「层级」**：清单 → 组首；定额 → 工序块首；人工 / 材料 / 机械 / 外委 → 消耗明细。明细区间 = 定额行下一行起，到下一个「清单 / 定额」行前。A 列多级序号与缩进只是版式，不作判据。

- 明细槽 B 列空、C 也无编码 → 未用槽，跳过。
- B 列空但 C 有编码或 F 有数 → 漏填层级的明细行：演练回执点名「层级为空」，工作簿里它仍计入定额金额，库里却缺这条消耗——补层级。
- 样表 E4:E333 上挂着一份用不上的下拉列表（含旧词「汇总」，位置也不对），层级列没有下拉校验：层级一律手填。

### 5.3 固定组结构（样表）与紧凑布局（项目簿）

```
组 n 清单行     R      = 4 + 11×(n−1)      ← B=清单，A=n
  块1 定额行    R+1                        ← B=定额，A=n.1
      明细×4    R+2 … R+5                  ← 填 B 层级 + C 编码 + F 含量 即出价
  块2 定额行    R+6                        ← B=定额，A=n.2
      明细×4    R+7 … R+10                 ← 可整块留空
清单表第 n 条对应行 = 3+n（4…33），与组号一一对应
```

**填好的项目簿用紧凑布局**——每组行数 = 1 + Σ(1 + 该块明细数)，不留空槽（实测 33 组 136 行，比固定骨架省 197 行，打印 9 页减到 4 页）。

- 紧凑布局下行号**不能再按 4+11×(n−1) 推**：生成方自己维护映射表，读表方按 B 列扫描还原，不假设等差。
- **综合单价 I 列（清单工程量）引的是清单表行号（3+组号）**，不是综合单价表自己的行号——紧凑布局下两者不相等，引错会让每行工程量错配到别的清单项（演练回执会报「清单工程量 ≠ 清单表工程量」）。

### 5.4 消耗量链与金额链

```
消耗量链：清单 F=1 → 定额 F=换算系数 → 明细 F=定额单位含量
金额链：  明细 H = ROUND(F×G, 2)                 ← 第一层 ROUND
          定额 H = ROUND(SUM(本块明细 H), 2)      ← 第二层 ROUND
          清单 H = ROUND(Σ(定额 H × 定额 F 系数), 2)   ← 系数必须进金额链
          清单 G = ROUND(清单 H / 清单 F, 2)  (清单 F=1 → 综合单价)
          清单 J = ROUND(清单 H × 清单 I, 2)
三费：    K/L/M = Σ(块系数 × 块内 SUMIF(类别))，且 K+L+M = 清单 H（外委并入 L）
取费：    直接费 = Σ 清单表合价 → 管理费 = 直接费×费率 → 利润 =(直接费+管理费)×费率
          → 规费 = 直接费×费率 → 税前合计 = 四项相加 → 增值税 = 税前合计×税率 → 含税
```

- **三层 ROUND 都要在**。库里走的是同一条链：对齐后 `cost_project action=summary` 与工作簿逐分一致；少一层就出尾差（实测 45 条清单差 747 元，先 ROUND 一层后反而变成 −967 元，补齐后归零）。
- **换算系数必须进金额链**。清单 m³、定额 100m³ 时系数 = 0.01；留空按 1 计。
- VLOOKUP 区间固定 `$A$4:$G$9999`，不要缩短（区间末行号 ≤ 工作簿最大公式行会被重算审计误判自引用）。
- **含量看编辑栏**：含量列最多显示四位小数，0.00015 显示成 0.0002、0.00002 显示成 0，计算与导回用的都是真值。

### 5.5 公式模板（按行号变量直接套用）

设组 n：`R` = 清单行，`Q1` = 块 1 定额行，`D1s..D1e` = 块 1 明细区间，`Q2` / `D2s..D2e` 同理，`M` = 清单表对应行。固定骨架按 5.3 取值，紧凑布局按映射表取值。

| 位置 | 公式 |
|---|---|
| 清单行 F | `1` |
| 清单行 G | `=ROUND(H{R}/F{R},2)` |
| 清单行 H | `=ROUND(IF(F{Q1}="",1,F{Q1})*SUM(H{D1s}:H{D1e})+IF(F{Q2}="",1,F{Q2})*SUM(H{D2s}:H{D2e}),2)` |
| 清单行 I | `=IF(清单!G{M}="",0,清单!G{M})` |
| 清单行 J | `=ROUND(H{R}*I{R},2)` |
| 清单行 K（人工） | `=IF(F{Q1}="",1,F{Q1})*SUMIF(B{D1s}:B{D1e},"人工",H{D1s}:H{D1e})+IF(F{Q2}="",1,F{Q2})*SUMIF(B{D2s}:B{D2e},"人工",H{D2s}:H{D2e})` |
| 清单行 L（材料 + 外委） | 同上结构，每块两段：`SUMIF(...,"材料",...)+SUMIF(...,"外委",...)` |
| 清单行 M（机械） | 同上结构，类别 `"机械"` |
| 定额行 G | `=ROUND(H{Q}/F{Q},2)` |
| 定额行 H | `=ROUND(SUM(H{Ds}:H{De}),2)` |
| 明细行 D | `=IFERROR(VLOOKUP(C{r},工料机价格!$A$4:$G$9999,4,FALSE()),"")` |
| 明细行 E | `=IFERROR(VLOOKUP(C{r},工料机价格!$A$4:$G$9999,6,FALSE()),"")` |
| 明细行 G | `=IFERROR(VLOOKUP(C{r},工料机价格!$A$4:$G$9999,7,FALSE()),0)` |
| 明细行 H | `=ROUND(F{r}*G{r},2)` |

块数不为 2 时：清单行 H 的每块一段、K / L / M 的加权段**各续各的**。只用 1 块时第 2 段留着也无妨（空槽的金额是 0）；要第 3 块就必须续写——漏续则那块金额为 0、三费不平（演练回执会报）。

| 1 | 清单 | Q01 | 垫层 | m³ | 1 |
| 1.1 | 定额 | D-A1 | 垫层浇筑 | m³ | 1 |
| | 人工 | L01 | （公式） | （公式） | 0.1 |
| | 材料 | C20 | （公式） | （公式） | 1.02 |
| 1.2 | 定额 | D-A2 | 垫层夯实 | m³ | 0.5 |

## 六、清单表（参考表）

列：A 序号、B 分部、C 编码、D 项目名称、E 工序特征、F 单位、G 工程量、H 综合单价、I 合价。

- H 列：第 4 行与综合单价首组清单行同址，走反推公式 `=IF(综合单价!I4=0,0,ROUND(综合单价!J4/综合单价!I4,2))`（避开重算审计的同址自引用误判）；其余行直引 `=ROUND(综合单价!H{组清单行},2)`。
- I 列：`=G×H`。首部：A1 标题带、G1:H1「直接费合计（元）」、I1 `=SUM(I4:I33)`。
- 分部（B 列）非空即有效分部，费用汇总按它归集。
- **版式可以改**（它是参考表）：按单项工程 / 单位工程分段、加列、调列序都行。程序按**列名关键词**定位，不看列位：「单项工程」「单位工程」列可以顶替「分部」；表头可以不在第 3 行（搜到第 30 行，优先带「编码」列的那一行）；分段标题行与小计行自动跳过。列名保留 编码 / 名称 / 单位 / 工程量 即可。
- 工程量以本表为准；本表没有这一行、或工程量格空着时，取综合单价「清单工程量」列的值（先 `xlsx_recalc` 才有）。

## 七、费用汇总表

行 1 标题带、行 2 说明、行 3 取费链表头。

- **分部构成段**：行 4 段落条 → 行 5 子表头 → 行 6–15（10 行公式骨架，B 列填分部名即自动汇总）：
  `C=IF($B6="","",COUNTIF(清单!$B$4:$B$33,$B6))`、`D=IF($B6="","",SUMIF(清单!$B$4:$B$33,$B6,清单!$I$4:$I$33))`、`E=IF($B6="","",IFERROR(D6/$E$16,0))`。
- **行 16 直接费合计**：`E16 = SUM(清单!I4:I33)`；F16 自动勾稽，显示「✗ 差 x」即分部归集与清单累计不一致。
- **取费链行 17–23**：二 企业管理费 `=ROUND(E16*D17,2)` → 三 利润 `=ROUND((E16+E17)*D18,2)` → 四 规费 `=ROUND(E16*D19,2)` → 五 税前合计 `=ROUND(E16+E17+E18+E19,2)` → 六 增值税 `=ROUND(E20*D21,2)` → 七 含税总造价（行 22）→ 八 招标控制价（占位，不据本表反推）。
- 费率列 D17–D21 预填的 5% / 4% / 0% / 9% **只是样例**，按项目改；**0 = 该段显式不计取**，不是漏填；> 1 需向用户确认口径。费率存小数（5% 存 0.05），不是文本。
- 分部段（D=金额、E=占比）与取费链（D=费率、E=金额）同列不同义，读表时按行号区分。
- 行 25–30 是说明注释区，不参与计算。

## 八、工料机价格表

列：A 编码、B 自有码、C 类别、D 名称、E 规格 / 计算式、F 单位、G 不含税单价、H 来源、I 备注。

- **A 列编码是综合单价明细行的引用键**；B「自有码」留空待库发码，不是缺漏。
- **空白骨架**：按项目查造价库后逐行填写（`cost_project action=resources`），可按 人工 → 材料 → 机械 → 外委 分批。
- 类别必须四值之一（C 列有下拉）。
- **填了编码与名称的行，G 列不得空价**：空价在综合单价里按 0 计，清单金额静默偏小（演练回执会点名）。
- 工料机按省分行：同一种工料机每个省一行（编码不同）。地区只到省。
- 价格是不含税单价；改价后清单、综合单价、费用汇总按公式链自动重算。

## 九、工程量计算表

列：A 编码、B 名称、C 数值、D 单位、E 公式 / 口径、F 来源、G 去向、H 备注。C 可为数值或 `=清单!G` 引用；E 是文本算式（溯源用）。**不落库**：工程量只认清单表 G 列，本表是溯源底稿——这里改了数、清单表 G 列不动，入库仍是旧量。

## 十、封面

- **B2 是项目名**（入库即项目名）；D10「项目名称」与它同步填写。
- 项目概况（行 10–15）：建设地点、专业 / 计价期、计价方式、工期、编制依据。封面上写明的专业 / 地区 / 计价期，只在导入参数没给时拿来兜底，仍要过字典校验。
- 主要工作内容（行 18–24）、主要工程量（行 27–30）、编制说明（行 41–44）按项目改写。
- **结果摘要（行 33–38）全是公式**：F33 `=费用汇总!E16`、F34 `=费用汇总!E17`、F35 `=费用汇总!E18+费用汇总!E19`、F36 `=费用汇总!E20`、F37 `=费用汇总!E21`、F38 `=费用汇总!E22`——不要手填。
- 签署栏在行 47（编制 / 审核 / 批准 / 日期）。

# 第三部分 入库

## 十一、导入造价库：边界与读取规则

**测算簿走快速通道 `cost_library action=import_project`**（现行程序：综合单价表是唯一硬契约，见下）。别的格式的资料（报价单、手算表、别的软件导出的表）走模型读表导入。

**导入边界：三表落库，三表不落库**

| 表 | 落库内容 | 落成库内什么 |
|---|---|---|
| 工料机价格 | 有效资源行 | 工料机（按身份 + 省份 UPSERT）+ 一条价格事实（期 + 地区） |
| 综合单价 | 每个定额块（1 定额行 + 明细行） | 定额（含含量行）；块内换算系数进该定额的工程量 |
| 清单 | 清单行 | 项目清单项，1:N 挂接定额块 |

| 表 | 不落库 | 它的值怎么进库 |
|---|---|---|
| 封面 | 全部 | B2 项目名 |
| 费用汇总 | 分部构成、取费链、金额 | D17–D21 四费率进项目；控制价行读进项目控制价 |
| 工程量计算 | 全部 | 不进；工程量只认清单表 G 列 |

**读取规则**

- **综合单价表（硬契约）**：表名含「综合单价」；表头有 层级 / 编码 / 名称，且有 工程量 列；行型看层级。不合规**整份拒收**——旧「行类」版式已停用。库内的 1:N 挂接、换算系数、消耗行全靠它。
- **其余表是参考**：有就读、没有不拦。缺清单表 → 工程量取「清单工程量」列；缺工料机价格表 → 消耗行按库内既有编码解析，库内没有的按零价核算；缺费用汇总 → 费率落 0。演练回执逐条告警。
- 清单表里有、综合单价表里没有的编码：补进清单并告警「消耗量待补」。
- 口径参数 specialty / region / period 必须是字典值（`cost_library action=dict` 查看；地区只到省）。
- 同码幂等：重导同一份表走更新，不制造重复。

**演练回执（dry_run=true）会报什么**：项目与口径、规模、工程量来源、取费、取费链核对、同名项目、跳过行明细（表名 + 行号 + 原文摘要）、告警、将被拒收的工料机行、**疑似明细行溢出**、**工作簿内对账**、落库口径。

- 跳过行的常见原因：清单行缺编码（整组跳过）、清单编码重复出现（只取第一组）、定额行缺编码（整块跳过）、明细行层级为空、明细行有含量却没有工料机编码。
- **疑似明细行溢出**：定额行的编码却是本簿工料机价格表里的工料机编码——上一块的明细行超过 4 条顺着往下写，盖住了这一块的定额头。这几块整块跳过，工作簿里的金额同样偏低。按第三节在块内插行。
- **工作簿内对账**：拿工作簿自己的缓存值按金额链逐级复算（定额行 = Σ明细；清单行 = Σ(定额 × 系数) 与按明细重算；三费拆分；「清单工程量」与清单表引用；直接费合计；工料机空价）。对不上就回表修，修完 `xlsx_recalc` 再演练。

**模型读表导入（非测算簿资料）**

```
import_open（project 口径 + controls 控制数）
  → import_add（先工料机、再定额、后清单；每行带 src = 工作表名 + 行号）
  → import_check（控制数 / 回读核对 / 单价对照）
  → 用户确认 → import_commit
```

- 手写数组每批 ≤200 行。**行多时走文件**：让脚本从资料直接生成行 JSON，`import_add` 带 `resources_file / quotas_file / bills_file=<工作区路径>`（单文件 ≤2000 行，字段与数组相同）——数字不经模型转录。被退回的行改好后只重发那几行（同码只带改动的字段）。
- `import_status` 回读暂存区；加 `export=<路径>` 可导出成 JSON 与你的载荷文件逐行比对。
- 改费用汇总的费率、改工程量计算表的数量，都不会经这条路同步进库：费率用 `cost_project_apply action=update_rates`（或 `import_open` 的 `project` 给四费率）；工程量在清单行上给。

## 十二、两道门与入库红线

1. `xlsx_recalc`：回执写「零错误，达到交付门」才算过（未用槽位的「空结果」公式不算问题；想让表干净可用 `xlsx_apply` 的 `clear_where` 清掉）；没过按回执点名的问题修了再重算。
2. `cost_library import_project dry_run=true`：核对项目名、规模、口径、跳过行、将被拒收的行；「工作簿内对账」必须打勾，「疑似明细行溢出」必须为 0。

**入库红线：测算表必须经用户检查同意后才能导入造价库。** dry_run 通过 ≠ 可以入库。把工作簿交给用户（可点击路径 + 直接费 / 含税合计 + 过门结论 + 已知遗留），**等用户明确说可以入库**，再去掉 dry_run 正式导入（会弹确认卡）。半成品草稿入库会污染造价库，事后修改很麻烦。

入库后：`cost_audit` 机检 HardCount 应为 0；`cost_project action=summary` 与工作簿对账（库内现算 vs 导入快照）。

## 十三、核查清单（交付前按序过）

| # | 查什么 | 谁来查 |
|---|---|---|
| 1 | 行型只看 B 列；A 列缩进只是版式 | 解析器 |
| 2 | 换算系数进没进金额链（清单 H = Σ(定额 H × 系数)） | 演练回执自动（清单行金额 ≠ Σ(定额 × 系数)） |
| 3 | 金额链逐级复算：明细 → 定额 → 清单，三层 ROUND | 演练回执自动（定额行 = Σ明细；按明细重算） |
| 4 | 三费勾稽：K+L+M = 清单 H | 演练回执自动 |
| 5 | 引用行号：清单表 H 列引该组的清单行；综合单价 I 列引清单表行 | 演练回执自动（清单表综合单价、清单工程量两处） |
| 6 | 三处合计一致：清单 I1 = 费用汇总 E16 = 分部段合计（F16 打 ✓） | 演练回执自动（直接费合计）+ 费用汇总 F16 目检 |
| 7 | 取费链逐段复算；费率 0 = 显式不计取 | 演练回执「取费链核对」 |
| 8 | 工料机价格表 G 列无空价；类别只四值 | 演练回执自动 + 「将被拒收的工料机行」 |
| 9 | 空槽：明细行 B 空且 C 无编码 = 无效槽 | 解析器自动跳过 |
| 10 | 交付门：`xlsx_recalc` 零错误；版面（长表横向、按宽适应、表头行重复） | `xlsx_recalc` / `xlsx_audit` 版面段 |
| 11 | **用户检查同意** | 你：交工作簿，等用户点头 |

## 十五、常见错误（都是实测踩过的）

| 现象 | 原因 | 处置 |
|---|---|---|
| 某条定额整块丢失、合计偏低 | 明细行超过 4 条时顺着往下写，盖住了下一块的定额头 | 按第三节插行；演练回执报「疑似明细行溢出」 |
| 清单项人工 / 材料 / 机械全是 0，或三费不平 | 明细行漏填 B 列层级；K / L / M 没续写新块 | 补层级；续写三费公式 |
| 整组没导进去 | 清单行没填编码，或同一编码出现两次 | 补编码；编码唯一 |
| 工程量全为 0 | 没重算，「清单工程量」列没有缓存值 | `xlsx_recalc` |
| 工程量错配到别的清单项 | 综合单价 I 列引了综合单价表自己的行号 | I 列引清单表行（3+组号） |
| 新加的定额块金额为 0 | 清单行 H 没续写新块 | 续写公式 |
| 综合单价与库内差几分到几百元 | 少了一层 ROUND，或系数没进金额链 | 补齐三层 ROUND |
| 金额明显偏小 | 工料机价格表单价为空 | 填价 |
| 清单合计对不上 | 删了末尾的组却没改 I1 / E16 的区间 | 改到第 3+N 行 |
| 用户审阅时被退回 | 留着空骨架、硬凑第二块 | 先删未用的组；定额块按真实工序定 |
