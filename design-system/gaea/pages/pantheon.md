# gaea 板块蓝图 · pantheon 众神殿（议事厅 / 立题卷）

> 页面级规范覆盖 `MASTER.md`。本版为 2026-10-31「首页重设计」后的当前态；
> 功能、数据绑定、状态机与测试契约以 `frontend/src/pages/PantheonPage.tsx`、
> `frontend/src/pages/pantheon/PantheonComposer.tsx` 为准。

## 设计判断

众神殿不是聊天首页，而是一间本机议事厅：

- **先看问题，再看席位**：首页以“立题入口 + 本机席次图”组织，不用通用 SaaS
  三卡、居中营销 Hero 或第二套仪表盘。
- **本机与边界可见**：只读运行、可入席人数、四位 Agent 的真实就绪状态都在首屏
  可读；状态同时使用文字、点位和位置表达，不只依赖颜色。
- **两段式入口**：卷首负责建立议事语境与进入动作；立题卷负责填写议题、范围、
  参与者、轮次和材料。需要展开的字段按需披露，不把表单一次全铺开。
- **金只做判断落点**：月华金用于主行动、当前状态、规则编号与收束线；正文保持
  中性高对比，不使用紫蓝 AI 渐变。

## 立题结构

- 宽屏主画布 ≥980px：左侧“议题卷”承载问题、材料与补充背景；右侧“议事配置”
  纵向收束工作空间、参与席位、发言顺序与讨论参数。议题始终是唯一视觉主角。
- 窄画布：按“议题卷 → 议事配置”单列回流；材料与补充背景仍紧随议题卷，不跳到
  配置之后。工具栏自动换行，开议按钮保持 44px 高且始终留在可视区内。
- 议题使用可见 `<label>`；空值仅在失焦后显示就近错误，使用 `role="alert"`，
  开始按钮同步保持禁用。输入后错误即时解除，不使用提交后才报错的旧模式。
- 图片附件在开议前逐席校验 `image-input` / `image-path-tools`；不支持当前附件的
  席位必须点名显示并阻止开议，后端执行同一 preflight，不能只靠前端提示。
- 主行动只有一个：“开始讨论”。工作空间、路径、汇总人、轮次与顺序均为辅助
  配置，展开材料/背景不会改变主行动的视觉层级。
- 主输入与既有提交字段、绑定、testid 保持不变；议事形态只新增可选 `preset`
  字段与 `pantheon-preset` 控件，新增视觉仅使用既有主题令牌。
- 工具栏增加“议事形态”：`圆桌会诊`、`定向质询` 与 `红队评审`。后两者是辅助配置，
  不能压过议题主输入；选择后议事路径固定为“独立开场”，并在记录摘要中可回看。

## 视觉令牌与工艺

| 项目 | 规则 |
|---|---|
| 底色 | 沿用天玄 / 当前主题的 `--md-sys-color-bg-layout` |
| 强调 | `--pantheon-accent` / `--pantheon-accent-strong`，不新增硬编码色 |
| 卡片 | `--pantheon-surface-raised` 实底信息面，叠加低比例金雾与 1px 内高光 |
| 标题 | 项目衬线字体栈；首屏 `clamp(35px, 3.45vw, 50px)`，负字距、两行断句 |
| 圆角 | 首页席位图 `5px 28px 5px 28px`，内部件更紧；避免全页统一胶囊 |
| 背景 | 主题色低透明径向 washes + 无障碍隐藏的“議”轮廓；不依赖外部图片 |
| 动效 | 入场 520–600ms；席位错峰 55ms；hover 位移 ≤2px；全部支持 reduced-motion |

## 纪要页 · 分歧台账

- 共享讨论流和独立席位详情用动作徽标显示“主张 / 质疑 / 回应 / 修正 / 补强 /
  拓宽”。动作只是辅助辨识，不替代原始发言。
- 质疑、回应与修正下方显示关系条：被挑战命题、目标贡献、目标分歧与回应结论；
  贡献 ID 过长时中部省略、悬停可看全文，不撑破单列。
- 动作解析失败不隐藏发言，只在运行警示中说明；界面不把未知格式伪装成有效关系。
- 台账置于轮次进度下方，先于协作拓扑；首次出现分歧时自动展开，用户可手动收起。
- 每条记录按“提出轮次 + 提出者 + 当前状态”组织；`待收口 / 已撤回 / 保留异议`
  同时使用图标、文字和语义色，不只依赖颜色。
- 台账摘要标明来源“定向质疑 / 剩余分歧”；定向质疑条目显示目标贡献与被挑战命题，
  回应后保留“回应结论 / 回应证据”，不用颜色或末轮汇总覆盖原始异议。
- 用户插话是第三类来源“用户插话”：生成同源台账条目，正文与贡献 ID 可定位；
  席位接受后闭合，部分接受或拒绝时继续保留，不另做一套“用户意见”列表。
- 至共识模式若没有新的可执行核验动作，共享时间线明确显示“停止空转”；用户可从
  事件文本理解为什么提前进入汇总，不能只看到轮数悄悄缩短。

## 结论页 · 独立确认与行动提案

- 红队评审在结论区显示独立确认分布“支持 / 有条件支持 / 反对”，每席保留理由、
  条件与相关分歧；不使用团队评分或 Agent 胜率。
- 若出现反对且主席修订，结论区显示修订理由，原小结与版本哈希进入纪要；
  修订不覆盖原稿，也不抹除反对。
- 行动提案以独立浅色记录面展示动作、理由、依赖、验收证据、建议负责人和风险，
  固定标注“只读 / 不会自动运行”。
- 行动提案不是待办；用户签注只确认小结，不能凭该动作自动派工或写盘。
- 摘要行分别标明“主张方 / 异议方”；主张方只按明确引用的贡献归因，
  未定位时显示“未定位”，不推断其他席位属于哪一边。
- 每条记录保留“分歧依据 / 翻转条件 / 下一步核验”；撤回条目另列“撤回依据”。
  缺失字段明确显示“未提供”，顶部同步提示待补数量，不以空白冒充已闭合。
- 主席逐条审阅以独立浅色记录面展示“建议撤回 / 建议保留 / 交用户裁决 / 先补核验”，
  并注明“仅作整理建议，不替代提出者撤回”；审阅不能覆盖台账真实状态。
- 撤回条目写明撤回轮次与去向，保留异议写明结案留档；台账不在汇总后静默消失。
- 左侧档案项同步显示“N 项待收口”或“N 项分歧”，打开纪要前即可判断是否需要复核。
- 结构化字段在宽屏多列并排，≤640px 时降为单列；状态标签与元信息允许换行，
  主标题保持可断行，不产生页面级横向滚动。

## 响应式

- 主画布使用 `@container pantheon-canvas`，按真实可用宽度而非视口猜断点。
- ≤960px：首屏双栏改为单列，席位图落到标题下方；议事守则收为两列。
- ≤680px：标题允许自然换行，流程说明精简，守则改为单列。
- ≤640px：席位图改为单列，工具条换行，开议钮保持 44px 可视触达面。
- 375 / 768 / 1092 / 1440 实测主画布无横向溢出。
