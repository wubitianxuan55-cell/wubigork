# runtime 运行监测

> 覆盖 `design-system/gaea/MASTER.md`。本页是数据密集型内部运维工作台，不是营销页。

## 设计判断

- 读者：需要判断服务是否正常、定位失败请求并采取下一步的技术使用者。
- 视觉方向：单一主题强调色、实底信息层、边界和留白建立层级；绿色与红色只表达状态。
- 设计参数：`variance=5`、`motion=3`、`density=8`。动效只用于状态反馈和定位后的空间连续性。

## 信息架构

1. 页面标题与同步状态：实时、暂停、后台暂停、同步中断。
2. 运行摘要：服务、引擎、吞吐、上下文。
3. 当前判定：把异常转换为可执行关注项；窄屏时该区先于健康摘要。
4. 调用统计：范围 KPI、趋势、质量、错误与耗时。
5. 模型明细：累计口径，支持搜索、范围和排序。
6. 运行详情：推理、缓存、硬件与引擎。
7. 最近请求：搜索、失败筛选、从错误或模型直接下钻。
8. 引擎侧请求：用于核对 Prompt、Prefill、Decode 与缓存口径。

## 交互契约

- `2s` 快照轮询必须防重入；页面不可见或用户暂停时停止自动读取。
- 暂停应同时停止调用统计的自动刷新；手动刷新仍可用。
- 快照失败保留最后成功数据，但同步标志必须切换为“同步中断”，并显示最后成功时间。
- 每个关注项必须有明确动作：检查引擎、查看资源、查看失败请求或重新读取统计。
- 错误汇总和异常模型必须能定位到相应最近请求，并允许清除聚焦条件。
- 最近请求搜索覆盖模型、引擎、功能与错误文本。
- 所有资源进度条使用 `role=progressbar`；压力和状态同时提供文字，不只依赖颜色。

## 视觉规则

- 信息层不使用玻璃叠加；关注项使用左侧状态线区分，不新增另一套卡片阴影。
- 数字使用表格数字或等宽字体；正文不低于可读密度线。
- 桌面端健康摘要与当前判定并排；`900px` 以下改为单列并优先展示当前判定。
- 图表保留可展开明细表，失败标记同时使用形状与文字。
- 键盘焦点必须可见，跳转目标获得可见焦点环。
