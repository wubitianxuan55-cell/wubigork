# gaea 板块蓝图 · chat 聊天「对话工作台」

> 覆盖 MASTER。实现以 `ChatPage.tsx` + `chat-workspace.css` 为页面外壳，
> 保留会话、流式回答、角色、语音、工具轨迹、Markdown/GenUI 与持久化契约。
> 技能来源：`redesign-existing-projects` 审计流程 + `ui-ux-pro-max`
> Chat & Messaging、Minimalism、键盘可达与移动端适配规则。

## 视觉性格：安静的对话工作台

聊天不是演示型 AI 首页，而是可长期停留的阅读与输入空间：

- 三栏结构明确：左侧会话索引、中央对话正文、右侧上下文；
- 侧栏信息层使用实底表面，只有输入器保留必要的玻璃和柔光；
- 单一主题强调色用于当前会话、发送、语音状态和焦点；
- 正文使用系统字体，标题收紧字距，元数据使用等宽字与 tabular-nums；
- 大面积网格只保留在中央低层，不抢正文与消息操作。

## 信息架构

### 左侧：会话索引

- 顶部为「会话」标题、折叠与新建会话；
- 搜索支持即时过滤；
- 每条会话以独立 button 作为选择目标，删除按钮为 sibling，避免嵌套交互；
- 激活会话使用强调色浅底与左缘刻线；
- `F2` 或双击重命名，`Escape` 取消编辑；
- 空态提供「新建对话」动作，搜索无结果给出退出路径。

### 中央：对话正文

- 顶部 `chat-workspace-head` 显示 `CONVERSATION`、当前会话标题、消息数/生成状态，
  右侧固定显示“本机保存”；
- 消息阅读宽度约 780px，用户消息使用右对齐单层气泡，AI 消息保持文档式阅读宽度；
- 流式光标、复制、朗读、重试、回答来源沿用原契约；
- 回答操作行提供“输出指标”展开/收起；展开后显示输入、输出、总计 token，
  首字与解码耗时，预填与续写速率，并保留缓存命中量；
- 新对话时展示紧凑欢迎屏：小尺寸声核、明确标题、状态行、任务入口；
- 输入器从绝对浮层改为文档流底部 dock，不再覆盖建议卡和历史消息。

### 输入器

- 工具行：联网搜索、深度思考、语音输入；
- 输入卡：textarea + 发送/停止，发送按钮仅在可发送时点亮；
- 键盘提示保留 `Enter 发送 · Shift+Enter 换行`；生成时显示“正在生成”；
- 语音降级时允许继续文字输入，并把“麦克风不可用”作为事实展示；
- `prefers-reduced-transparency` 与低帧率环境下不使用高强度模糊。

### 联网搜索状态

- 搜索回合在 assistant 占位区内显示单行进度，不新增消息，也不让状态卡压过正文；
- 状态覆盖“理解问题 / 正在检索 / 已找到来源 / 主源降级 / 未找到结果 /
  联网不可用 / 正在组织回答”；
- 使用图标、文字和辅助色三重表达，进度区 `aria-live="polite"`，查询词单行省略；
- 30 秒只代表“没有真实进度”，`delta`、`reasoning` 或搜索状态会重置；
  另有 120 秒绝对硬上限，超时保留已经显示的正文并提供重试；
- 不把内部枚举、引擎名或原始错误直接暴露给用户；降级与失败必须给出可理解的恢复路径。
- 回答完成后，在 assistant 正文下展示紧凑搜索卡：默认只显示状态、检索次数、
  来源数和耗时，展开后显示实际查询与最多 5 个来源链接；
- 来源项包含标题、站点、检索源和短摘要，只允许 `http/https` 链接；
- 未触发搜索的普通回答不显示搜索卡；空结果、降级和全失败仍保留卡片，
  用文字说明原因，不制造“有来源”的假象。

### 右侧：上下文

- 人格、当前模型、上下文摘要、快捷建议；
- 信息卡由嵌套卡片改为轻分隔行，避免与中央正文争夺视觉权重；
- 模型状态使用色点 + 文案；无模型/无上下文时显示真实空态；
- 导出、清空、语音设置、角色库保留，危险操作继续二次确认。

## 专用语音交互界面

语音输入不再只停留在输入框的占位文案中。点击欢迎页“进入语音对话”或输入器语音按钮
会打开 `VoiceConsole`：

- 顶部显示语音状态：聆听 / 回应 / 等待 / 暂停 / 麦克风不可用；
- 声场主区包含大尺寸粒子声核、双层轨道、音量波形与稀疏星点；
  粒子只使用单一主题强调色，用户说话和 AI 回应通过扩散、亮度和轨道速度区分；
- 语音模式自动收起右侧上下文栏，把宽度让给声场；左侧会话索引保持可用，
  退出语音后恢复原面板状态；
- HUD 由细线边角、环形轨道、雷达扫迹、实时能量谱和等宽遥测读数组成，
  装饰层不接管焦点，所有状态仍同时有文字表达；
- 右侧信息轨显示实时转写、最近一条 AI 回答与真实麦克风设备；
- 顶部状态条显示聆听/回应/等待/暂停、实际会话时长与输入电平；
- 操作：结束/开始语音、AI 回答中打断、语音设置、返回文字对话；
- `Esc` 返回文字对话；关闭或离开聊天板块时停止采集并释放语音会话；
- 语音会话绑定打开时的话题；切换话题、人格或离开聊天板块先结束当前语音会话，
  迟到的识别/回复事件不得串入新话题；
- 语音消息仍经 `ChatAppendMessages` 写入同一话题，并复用文字发送的标题、预览与
  最近活跃收尾，不产生独立数据体系；
- 麦克风失败、错误与降级全部显形，不把静音伪装成“正在聆听”。

### V2 实时语音台：声场工作台

`VoiceConsoleV2` 与 `?voicev2=1` 协议实验台共用同一套 V2 视觉语言，不再使用
左右两个等宽文本框和常驻原始日志。

- 顶栏只保留角色身份、`实时语音` 方块徽标、连接状态、设置与关闭；文案明确
  “本地实时对话，声音与记忆留在这台设备”；
- 主区为不对称双区：左侧 `VOICE FIELD` 是唯一大焦点声核，右侧 `LIVE TRANSCRIPT`
  用同一条对话流同时承载用户转写与当前助手回答；
- 声核按 `idle / listening / thinking / speaking / interrupted / error` 直接由
  实时协议相位驱动；聆听、回应分别用轨道呼吸与波形变化表达，思考用缓慢旋转与
  三点节奏，禁止用音量阈值猜 AI 状态；
- 所有状态均同时提供图标、文字和说明句；颜色只做辅助，不作为唯一信号；
- 底部控制 dock 只保留一个主操作：
  `准备本地语音 → 连接语音 → 开始聆听 → 暂停聆听`，并保留“打断本轮”；
- 依赖未就绪时切换为 `准备本地语音` 预检面，四项服务分别显示“已就绪/未启动”，
  一个按钮完成按序拉起，不使用“依赖链”等内部工程术语；
- 播放队列、协议尾屏、四服务状态收进“连接与播放详情”折叠区；主界面不常驻
  token 数、原始事件或调试日志；
- 实验台保留 endpoint、连接、开麦、取消、mock 回放与依赖启动能力，但复用相同
  声核、对话流、明暗主题与诊断折叠结构；
- `940px` 以下声场与对话流纵向堆叠；`700px` 以下控制区换行，375px 仍无横向滚动；
- 键盘焦点使用 2px 强调色描边；`prefers-reduced-motion` 与 `ui-reduced-motion`
  同时关闭轨道、波形、光标和三点动效。

## 响应式

- `≤1180px`：两侧栏收窄；
- `≤980px`：中央保持优先宽度，欢迎入口变两列，语音台转单列；
- `≤900px`：展开的会话栏/上下文面板改为覆盖式侧板，不继续挤压正文；
- `≤700px`：折叠栏变顶部浮动控制，欢迎入口单列，工具提示隐藏，顶部模式文字折叠为图标；
- 输入器、消息正文、语音台均使用可滚动主区，页面本身不横向溢出。

## 可访问性

- 提供“跳到对话内容”；
- 对话区 `role=log`、`aria-live=polite`、生成时 `aria-busy`；
- 会话选择、删除、折叠、新建均有明确可访问名称；
- 语音状态、实时转写与错误分别使用 `role=status` / `aria-live` / `role=alert`；
- 语音台打开后聚焦标题，关闭按钮和返回入口均可键盘到达；
- 所有交互保留可见焦点环；减少动效时关闭声核轨道、波形和消息入场动画。

## 流式性能与指标

- plain 与角色对话统一走后端真实流式，角色回复不再先等整段生成再由前端模拟打字；
- 语音对话按完整句子增量合成与播放，首句结束后即进入 TTS，后续句子在模型继续生成时预合成；
- 语音模式使用独立的低延迟上下文预算：保留人格状态与高相关记忆，压缩尾部低权重召回，
  并将语音回复上限收紧到适合连续对话的长度；
- 前端以 `requestAnimationFrame` 合并高频 delta，最多每帧刷新一次；
- 切换话题、停止生成和组件卸载都会取消后端 run，避免旧回复继续写入；
- 指标从流结束块的真实 usage 与首个正文分片时间计算，缺失 usage 时不伪造 token
  或速率，只展示可验证的耗时。
