## 背景与过程

续 v4.17.0（事件日志默认开启，轨迹/上下文数据源接通）之后的「继续完善」：
把两个看板剩余的占位尾巴收掉——页脚「文件活动将在后续阶段接入」、趋势图被
灰掉的「增量」按钮（Phase B 占位）、回合进行中不刷新的观感。三件事互不相交，
同一轮一并落地。

## 交付明细

### ① 文件活动时间线（上下文标签新卡）

- 后端 `contextview` 折叠新增 `FileActivity`：从工具参数确定性提取路径
  （`path`/`rel`/`source`/`destination`/`image_path`/`output` 键优先级）+
  工具→动作白名单（read_file/grep/vision/format_convert=读；write_file/
  edit_file/multi_edit/edit_lines/chart_gen/diagram_gen/screen_capture=写；
  move_file=移；ls=目录）。参数无路径但结果携带路径的工具（screen_capture）
  在结果阶段补记；bash 等无法确定性取路径的工具**诚实不造数**。
- 同一轮同一步骤内同工具+同路径重复调用合并为一条（刷新时间戳），时间线
  上限 200 条；`ContextTimeline.Files` 非 nil（空切片序列化，前端不崩）。
- 前端 `FileActivityCard`（上下文标签、事件流下方）：动作徽标（读/写/移/目录）
  + 工具名 + 路径（截断悬浮全文）+ 时间，倒序展示最近 40 条；页脚改为
  「上下文浏览器将在后续阶段接入」（文件活动不再是占位）。

### ② 增量（Delta）模式启用（Phase B 占位收口）

- 趋势图「增量」按钮去掉灰置（opacity-40）与 Phase B 标题，切换后展示每步
  相对上一步的上下文净变化（绿=净增 · 红=净减，图例随模式出现）；柱内
  `--color-success/--color-destructive` 未定义，改用与全站一致的可视化语义色
  （#22c55e/#ef4444，hex-exempt 注释）。

### ③ 运行中实时刷新（三个看板统一）

- 新 hook `useLiveReload`：订阅 gaea 事件流——运行中随事件**节流刷新**
  （1200ms，后端每事件已落盘事件日志，折叠读盘即最新），`turn_done` 立即
  刷新，running true→false 保留整轮刷新；挂载首载仍由组件负责。
- 接入轨迹 / 上下文 / Agent 网络三处，替换原先「仅回合结束刷新」的 effect；
  mock 事件总线（browser dev）同路径可用。
