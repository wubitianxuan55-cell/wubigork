# v4.162.0 · 进度计划导入导出壳内修复：原生对话框链路（2026-09-08）

> 用户实测反馈：进度计划「导入导出点击没有反应，包括菜单栏这些也是」。零可见断点的排除法定位（细节见「诊断方法论」）。

## 根因

- **导入链**：SchedulePage 隐藏 `<input type=file>` + `.click()`——**Wails WebView2 壳内不弹文件对话框**（浏览器正常）。四路导入（XML/Excel/MPP/新工程）全走此通路，全灭。
- **导出链**：`<a download>` Blob 下载——**壳内下载不落盘**。五路导出（XML/Excel/PNG/PDF）全走此通路，全灭。
- 菜单栏/下拉本身正常（壳内受信任点击实测菜单开启 9 项齐全）——用户所见「菜单栏也没反应」= 菜单开了、菜单项点了、但后续对话框永不出现的主观合流。
- 浏览器（dev 与 prod build）两通道全部正常 → vitest/tsc 全绿不可见。**只有壳内真机才可复现。**

## 修复

- **新 Go 绑定 ×2**（599→601）：
  - `GaeaReadFileB64(path)`：读用户所选文件为 base64（上限 64MB），喂给既有 Go 解析器（ScheduleImportXlsx/Mpp 本就吃 base64）。
  - `GaeaSaveFileAs(defaultName, b64)`：系统「另存为」对话框 + 写盘；返回写入路径（取消=空串）。
- **导入四路**：runMenu 壳内分支 `pickImport(kind)`= `app.PickFiles()`（既有绑定）选文件 → `app.ReadFileB64` 读内容 → 还原 File 喂**原解析器/原回执文案**（零解析逻辑改动）；浏览器回退原 `input.click()`（jsdom/浏览器用例口径不变，hidden input 保留）。
- **导出五路**：`saveExportBlob(blob, name)`（exportArtifact.ts）= 壳内 `app.SaveFileAs` 系统另存为 / 浏览器回退 `downloadBlob`；exportXml/exportScheduleXlsx/导出图面 PNG/PDF 统一切换。
- 契约同步：bindingNames.ts 重生成（601）、bridge.ts AppBindings+名字映射、mock/office.ts 两方法（浏览器 dev：PickFiles 返回空=取消、SaveFileAs 回显名字）、spaceBindings.ts 分类（+2）。

## 诊断方法论（复用价值）

1. **分层排除**：浏览器 dev ✓ / 浏览器 prod build ✓ / 壳内 ✗ → 锁定 Wails 壳特有。
2. **壳内 DOM 级调试**：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333` 启动 exe → CDP（Node25 内置 WebSocket）Runtime.evaluate + **Input.dispatchMouseEvent 受信任点击**——合成 el.click() 与真实点击在 rc-trigger 下行为不同，必须用受信任事件。
3. **原生对话框探测**：UIA RootElement #32770 搜索会漏报；用 P/Invoke EnumWindows 按 pid 枚举可见窗口（class #32770 title=选择文件）才看得到。
4. 前端诊断器（gaea.log）无 error/rejection 记录 = 排除 JS 异常类根因的快速证据。
5. 坑：壳内首页能力矩阵入口是 `[role=button]` div 非 `<button>`，querySelector('button') 找不到；冷启动渲染慢（>10s），脚本要轮询等待。
