# v4.373.0 — Reasonix (dsh) 0.1.6 内核蒸馏：溢出自愈 + 缓存对齐摘要等五刀

> 用户口径「继续优化迭代 gaea，本次优化进行蒸馏最新版的 reasonix」——对 `/c/AI/deepseek-harness`（dsh v0.1.6-alpha.2，上游同步 2026-09-19）做三域全量侦察（压缩/上下文、循环控制/护栏、子代理/计划/技能/记忆），对出真增量落地五刀。全 Go 内核，绑定面 707 零变更。侦察结论与留池 12 项落档 docs/gaea-reasonix-dsh016-kernel-distill-2026-09.md。

## 落地（五刀）

1. **刀1 上下文溢出自愈**（源：compaction-basic `agent/request-error` CONTEXT_WINDOW_EXCEEDED）——此前 gaea 收到「上下文超限」即回合失败。现在 `provider.IsContextOverflow` 分类器（七措辞：context_length_exceeded / maximum context length / context window / prompt is too long / input token count / input length exceeds / context limit，绝不误判输出侧 max_tokens）命中后：先免费剪枝陈旧工具结果 → 强制压缩 → 以 session rewrite version 验证持久进展（dsh 的 replaceGeneration 语义）→ 有界重试同一轮。采样成功即清零预算，连续上限 1 次；剪枝+压缩都无进展时如实放弃并带着真实错误结束回合，不做无效空转。无窗口配置时不动（无从自愈）。
2. **刀2 缓存对齐的摘要调用**（源：compaction-basic summarizer）——原实现=静态 system prompt + transcript 平铺成一条 user 消息，每次压缩按**全价**重付被折叠区间的输入 token。改为：会话真实 system 消息 + 被折叠区间消息**逐字原样原序**重放为前缀 + 压缩指令作最后一条 user 消息（动态注入如 todo 进度只进末尾指令消息）——该辅助调用成为上一真实请求的「真前缀」，命中 provider 热 KV 缓存按 cache-read 计价，且模型在原生对话格式里做摘要质量更好。工具 schema 经 `currentSchemas()` 与 stream() 同源解析（activeSchemas 过滤态也镜像）。renderTranscript 平铺路径退役删除。
3. **刀3 shrink 硬校验**（源：region.ts）——摘要消息的估算体积必须小于被折叠区间的估算体积，否则这次「压缩」反而更贵；不达标退机械摘要（确定性、必然更短）。压缩自此永不膨胀。
4. **刀4 force 路径多轮压缩**（源：compaction-basic compactionRetries）——越过强制水位（90%）压缩后重测，仍超就立刻再来一轮；rewrite version 只计真实落地的压缩，空转不计入既有 compactStuck 熔断（连续 2 次封顶不变）。
5. **刀5 repeat 分级提醒链**（源：guard/repeat-tool-reminder）——原实现单阈值 3 且此后每步都注入（上下文噪音）。改 [3,5,8] 三档递进：3=通用 reconsider、5=点名工具+参数预览（500 字符上限，检测键仍用全量参数）、8=终止指令（停止调工具如实交接）；4/6/7/9+ 沉默。被拒绝（deny）的调用同样计数——死磕被拒调用恰是最值得打断的循环；用户插话消费点重置链（新指引给新绳子）。

## 坑

1. **isCompactionSummary 钉住的前缀语义 vs 摘要重放**——折叠区里若有旧 digest（kept），逐字重放只到第一个 kept 消息处与上一请求分歧；system+tools 这段最贵的稳定前缀仍全命中，属可接受的部分对齐（完全对齐需重放整个含 kept 的区间，会把旧 digest 再摘要一遍，破坏「旧 digest 不可变」设计，故不取）。
2. **无进展判定必须看会话重写版本而非 compact 返回值**——compact() 对「无可折叠区」返回 nil（无错误），若按返回值判进展会把空转当成功无限重试；session.RewriteVersion() 前后对照是唯一诚实的进展信号。
