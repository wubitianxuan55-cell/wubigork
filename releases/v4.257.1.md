# v4.257.1 — 修复：真机插图报「AttachmentDataURL is not a function」（2026-09-12）

## 现象

真机（Wails 壳）点出图后，插图位显示「插图失败：e(...).AttachmentDataURL is not a function」。

## 根因

S2-3 绑定面拆分留下的兼容代理 `window.go.app.App`（`frontend/src/gaea/lib/bridge/http.ts`
`ensureLegacyAppProxy`）只按**字面名**在各板块门面里查方法，**不做 `gaeaToGaea` 短名映射**：
`api/image.ts` 的图像域 helper 直连该代理并写短名 `AttachmentDataURL`，而 OfficeB 上的真名是
`GaeaAttachmentDataURL` → 查找落空返回 `undefined` → 调用即抛 not a function。

走 bridge 代理（`app.*`）的调用点会做映射，所以角色头像、消息内联图一直正常——这解释了
「为什么只有一部分功能中招」。

同一根因波及 4 个方法：`AttachmentDataURL`（读图，原罪插图 / 章节配图历史缩略图）、
`SavePastedImage`（粘贴落盘）、`RecognizeImage`（识图）、`OCRText`（OCR）——后三者此前多被
调用点 catch 成空值，属静默失败。

## 修复

1. 兼容代理补映射回退：字面名优先 → `gaeaToGaea` 映射名 → 仍未命中才返回 `undefined`
   （诚实失败，不静默塞假实现）；
2. `api/image.readFileAsDataURL` 改走规范 bridge 路径（映射 + mock 兜底），仅当 bridge
   未认领该方法时才退回旧直连形态；
3. HTTP 模式门面补齐表加 `SinB`（移动端/调试页同口径）。

## 测试

新增 `frontend/src/gaea/lib/bridge/legacyAppProxy.test.ts`：用**真机形态的假门面**
（OfficeB 上只挂 `GaeaAttachmentDataURL`）跑 `initBridge()`，断言短名经映射命中、
字面名仍优先、未知方法返回 undefined、`readFileAsDataURL` 经映射命中 OfficeB（3 例，改前必红）。
