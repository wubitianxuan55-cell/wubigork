# 每 10 章一阶段 + 阶段内起承转合：分支与章节计划共用位置注入（v4.452.0）

> 用户指令：「把分支剧情的阶段改到每10章一个阶段，章节计划的提示词也要像
> 剧情分支一样，不同的时间段用不同的提示词，一个阶段的起承转合要做好」。
> **绑定面 743 零变更**（QuickBrainstormBranches 签名扩展 +chapterNum）。

## 阶段模型（唯一真相）

`stagePhaseOf`（create_chapter_stage.go，`stageLength = 10`）：

- 第 1 章 = **全书开篇**（create-chapter-first 三扇门）
- 第 11/21/31/… 章 = **新阶段开篇**（承接余波 + 立新驱动）
- 阶段内第 2-3 章 = **起**（布局：目标落地、埋线）
- 阶段内第 4-6 章 = **承**（推进升级：赌注/对手/关系）
- 阶段内第 7-9 章 = **转**（反转高压：揭底/倒转/爆雷）
- 阶段内第 10 章 = **合**（阶段收官：兑现、代价、留线头、大钩）
- chapterNum<=0 = 位置未知（兜底：无前文=开篇，有前文=常规推进）

stageLength 20→10 全局一处改：阶段开篇合账（stage-recap）从第 21/41/… 章
提前到第 11/21/… 章，`stage-recap.json` 文案同口径（约20章→约10章）——
分支位置、计划位置、生成合账三者共用同一常量，阶段节奏只有一份真相。

## 落地

- **分支教义**（`branchPositionContext` 重写）：起=三分支三种开局推进路线
  （正面主攻/侧翼支线/暗线布局）；承=三种升级形态（赌注加大/对手升级/关系
  生变）；转=三种反转形态（揭底/倒转/爆雷）；合=阶段收官兑现（原文本）；
  开篇三扇门、新阶段开篇三新驱动保留。每段带阶段区间（第X~Y章）与阶段内位置。
- **计划教义**（`chapter-plan.json` 增 `story_position` P0 槽 + 新
  `planPositionContext`）：各段计划任务各不相同——开篇=引爆点前置/基调承诺/
  最小完备入场；起=阶段目标落地+埋线；承=递进升级+支线交错；转=反转高压+
  代价；合=收束兑现+留线头+大钩。全段带「不透支后段」纪律（起段不摊牌、
  承段不收束、转段把终极摊牌留给收官章）+ must 约束。
- **盲区根修**：`QuickBrainstormBranches` 签名扩展 +chapterNum（分支目标章）。
  向导主链路此前恒传 0——位置教义（含旧的 20 章四位置）在 UI 主流程从未
  生效过。CreatePage 按 `覆盖章>0 ? 覆盖章 : prevChapter+1` 下发（位置注入
  只影响教义段，章号事实源仍在后端磁盘大纲）。
