## 落地（七刀）

**安全四刀：**

1. **刀1 Host 白名单（HTTP 421）**（源 serve/hostguard.go）——绑定 loopback 的本地 HTTP 服务可被 DNS-rebinding（恶意网页把域名解析到 127.0.0.1 变「同源」）无预检驱动。`httpbridge.HostGuard` 按 Host 头比对 loopback+监听地址名单，其余 421；桥 Handler 默认挂、ServeWithToken 按监听地址派生（通配绑定豁免）；app 诊断端口（/healthz、/stack 栈倾倒）同挂。
2. **刀2 只读表修正**（源 shellsafe/effect.go + permission/bash_approval.go）——堵三个可自动放行任意代码的洞：移除 `env`（`env VAR=x rm …` 间接执行）、`awk`/`sed`（程序体可 system()/`e` 命令执行 shell、`-f` 脚本同样可以，字符串层不可分类 → fail-closed 交审批；上游保留 -f 例外依赖其「已记忆规则」模型，gaea 自动放行无此前提）；cargo 移除 check/doc（执行 crate 的 build.rs）仅留 search；find 补 -ok/-okdir；git 补 --ext-diff/--textconv（执行 .gitattributes 配置的外部程序）、cat-file --filters、grep --open-files-in-pager 守卫。
3. **刀3 git clean-filter 中和**（源 internal/gitcmd）——diff 是唯一会在工作树内容上跑 clean filter 的 git 子命令，而仓库 .git/config+.gitattributes 是不可信输入（克隆来的仓库可借查看 diff 执行任意 clean 程序）。gaea_git 的 gitRun 统一枚举 repo 本地 filter.* 并注入 `-c filter.<n>.clean= / -c process= / -c required=false`（恒等直通，diff 仍渲染真实变更；非 repo fail-open）。
4. **刀4 SSRF 共享件+booksource 补洞**（源 installsource/ssrf.go parity）——判据提升 `netclient.BlockedSensitiveIP / BlockedInternalIP / GuardedClient`（webfetch 委托共享谓词，loopback 放行语义不变）；booksource HTTPFetcher 默认 client 从裸 `http.DefaultClient` 换守卫版——书源 URL 是用户配置但可被诱导注入规则的输入，此前可被引向内网/云元数据（169.254.169.254、100.100.100.200）。

**内核三刀：**

5. **刀5 收尾判定**（源 run_loop.go Deterministic natural-turn completion，v1.37 删 completion-validator）——reasoning-only 的干净 stop 即最终回答（思考完整收束而正文为空：不再强制可见文本、不再注 nudge 重试，上游实测重试无收益）；真零内容响应=冻结请求原样重放（不注入合成 user 消息污染缓存前缀、不落库空历史），上限 3 次不变，超限如实报错。emptyFinalRetryMessage 退役。
6. **刀6 前台输出运行中内存上限**（源 shellrun/bounded.go）——bash 输出缓冲改为 Write 即封顶：head 1MiB + 滚动尾 64KiB + 截断标记（含丢弃字节数），内存峰值恒 ~1.07MiB/流。`yes`、失控构建这类不退出命令不再能打爆 app 内存——与「退出后再截断」是本质区别。
7. **刀7 compactStuck 新消息解锁**（源 context_manager.go stuckInputHash）——压缩卡死熔断绑定当时会话形状（stuckAtMessages）；之后新增的消息产生新折叠边界、压缩可能有救，自动解锁重试（旧熔断是会话级永久，只能等 prompt 自然回落）。mid-turn 路径不再提前短路。

## 坑

1. **gaea 自动放行模型下 -f 脚本没有豁免资格**——上游 awk -f 例外依赖「已记忆规则」（用户批准过具体脚本）；gaea 只读=直接自动放行、无批准记录，-f 脚本同样可 system()，故 awk 整体退出只读面而非照抄上游的 -f 例外。蒸馏判据要带上「上游该机制的前提在本地是否成立」。
2. **测试假站走默认 fetcher 的用例会被安全刀打碎**——TestDownloadChaptersExplicitList 未注入 Fetcher，守卫上线后 127.0.0.1 假站被拒；安全刀落地时先全仓 grep 假站/httptest 用例的 client 来源。
