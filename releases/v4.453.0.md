# 角色库「与主角的关系」：AI 随机生成，范围 全部/剩余全部/个人（v4.453.0）

> 用户指令：「小说角色库增加AI随机生成与主角的关系功能（可选全部、剩余全部
> 和个人等功能）」。**绑定面 743→744（+1：CharacterGenerateProtagonistRelations）**。

## 数据面

- `characterlib.Character` 增 **ProtagonistRelation**（json `protagonistRelation`，
  2-8 字关系短语，如 师妹/宿敌/结拜兄弟）。
- SQLite `characters` 表增 `protagonist_relation` 列（migrateSchemaV2 幂等补列，
  旧行默认空串）；store 四处 SELECT（getOn/FindByName/List/DrawRandom）+
  upsert + scanCharacter 同步。

## 生成链

- 字段收编 `libFillKeys`/`libRandomKeys`/`libRandomLabels`/`libSnakeFallback`：
  编辑器「与主角关系」字段行 + 每字段 ↻ AI 单字段随机免费获得；
  「随机补齐」（fill）也把它算进空缺。
- `characterGenerate` 注入【与主角关系】段：
  - **主角锚点**：库内 `RoleType=protagonist` 卡的姓名+性格摘要；
  - **已用关系避重**：库内其他角色已占用的关系短语尽量避免雷同；
  - **口径**：只输出 2-8 字短语，与双方设定自洽；
  - 主角本人 → 恒输出空串；库内无主角卡 → 按世界观虚构兜底（编辑器单字段
    路径不堵死）。
- `prompts/character-generate-single.json` output 契约 + `protagonist_relation`
  + must 约束。

## 批量绑定与 UI

- **`CharacterGenerateProtagonistRelations(mode, name)`**：
  `all`=全部（除主角本人与助手人格，覆盖重写）/ `missing`=剩余全部（只补
  空白）/ `one`=个人（点名单个）。无主角卡诚实报错指路；主角本人请求友好
  报错；逐角色广播 `character-fill-progress` 进度（与一键补齐同通道）。
- **UI**：筛选栏「AI 主角关系」Dropdown（全部〔覆盖须确认〕/剩余全部）；
  Inspector「AI 主角关系」个人钮；编辑器字段行 + ↻；批量进度提示条。
