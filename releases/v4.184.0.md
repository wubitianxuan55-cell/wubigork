# v4.184.0 — 小说主路径接通：blob 章物化场景 + 加场景走 CreateScene + 章节体检进检查器（2026-09-09）

> `docs/gaea-outlook-longterm-plan-2026-09.md` 阶段一 1A 出口刀：不再平行两套
> 生成管线假装是一个产品——创作侧 `CreateChapter` 仍写整章 blob（保持兼容），
> 但阅读页从此真正接进 v4 场景制：逐场景生成有 id 可用、加场景真落盘、
> 章节闸门从假门面变成检查器里的手动体检。

## 1. blob 章物化接进场景制（Go）

- 根因：`CreateChapter` 写 `chapters/NNN.md` 整章 blob；V4 项目下
  `GetChapterScenes` 走 `SceneManager.List()` 只认场景文件——创作生成的章
  一个场景都没有，阅读页逐场景生成按钮全部禁用（「该场景无绑定 ID」）。
- 新 `ensureBlobChapterScene(pm, chapterNum)`（scene_gen_handler.go）：纯 blob
  章首次触碰场景 API 时，把 blob 全文物化为首场景（slug=`chapter`、标题取
  大纲章标题（`gateOutlineTitle`，缺省「第N章」）、status=done）。
  **幂等**：已有场景或无正文时不动盘；**失败只降级**——物化失败仅 warn，
  不阻断 GetChapterScenes/CreateScene 主流程。
- 两处接线：`GetChapterScenes`（V4 分支，读列表前置）+
  `CreateScene`（建新场景前置——先物化首场景再建，新场景自然排第二）。

## 2. 阅读页加场景走 CreateScene（前端）

- `ChapterEditor.addScene` 从「`onUpdate('scenes', [...scenes, ''])` 只改
  React 数组」改为：`CreateScene(chapterNum, scene-N, 场景 N)` 真落盘 →
  重拉 `GetChapterScenes` 取权威 id 序 → 文本框数对齐 id 数（物化增框）→
  新场景生成按钮立即可用。
- 双降级：分支章（branch 无场景 API 语义）与 CreateScene 失败时回落本地
  加框（提示不落盘），不丢输入；加场景按钮 loading 防重复提交。

## 3. RunChapterGate 挂检查器（不再是假门面）

- `RunChapterGate` 本就在 NovelB 门面（bindings_novel.go）与 wailsjs 生成层，
  属 legacy 直调面（drift.ts ExcludeNames 在册）——规划所谓「不在
  NovelBindings」实为前端从未消费。本刀挂进 `NovelInspector` 阅读页分区：
  **「章节体检」单按钮手动触发**，合并渲染 分析/审查/一致性/AI味 四路
  （章节质量 x/10、情节质量 x/100、一致性 N 处疑点、AI 味 N 分 + 首条建议），
  单路失败诚实降级显「未启用」；换章自动弃旧报告。**不是每章盖章向导**。
