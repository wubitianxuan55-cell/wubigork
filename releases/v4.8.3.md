# v4.8.3「微信图片双向」

> 发布日期：2026-08-30 ｜ tag：`v4.8.3` ｜ 基线：v4.8.2（ba36c89）+ 五个增量提交
> （1bfd41d / 2cca12a / b1921e9 / cda6522 / 72e11e3）

## 背景与过程

v4.8.2 发布当日用户真机实测微信通道，暴露三组问题：①回复慢 + 夹杂随机
字母 ②微信要图只回本地路径文本 ③发图给 bot 识别乱。日志实证逐一定位后
当日五刀修复，其中图片双向升级为真协议实装（取代 v4.8.2 的推断探针）。

## 交付明细

### ① 识图排障（1bfd41d）
- **乱字母根因**：「你是谁」命中搜索触发词「是谁」→ Bing 无关英文摘要注入
  提示词 → 角色扮演模型把网页片段混进回复。修复：`isIdentityQuestion`
  守卫（你是谁/你叫什么/你会什么/介绍一下你…）跳过 auto-search。
- **慢主因**：chat 路由在本地 35B Q4（首问冷加载 24s、稳态 10s/轮），属
  模型选择非代码缺陷（已在对话中建议换绑）。
- 顺手修：WhisperChat 日志预览 `userMsg[:80]` 按字节切汉字出 `\xe6\x81`
  伪影（误导排查为提示词损坏）→ rune 化。

### ② 微信出图回推——真机 `delivered`（2cca12a → b1921e9 → cda6522）
- 协议定稿（三方印证：本机抓包实测解密 + hermes-agent weixin.py 生产实现
  + openilink SDK 导出符号）：
  `getuploadurl{filekey, media_type:1, to_user_id, rawsize, rawfilemd5,
  filesize(PKCS7), aeskey}` → `upload_full_url` 密文直传（application/
  octet-stream，响应头 `x-encrypted-param` = 下载票据）→ `sendmessage`
  `image_item{media:{encrypt_query_param, aes_key, encrypt_type:1},
  mid_size}` + caption 独立文本补发（图先文后，失败整体降级单条文本）。
- 实装：`media_crypt.go`（Go 无 ECB，手写 AES-128-ECB 块模式 + PKCS7）、
  `media_upload.go`（真链路 + 各失败节点抓包 + 全败降级文本卡片逐字节
  不变）。
- **接线修复（cda6522，真凶）**：SendFileCard 真实现在包内就绪后生产路径
  仍是孤儿——whisper_state 把 CardPath 拼成「（产物：路径）」文本返回。
  接线后 CardPath 非空即真调上传；handle 空回复守卫防空文本泡。
- 真机验证：`upload_probe stage=delivered`（一只猫咪.png 全链路送达）。

### ③ 微信发图识别——真机两连发通过（b1921e9 → 72e11e3）
- 入站真形态：`type=2` + `image_item{aeskey(32hex), media{full_url(novac2c
  CDN), encrypt_query_param, aes_key(base64-of-hex)}}`，无 url/file_id/
  name/md5（抓包实证）。
- `DownloadImageEncrypted`：dial-time SSRF（私网/回环/CGNAT 全拒、不走代
  理防绕过）+ 20MiB 双保险 → AES-128-ECB 解密 → **魔数终审才落盘**（解密
  失败零残留）；`DownloadImage` file:// 分支限 TempDir 前缀 + 魔数终审。
- **识图模型升级（72e11e3）**：多模态 Qwen3.6-35B 主模型优先（真机探针
  实测视觉链路完好；手写体显著强于 OCR 专线；与聊天同体常驻显存零额外
  开销；OCR 式提示词只提取文字不描述画面），失败回退 PaddleOCR → MinerU
  → OvisOCR2 既有三级链。真机验证：解密+识别 33/45 rune 两连发。

### ④ 关键坑（全部锁死进协议文档 docs/ilink-non-text-protocol.md）
- 入站图片 `type=2`（早期猜 3 错）。
- `aes_key` 必须 base64(**hex 字符串**)——base64(原始字节) 接收端灰框。
- 上传域与扫码登录 baseurl/redirect_host **无关**（v4.8.2 媒体域假设作废，
  无需重扫）。

### ⑤ 抓包基建留存（2cca12a）

  upload_probe 三类，未注册 no-op + 全失败静默，排障可用。

## 本版教训

- **build.bat 无条件打印成功块**（从不检查 wails build 退出码）——判断构建
  成败唯一可信标准 = exe LastWriteTime（本次两轮假成功即此坑）。
- **pwsh 5.1 `Set-Content -Encoding UTF8` 写 JSON 带 BOM** → vite jsonLoader
  炸（`"name"... is not valid JSON`）——改 JSON/package.json 一律
  `[IO.File]::WriteAllText + UTF8Encoding($false)`；ReadAllText 会吞 BOM
  导致检测假阴性，验证必须看原始字节。
