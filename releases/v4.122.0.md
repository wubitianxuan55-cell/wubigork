## 一、本刀内容

### 1. 数据模型（types.ts / types.go 双侧同构，JSON 字段一一对应）
- `ResourceType`：work（工时）/ material（材料）/ cost（成本）三类（对齐 Project）。
- `SchedResource`：id/name/type + unit（材料计量单位）/ standardRate（元/工日、元/单位）/ costPerUse（每次使用）/ maxUnits（可用上限，仅承载）。
- `SchedAssignment`：taskId/resourceId + units（工时投入，默认 1）/ quantity（材料固定总量）/ amount（成本资源金额）；(taskId,resourceId) 唯一。
- `SchedTask.fixedCost?`（任务固定成本，元）；`SchedProject.resources?/assignments?`——全部 optional，旧文件零迁移可读。

### 2. 成本 rollup 引擎（cost.ts / cost.go 纯函数镜像）
- 公式（确定性，无隐式行为）：work=工期(工作日)×units×费率+每次使用；material=总量×单价+每次使用；cost=金额。effDur 复用 cpm 的有效工期口径（里程碑=0，费率项自然归零）。
- `CostResult{ok, rows(叶任务 fixed/assigned/total), byResource, total}`；分组行不入 rows（汇总=子孙求和，视图层滚动口径）。
- **fail-closed**：CPM 循环依赖 → ok=false 成本不出；悬空引用分配跳过（引擎只算在册数据，闸在 Validate）。
- 金额 rollup 后四舍五入到分（math.Round/Math.Round 同律，正值同向）。

### 3. 两道闸（分工同现状：容错进板块、拒绝落盘在 Go）
- 前端 `normalizeProject` 扩展：补 resources/assignments 空数组；坏形条目逐条丢弃（坏类型/空 id/负值/NaN/Inf）。
- Go `Validate` fail-closed 扩展：资源 id 唯一非空+类型合法+数值非负有限；分配引用存在+(taskId,resourceId) 唯一+**分组行禁止挂分配**；FixedCost 非负有限。Load/Save 一体生效（agent 与板块同受约束）。

### 4. 测试（镜像纪律，同批场景同批期望值）
- TS cost.test.ts 13 例（work/material/cost 三公式、fixedCost、里程碑每次使用、镜像样板、旧计划零值、循环 fail-closed、悬空跳过、到分舍入、units=0、手动任务工期计成本 + normalize 演进 3 例）。
- Go cost_test.go 9 例 + project_test.go 5 例（含 Save/Load roundtrip 往返保资源）。
