# gaea v3.0.2 发布说明

> 2026-08-16 · **移除运行态看门狗**（用户决策：看门狗反复误杀办公板块回合）

## 变更

### 移除运行态看门狗（internal/gaea/control/watchdog.go 整体删除）

**背景**：T6-2.4 引入的看门狗（墙钟 10 分钟 / 停滞 30 秒）反复误杀办公板块回合，
报错形如：

```
看门狗终止回合：stalled: no progress for 30s
turn terminated by watchdog: stalled: no progress for 30s:
bridge: chat stream: 等待 API 槽位: context canceled
```

根因：停滞检测只豁免「工具执行」与「等待用户输入」，**模型调用等待期**（请求发出
→ 首 token，或信号量排队）期间无任何推进事件，30 秒即判停滞并取消回合上下文，
x.ai 首 token 慢 / 并发排队时几乎必然触发。此前已尝试以 ModelCallStarted/Done
事件豁免模型等待期，仍无法覆盖所有场景（信号量等待等），用户最终决策**整体移除
看门狗**。

**改动**：

- 删除 `internal/gaea/control/watchdog.go`（WatchdogConfig / watchdog / watchdogSink）
- `controller.go`：移除 Watchdog 字段、装配、beginWatchdog、runTurnGuarded（回合
  直接走 runOneTurn，panic 兜底保留）
- 删除 `controller_watchdog_test.go`（10 个看门狗测试）
- `event.go`：移除 ModelCallStarted / ModelCallDone 事件
- agent 4 处模型调用点（stream / Plan / compact / judge）移除豁免事件 emit
- `session/log.go`、`gaea_handler.go` 移除对应映射与过滤

**保护仍然存在**：ai.Client 的流空闲超时（默认 60s，idleTimeoutBody）与
ResponseHeaderTimeout 仍兜底模型流挂死；回合 panic 恢复保留。
