# v4.40.0「对话式改图 · 百炼引擎 + 微信发图即改」

> 发布日期：2026-09-02 ｜ tag：`v4.40.0` ｜ 基线：v4.39.0 ｜ 绑定面 **557 零变更**

## 定位与来源

微信助手专项调研（`docs/market-research-2026-09-02b.md`）A 刀。定位（用户拍板）：
微信 = 与 gaea 对话进行各项工作的通道——聊天/出图/改图/收发文件/多微信并行。
本刀补「改图」缺口：微信发一张图 + 一句指令 → 编辑出图 → 图片卡回推。

实施方式：三路并行子代理（引擎线 / 接线线 / 前端线，文件所有权互斥），主代理定
跨线契约并收口（含 EditImageFromCard 改未导出保绑定面 557、两处越权白名单收口）。

## 交付

- **① 百炼改图引擎**（`internal/ai/image_dashscope.go` 新建）：阿里云 DashScope
  多模态生成端点（同步免轮询，官方契约核实后实装：POST `/api/v1/services/aigc/
  multimodal-generation/generation`，Bearer 认证，`input.messages` 单图单文，
  parameters 只发官方字段）。默认模型 `qwen-image-edit-plus`（可选 edit/plus/max
  系列）；仅支持 img2img（txt2img/t2v 诚实报错）；改图不传 size 保持原图比例
  （size 星号格式自动转换）；响应 24h URL 自动下载转 data URL（同 GLM 口径）；
  输入图 10MiB 上限；kind=`dashscope` 注册表自注册 fail-closed。
- **② Key 管理**：config 新增 `dashscope_api_key`（secure 密文落盘，saveSetters
  登记，启动旧明文一次性迁移）；SetImageBackend 绑定追加第 5 参（方法名不变，
  绑定面零变更），传空保留存量 Key。
- **③ 改图意图 + 微信接线**：intent 层新增 `ActionEditImage`——动词∧指代双门槛
  保守正则（「把这张图的背景换成海边 / 去掉图里的路人 / 刚才那张图调成黑白」，
  画一张仍归生图；无动词或无指代不接管，宁漏勿误）；入站图片旁路 hook
  （`Server.OnInboundImage`，OCR 识图链路零改动——vision 红线）→ 助手级图片缓存
  （`wx_edit_cache/` 自持副本、TTL 10 分钟不活跃、同助手只留最新、10MiB 上限、
  魔数探 mime）；`routeIntentWithResultForAssistant` 内部变体（GaeaRouteIntent
  绑定零变更）；缓存未命中/面板与语音入口=不接管回落聊天；产物走现成 CardPath
  图片卡回推链。
- **④ 改图执行核心**：`editImageFromCard`（**未导出**，不进绑定面）——img2img/
  N=1/无 size，落盘同 GenerateMedia 口径返回 cardPath；非改图引擎（xai/glm/
  ollama）诚实报错「当前生图引擎不支持改图」。经 `imageEditor` 接口断言消费
  （并行线编译解耦，落地后运行时命中）。
- **⑤ 前端**：绘梦引擎切换器新增「百炼改图」（txt2img 下 disabled+Tooltip「百炼
  仅支持改图」，残留态警告框）；img2img 门禁三处白名单同步（ControlPanel/
  ImageGenPage needsComfy/useImageGenQueue 拦截，文案含百炼）；设置页 ImageGenPanel
  新增百炼 Key 密码框（只写不读，留空=不覆盖）；模型区 dashscope 帮助文案。

## 边界与已知限制

- 微信改图依赖当前生图后端支持 img2img（comfyui/herdsman/dashscope）；未配置
  百炼 Key 且无本地引擎时诚实报错（不静默降级）。
- 缓存只留每个助手最新一张入站图；「上上张图」类多图指代不支持。
- vision 识图链路未动（红线）；绑定面 557 零变更。
