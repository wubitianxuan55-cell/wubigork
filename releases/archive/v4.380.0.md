# v4.380.0 — dsh 蒸馏第三弹·子代理编排：Fork 型子代理 + 结构化输出补完 + V10.36 对齐复活

> dsh 留池再进两刀（余 5）：Fork 型子代理（上下文继承方向）+ 结构化输出补完（结果回收方向），凑成「子代理编排」一组。全 Go，绑定面 711 零变更。**顺带根修一个被测试当场抓出的既有缺陷**：V10.36 子代理 schema 缓存对齐自 P0-1 回合重置加入起就是死代码。

## 落地（两刀 + 一根修）

1. **刀1 Fork 型子代理（dsh subagent-fork-in-process 蒸馏，~百行机制）**——
   - `task` 工具新增 `fork: boolean`：子代理以**父会话完整历史做种子**开跑——带完整上下文的委派，模型不再需要把前文手工粘贴进 prompt。
   - **取道不取器的缓存账**：种子自带父 system 首消息（不再注模板系统提示），子请求前缀与父请求逐字节一致 → provider KV 缓存直接继承（fork 的第一轮采样近乎免费）；这就是上游「父会话平衡前缀做种子」的本义。fork 路径不发 TemplatePrefix。
   - TaskTool 实现 `tool.ContextualTool`（父历史经 executeOne 盖章的 ToolContext.Messages 注入，字节即父会话真相）；Execute 直调形态（技能/测试）无父上下文时如实报错。
   - 组合禁忌：`fork` × `run_in_background`（种子会话生命周期与回合绑定）× `continue_from`（续跑自带历史，种子冲突）× `retry_until`（重试循环自管会话）均拒绝。
   - 会话统一在 runSubSession 本地持有（原 RunSubAgent 把会话藏在内部拿不到）——fork 种子与刀2 的 guard 同会话重入共用这一重构。
2. **刀2 结构化输出补完（dsh outputSchema/两阶段捕获/terminal guard 蒸馏）**——
   - 原实现的 `output_schema` 只在父级事后验：子代理根本不知道要产 JSON，不合法就丢回父级重派（整轮重跑）。补完三件：
   - **schema 注入**：output_schema 追加进子代理 prompt（`[OUTPUT FORMAT]` 格式指令），子代理在运行时就知道终答形态。
   - **terminal guard**：终答非合法 JSON → **同一会话纠偏重入**（合成 nudge 消息，热前缀缓存成本极低），有界 2 次；仍不合法如实降级为诊断前缀+原样文本（宁带原样不造假）。
   - **剥围栏**：`stripJSONFences` 剥掉模型常见的 ```` ```json ```` 围栏后再验（护栏误杀的最大来源）。
   - 会话本地持有重构使持久化路径（transcripts）与临时路径都能重入同一会话。
3. **根修：V10.36 子代理 schema 对齐复活**——
   - P0-1「每轮重置 activeSchemas」无条件清 nil，把构造期注入的 `opts.ActiveSchemas`（子代理父对齐 schema，V10.36 缓存对齐）在**第一轮就抹掉**——对齐自重置加入起就是死代码，fork 测试当场抓出（子请求 schema 数 1 vs 父 2）。
   - 修法：New 存构造期基线 `baseSchemas`，回合重置恢复基线而非一律 nil。主代理基线为 nil，重置语义与历史逐字节一致（动态过滤 SetActiveSchemas 照旧回合间失效）；子代理从此每轮都保持父对齐 schema。
   - 两个 V6.0 测试钉的是「死形态」（子请求=过滤后 subReg 目录）——按复活后的设计改写：**请求目录=父注册表全量（缓存对齐）；执行面过滤（meta-tools/持久化写入不继承）由 buildSubReg 注册表承担**，两者分开断言。一层委派红线不破：子代理调未授权工具得 unknown tool 错误。

## 坑

1. **「每轮重置」类清理会把构造期注入的配置一起抹掉**——重置要回到「基线」而不是「零值」；死代码的辨识靠端到端断言请求形状（schema 数 1 vs 2 当场暴露），单看配置流是看不出来的。
2. **V6.0/V10.36 两代测试钉着互相矛盾的行为各活各的**——对齐复活前两边都绿（因为对齐是死的）：修复一处会让另一处的历史断言爆开，改的是断言不是实现（实现才是设计意图）。
3. **RunSubAgent 把会话藏在内部**——凡是需要「同会话二次进入」（guard 重试）或「会话预置」（fork 种子）的功能，都要把会话持有上移到调用方；签名重构时顺带统一了两条路径。
4. **executeOne 会把工具结果包进信封 JSON**——测试透过信封断言内容（Contains），别假设裸文本。

## 升级说明

- `task` 工具新增 `fork` 参数、`output_schema` 语义增强（子代理可见+会话内纠偏）：工具目录随新会话生效。
- 子代理请求目录从此为父注册表全量（此前因缺陷实为过滤后目录）：子代理调用未授权工具将得到 unknown tool 错误而非不可见；执行面白名单/红线不变。
- 无破坏性配置变更；fork/guard 均为模型按需触发的行为。
