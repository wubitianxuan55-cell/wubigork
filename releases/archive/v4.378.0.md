> Reasonix（esengine/DeepSeek-Reasonix v1.15→v1.38）真身蒸馏第四弹，全 Go，绑定面 711 零变更。三刀落地后，`docs/gaea-reasonix-v138-distill-2026-09.md` 留池 9 项全部销号（落地 8 + 辨伪并入既有），真身蒸馏线收官。同日对账 dsh 0.1.6 留池销号 3 项（12→9）。

## 落地（三刀）

1. **刀1 bash 会话状态锚定（留池⑤主值落地）**——
   - `cd`/`export`（含导出函数）跨 bash 调用存活：会话内第一条命令 `cd build && export FOO=1`，之后所有调用直接落在 `build` 目录、看得见 `$FOO`。工具描述同步改口（状态持久语义+不更新形态）。
   - **取道不取器——进程不持久，状态持久**：上游 persistentshell 是单进程 PTY+marker 协议+分帧（Windows 需 conpty）；gaea 的 bash 链路（每调用新进程+Job Object 灭树+boundedOutput 运行中封顶+超时硬杀）深绑「无状态进程」形态，PTY 化处处打架。本刀保留全部既有进程语义，只把 cwd/env 锚在会话上。
   - **漂移治理在「观测」不在「推断」**（上游廉价近似=盲缓存 cwd 前缀注入的病根）：命令真实退出时 EXIT trap 采集终态——cwd 经 `cygpath -w` 转 host 形（MSYS `$PWD` 的 `/c/...` 形 `exec.Cmd.Dir` 不认），env 用 `export -p` 全量转储、下次调用前置 `eval` 重放（转储即真相，不做差量解析）；显式 `exit` 走 trap 照采且退出码 `exit $__gaea_rc` 原样传播；被杀（超时/取消是 taskkill /F 硬杀，trap 不跑）、trap 被覆盖、exec 换身一律不采纳——缓存永不超前于现实。并行批次各用独立探针文件、完成序采纳（与两进程共用一个终端同语义，锁兜内存竞态）。锚定目录消失自愈回落工作空间。
   - 豁免面：PowerShell 壳（语法不通）/ WSL sandbox enforce（壳内 cwd/env 是另一个世界，host 侧锚定无效，整体退旧行为）/ `run_in_background`（任务生命周期与调用脱钩不回写；起始目录仍锚定）。
   - 会话切换（NewSession/Resume）经新接口 `tool.SessionStateResetter` 由 controller 整体重置（cwd/env/探针目录），防跨会话泄漏；恢复会话时锚定态从不持久化——重置是唯一诚实态。
2. **刀2 memory activation 二维（留池⑦之一）**——
   - 上游把事实「怎么触达模型」立为与 scope 正交的一维：pinned=正文随会话快照装配，relevant=仅索引+检索可达。gaea 的「固化」此前只有排序加权与生命周期豁免，本刀补齐正文维度：`BuildPinnedFactsBlock` 把固化事实正文预算化注入缓存稳定前缀（块 1200 rune/单条 400 rune 截断留标）——记忆面板的「固化」动作从此有功能后果（standing context）。
   - 排序刻意 Name 升序而非 recency：块 ride 稳定前缀，touch 不能翻动它（否则每次检索触碰都打碎前缀缓存）；只有固化集合本身变化才换前缀、新会话生效。门控仅记忆总开关（两空间各注入各的收窄视图——activation 与 scope 正交）；空集合零注入、前缀逐字节不变。
3. **刀3 memory subject keys（留池⑦之二）**——
   - `remember` 新增可选 `subject_key`：点名事实回答的**单值问题**（如 `project.package_manager`/`user.response_style`），同空间同键仅一条活跃值。撞键保存被**拒绝**并回报持有者名——「改包管理器」应重写原条目（revision），不是再存一篇自相矛盾的新记忆（contradiction）；同名重存=修订放行；置空重存=释放键；空键=叙事型事实不受约束。
   - 落点：`Store.Save` 统一写入侧检查（remember/面板编辑/做梦蒸馏全部经此，dream 写入不带键零影响）；SQLite SchemaV23 `facts.subject_key` 列（NOT NULL DEFAULT '' 零成本回填）+List/Get 回填；文件后端 `metadata.subject_key` 嵌套键往返（frontmatter 扁平化读回；仅声明时写出=旧文件逐字节不变）。

## 坑

1. **bash printf 的 `%s` 是 Go Sprintf 的动词**——wrapper 模板常量里必须写 `%%s`，否则 vet「format %s reads arg #2, but call has 1 arg」拒编（报错指向 Sprintf 调用点，真凶是模板里的 bash 格式动词）。
2. **MSYS 路径形态**——探针必须经 `cygpath -w` 转 host 形再采纳；直接采 `$PWD` 存进锚，下次 `cmd.Dir` chdir 直接失败（`/c/...` 不是 Windows 路径）。
3. **事件日志列与 Event 结构一一对应**——memory_events 是显式列 INSERT 不是 JSON 整包，想给事件「顺手」加审计字段就得连迁移一起加；subject_key 真相归 facts 表（与 body 同待遇：日志只留摘要），不为审计单独开列。
4. **NormalizeSubjectKey 的空白折叠与下划线不是一回事**——`project.package_manager` 归一为 `project.packagemanager`（无空白可折叠），测试里拿 `project package_manager` 当同键变体会假红；键等价只走「trim+ASCII 小写+空白折叠'-'"一条路。

## 升级说明

- bash 工具描述变更进入 system prompt 目录（新会话生效）；模型从此可以 `cd` 一次后续调用免带路径，超时/被杀的命令不更新状态。
- 记忆面板「固化」的事实正文将进入新会话系统提示词（预算 1200 rune）；不想让某条进前缀就取消固化。
- `remember` 工具新增 `subject_key` 可选参数，模型对单值事实（包管理器/发布分支/回复风格）会开始使用它；撞键报错是预期行为，按提示更新持有条目即可。
