## 二、真发现：UnifiedSearch 三调用方参数序错位（真壳上统一检索一直坏）

- **走查过程**：记忆中枢检索探针读到「检索失败，请重试」（v4.350 失败可见化三态——修复前
  这种情况用户看到的是「检索中…」一闪即无）。查 gaea.log：
  `UnifiedSearch 失败: json: cannot unmarshal string into Go value of type int`。
- **根因**：Go 绑定 `GaeaUnifiedSearch(query string, topN int, scope ...string)`
  （v2.23.0，2026-08-14 起），而前端 bridge 声明与全部调用方传
  `(query, scope, topN)`——**scope 字符串落进 int 形参**，每次调用 unmarshal 失败。
- **为何捂了一个月**：①mock 按前端期望签名写（`(query, scope="", topN=10)`），mock
  契约测试全绿——mock/真契约分叉又一例；②`bindings_completeness_test` 只收方法名不校验
  签名（在册已知坑）；③前端吞错（`.catch(() => null)` 静默），直到 v4.350 失败可见化才露出。
- **修复**（零 Go 改动、绑定面 706 不动）：bridge 接口签名改 `(query, topN?, scope?)` +
  三调用方换序（MemoryHubPage / WorkspaceSearchPanel / SearchModal）+ mock 同序 +
  mock-contract-e5 / MemoryHubPage / WorkspaceSearchPanel 三测试文件断言换序。
- **波及面**：记忆中枢三脑检索 / 工作区搜索面板跨库检索 / Ctrl+K 搜索——真壳上自 v2.23.0
  （一个月）全部失败，语义检索与跨库命中一直不可用。

## 修复确证（新壳 CDP 复验）

- 错误面变化：`cannot unmarshal string into Go value of type int`（参数错位）→
  `embedding 请求失败: Post "http://localhost:8080/v1/embeddings": context deadline
  exceeded`——请求真正到达业务层，卡在本机 8080 语义服务超时（环境事实：embedding 服务
  未部署/未启动，非前端 bug，挂观察池）。UI 三态「检索失败，请重试」如实呈现。
- 真机语义检索完全可用需先起 embedding 服务（8080），届时再补一条龙走查。

## 坑（本轮新增）

1. **mock 契约测试的信条破绽**：mock 按「前端怎么调」写而不是按「Go 怎么收」写——签名
   错位时 mock 全绿、真壳全坏。修复后纪律=mock 签名必须从 Go 绑定复制（含参数序），
   mock-contract 测试断言调用参数序与 Go 形参一致。
2. **静默吞错捂 bug 的时长与可见性成反比**：`.catch(()=>null)` 让 v2.23 起的失败消失了一个
   月；v4.350 失败可见化一次走查就拽出来了——「失败可见化」是最便宜的测试。
3. **走查探针的按钮定位优先用类名/testid**（`.hub-search-btn`），textContent 匹配会撞到
   别的按钮（「检索中…」/其他面板）得到假阴性。
