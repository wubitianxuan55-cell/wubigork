# v4.348.0 · 原罪板块优化双刀：故事底稿直注前情 + EPUB 电子书导出（2026-09-19）

> 原罪板块优化完善班两刀：①长程一致性根子上的优化——模型自己记的故事底稿（便签设定集+大纲）非空时随每轮前情直注提示词；②图文成品出口补全——故事可导出 EPUB 电子书（插图内嵌）。绑定面 705→706（+SinExportEpub，play）。

## 背景

原罪故事越长越容易「失忆」：前情只带最近 12 条历史（单条截 1500 rune），几十回合后早期设定全部掉出上下文。既有缓解是模型用 sin_notes/sin_outline 工具自己记底稿——但底稿**不在提示词里**，模型要花工具轮 read 才能看到自己记的设定，忘 read 就自相矛盾。小说板块 t3 的结论同样适用：设定一致性应该靠确定性注入，不能靠模型自觉。

导出侧，故事只有 Markdown 一种成品（插图以本地路径引用），阅读器/传设备场景缺一个内嵌插图的可分发格式；书源线已有 go-epub 先例（SinBookSourceBookExportEpub），依赖零新增。

## 落地

**刀1 底稿直注前情**
- `buildSinUserPrompt` 新增底稿块参数：大纲（write 时已限 4000 rune，防御性再截）+ 设定便签（按写入顺序，合计 `sinPromptNotesBudgetRunes=4000` rune 预算内从头带）；块位次=角色块之后、前情回顾之前。
- 超预算如实报数：「（其余 N 条未展示，需要全文用 sin_notes read 查看）」——不静默丢；被截断的末条带省略号。
- 空底稿 = 提示词与旧版逐字一致（增量不漂移）；回合中途 write 的新条目下一轮生效（装配一次/回合）。
- sin_notes/sin_outline 工具描述与系统提示词同步改口：底稿已随前情附上，通常无需 read 即可核对（省工具轮），要确认单条全文才 read；新设定仍 write 落稿。
- `sinDraftForPrompt` 取稿 fail-open：id 非法/文件缺失/损坏 = 空文档，底稿绝不阻断创作；锁内读取（工具可能正在写）。

**刀2 EPUB 电子书导出（SinExportEpub）**
- 与 Markdown 导出同一数据源（消息流 + extra.illustrations），不经过 MD 文本再解析：每条助手回合一小节（「第N回」中文序数），用户指令以引块置节首（导出含用户每一轮，同 MD 口径）。
- 插图标记就地内嵌：go-epub `AddImage`（本地路径，支持 png/jpg/jpeg/gif/svg；webp 等不在支持集→保留「插图未能内嵌」占位不硬塞）；第一张成功内嵌的插图兼作封面；未生成标记保留「插图未生成：画面描述」占位（cue 次序键优先、画面描述键兜底，与 MD 导出同规则）。
- 落 `sin/exports/` 与 sin_export 工具同目录，同名不覆盖（-2/-3）；写出失败删半截产物（书源线同纪律）；守卫/空故事拒绝复用 sinTopicGuard。
- 前端顶栏导出按钮改下拉：图文 Markdown（另存为）/ EPUB 电子书（后端落盘后 message 告知路径——二进制不走前端另存为，壳内 a[download] 是死的）；mock 模式如实抛「EPUB 导出需桌面端文件系统」。

## 坑

- ToolbarButton 无 forwardRef 且 onClick 必填：Dropdown clone 子元素注入的 onClick 会覆盖占位函数，`onClick={() => {}}` 即可——不为原罪改办公组件（板块纪律）。
- go-epub `AddImage` 收本地路径、返回值直接用作 `<img src>`；webp 不在其支持集，宁可占位不硬塞（AddImage 报错路径已兜）。
- 预算边界：单条便签恰好等于预算时 `runes > room` 为假，应整条收下不带省略号——截断语义是「超了才截」。
