# v4.147.0 · diff 确认卡刀B：schedule_apply 审批卡升级为结构化 diff 预览（2026-09-08）

> diff 确认闭环设计刀B（设计 docs/gaea-schedule-diff-confirm-design-2026-09.md §2.2）：ask 级别下审批卡本就弹出，但卡上只有「schedule_apply 当前计划」一行字——**有确认之形、无审阅之实**。本刀把卡体升级为结构化 diff：批准前先看清「改了什么、工期/成本怎么动」。决策钮/快捷键/超时/两宿主挂载全部复用 ApprovalModal 既有件，零 Go 改动，绑定面 **597 零变更**。

## 1. 纯函数层 applyDiff.ts（schedule 域，与 gschedSummary 同层同范式）

- `diffProjects(before, after)`：两侧先 normalizeProject 归一（缺省字段口径一致，不把归一差异冒充改动），纯比较输出渲染就绪结构：
  - **任务** id 键控 added/removed/modified（modified 展开字段级 from→to：任务名/工期/进度/层级/里程碑/模式/手动开始/固定成本，中文 label+单位）；
  - **搭接** 按 to 任务分组比对入边集合（与 set_links「整体替换入边」语义对齐）：added/removed/changed（type·lag 变化）；
  - **资源** upsert/删除（删除标注随行级联分配数）；**分配** (taskId,resourceId) 键控增删改（投入强度/材料总量/金额展开）；
  - **meta** 工程名/开工日期/工作日历/目标竣工；
  - **汇总行**（卡头醒目，审批疲劳对策）：总工期 X→Y 天（computeCpm 双方）、关键 N→M 项、总成本 A→B 元（computeCosts）；after 有 deadline 附倒排校核预览（可行/超期 N 天）、有基线附漂移预览（挪移/新增/移除行数）；
  - **fail-closed 预览**：after 侧 CPM 不过 → 如实标注「引擎将拒绝（CPM 不过）」——批准也不会落盘；
  - `empty`：两侧无实质改动 → 卡上直说。
- `scheduleApplyArgsOf(items)`：宿主从 Transcript 取弹卡期间 status=running 的 schedule_apply 完整 args（设计 §1.3：ToolDispatch 先于闸门弹卡）。

## 2. ScheduleDiffCard 卡体 + ApprovalModal 接线

- ApprovalModal 增可选 prop `scheduleApplyArgs`；`approval.tool === "schedule_apply"` 时通用参数原文区替换为 diff 卡体（决策钮/快捷键/hardAsk 形态不动）。
- 数据来源与降级（全部诚实口径，绝不伪造 before 值）：
  - before = `loadScheduleFile()` 文件实况（缺省路径）；**非缺省路径 → 降级「非当前计划文件，无现状对比」**仅列改动清单；
  - before 读取失败 → 同样降级；after 解析失败 →「参数尚未就绪」提示；
