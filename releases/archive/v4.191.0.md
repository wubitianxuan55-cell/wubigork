## 缺口（survey + contract 已读口径）

agent 工具表有 `cost_search`（对上历史）与 `cost_save`（确认沉淀，hardAsk），
但**组价不在工具表**——`GaeaCostCompose→Apply` 全链（检索+价格带+嵌套 LLM
拆解+V16 留痕）只在造价页 UI。会话里说一句「帮我组个价」，管家接不住。

## 实现：新 agent 工具 `cost_compose`（只读）

- **检索**：与 cost_search 同款组合（SQL → 语义补召回 → 本地精排）——检索
  基建零新建，复用 builtin 层 openCostStore/semanticCostRecall/
  rerankCostResults。
- **价格带**：`cost.ComputePriceBand`（P25/中位/P75/均值/最低/最高/样本数/
  离散度/离群数/置信度，unit 可选过滤）+ `RecommendPrice("median")` 推荐价
  与理由。
- **证据链**：溯源五元组表格（来源/地区/期数/口径，含离群甄别提示）——
  AI 组价的核心护城河原样进会话。
- **设计取舍：嵌套 LLM 拆解不做**。管家本身就是 LLM——人材机拆解由它基于
  证据自行给出（输出里明说）；也符合规划「不把组价拆成逐步盖章」。
- **确认进工程走既有门**：采用后 `cost_save` 沉淀（hardAsk 落盘门=确认进库，
  不新造门；source 建议标「AI组价」+本次上下文）。V16 留痕快照仍归 UI 全链
  （会话路的沉淀以 cost_save 条目本身为准）。
- **隔离红线**：spacetags 钉 `work`——组价是工地话题，不进会客厅
  （+TestCostComposeSpaceTag 锁）。
- compact 表登记（compactDesc/compactSchema）；绑定面 604 零变更（agent
  内部工具，非 wailsjs 门面）。
