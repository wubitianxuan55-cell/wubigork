## 落地

### ① 引擎：`DownloadChapters` 显式清单抓章（`internal/booksource/chapter.go`）

`Download` 抓取编排水从函数体抽出为 `fetchChapters`（有界并发/重试/进度纪律零变化），新增 `DownloadChapters(ctx, items []TocEntry, opt)`：按调用方给定的显式 URL 清单抓章，成功章按清单顺序归并、失败章如实进 `Failed`。空清单显式报错。

### ② app：`NovelBookSourceImportChapters(source, projectPath, chaptersJSON)`（NovelB +1，654→**655**）

- **清单来源**=整本导入 done 事件的 `Failed` 原样回传（前端无加工；清单仅存于本次会话，关闭 Modal 即弃——不做持久化/断点续传，规格 §6 不做清单照旧）。
- **同步预检 fail-closed**：规则不存在/未启用、清单空/缺 URL、项目目录无效，起跑即报错不入队。
- **追加落库**（`appendProjectChapters`）：`project.Open` → 现有最大 `OrderIndex` 续编章号 → 逐章 `WriteChapter` → 大纲节点（`imp-NNN`/done，与整本导入同编号规则不撞号）追加、**既有节点原样保留**；字数按 rune。
- **并发写核实**：`outline.Agent.SaveNode` 等写路径每次调用重读 `outline.json`（无内存缓存副本），外部 Manager 追加不会被 UI 侧旧副本覆盖。
- **进度/取消全复用**：同 `novel-import-progress:<jobID>` 通道（新增 `append-done` 终态语义），同一 `bookImportRuns` 登记簿 → 既有 `NovelBookSourceImportCancel` 直接可取消补下任务。
- done 载荷 `NovelBookSourceAppendResult{path,title,appended,totalChapters,addedWords,failed?}`——追加语义词（增量与总量分列），失败清单若再有残留可继续重试。

### ③ 前端：失败面板 + 一键重试（`BookSearchModal`）

- done 带失败清单：Modal **不再自动关闭**（关闭权收归组件——全部成功自动关 / 失败面板「完成」手动关），面板直显失败章标题（前 3 + 计数）+「重试补下 N 章」；补下中显示进度条（同每 20 章节流）+ 可取消；完成显示「已补下 M 章，全部章节已齐 / 仍有 K 章未取到」，残留可继续重试。
- `HomePage.onAppended`：刷新书架 + 增量提示；关闭守卫扩展到补下中。
