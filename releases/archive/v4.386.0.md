## 落地

1. **`GaeaCostSearchPage` 分页绑定（App 层实现，cost.Store 零改动）**——
   - 管线复用：检索管线（SQL 过滤 → Go 关键词过滤 → 语义召回 → 本地精排）提为 `costSearchAll` 助手，原 `GaeaCostSearch` 与新分页绑定共用——分页与非分页口径一致，工具面 `cost_search` 零影响。
   - 排序进服务端：sortKey ∈ title/price/updatedAt（空=管线序），**tie-break 恒定 name**——全序是跨页翻页不漂移的前提；limit 钳制 [1,200]（≤0 → 100），offset 负数归零，Total=过滤后总数。
   - 排序键不认识 → 不排序保持管线序（防御前端传错键）。
2. **CostLibraryView 分页改造**——
   - 首屏 100 条 + 尾部「加载更多（余 N 条）」；计数如实显示「已载 100 / 共 1500 条」，载完收口「1500 条」；分类树「全部条目」计数用 total。
   - 客户端排序删除（只排已载子集是错的）：表格排序点击 → 服务端排序重拉第 1 页，箭头语义不变。
   - 过期响应丢弃（reqSeq 序号）：筛选/排序变化后，在途旧响应不覆盖新状态；追加页跨页按 name 去重（翻页期间数据增删的偏移漂移兜底）。
3. **EntryPicker 切分页绑定**——测算项目「单价搜索下拉」只要 top 8，此前全表拉回后客户端截断，现在 `CostSearchPage(…, 8, 0)` 载荷从全表降到 8 行。
4. **消费面保留说明**——`CostLibraryPage` 总览 loadStats 仍用 `GaeaCostSearch` 全量（聚合统计需要全表，每次开页一次非热路径）；mock 同口径实现分页（浏览器演示态一致）。

## 坑

1. **App 层检索类测试必须断死语义通道**——`modelengine.NewManager` 种子目录 herdsman 恒 Enabled + `localhost:8080`：本机 embedding 服务在跑时，零命中查询（SQL 召回 <3 触发语义补召回）会走**真实**管线——`Stale("cost", keep)` 按测试条目集清掉真实库向量行 + `Ensure` 写入假向量。本轮开发中实际发生（真实库 cost 向量被清），已用应用自身 `GaeaSemanticIndexBackfill` 通道全量重建（1553/1553，24s），测试侧改为显式 `SaveEngine` 禁用 herdsman 断通道。教训：`hubSemanticStore`/`hubCostStore` 族 override 注入只护住了一半，`resolveHerdsmanSearchModel` 的引擎目录在测试环境是活的。
2. **`App` 嵌 `*core`：裸 `&App{}` 的 `a.engineMgr` 字段访问即 nil-core panic**——测试构造须 `&App{core: &core{…}}`（既有测试先例在 consistency_deep_handler_test 等）。
3. **分页绑定的排序必须全序（tie-break 收尾）**——同键同值的两条若无 tie-break，`sort.SliceStable` 的稳定性在不同切片边界下不保证跨页一致；name 全局唯一收尾后翻页永不漂移。同理客户端排序在分页时代必须删除：对已载子集排序是静默的错误答案。
4. **updated_at 落盘是 RFC3339 秒级**——同一测试内连发保存回读后全同秒，按保存顺序断言时间序不成立；要确定时间序用 SQL 直铺。
