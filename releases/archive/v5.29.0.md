# wubigrok v5.29.0 — Krea2 Turbo 打通 + LoRA 完整支持

**发布时间**: 2026-07-28

## 核心修复：Krea2 Turbo 生图打通

### 问题
- 绘梦 ComfyUI 生图一直失败，Krea2 模型出乱码/灰紫色图片
- Flux 模型是 inpainting 版本，无文生图能力
- LoRA 前后端断裂（前端有选项，后端未实现注入）

### 根因与解决

| 组件 | 之前（错误） | 修复后（官方工作流） |
|------|:-----------:|:------:|
| UNET | redcraft23INT8INT4FP8 | **krea2_turbo_fp8_scaled.safetensors** |
| CLIP | qwen3vl_4b_krea2 (BF16自合并) | **qwen3vl_4b_fp8_scaled.safetensors** (官方) |
| VAE | ae.safetensors | **qwen_image_vae.safetensors** |
| Latent | EmptySD3LatentImage | **EmptyLatentImage** |
| Negative | 空 CLIPTextEncode | **ConditioningZeroOut** |
| AuraFlow | ModelSamplingAuraFlow shift=3 | **无** |
| CFG | 3.0 | **1.0** |
| 步数 | 6 | **8** |
| CLIP模型 | 自反量化 FP8→BF16，缺视觉键被误识别 | HuggingFace Qwen3-VL-4B BF16 官方版 |

### 关键发现
- Krea2 CLIP 必须包含 `model.visual.*` 键，否则 ComfyUI 的 `detect_te_model` 无法识别为 `QWEN3VL_4B`
- 12GB的 `redcraft23INT8INT4FP8` 是 INT8 混合版，在 AMD ROCm 的 comfy_kitchen eager backend 下 `fast_int8_mm` 会段错误
- 13GB 的才是 FP8 版，能在 AMD 上运行但质量差
- 官方 Comfy-Org 模型最稳定

## LoRA 后端注入

新增 `injectLoraNodes()` 函数，在工作流中动态插入 `LoraLoaderModelOnly` 节点链（ID 20+），支持多 LoRA 逗号分隔链式调用。

支持的 LoRA（前端已配置）：
- Krea2: `Krea-2-Turbo-zishi_c1-st10000`, `MysticXXX_KREA2_v3`
- Z-Image: 细节增强、3D卡通、氛围光影、极致写实、女帝风格、NSFW

## ComfyUI 环境修复

发现 `standalone-env/python.exe` 需要安装 ROCm PyTorch（`requirements-amd-win.txt`），系统 Python 是 CPU-only 会导致崩溃。

**正确启动方式**:
```bash
C:\AI\ComfyUI\standalone-env\python.exe main.py --listen 127.0.0.1 --port 8188 --windows-standalone-build
```
