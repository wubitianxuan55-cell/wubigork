## Wails v2.13 变参真相（源码 + 经验矩阵双重定论）

**源码**（`internal/binding/boundMethod.go`）：`ParseArgs` 要求
`len(args) == InputCount` 严格相等，逐参 `json.Unmarshal`；`Call` 用
`reflect.Call` 直接调。变参方法 `fn(...string)` 的 reflect `In(0)=string`，
而绑定 Inputs 构建把变参参数记作 []string——**两层口径自相矛盾**：
- 传 `"x"`（1 个串）：数量对，unmarshal string→[]string 失败
  （`json: cannot unmarshal string into Go value of type []string`）；
- 传 `["x"]`（数组作单参）：unmarshal []→[]string 成功产出 []string，
  `reflect.Call` 按 In(0)=string 校验 → panic
  （`reflect: cannot use []string as type string`，被上层 recover 后
  **回调永不送达** = 前端 promise 永久 pending）；
- 传 `()` / 2 参：数量错立即报。

**经验矩阵**（真机 probe 双方法 × 7 形态 × 3s 超时，对照无参绑定秒回）
完全吻合：无任何 wire 形态能让数据到达 Go 逻辑。**结论=变参绑定在
Wails v2.13 不可用，唯一修法=绑定层不用变参。**
