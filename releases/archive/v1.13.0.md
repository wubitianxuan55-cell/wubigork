## 修复的 bug（真实运行时缺陷）

- 记忆检索双轨：buildTierBBlock 是运行时生效主流程，但 PrepareTurnContext → MemoryRetriever.Retrieve 重复实现整套检索且从未被消费——维护成本翻倍、测试测死代码 → 收敛单轨
- FTS5 索引建而不用根因：V2 外部内容表列名 `fact_id` 与主表 `id` 不匹配，rebuild 报 `no such column: T.fact_id`（12+ repo 函数全部零调用）→ V11 迁移独立表
- RebuildFactsFTS 死锁：MaxOpenConns(1) 下 rows 未 Close 时 Exec 插入 → 连接池永久等待（先读后写修复）
- 中文全文检索召回缺失：unicode61 整词匹配对中文子串弱（「美式」匹配不到「美式咖啡」整词），且 MATCH 成功空结果不降级 → 空结果也降级 LIKE + 2-gram 多模式
- 触发词检索局限：只匹配 Triggers 字段，用户提到摘要里的词（问「她平时喝什么」而触发词是「咖啡」）检索不到 → FTS 按 subject/summary/triggers_text 全文召回

## 记忆检索链路全景（v1.13.0 后）

```
对话 → buildTierBBlock（唯一检索主流程）
     ├─ SelectForInjection 全量相关性评分（weight×decay×selfRelevance×情绪）
     ├─ 触发词命中 boost 1.5x（SearchByTriggers）
     ├─ FTS 全文检索召回 1.3x（hermes.db FTS5 索引 + LIKE 中文 2-gram 降级）
     ├─ 时间感知调制（ComputeTemporalBoost）
     ├─ KG 图谱 + 情节检索 + 关联扩散 + 主动回忆
     └─ 记忆回声 → 情绪状态调制（ComputeMemoryEchoFacts）
写入 → persistFactsToDB/persistEpisodesToDB 写回后自动重建 FTS 索引
```
