# v4.248.0 — 后端性能刀C：SQLite 连接池放宽 + 批量清理事务化（2026-09-12）

## 为什么是这一刀

普查档刀C（#6+#11），风险最高单独走一刀：Hephaestus.db 是全应用共享库
（记忆/成本/分类/任务），改前 `SetMaxOpenConns(1)` 把读也串到单连接，
且是仓内两处在册死锁注脚的根源。全量回归（app 67s 等）通过后才发布。

## 修复

1. **连接池放宽 1→4**（普查#6）：WAL 模式本可读写并行；放宽后死锁类
   整体消除。写并发由 SQLite 单写者锁串行化 + DSN 逐连接
   `_busy_timeout=5000` 兜底（modernc 驱动对池内每个新连接应用 DSN
   参数，PRAGMA 不随连接切换丢失）。写事务全部「首语句即写」形态，无
   deferred 升级死锁面。`cache_size=-8000` 每连接 8MB，4 连接 ≤32MB。
   两处死锁注脚（portrait.go / whisper fts.go）更新注释，收集再写回
   习惯保留。
2. **批量清理事务化**（普查#11）：`memory.CleanupArchived` 逐条 DELETE
   （N 次 fsync）改单事务，并收紧为原子语义——改前删一半失败仍把整批
   doomed 报给审计（虚报），现在全删或全不删如实上报；`semantic.Stale`
   同款单事务。

## Benchmark（2s 时间制）

并行点查 7.6μs→2.5μs/op（**3.0×**）。

## 测试

Go +2：并发写 8 goroutine×25 全量落库零 BUSY 逃逸；写事务进行中另一
连接可读且 WAL 快照隔离——该测试在改前单连接池下会死锁，即新形态的
回归守卫。db bench 2 组入库。全量回归：app / builtin / cost / memory /
semantic / characterlib / whisper 全绿。
