## 主旨

用户指令「记忆中枢增加数据库，管理此设备上保存的聊天记录和上传的文件」。勘察结论：聊天记录实际落点是各工作区 `<root>/.gaea/sessions/[work|play]/*.jsonl`（归档在 archive/ 子树），上传文件落点是 `<root>/.gaea/uploads/`（attach-\* 聊天上传附件、paste-\* 粘贴图片，均由既有保存链写入）——两者此前只有「当前工作区」的管理入口（办公侧边栏），没有设备级总览。本版把它们作为新库「数据库」收进记忆中枢，沿用 hub 的「库管理」模式。

## 落地

- **Go 三新绑定**（internal/app/gaea_database.go，MemoryB 门面委托）：
  - `GaeaDatabaseOverview()`：按工作区统计活跃会话/归档会话（.jsonl 计数与字节，递归含空间分区与 archive/ 子树）、上传文件数与字节、最近活动时间；roots=当前+最近工作区（与 `GaeaListProjectSessions` 同口径——记忆中枢是设备级管理面，只看当前工作区会重复「办公记忆按项目过滤」的旧困惑）。只 stat 目录项不读内容，成本与侧边栏项目视图同级。
  - `GaeaUploadsList(root)`：指定工作区的上传文件列表（新→旧，kind 按前缀分类 attach/paste/other）；root 必须在白名单（数据库 roots）内，否则返回空。
  - `GaeaDeleteUpload(path)`：删除上传文件；护栏=路径必须落在白名单工作区的 `.gaea/uploads` 内（`wspath.Within` 判定），uploads 外/任意绝对路径/空串/不存在一律拒绝；root 比较双侧 `filepath.Clean`（历史 recent-workspaces JSON 可能存正斜杠路径，防误拒）。
  - `MemoryHubOverview` 加 `sessionCount`/`uploadCount`（同口径走查），供 hub 左轨数据库角标。
- **前端**：新库「数据库」（teal `#2dd4bf`，与 DOMAIN_COLORS.database 同源）挂记忆中枢左轨末位；`DatabaseLibrary` 面板=五格统计带（工作区/会话/归档/上传文件/占用）+ 聊天记录按项目原生 `<details>` 折叠（复用 `GaeaListProjectSessions` 行数据：标题/轮次/空间标/归档标/时间）+ 上传文件按项目折叠展开时懒加载。动作：会话删除与附件删除一律**两段确认**（首点变「确认删除」，再点执行）；「在文件夹中定位」走 `GaeaRevealWorkspacePath`；附件预览复用全局 `FilePreviewModal`（usePreviewStore）；删除失败横幅可见化（不静默）。会话打开/恢复仍以办公板块为主入口，hub 保持管理面定位。
- **绑定管线**：MemoryB 门面委托（完整性测试核验）、gen_bindings -signatures-ts 再生（绑定面 643→646）、bindingNames 手工同步（-names 只打印在册坑）、mappings/spaceBindings（work 面）/mock 三处认领、wails generate module 再生 models。
