# v4.326.0 · GenerationGate 闭环收口：生成后自动分析门 + 全书体检

> 2026-09-16 发布。规格书：`进度计划/gaea-gen-gate-closure-20260916.md`。
> 阶段七 §4 在册项（revolution 文档「GenerationGate 完整闭环」未勾项收口）。

## 论点

生成 done 事件只挂去味 + AI 味分 + 角色提取——**分析路从不自动发生**。
t1-P2 伏笔自动回收、t3-P1 记忆回填、t4 V2 落盘三条已建成的管道，水源只能
靠用户手动点「分析本章」，闭环名存实亡。全书层面：单章门（RunChapterGate）
与伏笔 Lint 各自孤立，没有「点一次、出全书报告」的聚合面。

## 落地

- **生成后自动门**（`novel_book_health.go`）：
  - `buildAutoGateReport`（同步可测）+ `runAutoGateAfterGeneration`（go 位
    包装 + recover 兜底 + emit `chapter-gate` 事件）；
  - 确定性三路必出（写前契约 / 写后质量 / AI 味白名单豁免后），零 LLM；
  - 分析路（一次 LLM：V2 落盘 + 伏笔同步 + 记忆回填）仅主线章——**分支章
    跳过**（V2/登记表是主线口径，upsert 会污染主线条目）；失败只 warn 降级；
  - 挂接点=create_chapter_handler done 之后（extractCharactersAfterChapter
    同款异步位，不阻塞 done）。
- **全书体检 `RunBookHealthCheck`**（+1 绑定，704→705）：触发式全量编译，
  **纯确定性零 LLM**——逐章写前契约 + 写后质量 + AI 味 + 字数；伏笔 Lint
  复用；V2 覆盖率计数；`BookHealthReport` camelCase typed（S1/S2 记阻断级）。
- **前端 `BookHealthPanel`**（CreatePage 工具栏「全书体检」）：聚合卡
  （总章 / 契约问题章 / 质量问题章 / 最差 AI 味 / V2 覆盖 / 伏笔告警数）+
  最差 AI 味 ≥60 告警（指引去味复检）+ 逐章表（越线红标）+ 伏笔 findings。

## 裁决要点

- 自动门默认武装（分析是加法数据，与既有自动角色提取同性质）；review/
  consistency 两路仍留单章门手动——成本纪律，不自动烧模型。
- `chapter-gate` 事件 V1 零前端消费：t7 章节分析面板天然是消费面（V2 在
  每次生成后保证新鲜）。

## 测试与门禁

- Go +5：自动门三例（确定性三路必出 / 分支跳分析 / agent 失败降级不 panic）
  + 体检两例（干净+脏章聚合断言 / V2 覆盖与空书）。
- 前端 +5：面板聚合渲染 / 重新体检 / 零章空态 / 失败空态 / mock 契约。
- 门禁：go build/vet 全过、internal/app 全绿（-count=1）、tsc -b 零错、
  eslint 零告警、vitest 全量、drift OK@705、计数锁 528、版本三处 4.326.0。

## 坑（沉淀）

- `analysis.New(nil client)` 在 Analyze 内部 nil 解引用 panic——测试须用
  无引擎真 client（LLM 调用走 error 返回）。
- JSX 泛型不认索引访问（`Table<Obj['rows'][number]>` 语法错）——抽 type 别名。
- `gateOutlineIssues` 找不到大纲节点返回空表=无契约可违，不计问题章。
