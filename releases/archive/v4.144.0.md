# v4.144.0 · 导入为新工程：三路导入安全化 · 非破坏口径（2026-09-07）

> 观察池销项（「mspdi 导入为新工程候选池」）：此前 MPP 二进制 / MS Project XML / Excel 三路导入一律走 `importProject` **原地整体替换当前工程**——导入一个 146 任务的 MPP 直接顶掉当前工程内容，仅靠撤销兜底；防抖落盘后原工程文件被静默覆盖，数据安全隐患 + 与 v4.139「每文件一工程」语义脱节。本轮把导入分流：**新工程=安全默认，替换当前=显式标注**。纯前端，绑定面 **596** 零变更。

## 1. store 新动作 importAsProject（importThenSwitch）

- 流程：名字空兜底「导入工程」→ `createThenSwitch`（Go `GaeaScheduleProjectCreate`：slug 去重落空工程 + 登记索引 + 自动切指针 + 重水合）→ `importProject(named)` 内容替换 → `flushDirty()` 立即落盘（不悬在防抖窗口）→ `refreshProjectsCache()` 刷列表摘要。**slug、文件内容 name、列表摘要三处同源一个名字**，不会出现「文件名 A 内容名 B」。
- fail-closed：Create 失败（`currentPath` 未变）→ 返回 `false`、`syncError` 已置位、当前工程原状——绝不半切换、绝不静默覆盖；成功则导入内容**不触碰原工程文件**（与 v4.139「办公卡复制=切指针」同款非破坏口径）。
- 同名导入不冲突：slug 去重由 Go 侧既有逻辑兜底（冲突加序号，登记条目与目录游离文件都算）。

## 2. 页面菜单重组（导入分流）

- **「导入为新工程…」=主入口**（文件菜单 + 工具栏导入下拉同源）：`.xml/.xlsx/.xlsm/.mpp` 按扩展名分发到各自解析器，文件名兜底工程名（MPP 文件内常无工程名）；成功回执「已导入为新工程「名」：N 行 / M 条搭接（口径注）」；不支持格式诚实报错且不动 store。
- 三路替换入口改显式标注「导入 XML/Excel/MPP **替换当前工程**…」——模板载入/签证调整覆盖场景保留（TemplatesPanel 的 Popconfirm 口径不变），「覆盖」语义不再隐藏在「导入」背后。
