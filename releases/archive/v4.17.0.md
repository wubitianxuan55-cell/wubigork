# v4.17.0「轨迹上下文接通 · 事件日志默认开启」

> 发布日期：2026-08-31 ｜ tag：`v4.17.0` ｜ 基线：v4.16.0 + 1 提交
> ｜ 绑定面 545 → 545（零新增绑定）

## 背景与过程

用户反馈：办公板块的「轨迹」「上下文」两个标签「根本是个空壳」——点开只有
空态/统计零值，没有任何回合数据。逐层排查（前端组件完整 → 绑定完整 →
折叠器完整）后定位根因在**数据源**：轨迹/上下文看板依赖追加式会话事件日志
（`<id>.gaea-log.jsonl`），而事件日志 sink 由 `session.log_format` 回退开关
控制，**缺省 legacy = 不接线**。用户配置 `log_format = ""`，于是 sink 从未
创建、日志从未落盘，`GaeaTrajectory`/`GaeaContextView` 恒读空日志 → 前端
恒空态。这不是 UI 空壳，是事件日志没开。

## 交付明细

### ① 事件日志默认开启（数据源接通）

- `config.EffectiveLogFormat()` 新增：**缺省 = "event"**（大小写不敏感），
  仅显式 `log_format = "legacy"` 退回旧行为（整文件重写 JSONL、不写事件
  日志）；`LogFormatIsEvent()` 改用生效值。
- `gaea_handler.go` 注入生效值（`ctrl.SetLogFormat(EffectiveLogFormat())`），
  boot 同源判断创建 `EventLogSink`——轨迹/上下文/Agent 网络三看板从下一次
  启动、第一轮对话起即有真实数据。

### ② 旧会话读端兜底（存量 legacy 会话也能看板）

- `session.ReadEntriesFor(path)` 新增：优先读事件日志；日志缺失时回退为把
  旧 `<id>.jsonl` 消息投影为折叠条目（**纯读，不迁移磁盘、不写日志**）。
- `GaeaTrajectory` / `GaeaContextView` / `GaeaAgentNetwork` 统一改用该入口，
  会话或日志都不存在时保持空快照语义（ok=true，前端空态不崩）。

### ③ 迁移/投影产物带回合边界 + 轨迹折叠兼容完整消息

- `ToLogEntries` 升级：每条 user 消息前写 `turn_started`、下一条 user 前
  （或流末尾）写 `turn_done`——迁移/投影产生的日志对轨迹/上下文折叠同样
  成立。边界条目不投影为消息（`ProjectMessages` 忽略），恢复路径逐字节
  不变（golden round-trip 测试保持）。
- `trajectory.FoldTrajectory` 兼容 `assistant_message`（迁移产物的完整消息
  形状）：正文/推理并入 assistant 记录，内嵌工具调用展开为 tool 记录并与
  后续 `tool_result` 按 ID 合并——与运行期事件流折叠结果同构。

### ④ 事件日志写入器随控制器生命周期释放

- boot 把 `EventLogSink.Close()` 挂进 `Controller.Cleanup`（与插件 host
  cleanup 组合，幂等）——缺省 event 后若控制器重建/关闭时漏关文件句柄，
  Windows 上会话目录将无法删除/迁移（测试暴露的真实面，一并修掉）。
