# v4.283.1 — 走查补刀：书源取书零注入 nil-Fetcher panic 修复（搜索/目录/导入四绑定全路径）（2026-09-14）

## 来源

v4.283.0 发布后按规格 §5 t2 验收项补做的**真机走查**（壳内 CDP 全流程，v4.277 夹具走查同款范式：本地 127.0.0.1 假站 + 临时书源规则 + 本地夹具项目，走查完即删）当场抓到 **P0 缺陷**：书架「在线搜书」点搜索即 `runtime error: invalid memory address or nil pointer dereference`——在线搜书在壳内**完全不可用**。

## 根因

`internal/booksource/fetch.go` 的 `newCrawler` 只对 `Sleeper`/`Rand` 做零值兜底，**不对 `Fetcher` 兜底**；而 `NovelBookSourceSearch/Toc/Import` 四绑定全部传 `booksource.Options{}`（Fetcher=nil）→ `WebSearcher.DiscoverySearch` / `Engine.Toc/Download` 首个网络请求即 nil 接口解引用。**单测零暴露**：引擎 34 例 + app 层 13 例全部注入假站 Fetcher（「零真网络」纪律），生产缺省通道反而从未被走到。

## 修复

一处根治、全路径覆盖：`newCrawler` 补第三项零值兜底——`Fetcher == nil` 时回落 `&HTTPFetcher{}`（引擎自带生产实现，`Client==nil` 回落 `http.DefaultClient`、`Timeout` 有缺省，`fetch.go` 注释即此意图；app 层未来注入带代理的实现仍然优先）。Engine（Toc/Import）与 WebSearcher（Search）同走 `newCrawler`，四绑定一次修净。

## 测试

Go +2（`internal/booksource`）：

- `TestNewCrawlerZeroOptionsMustNotNilFetcher`——零注入 Options 的 crawler/Engine/WebSearcher 三条构造路径 `fetch` 通道必须非 nil（回归锁：Sleeper/Rand 兜底同锁）。
- `TestHTTPFetcherZeroValueLocalServer`——零值 `HTTPFetcher{}` 对本地 httptest 夹具真实取回一页（仅回环，零真网络），证明缺省生产通道端到端可用。
