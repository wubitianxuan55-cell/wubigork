# v4.307.0 — t5 首刀：角色状态机差分更新器（水位守卫+存活级联+关系差分）（2026-09-15）

## 来源

MuMuAINovel 蒸馏线 t5 角色状态机与职业/境界域首刀（`docs/distill/05-character-career.md` §3.3~§3.6/§7.2/§7.3）。契约（`types/character_state.go` 三态水位/守卫 helper/差分输入）v4.278 已落库，差分器实现是缺口——旧 `syncCharacterStatesV2` 只把 `NewState` 直写 `Character.Status`（把心理文本写进离散枚举字段），既无水位守卫、无存活级联、无关系差分、无亲密度算法。

## 落地

- **差分更新器**（新 `internal/characterstate`，纯函数零 IO，`ApplyChapterDiff`）：三阶段严格顺序——存活（短路+级联）→ 心理 → 关系 → 职业推进 → 组织成员 → 组织自身。七条不变量全实现（spec §7.2 表）：
  1. 心理状态水位单调（`StateAdvanceAllowed`，低章节重放拒绝并记 Skipped）；
  2. 存活状态水位单调（`SurvivalStatusAdvanceAllowed`）；
  3. 存活短路：死亡/失踪/退场后 `continue`，不再更新心理/关系/职业；
  4. **存活级联三件套**（规格标注"最值得蒸馏"）：active 关系 → past+EndedAt（保留行不删除，历史可回溯）；active 组织成员 → deceased/retired + LeftAt + Notes 追加 `[第N章] 原因` 时间线；心理字段文本化 `死亡（第N章）` 并同步推高心理水位；
  5. 职业阶段 ≥1 下端钳制；
  6. 副职业上限 `MaxSubCareers=2`（修正 MuMu 四处不一致：2/5/[:2]/[:2]）；
  7. 职业推进水位守卫：副职业 `CharacterCareerRef.UpdatedChapter` 完整实现（主职业水位无独立字段，如实降级为同章幂等覆盖，码内注明）。
- **亲密度算法**（`CalcIntimacyDelta`，§7.3）：MuMu 全词典（34 词）+ **最长匹配优先、命中即停、禁子串累加**——修正实测缺陷（「不信任」在 MuMu 同时命中「信任」+10 与「不信任」-15 → 净 -5 的失真，gaea 正确 -15）；钳 ±30。LLM `DeltaHint`≠0 时直接采纳（钳 ±30），词典退为兜底（A/B 并用）。
- **关系差分**：双向无向语义（A→B 与 B→A 同一条，MuMu :377-390）；新建基线 `clamp(50+delta)`、StartedAt/Status=active/History 时间线；已存在 → Description 追加 `[第N章] 变化` + Intimacy 钳 [-100,100] 调整 + History 追加；NewType/Status 可选更新。
- **分析模板扩差分字段**（`prompts/analysis-chapter.json`）：`character_states` 增 `survival_status`（null|active|deceased|missing|retired）与 `relationship_changes`（对方角色名→变化描述）；新增**稀疏差分纪律**约束（§3.2 精髓「让 LLM 默认什么都不填」：只记录本章明确变化的角色与关系）。
- **接线**：`syncCharacterStatesV2` 委托 `characterstate.ApplyChapterDiff`（survival_status 映射 gaea Status 值域 Alive/Dead/Missing/Retired；relationship_changes 展开为逐条关系差分）；有变更才写盘；净产出（含 Skipped 计数）进 slog。
