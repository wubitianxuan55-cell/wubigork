MuMuAINovel 蒸馏线 t1 伏笔域的消费方第一刀。契约（6 态并集 + 计划回收章 `target_resolve_in` + 注入控制字段）v4.278.0 已落库，但生成侧消费仍是旧「未回收伏笔（创作约束）」单层平铺——计划回收章这个**本域最大增量**（超期预测的唯一前提）没有任何消费方。本刀按 `docs/distill/01-foreshadow-spec.md` §4 落分层注入（spec P1），生成侧收益最大且零绑定面。

## 落地

- **纯函数层（`internal/types/foreshadow_urgency.go` 新）**：`UrgencyLevel`（0-3 紧急度，运行时算不落库，D15 修正：partially_resolved/hinted 也有回收压力，缺失计划章不猜值不假超期）；`ClassifyResolve`（四值回收时机）；`ForeshadowLayerOf`（单条目分层唯一入口：L1 必须回收 / L2 超期 / L3 近期参考 / L4 本章计划埋入 / L5 无计划兜底〔gaea 扩展〕）；调度常量唯一声明（lookahead=5 上限 20、remind 缺省 5、急需阈值 ≤2、每章新建上限 5）。
- **两层修正**：`include_in_context=false` 全层排除（作者显式排除）；`auto_remind=false` 只抑制近期参考层（D8：必须回收/超期是硬约束，不因提醒开关消隐）。远期伏笔（计划章 > 当前+lookahead）不注入（防干扰）。
- **四层渲染（`internal/app/foreshadow_context.go` 新）**：`buildForeshadowSection(pm, currentChapter)` 替代旧单层注入——层标题/内容截断（L1 100、L2/L4 80）逐条对齐 spec §4.2 模板（D14 修正：截断省略号按长度判断）；L2 ≤3、L3 ≤5、总量 ≤15 条、**整区含标题 ≤1600 rune**；消耗顺序 L1→L2→L3→L4→L5（硬约束优先）；层内确定性排序（L1/L4 重要性降序缺省 0.5，L2/L3 计划章升序，L5 埋入章升序）；空层不输出标题。区段头带「调度规则」约束行（必须回收务必完成/超期优先安排/近期禁止提前揭晓/计划埋入自然埋入）。
- **L5 兜底层（gaea 扩展，防存量回归）**：存量 `foreshadows.json` 大多没有 `target_resolve_in`，严格按 MuMu 四层会让全部已埋伏笔从注入中消失——无计划的存活条目降入兜底层，保留旧「背景约束」行为（不得矛盾、勿强行提前揭穿），优先级最低。
- **接线（`create_chapter_handler.go`）**：新增 `resolveTargetChapterNum`（显式章号 / 分支取父节点章号 / 顺延新章，与 `ensureChapterNode` 定号同源并为其复用），生成 prompt 按正确「本章章号」分层。
- **场景圣经同步（`novelcontext`）**：`buildForeshadows` 改分层优先采样——同一分层入口，硬约束层（带 `[本章必须回收]`/`[已超期N章]`/`[本章计划埋入]` 标注）先于参考层（`[计划第N章回收]`/`[待规划回收章]`）输出，280 rune 预算口径不变；D9 消除：全仓分层逻辑只有 `types.ForeshadowLayerOf` 一处。
- **副本清理**：删除 `docs/mumu-distill/` 重复副本（与 `docs/distill/` 逐字节一致，v4.278 在案观察项销账）。
