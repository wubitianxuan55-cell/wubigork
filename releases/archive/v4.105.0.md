## 改动

### MH4 modelhub 常驻预热（Go：`internal/app/gaea_schedule.go` + `internal/modelengine/engine.go`）

- 启动自动预载（T5-3b）扩到 modelhub：与 herdsman 预载同一延迟节拍（10s）、同一 goroutine、同一 `auto_preload` 总闸。
- **四重门控**（任一不过即静默跳过，只记日志）：
  1. `modelHubPreloadArmed` 显式武装位（Startup 置位；同 imageHubRuntimeArmed 先例，禁「cfg!=nil 即运行态」惯性闸）；
  2. 活跃引擎跟随（`ActiveEngineID()=="modelhub"`）——规划 §四-4 单卡显存互斥：不得无条件预热；
  3. 引擎启用 + 钉选默认模型 + Key 已配置（`ModelHubKeyConfigured`，只查布尔不回传明文）；
  4. **显存互斥让路**：herdsman 预载将启动大模型（catalog 判定「已安装且未运行」）时跳过，避免两个大模型同入统一内存互相挤占。
- **幂等守护**：新增 `Manager.ModelHubModelLoaded`（轻量 GET `/v1/models` 精确 ID 匹配，含 `loaded` 字段保守放行），已加载即跳过。
- 预热动作：`StartModelHubModel` → 5s 一拍轮询收敛到 loaded（上限 6 分钟，§七实测冷加载 50s+/挤占可超 2min），超时只记日志。失败全部静默降级，不阻塞启动、不弹错。

### CU1 ComfyUI 绘梦预热（Go：`internal/ai/image_comfyui.go` + `internal/app/image_handler.go`；前端：`ImageGenPage.tsx`）

- `ComfyUIBackend.Warmup(ctx, model)`：**64×64 / 1 步**极小空跑（krea2/z-image 传 steps=1，flux 固定 4 步），复用既有 workflow 构建器——预热加载的就是下次真实生成要用的模型文件；空跑产出直接丢弃。与真实生成共用 ComfyUI 队列，天然串行无冲突。
- 新绑定 `WarmComfyUI`（ImageB 门面 → mediaState）：绘梦页首入触发，进程内一次闸 + 武装位；门控：引擎=comfyui / 模型已登记工作流（`ComfyUIWarmupSupported`）/ ComfyUI 运行中 / 无生成在途（`imageGenRunning`）；跳过返回 `{started:false, reason}`，前端零弹错。触发时机=「绘梦模块首次进入」，**非 gaea 启动**（§六-2：开机常驻 8GB 生图模型会挤掉聊天主力）。
- 门面生成：`gen_bindings` 重生成（585）；receiver 默认归 image 面，无需 explicitOverrides。

### CU2 fp8 量化档位引导（纯前端：`modelcenter/utils.tsx` + `ImageSection.tsx`）

- `COMFY_MODEL_CHECKPOINT`：逻辑模型 → checkpoint 文件名（与 Go 侧 txt2imgWorkflows 构建器同源锚定，仅展示层）。
- `comfyModelQuantFlag`：文件名含 `fp8/scaled` 判定为量化高效档（krea2 ✓；z-image bf16 ✗；flux 文件名无标记诚实不猜）；`sortComfyModelsQuantFirst` 稳定置顶 + 「fp8」徽标（title：显存占用更省、加载更快）。
