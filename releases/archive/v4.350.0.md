## 一、事件总线连环炸根修（真缺陷，v4.61 同类事故未修完的部分）

1. **`gaea-task` 通道全清连环炸**：`bridge/events.ts` 的 `onTaskEvent` 清理走
   `EventsOff(channel)`——wails 全清会注销该通道**全部**监听者（`wailsEvents.ts` v4.61
   事故注记立过红线，v4.62.2 只修了 `onEvent/onSubagentText`，本通道漏网）。该通道有
   **5 个并发订阅点**（侧栏运行角标 / 任务自动激活 / 任务面板 / 价格源任务 / 索引任务），
   任一卸载（最常见：开一次任务面板再关掉）= 角标冻结、新任务不再自动弹、价格源下载卡
   「进行中」永不收尾，keepAlive 下直至应用重启。修复=一律走 `subscribeWailsEvent`
   （按监听者精确注销）；`onUpdaterProgress` / `onReady` 同纪律收口。
2. **runtimePolyfill（网页/HTTP 模式）双修**：①`EventsOn` 此前返回 void，消费方 effect
   拿不到退订函数——ModelCenter 四通道 deps 每变一次就往 eventBus **叠加**一套 handler，
   单事件触发 N 次重复后端拉取随使用时长线性涨；修复=返回「只摘自己」的退订函数，对齐
   wails v2.13 桌面语义。②`EventsOff(带 callback)` 此前无条件 `sse.close()`——共享通道
   任一订阅者的常规清理把他人实时推送一并掐断；修复=只摘该监听者，通道仍有监听者则保留 SSE。
3. **测试**：`events.test.ts` 新建 4 例（双订阅退订隔离 + EventsOff 永不被调用 / space 过滤
   语义不变 / updater、ready 同纪律）；`runtimePolyfill.test.ts` +3 例（EventsOn 返回退订 /
   EventsOff 只摘自己 / EventsOnMultiple 语义保持）。

## 四、静默失败反馈补齐（用户可见操作失败零提示）

1. **记忆中枢三脑检索**：失败与 0 命中此前都是「检索中…」一闪即无，无法区分「没搜到」还是
   「坏了」——新增三态（命中 / 「没有找到相关内容，换个关键词试试」 / 「检索失败，请重试」，`role=status`）。
2. **排程导出 XML**：无任何反馈，`SaveFileAs` 抛错只落 unhandled rejection，用户「点了没反应」
   ——补成功/失败提示对齐 `exportXlsx` 口径（用户取消保存不扰）。
3. **章节载入失败**：此前只 `console.error`，章节 tab 白板且未被标未保存，用户误以为正文丢了
   ——`message.error` 带原因。

## 五、渲染性能（流式与长会话路径）

1. **Transcript 提及扫描按文本缓存**：`tailOmitBySeg` 每 chunk 对**全会话所有段**的 assistant
   正文跑双全局正则（`deliverableMentions`，含 lookbehind）+ O(m²) 重叠检查——长会话（数百轮、
   数百 KB 文本）每 chunk 数 ms~数十 ms，正落在最敏感的流式路径。修复=按文本内容缓存提及键集
   （段内文本完成后不可变，缓存命中后每 chunk 只对仍在增长的流式段付扫描成本；上限 512 清理防
   跨会话滞留）。
2. **聊天页流式重渲染**：`topicList` memo 化（此前每 render 重建，含 O(T×P) `personalities.find`；
   角色模式打字机 ≈70 renders/秒 × 数百会话全列表含 Tooltip 重渲染）；`ChatTopicSidebar` 整体
   `React.memo` + 过滤 `useMemo` + **行 hover 改纯 CSS**（删 `hoveredId` state——此前鼠标每扫过
   一行就全列表重渲染；删除钮显隐走 `.chat-topic-del` 规则，行为等价）。
3. **ToolCard 漏网三处 memo**：`summary`/`prettyArgs`/`outputLines`——`write_file` 等工具 args
   内联整个文件内容（数百 KB 常见），此前折叠态每次自身更新仍全付 JSON round-trip + 全文 split
   （`diffsFor`/`boundedOutput` 已 memo，本刀补齐）。
4. **`useNow(active)` 条件订阅**：已完成 AssistantMessage/ProcessCard/RunStatus 此前无条件订阅
   全局 1s 时钟——长会话数百条消息每秒全体重渲染，O(N)/秒常驻开销随会话线性涨；改=仅运行中订阅
   （WorkHeader 完成态本就走定格 ref），全部订阅者转 false 后时钟自动停摆。**伴生行为修复**：
   AssistantMessage「思考 Xs」完成后耗时持续增长（三天前的会话还在涨）——完成边沿定格
   （`Date.now()` 拍终值，WorkHeader 同款渲染期前值比较模式）。
5. **审计辨伪（不改）**：ModelCenter ctx（100+ 字段）不 memo 化——五个 hook 返回对象字面量每
   渲染新引用，deps 无法建立，强行 memo = 陈旧 ctx 真 bug，影响有界（设置页单 section）挂观察池。

## 坑（本轮新增）

1. **审计阈值/结论必须复核**：本轮 4 路审计证据全部逐条读码核实后才动手，其中「渲染热点 #7
   ctx 无 memo」读码后发现 deps 根本无法建立——审计对、修法错，辨伪省一次引入真 bug。
2. **`EventsOff(channel)` 红线是「全清」而非「禁用」**：polyfill 侧正确语义=带 callback 只摘
   自己、通道空了才关 SSE；照搬「绝不调用」会丢全清分支。
3. **Popconfirm 会 clone 注入 onClick 覆盖子元素**（同 v4.348 Dropdown 坑家族）：子按钮原有
   onClick 必须移除由 onConfirm 接管；无 forwardRef 的自研按钮（ToolbarButton）包不上，改
   `Modal.confirm` 命令式。
4. **antd 两字按钮可访问名带空格**（「删 除」）：确认钮定位一律 testid（`okButtonProps` 透传），
   不按文案找。
5. **`useNow` 停订后完成边沿定格的 1s 误差**：running true→false 那次渲染 now 是最后一次
   tick 值，耗时显示误差 ≤1s——显示层可接受，注释写明。
6. **行内 hover state 改 CSS 必须连 transition 一起搬**，否则视觉回归（闪烁/常显）。
