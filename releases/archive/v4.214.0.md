# v4.214.0 — 阶段六 6.1 首刀：可审计默认化——文件预览默认版本条（2026-09-11）

> 阶段旗交阶段六（书斋纵深·办公主角），6.1「Verify→Journal→一键回滚从
> 能力升为文件工作台默认 UI」首刀。纯前端，零新绑定，零 Go 改动。

## 缺口

逐版本「预览 → 恢复」能力早已有（v4.28 B1 VersionTimeline：证据卡基线快照
聚合、对比/预览/恢复三操作），但入口藏在右侧交付面板的 vN 徽标里——用户
打开一个刚被 AI 改过的文件，看不到「改了哪几次、能不能还原」。6.1 把可审计
从「能力」升为「默认 UI」。

## 落地

- **FileVersionStrip 新组件**：默认可见的版本条，挂在文件预览标题栏正下方
  （三件套及一切文件通用，数据源与交付面板同源 `GaeaJournalList(200)`）：
  - 有版本：`版本 N · 最近 AI 改动 HH:MM · 复核状态 · 可恢复`；
  - 无版本：`AI 改动此文件会自动成为版本点（可预览 / 一键恢复）` 说明条
    ——回滚入口恒在；
  - 点开展开该文件的逐版本时间线（`groupVersionsByPath` 按 target 过滤，
    传入 VersionTimeline：预览基线 / 一键恢复；顶部常驻「恢复会把该文件写回
    所选版本，当前内容成为新版本」护栏说明）；
  - 预览基线经 `openFilePreview` 新开预览 tab；恢复走 `RollbackRecord`
    （已被手工修改则后端拒写，零覆盖）+ toast + 重拉时间线 + 父级静默重读
    预览（恢复动作自身也生成新证据卡=恢复也是版本）。
- **pptx 页码归因**：证据卡摘要自带 `p3 → "…"` 页码格式
  （appendPptxEvidence 既有口径），时间线行内可见「改了哪几页」。
- **AI 改动自动成版本点** = 证据链既有能力（v4.1 起 RecordChange + 基线
  快照 + verdict 状态机），本刀零改动承接。
