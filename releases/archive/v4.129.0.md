## E1：自由时差 SS/SF 搭接口径（引擎级 bug）

- `freeFloatPart` 的 SS/SF 两型漏减前置 ES 锚点：搭接时间间隔 LAG_i-j 应为 ES_j−**ES_i**−lag（SS）/ EF_j−**ES_i**−lag（SF），旧版返回 ES_j−lag / EF_j−lag——**后继挂 SS/SF 搭接的工作自由时差虚高**，可违反「总时差为零 ⇒ 自由时差为零」定理。FS/FF 两型（锚点 EF_i）本就正确。
- 修法：`freeFloatPart(link, to, efFrom, esFrom)` 增锚点参数并**导出**（TS/Go 同），四型公式单测直接钉死。
- 实证（雨污例，?mock=demo 走查）：管道铺设 FF **11→0**（SS+8 后继）、沥青面层 FF **2→0**（SF+2 后继）、水稳基层 TF=0/FF=0 定理成立。

## G3：目标竣工作计划工期锚点进逆推

- 旧版逆推恒以计算工期 Tc 为锚，deadline 只做旁路校核——目标竣工**超期**时不出现负时差、关键工作仍按 TF=0 圈定，与规程「计划工期小于计算工期时总时差最小值为负、关键工作=总时差最小者」不符。
- 修法：`computeCpm(tasks, links, { planFinish })`（TS）/ `ComputeCpmPlan(tasks, links, planFinish)`（Go）——计划工期 < 计算工期时逆推锚点取计划工期：绑定链出现负时差、FF 终点口径=Tp−EF、关键工作=TF 最小集；planFinish 缺省/压线/富余时**与旧口径逐位一致**。`PlanFinish(p)`（Go）/`planFinishOf(project)`（TS）= deadlineWorkdays 换算。
- **minTF 仅在真正收紧（anchor<Tc）时启用**：manual 驱动总工期、非手动链无 TF=0 的场景维持经典口径（旧用例「manual 不回传约束」钉死此语义——避免把带浮动的任务误标关键）。
- 接线面：SchedulePage（cpm+buildAoa）/store.setBaseline/gschedSummary/mock analyze（TS）；`Project.Analyze`（Go，schedule_analyze 与 apply 回执自动生效）。schedule_tools 的 Before 摘要只用工期，不接锚点。
- AOA 同步：`buildAoa` 增 opts——事件逆推锚点同步收紧，箭线关键=浮时最小（不再恒为 0）。
- 实证（雨污例）：deadline 10-23→10-21（第 32 工作日）后绑定链 7 项 TF=**−2**、关键集 8 项不变、管道铺设浮时 4→2、状态栏「超 2 天」。
