## 背景与过程

v4.14.0 欠账「本地-云端自动路由 v1」（调研候选 ★★★）经**用户拍板收缩**为最小
价值刀：砍掉成本档位机制/auto_route 开关/开关卡 UI，只保留两块真实价值——
①plain 聊天离线过滤裂缝修复（探索发现的真 bug）②消息级「由谁回答/为何/花了
多少」回显（路线图 §13）。设计 `docs/gaea-v415-auto-route-design.md`。

**坦率的收缩理由**：调研叙事里的缓存命中价/峰谷价（0.1–0.19×、峰谷五折）无官方
逐模型数字，按「未核实不入表」纪律无法真实落地；成本档位兜底只对「无显式绑定」
场景生效，对大多数用户无感知。故本轮只交付确定性的价值。

## 交付明细

### ① 聊天路由归位（bug 修复：plain 聊天离线过滤生效）

- `chat_service.go:68`（chatSendPlain）/`:105`（ChatStreamPlain）/
  `chat_handler.go:9`（ChatGeneral）三处 `featureModel("chat")` →
  `routeModel("chat")`。
- **语义保证**：routeModel 步骤 1 读的正是 `GetFeatureModel("chat")`（与 featureModel
  同源）→ 用户功能绑定逐字节不变；新增收益：
  - **离线裂缝修复**——全局离线模式下 plain 聊天不再绕过云端过滤（此前绑云端
    引擎照样发云端，persona 路径却被滤，「总闸不总」）；
  - 无绑定时走全局活跃/兜底，与 persona 一致（此前交给 ai.Client 内部兜底）；
  - `model.route` 事件补齐（routeModel 每步已 emit），模型中心「当前生效」可展示 chat。
- `featureModel` 保留（模型中心展示用），`routeModel` 零改动。

### ② 「由谁回答 / 为何 / 花了多少」回显

- **后端**：
  - `modelengine.stats.go` 导出 `EstimateCostCNY(engineID, model, inTok, outTok, usdCny)`
    ——复用 estimatePrice 口径：本地（herdsman/ollama/cosyvoice）与未知模型恒 0；
    USD 按汇率折算 CNY、CNY 直用；非法汇率回退默认 7.2（防 0 汇率抹零）。
  - `chat_service.go` done 帧（流式路径，按流结束块 `chunk.Usage` 实算）与
    `chatSendPlain` 返回 map（ChatSimpleStreamDetailed 不返回 usage → cost_cny 恒 0
    并注释「usage 不可达，诚实不计」）各加 `answered_by`：
    `{"engine","model","source","cost_cny"}`（source 即「为何」：feature/global/fallback）。
  - 旧事件/旧消息无该字段 → 前端静默跳过（向后兼容）。
- **前端**：
  - `AnsweredByLine.tsx`：消息底部小字「由 {engine}/{model} 回答 · {sourceLabel}[ ·
    约 ¥x.xx]」——`cost_cny<=0`（本地/未知）隐藏费用段（不虚报）；source 标签
    feature=功能绑定/global=全局路由/fallback=兜底/未知原样；全 token 样式。
  - `useChatStream.ts`：done 分支/ChatSend 角色分支解析可选 `answered_by` →
    写入消息 extra（运行时守卫，缺失静默跳过）。
  - `ChatRow.tsx`：非流式、非错误行且 extra 带 answered_by 时渲染（`!= null`
    显式布尔化，避免 `unknown` 污染 `&&` 链类型）。
