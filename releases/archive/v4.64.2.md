# v4.64.2「修复：任务管理树丢失零工具子代理——enrich 补挂合成节点 + 六版实机验收收官」

> 发布日期：2026-09-04 ｜ tag：`v4.64.2` ｜ 基线：v4.64.1 ｜ 绑定面 **560
> 零变更** ｜ 用户实机报告：任务管理面板不出现新派发的子代理。

## 根因

`FoldAgentNetwork`（事件日志折叠）把子代理节点定义为「**拥有子工具记录**
的 task/run_skill 调用」——纯调研型子代理（prompt 明令禁止用工具、零工具
调用）在事件日志里没有任何子记录，永远成不了树节点；`enrichAgentNetwork`
又只在已有 Children 上做富化、不补挂。结果：**任何零工具子代理整批从任务
管理树消失**（运行中计数 `running` 来自 GaeaSubagentRuns 所以照常变化，
列表却不见行——正是用户看到的形态）。

实机对照：同会话内，土壤调研 A/B/C 三路（用了 grep/read_file，共 38/37/40
次工具调用）正常显示；本日新派发的三路并行纯调研 + 单路 Devin 纯调研
（零工具）四条全部缺失。

## 修复（internal/app/gaea_ui_contextview.go）

`enrichAgentNetwork` 两段式：

1. 富化段与原来相同（节点按任务摘要前缀双向匹配 run，回写状态/模型），
   但同时记录每个 run 是否被任何节点承载（ref 直等或任务前缀）。
2. **补挂段**：未被承载且 `kind != "model_tool"` 的 run（model_tool 由前端
   「本地模型工具」区块单独渲染，补挂会同名重复）追加为合成子节点——
   id=sa_ ref（前端 AgentTree transcriptRef 直用可开转录、run 元数据直
   匹配）、状态映射 failed→error、时间戳取 run CreatedAt/UpdatedAt、
   工具数/token 如实取 run meta。
