## 交付明细

### 根因（统一）：测试写进程级全局状态，`-count` 多次运行不兼容

测试用固定 / `t.Name()` kind 或固定会话 ID 写入**进程级全局状态**（provider / billing
注册表、app `whisperSessions` 会话缓存）——`-count` 多次运行同一测试时，第二次注册 / 命中
即冲突。**非产品缺陷**（除 whisper 一处外全部是测试侧对全局态的 -count 不兼容）。

### 修法（全部测试侧；唯一生产改动是 whisper +3 行）

1. **provider / billing / boot / app duplicate kind（19 个注册点）**：注册 kind 改
   `testKind(prefix)`（进程级 atomic 单调计数后缀，任意次 -count 唯一）。billing 另把
   `BalanceProviderKinds()==[deepseek]` 的无菌态断言改为「注册表含 deepseek」（语义词保留：
   `-count` 下「恰好一个」假设不成立，改为可构建性断言）。
2. **app whisper 会话串扰**：包级全局 `whisperSessions` 缓存（whisper_handler.go）固定会话
   ID 跨运行命中旧 orch → 隔离测试改唯一会话 ID + `cleanupWhisperSession`（t.Cleanup 删
   缓存，与既有 proactive / persist_concurrency 模式一致），覆盖 isolation / causal /
   graph_assoc / characterlib 12 个调用点。
3. **whisper 10m 超时（真 bug，唯一生产改动 +3 行）**：`PacedStreamEmitter.pump` 在
   streamDone 且文本已全部送出时不收尾末气泡 → `MarkDone` 排空等待因 `bubbleOpen` 恒真
   永久挂起（全量负载实测 10m 超时；**生产表现为最后一个气泡的 `OnBubbleEnd` 永不触发**）。
   修法：streamDone 分支收尾末气泡（仅 bubbleOpen 时收尾，不误开新气泡——主代理验收确认
   与 pauseBeforeNext / openNextBubble 路径无副作用）。
