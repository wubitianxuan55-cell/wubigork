## 落地

### ① 伏笔一致性体检（LintForeshadows，绑定面 645→646）

- 新 `internal/app/novel_foreshadow_lint_handler.go`：纯函数 `lintForeshadowItems` 跑 5 类确定性检查——

  | 检查 | 触发条件 |
  |---|---|
  | `ordering` | 回收章早于埋设章 |
  | `status-mismatch` | 状态=已回收但未填回收章 / 已填回收章但状态不是已回收（`partially_resolved` 豁免后一方向） |
  | `dangling` | 埋设章或回收章指向尚未写入的章节 |
  | `stale` | 非长线条目悬置 ≥10 章（`foreshadowStaleAfterChapters`，长线豁免） |
  | `duplicate` | 归一化描述重复（首个 ID 报给后出现者） |

- 报告形状 `totalChapters/items/planted/hinted/revealed/longTerm/findings[]`（`severity` high/medium/low +
  条目描述 + 章节引用）；登记表为空 / 文件缺失 = 空报告正常态（不算错，不落 findings）。
- 前端 `ForeshadowPanel` 新增「一致性体检」：概要行（全书章数 · 登记条目 · 已埋/暗示/回收 · 长线）+
  findings 直显（severity Tag 重/中/轻 + 说明 + 原文条目 + 章节引用）；报告保留至下次体检；
  Go 侧 omitempty 与 `findings` 可能为 null 全防御。

### ③ wire 口径纠偏（P0，本刀抓自交叉审查）

t1 在制品曾把「已回收」的**写入口径**定为 `resolved`（把 gaea 原生 `revealed` 降级为读取别名），
与实施交接书 §2-3/§4-7（「写入口径仍是 `revealed`；任何『归一化为 resolved』的改法都是破坏性变更」）相反。
若照此落地，7 类既有消费方会**静默读空**：统计回收率、伏笔 lint 计数、分析写回、章节上下文注入、
`SaveForeshadows` 白名单（会拒收新值）、narrative 状态映射、前端 `ForeshadowPanel` 12 处。

处置（A 方案，零破坏）：

- `NormalizeForeshadowStatus` 方向 = `resolved → revealed`；新增 `IsResolvedStatus` 覆盖两套 wire 值。
- 消费方接线（对存量数据行为等价，只增不减）：`internal/stats/stats.go`（回收率）、
  `novel_foreshadow_lint_handler.go`（一致性检查 / 状态标签 / 报告计数）、
  `create_chapter_handler.go`（已回收不再注入 prompt）、`internal/analysis/analysis.go`（聚合统计）。
- `SaveForeshadows` 白名单 3 态 → 并集 6 态，写入前先归一化（别名落库即 `revealed`）。
