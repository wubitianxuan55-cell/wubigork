# v4.199.0 — 场景元数据编辑面：POV/地点/时间/情感（2026-09-10）

> 小说域最后一个有名欠账（DSH 批次代收后 NovelPage 解锁，本刀趁势收掉）。
> 方向句验收：**角色在场景粒度上也是同一个人**——POV 圣经的入口从「生成时
> 隐式推断」变成「作者显式指定」。

## 缺口

`SceneMeta` 的 POVCharID/Location/TimeOfDay/Emotion/Tags 字段从 v4 场景制
设计起就存在，`GetChapterScenes` 也早把完整元数据回传前端——但**写路径
不存在**：SaveScene 只存正文，元数据成了「只读展示都不展示」的摆设。
POV 圣经（novelcontext 编译场景生成上下文）只能靠生成时隐式推断视角，
作者无法指定「这一场用谁的眼睛看」。

## 落地

**Go**：`SaveSceneMeta(chapterNum, sceneID, metaJSON)`（writingState，play
空间）——

- 元数据专职写路径：标题/概要/POV/地点/时间/情感/标签/状态一次落盘；
- 线格式与 GetChapterScenes 回传同构（camelCase；存储层 SceneMeta 的
  snake_case tag 不外泄）；
- 身份字段不可变：ID/Slug/Order/WordCount 以存储为准（patch 里传了也
  不生效）；标题 trim 后为空=保持原标题；
- 状态仅接受 draft/revising/done，非法值**整单拒绝**（不部分落盘）；
- 元数据不影响正文投影，故不触发 syncBlobFromScenes（blob 保持原样，
  测试锁定该行为）。

**绑定面 607→608**：NovelB 门面 + bindingNames + spaceBindings（play，
430）+ bridge novel.ts + wailsjs NovelB 双件（手同步）+ dev mock（no-op）。

**前端（ChapterEditor）**：每场景头部新增 ⓘ 钮（sceneBacked=false 时
禁用）→ 元数据弹窗：标题/概要/POV 角色（下拉=本书角色 characters.json，
与 POV 圣经同源，可清空）/地点/时间（黎明~深夜六档）/情感基调/标签
（逗号分隔）/状态（草稿/修改中/完成）。打开时从 GetChapterScenes 取当前
值回填；保存诚实 toast（注明 POV 影响本场景 AI 生成视角）。

## 测试

`TestSaveSceneMeta`（v4 物化环境）：字段落盘读回（含 tags 数组）→ 身份
字段不可变（slug/order 改不动、空标题保持原值）→ 非法状态整单拒绝 →
blob 投影不受元数据影响 → 不存在的场景报错。
