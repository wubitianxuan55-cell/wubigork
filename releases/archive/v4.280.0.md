## 落地

### ① 反推编排引擎（新 `internal/bookimport/reconstruct.go`）

| 能力 | 要点 |
|---|---|
| 具名契约 | `ProjectSuggestion`（title/description/theme/genre/narrative_perspective/target_words）、`OutlineStructure`（chapter_number/title/summary/scenes/characters/key_points/emotion/goal） |
| 逐字段归一化 | summary 2000 / emotion 200 / goal 300 / scenes ≤6 / key_points ≤8（**一律 rune 截断**）；characters 逐项须为对象且带 name，`type` 仅 `character|organization`，其余一律 character；**title 与 chapter_number 强制用输入值** |
| 位置对齐 | 批量归一化**按输入章节顺序逐位取 `ai[i]`**（不按 AI 返回的 chapter_number 对齐），非对象槽位直接 fallback——AI 少返/乱序都不会错章 |
| 断言式防线 | 归一化后数量与输入不符 ⇒ **整批回退规则结构**（宁可全丢 AI 结果，不用错位结构） |
| 规则兜底 | 逐字对齐规格：固定 scenes 两条 / key_points 两条 / emotion「紧张递进」/ goal「承接前章并推动后续剧情发展」；summary 取正文**首句**（无则用规格默认句） |
| 立项归一 | 视角归一：中文三值 + 11 个英文别名（first_person / limited third / omniscient / god_view…）；`target_words` <1000 回落、>3e6 夹取；**title 永不用 AI** |

### ② JSON 负反馈重试

- `CallJSON(ctx, prompt, expected, maxAttempts, call)`：**期望类型显式传入**（object / array，避免「AI 返对象但按数组解包」的静默错）；
  解析失败把**上次失败原文截 200 字**注入下次提示（对齐 `ai_service.py:689-690`）；
  **传输错误直接返回不空转**；ctx 已取消则零调用。
- `ExtractJSON` 容忍 markdown 代码块包裹与前后解说文字。

### ③ Prompt 模板移植（RTCO）

- 新增 `prompts/book-import-project.json`（立项五字段 + 视角/字数约束）与
  `prompts/book-import-outline.json`（七字段契约 + scenes 2-6 / key_points 2-6 / type 两值硬约束），
  按规格 §8.2 的映射表等价改写 MuMu 的五段式 Prompt。

### ④ 顺手补掉规格点名的引擎缺陷：输入节稳定序

RTCO 的 `BuildUserPrompt` 原按 **Go map 遍历**输入节（旧 `internal/prompt/prompt.go:194`）——
**同一模板两次渲染字节不同**，长文本无法稳定置尾、供应商 prompt 前缀缓存无法命中（阶段五 5.2 的出口判据之一）。

- `InputDef` 增 `order` 字段（`omitempty`，旧模板零迁移）；
- 排序规则：**Order 升序 → key 字典序**兜底；
- 新模板把长文本（`sampled_text` / `chapters_text`）固定置尾（order=9）。
