# gaea v2.15.7「通用办公 P0 · 开工前计划卡片结构化」发布说明（2026-08-13）
> 接回通用办公优化路线图（docs/market-research-2026-08-office-prework-context.md 的 P0 #1）：
> v2.10 已有「开工前计划确认」，但只是普通 ask 文本 + 两个选项。本轮把计划升级为
> 结构化「计划卡片」：任务理解、步骤（附资料/工具/产出物）、待确认问题分区展示，
> 用户确认后同一套答案协议继续执行。

## 一、结构化计划管线（后端）

- `planSystemPrompt` 改为输出**严格 JSON**（goal / steps[{title, detail, resources, tools, deliverable}] / questions），
  不再输出自由 Markdown。
- 新增 `agent.ParsePlan`：容错 Markdown 代码围栏与前后杂质，清洗空标题/空字段；
  解析失败或内容为空返回 nil，planGate 自动回退纯文本计划卡，不阻塞执行。
- 新增 `agent.RenderPlanMarkdown`：把结构化计划渲染为可读 Markdown（旧前端/纯文本兜底）。
- `event.Ask` 新增可选 `Plan` 载荷：planGate 下发 AskRequest 时随事件携带结构化计划；
  `gaeaEventMap` 同步序列化（goal/steps/questions），答案协议（AnswerQuestion）不变。

## 二、计划卡片渲染（前端）

- `WireAsk` 新增 `plan` 载荷；AskCard 检测到 `ask.plan` 时渲染 `PlanBody`：
  - 任务理解：accent 高亮卡 + 「任务理解」标签；
  - 步骤：编号圆点 + 标题/说明，每步下方资料、工具、产出物三类芯片（图标 + 文本）；
  - 待确认：琥珀色提示区，逐条列出需求不明确的关键点。
- 无 `plan` 时保持原样（纯文本 Markdown 问题 + 选项），多语言文案补齐 en/zh/zh-TW。
