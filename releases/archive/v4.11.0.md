## 交付明细

### GLM 生图后端（kind=glm，internal/ai/image_glm.go）

- **官方文档锚定**（docs.bigmodel.cn「图像生成」API，2026-08-30 核实）：
  `POST https://open.bigmodel.cn/api/paas/v4/images/generations`、HTTP Bearer。
  官方请求 schema 仅 model/prompt/size/quality/watermark_enabled/user_id——
  **无 response_format（响应只回 URL，链接 30 天有效）**，也不收 negative/
  seed 等 OpenAI 扩展字段。因此不复用通用 OpenAIImageBackend（其会序列化
  整个 ImageGenerationRequest），GLM 后端只发官方字段、其余诚实忽略。
- **响应处理**：URL 统一下载转 data URL（提取包级 fetchToDataURL 与 openai
  后端共享；下载失败保留原始 URL 不阻塞）；200 但 data 为空（官方
  content_filter 拦截场景）诚实提示「可能触发内容审核」；官方错误体
  `{"error":{code,message}}` 原样透出（code 字符串/数字两态兼容）。
- **img2img 诚实拒绝**：官方端点无图生图参数，携带参考图的请求在发出前
  直接报错，不静默丢弃。
- **缺省模型 cogview-4-250304**（cogview-4 锁定版；glm-image 仅 hd 档约
  20s，cogview-4 standard 约 5–10s 更适合默认交互节奏）。

### App 三处接线（internal/app）

- `initImageBackend`（启动恢复）+ `SetImageBackend`（设置切换）+
  `buildPortraitClient`（角色剧照独立后端）均支持 `glm`；引擎未启用/Key
  未配置给定向错误，启动期不可用回退 xAI 并告警。
- GLM Key 经 `Manager.GLMKey()` 与 chat 路径同源取用（Key 存 manager 而非
  EngineConfig.APIKey）；size 参数保留（官方接受 size，glm-image 默认
  1280x1280）。
- `GetImageBackendInfo` 模型归位：切到 GLM 后残留的非官方模型名（如
  grok-imagine-*）自动归位官方默认，避免表单带错模型名请求。

### GLM 官方双端点切换（SetGlmEndpoint，绑定面 543→544）

- 官方 coding-plan/quick-start 核实（2026-08-30）：std=`/api/paas/v4`
  （按量付费）/ coding=`/api/coding/paas/v4`（编码套餐额度）——填错端点
  编码套餐 Key 会 404 或误走按量计费。
- 后端 `Manager.SetGlmEndpoint(family)` **只收两个官方常量**
  （GLMBaseURLStd/GLMBaseURLCoding），未知家族 fail-closed，不透传自由
  地址——云端引擎不露地址框防线（v4.9.1）的延伸。切换即 saveState 落盘，
  重启保持。
- 前端 GLM 引擎卡新增端点 Segmented（标准（按量付费）/编码套餐）+ 说明行；
  `GlmEndpointFamily()` 供前端/诊断读取当前家族。

### 生图模型目录补全 + 误分类修复（modelengine）

- 静态目录补生图四模型：glm-image / cogview-4-250304 / cogview-4 /
  cogview-3-flash（锚定官方图像生成 API 的 model 枚举，18→22）。
- **修 glm-5-turbo 误分类**：通用 turbo 关键词把它判成生图模型（v4.10.0
  实际存在的分类 bug，会混进图片模型下拉）——GLM 引擎先按官方目录判型
  （glm-image 系→image，其余 glm-*→llm）再落通用关键词表，cogview 入通用
  表；回归测试锁死。
