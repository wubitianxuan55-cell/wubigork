## 改动

### MH1 采样让位 + 思考默认关（Go，`internal/ai/client.go` ChatStreamChunks）

1. **引擎判定**：`c.engineMgr.GetEngine(reqEngine)` 查 `Type == EngineModelHub`（自定义引擎 Type 恒为 custom，modelhub 型只有内置一个，但仍按 Type 查证不按 id 硬编码）。
2. **采样让位**：modelhub 且 `opts.Temperature <= 0` 时不再兜底 0.7——零值经 `omitempty` 丢弃、请求不带 temperature，让 Studio 自动调优；显式配置（>0）照常透传。其余引擎行为零变化（全仓温度兜底仅此一处；copilot.go 各处为显式固定值不受影响）。
3. **思考默认关**：modelhub 请求恒带 `chat_template_kwargs.enable_thinking`（默认 false；`opts.EnableThinking` 显式开启时 true + max_tokens<4096 抬到 4096 守护）。只走 A/B 实验证实的 kwarg 通道，**不发**顶层 `enable_thinking`（该字段是 herdsman/ollama 的 Qwen3 通道，对 unsloth 无实测依据）。

### MH2 加载状态收敛（前端，`useEngineState.ts` + `context.ts` + `LLMSection.tsx`）

1. 一键加载 stopped 模型：`startModelHubModel` 后立即挂「加载中」徽标（`hubLoadingIds`，卡片状态 accent + 按钮 LoadingOutlined + disabled），**轮询** `getEngines` 直到目标模型 `status==='running'`（5s 一拍 / 3 分钟上限；单次轮询失败不终止）。
2. 收敛成功才设活跃引擎 + 默认模型 + 报「已启动」；**超时诚实失败**：警告文案明说仍在加载、可稍后刷新确认、不设默认模型（Studio 冷加载实测 50s+，内存挤占可超 2min）。修复原「loading 即返回就谎报已启动、默认模型指向未加载模型」的坑。

### MH3 UD 量化档位引导（前端，`utils.tsx` + `LLMSection.tsx`）

1. `isUDVariant`：模型 id 含 `UD-` 判定为 Unsloth 动态量化变体（关键层保高精度、体积小 → 加载快、显存省，官方主推档位）。
2. modelhub 组内 UD 变体**稳定置顶** + 「推荐」徽标（title 说明动态量化）；与用户手动置顶的组合语义=手动置顶优先、UD 顺序在置顶组/普通组内部保留（先 UD 后 pinned，两排序均稳定）。
