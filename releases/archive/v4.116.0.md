## 一、为什么是基线对比

对话即排程（刀4~6）打通后，遗留一个量化缺口：调整完只报「新总工期」，回答不了「比原来怎么样」。基线把某一时刻的排程结果固化，之后每次调整都能回答：

- 总工期从基线的 X 天变成 Y 天（±N）；
- 哪些任务被推移/新增/移除，各偏移多少工作日；
- 关键链谁进了谁出了（风险迁移）。

## 二、数据模型（双侧同构）

`SchedProject.baseline = { name, savedAt, duration, rows }`，行键=任务 id：

| 字段 | 含义 |
| --- | --- |
| name | 基线名（缺省「基线」；ops 传 baselineName 可命名如「开工版」） |
| savedAt | 保存时间 YYYY-MM-DD HH:mm（工具层标注，引擎纯函数不取时钟） |
| duration | 保存时总工期（工作日） |
| rows[id] | { name, es, ef, dur, critical }——叶任务快照；分组行不入基线 |

口径：行值是**工作日序号**，对比=相对开工日的偏移（不受开工日调整影响）；dur 为有效工期（里程碑 0）；critical 与 CPM 口径一致（手动不标关键）。

## 三、引擎（TS 11 例 + Go 11 例镜像）

- **snapshotBaseline**：以当前 CPM 固快照。fail-closed：循环依赖（错误原文回传）/无叶任务 → 拒绝，绝不存空基线。
- **computeBaselineDrift**：
  - 汇总：durationDrift（正=拖后）、same/shifted/added/removed 计数、criticalGained/criticalLost 任务名；
  - rows 只含**有偏差**的行（一致行不进列表防淹没），顺序=任务表序、移除行按 id 排序（跨语言镜像一致）；
  - es/ef/dur 任一漂移**或关键标记翻转**都计为 shifted（单标记翻转测试钉死）；
  - 新增行 base=null、esDrift=当前 es；移除行 now=null、名字取自基线行（任务没了仍可读）。
- **ops 增量通道**（agent 可编程）：`set_baseline{name?}`（缺 savedAt 拒绝；CPM 不过/无叶任务拒绝；摘要「保存基线「开工版」（N 项工作，总工期 X 天）」）、`clear_baseline`（无基线报错——无事可做≠静默成功）。

## 四、agent 三工具接线

- schedule_get：带 `baseline` 元信息（name/savedAt/duration/rowCount）——编辑前知道基线存在。
- schedule_apply：ops 通道自动为 set_baseline 盖时间戳；回执带 `baselineDrift` 摘要（baselineToNow「9→11 天」、durationDrift、推移/新增/移除、关键链进出）——模型汇报先讲偏差。
- schedule_analyze：输出 `baselineDrift` 全量；checks 追加「较基线」发现（**漂移≠0 才出现**，不噪声化）：总工期 9→11 天（+2）、推移/新增/移除计数、新进/退出关键清单。
- schedule-edit 技能新增「基线对比」节（锚点锁 17→20）：调整前建议 set_baseline 固化现状；回执/analyze 先讲偏差再讲措施；结构性重排后旧基线失真，主动建议更新。

## 五、板块 UI

- 页头「基线」弹层：无基线=引导保存（守卫明示禁用原因）；有基线=漂移摘要（总工期 X→Y（±N 拖后/提前）、推移/新增/移除/一致计数、新进/退出关键、偏差行清单带推移/新增/移除徽标）+ 更新基线/清除基线（Popconfirm）。
- 横道图：基线条开关（有基线才出现，默认开）——灰描边细条垫行底显示基线位置，与当前条同排对照；悬停提示「基线：第 X~Y 工作日（当前第 A~B）」。
- 状态栏：基线段「基线 X → 当前 Y 天（±N）」，拖后红（sched-sb-crit）/提前绿（sched-sb-good）。
- store：setBaseline（返回错误文案不静默）/clearBaseline 动作；基线随 project 走既有防抖自动保存+agent 回读链路，板块与 agent 看到同一份基线。
