# v4.236.0 — 修复变参绑定 wire 契约：reflect 参数错误清零（2026-09-12）

> 清掉 v4.235 走查挂出的观察池项：`GaeaTaskList` / `GaeaAgentNetwork` 的
> `reflect: cannot use []string as type string in Call`。真机复验：进办公
> 工作台 reflect 错误从必现数条 → **0 条**。

## 根因（桥接约定与 Wails 真实形态不符）

- Go 侧五个绑定是**变参**：`GaeaAgentNetwork` / `GaeaTrajectory` /
  `GaeaContextView` / `GaeaContextNodeDetail`（seq, …）/ `GaeaTaskList`
  （均为 `...string`）。Wails 要求每个变参元素作为**独立顶层参数**传
  （`args:["path"]`），JS 传数组（`args:[["path"]]`）即 reflect 报错。
- 桥接 facade 却约定 `sessionPath?: string[]`（JS 数组整体作单参），7 个
  调用点照约传数组。**推断来源**：v4.174 退役的 wailsjsCompat shim 当年
  会展开数组，退役后数组约定调用点静默失去展开——接口报错被 `.catch`
  静默吞掉，UI 显示错误态/空态但无人深究，直到壳内走查抓到日志。
- 已确认其余变参绑定（`UnifiedSearch` 的 scope、`CostImportApply` 的
  inquirySource）调用方本就按字符串/展开传参，真机正常，不动。

## 修复（facade 单可选串化，与实际用法一致）

全部调用方只传 0 或 1 个路径，Go 变参天然支持——facade 签名改可选单串，
调用点同步简化，mock 实现对齐（tsc 逼出全部错配，编译期契约）：

- `bridge/core.ts` 五签名：`ContextView/Trajectory/AgentNetwork/
  TaskList/ContextNodeDetail` 的 `sessionPath?: string[]` → `?: string`。
- 七调用点：`AgentNetworkCard` / `agentNetworkStore`（`[p.path]`→`p.path`）、
  `TrajectoryView` / `ContextView` / `context/inspector`（同形）、
  `TaskCenter` / `useRunningBadge`（`TaskList([])`→`TaskList()`）。
- `lib/mock/core.ts` 四实现签名对齐。
- `agentNetworkStore` 补语义细节：poller 以**空串**表示「内核会话」哨兵，
  下发前归一 `p.path || undefined`，不得把空串当真实参数发。
