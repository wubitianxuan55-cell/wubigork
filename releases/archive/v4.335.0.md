# v4.335.0 · 办公输入动线对齐 DSH/Codex：运行中 Enter=排队，插话改显式

> 2026-09-17 发布。来源=用户报告「办公板块消息输入的排序/插话/撤回不见了，
> 现在直接插入正在跑的对话中——我们不是专门做过优化吗」。

## 归因（非回归，是入口被 v3.6.0 换掉了）

队列功能本体（拖拽排序/单条·全部插话/撤回编辑/发送中锁定，v4.200+v4.201）
一直在且测试全绿；丢的是**入口**——v3.6.0（2026-08-28）把运行中 Enter 从
「排队」改成「插话调整」（对齐豆包「边跑边改」），排队入口退到 Clock 小按钮
（运行中且输入非空才显示）。用户习惯性 Enter → 消息直插当前对话 →
队列卡（排序/撤回/插话控件）从未出现，体感即「优化不见了」。

## 落地（纯前端，零绑定 707，用户拍板「按 DSH/Codex 方式」）

- **Enter（运行中）= 排队**：消息入发送队列，队列卡立即可见——拖拽排序/
  撤回编辑/单条·全部插话/全部取消/发送中锁定全部回到主动线；回合结束
  FIFO 自动派发（既有机制）。
- **插话改显式**：Alt+Enter 直插当前回合（边跑边改能力保留）；队列卡 Zap
  单条插话与「全部插话」不变。
- Shift+Enter 纠正、Esc/停止清队列、Clock 按钮——语义零变化。
- 发送钮 title 三态更新（排队/排队 N 条/纠正）；placeholder 运行中提示
  「Enter 排队发送 · Alt+Enter 插话调整 · Shift+Enter 纠正」（三语）。
- `composer.steerTitle` 键删除（唯一消费点换 `sendQueuedTitle`，维持 0 死键）。
- Composer 发送组装逻辑抽 `assembleSubmit`/`enqueueSubmit`/`pushInputHistory`
  四处重复归一；入队与 Clock 按钮统一进输入历史。
