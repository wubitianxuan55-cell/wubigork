# v4.337.0 · 办公对话流美化三轮收官：对齐 Codex web（降噪+动线+语义归位）

> 2026-09-18 发布。规格：办公对话流美化线程（对齐 Codex web 三轮，本版收口发版）。
> 纯前端零新绑定 707；零 Go 改动。

## 论点

v4.26 工作态头部落地后，对话流的反馈层多线并存（顶条横幅/头部行/过程卡/耗时行），
同组信息占两行、卡头与卡内重复、垂直噪音大；用户消息无气泡与助手正文同权重，
轮次边界不清晰。本版按 Codex web 口径收敛。

## 落地（10 件）

1. **用户消息气泡化**（Message.tsx）：右对齐柔和气泡
   （surface-container-high 档位+细边框+`rounded-2xl rounded-br-md`），替代
   无气泡裸文本——用户/助手轮次边界扫读清晰。
2. **裸思考行（bare 模式）**（ProcessCard）：纯思考段（无工具/阶段/通知）不出
   过程卡——卡头「已工作 · N 段思考」与卡内思考行是同组信息占两行；改一行裸
   思考块，行数摘要并进思考行头部。行数 meta 走 i18n
   （`reasoning.metaLineOne/metaLines` 三语+英文单复数；收口时修掉初版硬编码
   中文「行」——en 界面漏中文）。
3. **过程卡完成即收起**：运行中自动展开（实时活动可见），完成即收起为一行
   「已工作 Xs · N 个工具 · N 段思考」；历史会话恢复同样折叠；用户手动展开/
   折叠不干预。旧「展开态默认展开」废——完成后整卡摊开是对话流垂直噪音主源。
   耗时角标只在卡头「已工作」缺席时补位（纯阶段/通知段），不再与卡头重复。
4. **WorkHeader 三改**：①本轮有过程卡时完成态「已完成·用时」行让位（
   doneSuppressed——信息由过程卡卡头承担，不再双行）②纯问答轮（0 步）完成态
   不渲染③运行态样式对齐过程条（左细线+hover 底），运行中反馈职责不变。
5. **尾随工具段合并**（Transcript.buildSegments）：store 事件序里工具项物理上
   排在流式 assistant 项之后（reasoning/text 先建项、tool_dispatch 尾追），末段
   若为纯过程段则并回前一段——过程卡随 Codex 语义渲染在正文之前，不再出现
   「答后动作」假象。
6. **轮尾登记-only 交付卡补挂+跨段去重**：reasoning-first 回合的轮尾段无正文时
   ，登记合并卡原先整体丢失（只挂正文段的 AssistantMessage）——补挂段尾
   DeliverableCards；`omitPaths`（deliverablePathKey 口径）排除同轮其它段正文
   已提及的路径，防同文件双卡。
7. **交付卡统一边框容器**（DeliverableCards）：细边框+行分隔线+整卡一个圆角
   （Codex 文件卡语言），行距收紧。
8. **消息操作 hover 淡入**：复制/沉淀为技能/评分按钮改 hover 淡入
   （`group-hover/msg`），复制/评分后驻留——常驻操作行降噪。
9. **顶条只留 waiting 档**（StreamingIndicator）：连接档（≤5s）与 WorkHeader
   spinner 完全同义不再显示；只有 >5s 无事件升级 waiting 档才出顶条（携带
   「切轨迹面板排查」指引）——正常回合的运行态不再有第二行反馈横幅。
10. **ToolGroup 文案精简**：已调用 bash · 3 次 → `bash × 3`（Codex 式紧凑），
    完整语义进 `title`；`toolGroup.called/calledTitle` 三语新键。ToolCard 内嵌
    代码块圆角统一 `rounded→rounded-md`。
