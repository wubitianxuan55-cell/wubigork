# v4.339.0 · t7 观察池「标注定位编辑器光标」：分析面板 → 正文编辑器定位闭环

> 2026-09-19 发布。观察池条目（v4.325.0 t7 收官刀记录）按「拍板池全决策项时从
> 板块观察池挑余项」既定习惯开刀；零新绑定 705，纯前端三组件。

## 论点

v4.325 t7 面板交付了标注「列表 | 高亮视图」（弹窗内只读定位），但标注锚定的
正文位置无法回到**正在编辑**的编辑器——重写工作流（看标注 → 改正文）要靠肉眼
找位置。本刀补全闭环：标注列表行一键把编辑器光标定位到标注区间。

## 落地（三组件，零新绑定）

1. **EditorPanel** 转 `forwardRef`，暴露 `EditorPanelHandle.locate(runeStart,
   runeEnd)` 命令句柄：rune 偏移 → code-unit 换算（toRune 的逆，代理对按
   codePoint 步进）后 `setSelectionRange` + `focus`——Chromium 聚焦即把选区
   滚动进视口，无需手算 scrollTop。无激活章返回 false 供调用方提示。
2. **ChapterAnalysisPanel** 增可选 `onLocate(ann)`：锚定命中的标注行（pos≥0
   且 length>0，buildSegments 既有判定）行内出「编辑器定位」按钮，
   stopPropagation 保证不触发行点击的高亮跳转；行内原「↩定位」标签改
   「↩高亮」消歧（弹窗内跳高亮视图语义）。
3. **CreatePage** 接线：`onLocate` 仅在**面板章=编辑章**时提供（gate 跳转他章
   时面板 content 是他章正文、编辑器选区无意义——入口整体隐藏而非点了报错）
   ；处理器关面板→复位 gate 态→`editorRef.locate(pos, pos+length)`，编辑器
   未就绪（无激活章）降级 message 提示。

## 测试

- EditorPanel +3：rune→code-unit 换算（𝌆 代理对 2 code-unit/1 rune）选区与
  聚焦断言 / runeStart 越界钳文末空选区 / 无激活章 false。
- ChapterAnalysisPanel +3：提供 onLocate+锚定 → 按钮回传标注且 stopPropagation
  / 仅未锚定标注 → 入口不出现 / 未提供 onLocate → 入口整体隐藏。
- tsc -b 0；eslint 0；两文件 18/18。

## 坑

- **gate 跳转的章≠编辑章**：ChapterAnalysisPanel 的 content 入参可以是
  gateContent（他章正文），此时标注偏移对编辑器无意义——入口按
  `gateChapter == null || gateChapter === activeChapterNum` 条件提供，不做
  「点了再报错」。
- antd TextArea 原生元素在 `ref.resizableTextArea.textArea`（t4-C3 选段先例）
  ；forwardRef 化时保持内部 editorRef 不变，useImperativeHandle 只包一层命令
  面，选段换算函数与既有 toRune 互逆各自就地实现（口径注释互指）。
