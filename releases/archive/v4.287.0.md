# v4.287.0 — 拆书导入 tail 模式出口：长书只取末 N 章入书架（2026-09-14）

## 来源

拆书导入线在案欠账（v4.281 起历版「未做」清单：**tail 模式出口**——引擎 `applyExtractMode` 自 v4.279 就支持「只取末尾 N 章」，但绑定只走 full，用户不可达）。tail 的产品意图（MuMu 蒸馏 §0.4）：**用末尾几章反推「这本书接下来该怎么写」**——长书续写参考场景不必整本入库。

oh-story 线 T4（导入结构映射与篇幅路由）调研后**暂缓**：聚合粒度（章级细纲 vs 卷级粗纲）需先定设计再动刀，避免半成品——池序顺延到本刀。

## 落地

### ① 后端：`ImportNovelBookEx`（NovelB +1 → **658**）

- 签名：`ImportNovelBookEx(filePath, title, genre, style, extractMode, tailChapters)`；`extractMode = full | tail`，非法值**起跑即报错**；`ImportNovelBook` 原签名保留（= full 委托），既有调用零变化。
- opts 全链透传：`parseNovelFile / parseTextChapters` 接受 `bookimport.ParseOptions`；引擎语义照旧——tail 章数按 **5 的倍数向上取整**，**>50 或 ≥ 总章数降级全本**（不静默乱裁），裁剪告知进 `warnings`；落库章号从 1 重编号（与 v4.283 书源线同一收口）。
- EPUB：spine 结构化清单无「末尾 N 章」语义，tail 暂不适用——用户显式选了 tail 时报告**如实告知**「EPUB 暂不支持提取范围，已按全本导入」（info 告警），不静默。

### ② 前端：导入向导「提取范围」选择（`ImportNovelModal`）

- Select：全本 / 末 5~50 章（5 的倍数步进）；提示语如实说明 tail 语义与 EPUB 限制。
- `HomePage` 解析 `full` / `tail:N` 传参给新绑定；纯前端状态，关闭即复位。
