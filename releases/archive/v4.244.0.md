# v4.244.0 — 记忆中枢办公面板口径对齐：facts 直读管理面（观察池清账）（2026-09-12）

## 为什么是这一刀

v4.243 壳内真机走查的观察池项：办公记忆库面板显示「不可用—未配置」，而同库的
生命周期行/注入体检都读出 2 条活跃记忆——同一面板两个取数路径口径分裂。

## 根因

`GaeaMemory()` 的 facts/available 依赖引擎控制器（gaeaCtrl → c.Memory）构建才有；
数据实体在 SQLite，经 `hubOfficeStore()` 直接可读（与 GaeaMemoryLifecycle/注入
体检同一路径）。新起壳控制器未建时面板误报不可用。

## 修复

- facts/available 改为**管理面直读**：`hubOfficeStore().List()`（与面板上生命
  周期行同口径）；available = 用户目录可解析。
- docs/scopes/storeDir 仍是引擎域文件面，控制器就绪时补充。
- 「不可用」退化为真不可用（用户目录不可解析的 Store 零值退化）。
- 零绑定零前端改动（面板空态分支本就区分 available 与「暂无记忆」）。

## 测试

Enabled 缺省 true。
