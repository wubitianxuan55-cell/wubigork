## 8.4 定稿回写（87e3c1b2 + 1463933b + e470391c）

**定稿 = 作者宣布本章正文为最终版的显式动作**（新概念：此前生成完即 done，作者改稿后生成时自动门的结果即漂移）。

- **建议制红线延伸**：AI 基于当前正文提取三件套草案（阶段合账/角色状态/伏笔状态），作者在 FinalizeModal 勾选确认后才落库；草案阶段经 analysis 包新抽 `ExtractOnly` 纯提取内核（与 Analyze 共用同一 LLM 提取但**零落盘**——五路落盘一件不许有，测试钉死）。
- **事务性口径**：三件逐件尽力落库，失败不回滚已成功件、不阻塞定稿标记；`chapters/NNN{,a,b,c}-final.json` 留痕回执（applied+errors），作者可重试。
- **幂等**：Progressions 按 Note 标记（「第N章定稿回写」）整批替换——重定稿同章不重复堆积；伏笔复用 SyncForeshadows 幂等 upsert。
- **阶段合账缓存** `chapters/stage-recaps.json`：阶段收官章（第10/20/…章）定稿时合成上一阶段总结合账落盘；阶段开篇章生成 `stageRecapSection` 先读缓存（区间匹配校验，脏数据弃用回落现合成），**不再每次重烧 LLM**。
- **分支章口径**（与自动门 Q3 同律）：只标记定稿+Skipped 申报——登记表/合账/状态卡都是主线口径，Progressions 章号锚点无分支维度不落。
- 前端：FinalizeModal 三区确认（合账可编辑/角色逐条勾选/伏笔徽标勾选）+回执视图；ChapterPage「章节工具」菜单「定稿本章」/「已定稿·重新定稿」。
