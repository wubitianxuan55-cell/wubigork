# gaea v3.3.0 发布说明

> 纯工程质量版本，零功能变更、零新绑定。

## eslint 366 → 0（errors 0 / warnings 0）

前端 CI 门禁约定里「存量风格问题降为 warn、随迭代逐步清理」的 366 条存量 warnings
本轮全部清零，分四层：

1. **配置显式化**（把「隐式警告」变成「显式约定」）：
   - `no-unused-vars` 增加 `^_` 前缀 ignore patterns——下划线开头 = 显式声明「故意
     不用」，属社区标准约定（mock 实现参数、解构占位等）；无前缀的真死代码仍报警告
   - `no-empty` 开 `allowEmptyCatch`——空 catch 块（localStorage/绑定降级吞错）是
     有意设计；空 if/for/函数体仍报警告
   - react-refresh 开 `allowConstantExport`（Vite 官方模板默认项）——组件文件内纯
     常量导出不破坏 Fast Refresh

2. **死代码清理 56 处**：未用 import 成员（MessageOutlined/Button/Tag/Typography/
   Sparkles 等 ~20 处）、未用 const/解构（bridgeAlive/kind/previewIndex/closeProject
   等）、未用函数（affColor/handleToggleOrgMember）、catch 参数、mock 只写不读变量
   （chat.ts cancelled 及其两处死写入）。跨 40 文件，全部删除或 `_` 前缀化。

3. **exhaustive-deps 40 处**（最需要判断的一类）：
   - 稳定依赖（useCallback 函数 / zustand store 方法 / useState setter / Wails 全局
     绑定 / 字符串原始值）→ 直接补全 deps；
   - 不稳定依赖（每次渲染新建的对象、props 可选回调）→ 显式 disable 注释并写明理由，
     绝不补依赖引发每渲染重跑；
   - 两处 **TDZ 陷阱**（GhostText/useVoiceChat）：被依赖的 useCallback 声明在 effect
     之后，直接补 deps 会 ReferenceError——已把定义整体上移（纯重排）；
   - 两处 disable 注释位置修正（GraphView/Composer：报告位置是 deps 数组行，注释
     原误放在体内）；
   - 复杂表达式 deps（StreamingIndicator/useComposerMenus）→ 提取具名变量；
   - 每渲染重建的数组（facts/scopes/allNodes）→ wrap useMemo；
   - ref cleanup 竞态（useRunningBadge）→ effect 内局部变量拷贝。

4. **混合导出显式声明 25 处 + 冗余注释移除 10 处**：
   - 14 个「组件 + 非组件导出」文件（i18n Provider+hook、ToastProvider+useToast、
     工具函数供测试/复用等）加文件级 `eslint-disable react-refresh/only-export-components`
     注释——混合导出是设计使然，显式声明优于隐式警告；
   - 10 处 `@ts-ignore` 移除——wails.d.ts 类型早已生成，注释多余（tsc 验证 0 错误）。

## flaky 治理

- **filewatch 测试超时 3s → 5s**：历史「首跑 FAIL 复跑绿」根因 = 沙箱/CI 高负载下
  fsnotify 事件投递 + 100ms debounce 延迟超过 3s 假红；统一放宽并加注释防回归。
- **CI 后端测试失败重试一次**：整体失败后重跑（重试后仍失败正常红，不掩盖真实缺陷）。
- 确认既有治理：CI 已排除 internal/tts（网络依赖）、test-all.ps1 已有 AV 锁重试。
