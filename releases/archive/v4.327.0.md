## 论点

现状「改图」按钮=把结果填回图生图参考图（整幅重绘），没有「原图 + 人话
指令」的语义编辑。编辑能力是旗舰标配（调研 §1.1）；gaea 后端已有 OpenAI
兼容图片面（/images/generations + /images/img2img），缺 **/images/edits**
——Qwen-Image-Edit 系云端网关的标准暴露面。

## 落地

- **线 A `internal/ai`**：
  - `image_openai.go` editImage 分支：`Mode="edit"` + `InitImage`（原图
    data URL）+ `Prompt`（指令，零新请求字段）→ multipart POST
    `/images/edits`（model/prompt/n/size + image 文件按 MIME 推扩展名）；
    响应解析抽 `parseImageResponse` 三分支共用（行为零变化）。
  - GLM：官方无 edits 端点 → 诚实拒绝；ComfyUI：本地档未接（B 计划）→
    诚实拒绝（不静默降级为图生图——编辑语义≠整幅重绘）。
- **线 B `GenerateMedia`**：mode="edit" 原图必填校验；**app 层不加后端门**
  （透传按后端能力诚实报错）；**零新绑定，绑定面 705 不动**。
- **线 C 前端**：`InstructionEditModal`（指令输入 + 原图|新图对照 + meta +
  错误展示 + 用到画布）；ResultStage 单图/网格两视图 +「指令编辑」Action
  （与既有「改图」并列）；ImageGenPage 接线（onApply 前插 results/history，
  镜像 queue 成功路径——后端已落盘+登记台账）。
