# v4.246.0 — 后端性能刀B：记忆写路径（重载出锁+写路径事务化）（2026-09-12）

## 为什么是这一刀

普查档刀B（docs/gaea-backend-perf-survey-2026-09.md）：一次 remember/quickadd/
forget 触发的记忆全库重载（SELECT 全部 facts 含 body + 全量分词 + 文档发现，
基线 50 条=2.3ms / 300 条=7.0ms）在控制器全局锁内执行，Send/Cancel/事件等
全部控制器操作被一并阻塞；同时 facts 写入与事件留痕是两条独立写事务，WAL
下双倍 commit/fsync。均先立 benchmark 基线再动刀。

## 修复

1. **全库重载出全局锁**（普查#2）：九个记忆写点改为「锁内取参 → 锁外
   Load → 按代号提交」。刷新保持对调用方同步（写后立即可见的语义与既有
   测试依赖不动）；代号守卫保证慢的旧 Load 被拒绝换入而非回退快照（被
   跳过的写必然已被更高一代 Load 读到——Load 起点晚于该写）。空间切换
   推进代号使在途旧空间快照失效（与改前「applySpace 不刷新」语义一致）。
2. **写路径事务化**（普查#12）：Save/Archive/Unarchive/ChangeType/touchInSpace
   五写方法（Touch 在引用解析热路径）单事务提交；事件仍尽力而为——事务内
   事件语句失败 → 回滚并退回单语句重放实体语句（写入本体不因事件失败而
   丢，语义同改前）。EventLog 抽 execer 接口：事件必须落在调用方事务连接
   上（Hephaestus.db 单连接池，否则死锁）。
3. **复核撤销普查#8**：BuildSearchIndex 实际分词 body（search.go:66），
   「索引不 SELECT body」会改变 memory_search 语义——证据不成立，已在
   普查档勘误。

## Benchmark（benchtime 20x）

- Save：0.95ms→0.49ms（1.9×）；Touch：0.86ms→0.45ms（1.9×）。
- Load 本体不变——其收益是不再阻塞全局锁。

## 测试

Go +5：事件失败回落保写入本体 / Save+事件原子提交 / 未命中行零留痕语义
不变 / Unarchive·ChangeType miss 报错；control 并发收敛（4 goroutine×5 写，
WaitGroup 全返回后快照含全部 20 条）。bench 3 组入库（memory bench）。
