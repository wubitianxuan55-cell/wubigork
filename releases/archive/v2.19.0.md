# gaea v2.19.0「数据与成本纵深·补测评缺口」发布说明（2026-08-14）

> 长期规划阶段 3 第二刀（D3-4）：受控测评补缺口——报告专项分析、压力任务预设、
> 快速流式探针（断流/卡顿观察）。延续 v2.18.0 的 D3-1/D3-2/D3-3 底座。

## 一、D3-4 · 测评报告专项分析（模板化打磨）

`renderBenchmarkReport` 在逐用例明细后新增 5 个专项段落：

- **每模型对比**：同任务下各模型平均 TTFT / TPS / 出入 token / 缓存命中——受控测评的
  横向可比核心（120 组对照方法学产品化）；
- **长上下文专项**（D3-4）：TTFT vs 上下文长度的分组表 + 解读提示（8K 以上 TTFT 大幅
  恶化 ⇒ 显存/批处理压力偏大）；
- **缓存复用专项**（D3-4）：首请求 vs 二次请求 TTFT + prefill 加速比/省时——验证
  cache_reuse_mode=same_prompt_second 的实际收益；
- **显存相关启动参数**（D3-4）：逐模型列出 effective_launch_params 关键字段
  （gpu_layers / no_kv_offload / no_mmap / context_size / batch / ubatch /
  cache_type / parallel / 类型）+ 解读；
- **并发专项说明**：运行并发 > 1 时提示 TTFT 回落幅度反映算力/显存余量。

## 二、D3-4 · 压力专项任务预设

受控测评任务集新增 3 项（配合上下文长度 / 并发 / max_tokens 参数组合成压力矩阵）：

| 预设 | 用途 |
|---|---|
| 压力·长上下文 | 长文本复述+要点总结（配 16K/32K 上下文） |
| 压力·长输出 | 深基坑支护专项方案 ≥1500 字（配大 max_tokens） |
| 压力·显存（长上下文+长输出） | 雨季施工方案 ≥1200 字 + 10 项以上措施（组合压测） |

## 三、D3-4 · 快速流式探针（断流/卡顿观察）

- 后端 `GaeaBenchmarkStreamProbe(model)`：对 Herdsman 模型发起一次真实 SSE 流式请求，
  测量 **TTFT（首块延迟）、分块数、最大/平均分块间隔（卡顿指示）、是否收到 [DONE]**
  （断流检测）、回答开头预览；模型未运行/未安装时给出明确错误。
- 前端「受控测评」新增「快速流式探针」区：每个已安装模型一键探测，结果内联展示
  （✓ TTFT/分块/最长间隔 或 ✗ 错误），不依赖完整 benchmark 即可做连通性检查。
