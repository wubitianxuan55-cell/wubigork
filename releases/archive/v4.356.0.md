## 三路审计结论（go build/vet 全净基线上）

- **线1 panic 防线**：Wails dispatcher 对绑定方法自带 recover（同步调用安全），但**绑定方法/事件回调里 spawn 的 goroutine 全部裸奔**——goroutine 内一个 panic = 整个 exe 闪退。全仓 65 处 `go func` + 约 30 处 `go xxx()` 逐一交叉比对 58 处 `recover()`，撞出 12 处漏网（微信轮询主循环/DAG 流水线三处/语音回合链/MCP 连接/书源导入搜索五处/dream/tts/SSE 解析）。
- **线2 并发安全**：整体纪律在水准之上（jobs 锁序注释/Registry leaf-lock/approval 双查/tasks 条件 UPDATE 堪称范本），真问题是**绑定层「调用方自觉」缺口**——1 处确定性自死锁 + cfg.Model 裸字段竞态 + NewSession/ResumeSession 无运行闸，全是「约定闲时调用、绑定不设闸」型而非内核锁错。
- **线3 资源句柄**：**零 P0/P1**——HTTP body 52 文件全配对、os 79 处全净、sql rows 93 处全配对、ticker 22 处全 Stop、子进程收尸全净、fsnotify 配对（v4.345 根修后），该轴线纪律极好。余卫生项（body drain/裸 rename/死代码 logger）转刀B。

## 刀A：panic 防线收口 + 并发守卫（12 处 recover + 3 处守卫）

1. **clawbot pollLoop+handle**（`internal/channels/weixin/clawbot.go`）：微信助手是唯一常驻外部通道，pollLoop goroutine 内**同步跑完整 AI 回合**（媒体识别→chatFn→意图路由→生图/改图→回推）全链零 recover——循环体加编排级兜底（panic 退出并复位 running 防 IsRunning 误报），handle 加消息级防线（panic 降级文案 `fallbackReplyText` 与 AI 回复失败同路，单条消息异常不杀轮询）。同文件 invokeInboundImageHook/invokeFileHandler/SendFileCard 三处先例证明这是漏网。
2. **DAG 流水线三处**（`internal/app/gaea_dag.go`）：节点 goroutine panic 转节点 failed（与 err 路径同形：置 failed+Error 带 panic 证据+波标记失败→下游 skipped），dagStart 编排层兜底 recover（run 状态残留由 dagSweep 重启兜底），节点改向 goroutine 补防线（与 GaeaSubagentFollowUp 逐行同构却没抄到防线——明确是遗漏）。
3. **语音回合链三处**（`internal/voice/voice_manager.go`）：handleSpeechEnd/runReply/runRealtimePump 三个 go 入口补防线——panic 转前端 EmitVoiceError+复位 StateIdle；文字聊天/TTS/章节生成流 app 层均有同款防线，唯独语音这条最长链全文件 0 recover。
4. **MCP 连接**（`internal/gaea/plugin/plugin.go` StartAvailable）：外部 MCP server=独立进程+外部协议数据，连接 goroutine panic 转该 server RecordFailure（对齐同文件并行 start 的 recover 先例——普查后新并行化引入的裸奔窗口）。
5. **书源五处**（novel_booksource_handler 导入/追加、sin_booksource_handler 下载、booksource/fetch runBounded worker、search 单源）：导入链 panic 转 error 事件（前端进度如实失败不永久挂起）；worker/单源 panic 转该槽位/该源错误项（宁漏勿误）。
6. **dream/tts/SSE**（gaea_dream.go/tts_service.go/ai/client.go parseStreamEvents）：defer 补 recover（单飞标志位照常复位）；SSE 解析 panic 不带崩进程，parseStreamEvents 自身 `defer close(chunks)` 在 panic 路径照常执行（消费方收帧不悬挂）。
7. **GaeaMemorySetRetentionDays 自死锁根修**（`internal/app/gaea_memory_lifecycle.go`）：持 ga.mu 调 GaeaInit（内部首行再取 ga.mu）——sync.Mutex 不可重入，**引擎未初始化时调用即确定性死锁**：绑定 goroutine 永久卡死且持有 ga.mu，GaeaSend/GaeaCancel/GaeaSkills 等全部消费方连锁冻结（办公板块整体僵死仅重启可解）。修法=先锁外探测 `needInit` 仅未初始化时调 GaeaInit（与 gaeaApplyCfg 先例同序；已初始化路径行为不变，幂等消化并发 Init）。
8. **cfg.Model 并发收口**（`internal/config/config_model.go` 新增 modelMu + SetModelMem/GetModelMem）：Model 是「UI 写路径（切引擎/设默认模型/SaveConfig 三写点）×请求热路径（resolveModelName 等四读点，每条请求必经）」交汇的唯一裸字段，string=ptr+len 双字并发读写未同步是形式 data race。3 写点+4 读点（ai/client / model_engine_handler / model_router / stats_handler）全部收口持锁；启动期 config.Load 单线程装配不受此限。
9. **NewSession/ResumeSession 运行闸**（gaea_handler.go/gaea_ui.go）：agent.go 注释明写 run loop「only swaps session while idle」是**调用方约定无执行强制**——回合中换会话=无锁直读 a.session 与 SetSession 交错+后续消息落旧 session 而路径已换新（转录分裂）。照 GaeaSubagentFollowUp 先例补 `Running()` 拒绝（错误文案可行动：先停止再切），绑定层自守防 httpbridge 绕过前端 busy 闸。

## 刀B：失败可见性 + 卫生

10. **回合收尾快照失败显性化**（`internal/gaea/control/controller.go`）：代码自述「每轮对话后自动快照保存，确保崩溃/重启不丢上下文」，但失败仅 slog.Warn——会话文件被 OneDrive/杀毒/备份短暂锁定或磁盘满时 **UI 全绿、重启回退数轮无任何提示**；模型调用前 checkpoint 是 fail-closed（:524 直接中止回合），收尾快照漏了同款纪律。升 Warn 级 Notice（前端 Transcript 按 level==="warn" 渲染可关闭错误卡）。
11. **chat 流式 runID 防碰撞**（chat_service.go）：毫秒时间戳尾部拼进程内 atomic 序号——同毫秒两路 ChatStreamPlain（双面板连发/程序化重试）不再同 runID 向同一事件通道交错发帧。
12. **HTTP body drain**（netclient 新增 `DrainAndClose`，替换 herdsman/health、modelengine 三文件、gaea/plugin/transport_http 共 9 处 defer Close）：非 2xx 早退不读尽 body→连接被丢弃而非归还连接池，周期性健康探测每次重新 TCP/TLS 握手；读上限 64KB 防异常大 body，成功路径 no-op+Close 统一替换安全。
13. **裸 rename 迁 RenameWithRetry 21 处/18 文件**（fileutil 既有 ErrPermission 退避实现，Windows AV/索引器瞬时占用致保存失败的韧性缺口）：app 13 处+config_save/backup/dag 模板与 store/narrative/office docxedit·pptxedit/project；跳过特殊语义点（moveOrCopy 跨盘回退触发条件/Archive 跨目录搬迁/恢复流程带 copyTree 回退等 12 处）。
14. **错误吞噬卫生**：characterlib ListChatEnabled 吞错返回空列表等 P2 项挂观察池不进本刀。

## 坑

1. **goroutine 裸奔是绑定层系统性缺口而非个例**——防线以「同文件/同型先例是否存在」为判据（clawbot 三处先例/followup 同构/plugin 双标），漏网处全是先例已立而新码没抄。
2. **sync.Mutex 不可重入死锁是确定性而非竞态**——持 ga.mu 调 GaeaInit 在 `cfg==nil` 分支下必现；「锁外探测+幂等重入」修法保持已初始化路径零行为变化，现有测试零改动。
3. **cfg.Model 收口走包级锁访问器而非改结构**——Config 是到处复制的值语义大结构，加 sync.Mutex 字段会破坏可复制性（vet copying locks 警告）；访问器+纪律注释（启动期装配不受限）是最小侵入解。
4. **vitest flaky 判定先复跑失败文件**（ContextView 28/28 绿）再定回归与本轮无关——本轮足迹零交叠（纯 Go）。
5. 后台复合命令 `taskkill …; cmd /c build.bat` 在 harness 下静默只出 banner（exit 0 假成功）——**构建产物必须核对时间戳/哈希/大小三件**，本次靠旧哈希识破。
