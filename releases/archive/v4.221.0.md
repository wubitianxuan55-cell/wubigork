## 缺口（真机核查发现的结构性问题）

子代理 Options 不带 JournalDir/SessionID → flushJournal 直接跳过 → **子代理写盘从不落
Journal**。三重后果：① v4.219 的「窗口归因」在真机上恒为空集（fake-runner 测试靠手工
塞卡才绿；壳内真机走查恰挂观察池未跑）；② task 子代理的文件编辑对版本时间线/回滚不可见
（6.1 可审计默认化的暗洞）；③ 波内并行被窗口归因锁死。

## 三合一落地

1. **子代理证据落账**（agent 包）：TaskTool 增 `journalDir`（`SetSubagentJournalDir`，
   boot 装配点注入，与主执行器同目录 `<cwd>/.gaea/work/journal`）+ `Options.SessionID`
   = run.Ref（sa_…），在 runSubSession 统一下发——task 工具 / RunNew / RunFollowUp
   三路径全覆盖；ephemeral（无 ref）不启用，宁缺勿错。子代理写盘回合收尾落证据卡、
   按会话分文件；开始建回滚基线（子代理编辑可恢复）。
2. **按会话归因**（app 层）：节点 outputs = `SessionID == ref` 的证据卡 Target——精确
   归因，主对话/其他节点同期写盘不再并入；ref 为空回退窗口增量口径。UI 口径注三语更新。
3. **波内并行**（app 层）：归因不再依赖「波内窗口不重叠」，dagExecute 波内 goroutine
   并发起跑；失败级联（后续波 skipped）/终止级联/dagMarkNode 互斥语义不变。
