## 一、启动反闪根修（亮色用户每次启动先看 ~2s 深空屏）

- 根因链：index.html 静态启动屏（bundle 加载期）硬编码深空底，主题 CSS 变量由 App.tsx
  useEffect 首帧后才注入，静态期无从消费；亮色用户 = 深色静态屏 → BootSplash（≥2.1s）
  → 闪到浅色，每次启动必现。
- 修法：`<head>` 内联脚本（bundle 之前）预读 localStorage `gaea-display-mode`——判定顺序
  **逐字对齐 appStore.loadMode**（`light` → 亮；`system` → matchMedia；旧布尔键
  `gaea-dark`/`wubigork-dark` 为 `'0'` → 亮；缺失 → 深色缺省），亮色会话给 `<html>` 挂
  `data-bs-light`。静态启动屏与 body 加浅色分支（#eef2f4 底 / #1f2937 字 / teal 深阶光环）；
  boot-splash.css 同步首帧兜底分支——App 注入真令牌后 `var()` 自然接管，两段同色无跳变。

## 二、绘梦历史有界化（无界增长三处收口）

| 环节 | 此前 | 收口 |
|---|---|---|
| 持久化 | 无上限——path-only 条目每条几百字节，localStorage 配额内可积数千条 | `HISTORY_META_MAX=500`，读/写两侧同截（截最旧，新记录在前） |
| 渲染 | `history.map` 一次性渲染全部条目（数百 img/video DOM） | 窗口 60 + 「加载更多（N）」+60 增量展开；窗口外数据完整 |
| 回填 | 挂载时把**全部** file_path 条目转 dataURL 常驻内存（每条数 MB，数百次生成=数百 MB） | `restoreHistoryImages(…, limit)` 按 `needsFileRestore` 过滤后取前 **48**（内联小图不占名额）；窗口外缩略图落既有占位（图标+模型名+重新生成），选中/下载/复用时 `resolveResultImage` 按需读文件 |

- 素材库（120 条 + 12/页懒加载）先例的对齐补漏；无功能删除——记录仍在，只是不再一次性物化。
- 测试：`HistoryRail.test.tsx` 新建 3 例（超窗渲染 60/点击增量展开到底按钮消失/不足窗口
  全量不回归）+ `historyMeta.test` +1（limit 按需恢复项计数）+ `meta.test` +2（读截/写截）。

## 三、亮主题中性叠加层失效群（30 处）

- `rgba(255,255,255,0.02~0.08)` 是暗底上的「白色提亮」惯用法——亮主题浅底上白叠白
  **不可见**：hover 反馈消失、卡片只剩边框、进度轨道消失、骨架屏 shimmer 不动。
- 30 处统一换 `color-mix(in srgb, var(--color-text) N%, transparent)`：暗主题 text 是浅色
  （原效果不变），亮主题自动变深色叠加（可见）。覆盖 PersonaPicker、imagegen 全家
  （AssetStudio×7/VisionTrial×4/ControlPanel×3/AssetLibrary×3/ModelDirectory×2/ResultStage
  shimmer/ui/TemplatePicker/TaskCenter）、RelationshipModal、CharacterFormHelpers、
  AppearancePanel、ChapterIllustration、WhisperDesirePanel 进度轨道。
- 辨伪保留：ChatCodeBlock 2 处白描边——`#0b0e14` 暗色代码面板的 chrome（hex-exempt
  既定例外，刻意不随主题）。
- 同族：`MarkdownContent` 的 `.md-content pre` 底 `rgba(0,0,0,0.3)`（亮主题中灰脏块）
  → `var(--md-sys-color-surface-container, …)` 令牌化。

## 五、反馈与确认补遗（上轮交互审计 B 系列遗留 4 处）

1. **角色记忆弹窗**（CharacterMemoryModal）：状态/记忆/追踪三路读取全部吞错——弹窗打开
   即空白，与「该角色还没有记忆」不可区分。加失败 Alert（部分失败也如实提示「内容可能不完整」）。
2. **青鸟助手列表**（WeixinPage）：Status/List 两路全失败此前伪装成「暂无青鸟助手——点 + 新增」
   假空态，用户误以为助手被删。改=全失败显示「载入失败，稍后自动重试」（role=status），
   单路失败仍走兜底视图不误报；轮询在，自动重试语义成立。
3. **图片下载**（useImageGenHistory + ImageGenPage 两处）：另存为写盘抛错原落 unhandled
   rejection「点了没反应」——补失败 `message.error` 与成功提示；用户取消保存（返回 false）
   不算错不提示。
4. **自定义生图模板删除**（TemplatePickerModal）：localStorage 持久数据此前一点即删——
   补 Popconfirm（确认钮 testid 定位）。

## 坑（本轮新增）

1. **静态启动期的主题预读必须逐字对齐 store 的 loadMode 判定序**（显式 light/system/
   旧布尔键/缺省 dark），多做一个 matchMedia 兜底就会和 appStore 分叉——首帧后跳变。
2. **limit 语义按「需恢复项」计数而非位置**：`slice(0, limit)` 会让内联小图占名额，
   回填条数不可控；先 `filter(needsFileRestore)` 再切。
3. **heredoc 写测试时的转义层数**：python 字符串 → 文件 → JS 源码三层，`\\\\` 才是
   JS 源码的 `\\`；写完必须看一眼原始字节（本轮 `\i` 无效转义被 eslint no-useless-escape
   逮住，字符串值也错了）。
4. **rgba(255,255,255,x) 不全是债**：暗色 chrome（代码面板）刻意不随主题，批量替换前
   先排除 hex-exempt 名单。
