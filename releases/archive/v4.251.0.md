# v4.251.0 — 后端第二遍扫描：goroutine/内存/启动链（2026-09-12）

## 为什么是这一刀

首遍普查（20 项，刀 A-E 全清）聚焦热路径；第二遍换镜头复查首遍欠覆盖的
维度——goroutine 生命周期、无界内存、锁跨慢操作、启动链——并补看
schedule/novel/channels/voice/browser/tasks 等首遍欠看的包。

**结论：goroutine 泄漏零**（全部 go func 有退出路径；time.After 循环均有
deadline 上界）。12 项发现，净修 5 项、观察 7 项（全表见普查档二遍扫描节）。

## 修复

1. **MCP StartAvailable 并行化 + 单 server 30s 上限**（最高危）：改前串行
   连接且无 deadline——一个挂死的 MCP server 无限期卡住会话装配。超时用
   AfterFunc 取消**仅失败路径生效**（成功连接的 transport 绑定该 ctx，定时
   器必须 Stop 否则健康 server 被误杀；fired 竞态下已连上的也撤下并统一
   按 timeout 上报）。测试=挂死子进程（select{} 会触发死锁检测器自己崩，
   须 sleep 循环保活）+「双挂死+好 server 耗时上界 3.5s」同时守卫超时与
   并行性（串行 >4s）。
2. **weixin apiPost 每请求 context 超时**：改前 timeout<90s 时每次克隆新
   Transport——长轮询循环（30s/轮）永久每轮新建连接+TLS 握手。
3. **notifyStart 异步化**：Startup 链上同步 POST，网络不可达时每助手 10s。
4. **tasks 节流时间戳随 outputs LRU 联动回收**（改前只增不删）。
5. **copyPath 流式拷贝**：旧数据迁移改前整文件读入内存（内存峰值=最大
   文件体积）改 io.Copy。
