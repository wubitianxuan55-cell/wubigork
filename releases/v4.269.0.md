# v4.269.0 — 造价域线上断链修复：costproject/coststage json 标签 + 五算带入空串时间字段（2026-09-13）

## 来源

维持轨「壳内真机走查池」既定项「五算带入与含量对照端到端」清账时抓到的**两个线上
真 bug**（真机走查池存在的意义实证）：

## Bug 1：costproject/coststage 全部结构体无 json 标签 → 列表卡空名/¥NaN（自 v4.204）

- 线上形状：Go 无标签序列化输出 PascalCase（`Name/ItemCount/Total/VersionCount`），
  前端契约读 camelCase（`name/itemCount/total`）→ 测算项目列表卡**名称空、行数空、
  版本空、合计 ¥NaN**；五算面板阶段值/对比/偏差同断。
- 为什么录入没暴露：Go 反序列化大小写不敏，保存方向一直正常；纯展示/读取面断裂。
- 为什么测试没拦：组件测试 mock 返回 camelCase，形状错配只在真机出现。
- **修复**：costproject（Project/ProjectSummary/Item/Version）+ coststage
  （StageValue/CompareRow/Deviation）全量补 camelCase json 标签；Go Unmarshal 大小
  写不敏 ⇒ 存量数据（含旧 PascalCase 版本快照）天然兼容。

## Bug 2：五算带入/手动保存/询价录入 payload 带空串时间字段 → Wails 解析必炸（自 v4.194/4.2）

- `confirmBring`/阶段手动保存/询价手动录入的 payload 显式带 `createdAt: ""`/
  `updatedAt: ""`——Wails 参数解析空串进 `time.Time` 直接报
  `parsing time "" as "2006-01-02T15:04:05Z07:00"`（toast 报错、永不落库）。
- **修复**：载荷省略时间字段（缺省=零值）；前端类型 `createdAt/updatedAt` 改可选
  （CostStageValue/CostInquiryRecord）；同型排查 `createdAt: ""` 全仓仅此三处（mock
  不算）。
