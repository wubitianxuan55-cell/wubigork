## 刀 A：docx/xlsx 对比迁移 ChangesDiff（v4.87 阶段二收口遗留）

- `lib/diff.ts`：`DiffRow` 增可选 `marker?: string` 列（docx 段落序号 /
  xlsx 单元格 ref）；可选字段 → 既有 ChangesPanel/GitPanel 数据源零变化
  （既有测试零改动通过）。
- `lib/diffRender.ts`：`pairModifications` 配对行改整行 spread（原先只挑
  text，marker 会丢）；`foldContext` 本就透传整行，确认无丢失。
- `ChangesDiff`：marker 存在时在 +/- 列后渲染定宽右对齐暗色 tabular-nums
  列（普通行 + 折叠展开行两处）。
- `VersionTimeline`：text/docx 对比体改构造 `{kind:"diff"}` 交 ChangesDiff
  （docx 段号→marker，path 透传得语法着色；`clampDiffRows(200)`+展开全部
  开关保留在下方）；xlsx 重写为每 sheet 一个 hunk——label=「sheet 名 ·
  状态文案（· 截断提示）」（复用 vcompare.sheet* 键），change 单元格→相邻
  del+add 对（自动获得 v4.87 改蓝配对+行内字符级高亮——较旧自绘表格的真
  升级），ref 进 marker 列，formula 追加 `  fx: =公式` 后缀，整表
  add/del 生成单行；不伪造 ctx 行。DiffStatChip/loading/unsupported/
  empty/contentMissing/竞态防护全保留。
- **红线核对**：段落序号列、单元格 ref、截断提示、sheet 状态、diffstat、
  展开全部——一项未删。vcompare.cellRef/cellOld/cellNew 三键不再被消费
  （键保留字典，功能文案全在 label/marker 中可见）。

## 刀 B：README 级内嵌 HTML 白名单渲染（3b 遗留收口）

- 新依赖：`rehype-raw@^7` + `rehype-sanitize@^6`（react-markdown 9 兼容线）。
- `Markdown.tsx`（文件预览链；**MemoMarkdown 聊天流有意不动**，已有 v4.92
  DOMPurify 消毒层）：管线挂 `rehypeRaw → [rehypeSanitize, mdHtmlSchema]
  → rehypeKatex`。
- `lib/sanitize.ts` 增 `mdHtmlSchema`：46 个白名单标签；script/iframe/
  form/button/svg/math 等 27 个 strip（连内容丢弃）；on*/style/id/data-*
  靠不在 attributes 表剥净；className 仅按值放行 md 管线自产类域（KaTeX
  `math-(inline|display)`、code `language-*`，逐 token 正则）。
- **两个关键实现发现**（头注成文）：①协议收口走渲染层（`mdUrlTransform`
  放行本地路径/mem:/data:image/* + 点击 `classifyExternalLink`）而非
  `schema.protocols`——hast-util-sanitize 内部 `{...defaultSchema}`
  浅合并，不显式给空 protocols 会带入默认协议表，把 `C:\` 盘符当 "c:"
  协议、剥掉 mem:/data:image（实测踩中）；②`rehypeSanitize(schema)` 返回
  transformer，必须用 Pluggable 元组 `[rehypeSanitize, schema]`——直接塞
  数组会被 unified 当 plugin 无参调用→静默 no-op（消毒形同虚设）。
- **收口修正（主代理）**：GFM 任务列表复选框回归——`input` 原在 strip
  清单，remark-gfm 的 `- [ ]` checkbox（styles.css `.md
  input[type="checkbox"]` 既有样式）会被误剥。修：input 移入白名单，属性
  按值受限 `["type","checkbox"]+disabled+checked`；raw `<input
  type="text">` 被剥成无类型空 input（无交互面）。红线：不许因消毒丢既有
  能力。

## 刀 C：子代理队列非唯一命中交互式确认（老账）

- `lib/taskActivity.ts`：新增纯函数 `matchRunningCandidates(args, runs)`
  返回全部文本匹配 running（保序）；`matchRunningRun` 改为其唯一命中包装
  （语义逐点等价，既有单测零回归）。歧义两槽位：
  `setTaskCardAmbiguityResolver`（渲染期逐卡查询是否 ≥2 匹配）+
  `setTaskCardAmbiguityHandler`（点击回调）；卡片侧 getTaskCardAmbiguity
  （try/catch 兜底 false）/hasTaskCardAmbiguityHandler/fireTaskCardAmbiguity。
- `ToolCard`：无唯一目标 && resolver 判真 && handler 在场 → 整卡与
  TaskLiveRow 渲染可点（cursor-pointer + aria「多个运行中任务，点击选择」）。
- `App`：点击瞬间用最新轮询数据现算候选，弹居中轻量选择器（antd Modal，
  destroyOnHidden，与 ContextModal 同款）——候选行展示任务文本/状态/模型
  等，点选走既有 `openSubagentThread`，Esc/遮罩/关闭取消。**宁缺勿错红线
  不变**：绝不自动跳转；0/1 候选行为与现状完全一致。
- i18n：taskpick.* 三语 +7 键（title/desc/cardAria/rowAria/statusRunning/
