# v4.27.1「seq 防线 omitempty 失配修复 · 对话窗运行中只显示读秒的根因收口」

> 发布日期：2026-09-01 ｜ tag：`v4.27.1` ｜ 基线：v4.27.0 ｜ 绑定面 550 → 550（零变更）

## 问题

用户报告（v4.26 重造后真机测试）：**「只显示一个思考读秒，并没有交替出现
过程卡、文本卡这些内容（只有轨迹面板有显示），对话面板的输出并没有对齐
Codex」**。

## 根因

v4.26 的 seq 补拉防线前后端形状契约失配，导致防线**静默失效**：

- Go `GaeaResyncItem` 全字段 `omitempty`：流式 assistant 条目的空 `reasoning`、
  写类工具的 `readOnly:false`，序列化后**键整个消失**；
- 前端 `parseResyncItems` 按「形状必须一致」严格校验（assistant 要求 text 与
  reasoning 同时为 string、tool 要求 readOnly 为 boolean），缺键即**整快照判坏
  弃用**；
- 真实流式回合里几乎每个条目都缺键 → 补拉快照 100% 被拒 → Wails 吞件期间
  对话窗无物可渲染。WorkHeader 是 store tick 驱动所以照常读秒；轨迹面板直接
  读磁盘日志不受害——与用户描述的形态完全一致。

## 修复

1. **Go 全字段去 omitempty**（序列化恒全键）；新增
   `TestGaeaResyncItemWireAllKeys` 锁「序列化恒全键」契约——谁加回 omitempty
   测试立即红。
2. **前端 `parseResyncItems` 缺省键宽容**：缺字符串/布尔键 → 零值（""/false），
   **present 但类型错仍拒**；kind/id/status 枚举校验不变（安全边界不放宽）。
3. 回归测试 +3：omitempty 真实形态快照正常解析、类型错仍拒、缺 id/未知 kind
   维持判坏。
