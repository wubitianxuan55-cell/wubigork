## 来源

MuMuAINovel 蒸馏线 t3 长程一致性域第三刀（`docs/distill/03-long-range-consistency.md` §3.3/§3.4/§12.1/§12.4-1/§12.4-2）。P1（v4.302.0）生产者已按章落盘故事记忆，本刀把召回消费接上——**分析自动回填 + 语义召回注入**的长程一致性闭环到此全通。检索底座全部复用现有设施：`internal/gaea/semantic.Store`（Ensure 增量向量化+正文快照比对）+ `retrieval` 本地 embedding（Herdsman bge-m3/qwen3，纯本地推理零云端 token），不引入 ChromaDB（§12.3 不适配项）。

## 落地

- **结构化 query 构造**（`buildMemoryQuery`，§12.4-1「本域最可借鉴的一段」）：不嵌大纲原文，按高信号字段分段限额拼接——人物[:8]/关键事件[:6]/叙事目标/情绪/本章要求[:150]，整体 [:800]，换行压空格。空 node 返回空（调用方降级）。
- **四段流水线**（`selectMemoryHits`，§3.4）：候选（Search 内部 Ensure 后全量余弦打分）→ 阈值筛选（`storyMemoryThreshold=0.35`，**gaea 归一化余弦语义，不照抄 MuMu 未归一化 L2 的 0.6**）→ 全部低于阈值时保留 top `storyMemoryFallback=3` 兜底（「无高分不如少带」，补关键词检索「一个不中就空手」短板）→ 注入 `storyMemoryTopK=8`。三常量唯一声明。
- **注入渲染**（`novelcontext`）：`SceneBible` 增 `Memories []string`，Render 在伏笔区段后增「## 相关记忆（按相关度）」——行格式 `- (相关度:0.82) 内容[:120]`（MuMu :789 content[:100] 同型），区段预算 `memoryBudget=400`，空记忆不出区段标题。生成侧提示为「参考信息辅助衔接」而非硬约束（与伏笔的硬约束层区分）。
- **索引维护**（规避 MuMu D1 向量残留）：recall 时 `Ensure` 增量向量化（缺失/正文变化才嵌）→ `Stale(kind, keep)` 清理已不存在条目的死向量（章节重写减条目后不留陈旧向量被误召回）。**项目隔离**：kind=`story_memory|<项目目录>`（§12.3 单机桌面以项目目录隔离，semantic_vectors 全局共享表）。**当前章排除**：只索引与召回 `ChapterNum < 当前章` 的记忆——当前章记忆描述的是正在写的内容。
- **接线与容错**（`CreateChapter`）：场景圣经编译后、渲染前，按大纲节点 ID 定位节点 → `recallStoryMemories`（结构化 query + 召回）。全链容错：库不可用/Herdsman 未启用/模型未启动/无记忆/无节点/任何失败 → 返回 nil 不出区段，绝不中断生成主链路；20s 超时上限。
- 零绑定面（召回是生成链路内部增强，无新 API）。
