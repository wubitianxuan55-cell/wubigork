# v4.488.0 · 阶段九 9.4 KV 缓存友好判据收口（2026-10-15）

> 阶段九第四刀，**9.1~9.4 全清**。规划判据：同会话相邻请求前缀字节级稳定判据延续并**覆盖压缩后首轮**。

## 盘底：机制面已完整在产

- **摘要请求 cache-aligned**（Reasonix/dsh 蒸馏，Letta self_compact 同口径）：`summarize` 的请求 = 会话真实 system 消息 + 被折叠区间逐字原样重放 + 压缩指令作为最后一条 user 消息——前缀与上一真实请求逐字一致命中 provider 热 KV，摘要输入按 cache-read 计价；slim 档（折叠区超预算）与 forceSlim（provider 真实拒绝后重试）是降档不是默认。
- **前缀字节级稳定判据**（5.2 编译器出口，v4.212）：`TestAdjacentRequestPrefixStable` 已在——相邻请求 Stable=true+CompileHash/PrevCompileHash 摘要链。

**真实缺口**：判据未覆盖「压缩后首轮」。本刀纯判据补测试，零生产代码改动。

## 判据测试

### TestPrefixStableAcrossCompaction（真实 CompactNow 链路）

| 请求 | 判定 |
|---|---|
| 压缩后首轮 | **如实判不稳定** + RewriteCount>0（digest 替换折叠区=结构性改写——诚实判漂移，此时谎报稳定才是 bug） |
| CompileHash 链 | 全程延续（PrevCompileHash 逐请求相接，可回放） |
| 压缩后次轮 | **恢复 Stable=true + 零改写**——`[system+firstUser+digest]` 固定前缀全量 cache hit 的设计承诺落成判据 |

附带确认：RequestHeader 只覆盖主请求路径（summarize 直连 prov.Stream 不 emit——现状语义，测试注释钉）。

### TestSummarizeRequestCacheAlignedPrefix（摘要请求传输面）

- 摘要请求的中间消息 = 压缩前会话的**逐字子序列**（原样原序重放，不重排不截断——子序列判定算法断言）；
- 压缩指令只允许出现在最后一条 user 消息——前缀内任何消息泄漏指令即破坏缓存对齐（逐消息断言）。
