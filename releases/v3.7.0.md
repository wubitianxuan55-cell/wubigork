## 记忆引用可追溯（C2）

蒸馏 codex memories/read 的 citation 闭环——办公用户可验证「你引用的资料
是不是真的」：

- **注入侧**：`RecallBlock` 每行带稳定引用键 `[MEM:<name>]`，块头附标注纪律
  （「采纳某条时在句末标注其引用键；记忆可能过时，以工作区文件为准」）；陈旧
  记忆（90 天未修订）自动附时效提示。
- **回传侧**：新包 `memory/citations.go`——回合结束（两条回合路径统一收口）
  解析最终回复中的 `[MEM:name]`（正则与记忆 Name kebab-case 同构，未知键静默
  丢弃），命中的记忆 `Touch` 更新 last_used_at（高频排序同源）。
- **前端**：`remarkMemCitations`（复用 remarkFileLinks 架构，`mem:` 自定义协议
  经 urlTransform 放行）把引用键渲染成可点击徽标，弹层展示记忆详情、类型、
  正文与**沉淀来源会话**（复用现有 `GaeaMemory` 绑定，零新增绑定面）。

## 审批决策语义族（C4）

对齐 codex `ReviewDecision`，审批从「允许/拒绝」二元补齐为完整决策族：

- **拒绝三分**：`deny`（拒绝但回合继续，模型可换路重试）/ `abort`（拒绝并
  终止本轮，`requestApproval` 收到即 Cancel 回合）/ 审批等待超时（TimedOut，
  见下）——不再只有「拒绝=单条放行 false」一种拒绝。
- **审批等待超时**：配置 `[agent] approval_timeout_secs`（默认 0=永久等待，
  交互场景零行为变化）后，无人响应的审批到点按拒绝处理、发 Notice、不静默
  放行——夜间批量任务审批无人响应时「不是卡死也不是放行，而是超时并记录」。
- **「始终允许」策略文件回写**（persist_allow，对齐 `append_amendment_and_update`）：
  会话 granted + 把 `ToolName(subject-glob)` 规则经 `config.AddPermissionRule`
  （幂等去重 + 解析校验）写入 `[permissions].allow`，`Save()` 原子落盘——重启后
  由策略文件直接放行，替代重启即失的内存 granted map。hardAsk 持久化写入
  （成本库/记忆/知识库）**完全降级**：不记 granted、不回写，「任何级别都逐条
  确认」的硬纪律不破；回写失败仅记日志不阻断批准。
- **接口重构**：`GaeaApprove(id, allow, session, abort)` 4 bool → 决策串
  `allow_once / allow_session / persist_allow / deny / abort`（`ApproveDecision`
  常量族）；审批卡快捷键固定映射 1–5，hardAsk 隐藏的选项按键不响应。

## 任务输出事件化（C9）

对齐 Codex「事件为主、轮询兜底」：`p.Output()` 追加输出时经 `gaea-task` 事件
推送输出尾部整尾回放（Task 新增非持久化 `outputTail/outputTruncated` 事件视图
字段，载荷有界于环形缓冲 200 行/64KB）；输出事件独立 400ms 节流，与进度事件
分开计时互不挤占；**终态事件兜底带完整尾回放**，覆盖节流窗口内被跳过的最后
几行。任务中心输出 dock 收到事件即推更新，2s 轮询降级为兜底。

## 上下文占用状态行（C5）

运行状态行（RunStatus）新增窗口占用迷你进度条与百分比，usage 事件实时驱动；
两档压缩前预警对齐 gaea 压缩引擎：≥75%「接近自动压缩」（触发线 80%）、
≥90%「即将强制压缩」（强制线 90%）；窗口未知时整段隐藏。

## 项目说明文件（C6，蒸馏 codex agents_md.rs）

排查确认 gaea 已具备完整层级发现（root→cwd、@import、.local.md 覆盖、
TIANXUAN/AGENTS/CLAUDE 三套命名），本刀补齐两处差距：

- **单文件 32KB 注入字节预算**（对齐 `project_doc_max_bytes` 默认值）：超限在
  UTF-8 字符边界截断并留 `<!-- truncated -->` 标记，防止单个超大记忆文件撑爆
  缓存前缀；
- **`.gaea/AGENTS.md` 子目录约定发现**：每层目录在平铺记忆名之后加载（更具体
  者后注入），发现后自动进入记忆面板 DocEditor 可编辑。

## 自动做梦 no-op（C3 收尾）

`runDream` 对整理输入做 sha256 指纹，与上次**成功处理**的轮次内容一致时直接
跳过 LLM 提炼（对齐 codex memories/write phase2「无变化即 no-op 成功，省一次
LLM 调用」）——重试/重入/同内容连问不再重复调用；指纹仅在完整处理后记录
（写入失败可重试），仅内存态不跨重启。排查结论：三层渐进披露（画像常载 /
索引注册表 4KB 截断 / 逐轮 recall / memory_search 按需）已存在，映射 codex
summary/registry/rollout 完整；LLM 滚动摘要层（memory_summary.md 式）列观察项。
