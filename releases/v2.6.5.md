# gaea v2.6.5「CosyVoice2 LLM 核显加速」发布说明（2026-08-09）

> 本版把 CosyVoice2 最慢的 **LLM 环节**从 PyTorch CPU 切换到 **llama.cpp GGUF + Vulkan 核显**
> （Radeon 8060S），整条本地 TTS 管线提速约 **8–10 倍**：
> 短句 6.5s→**~1.5s**，长句 24.5s→**~2.8s**。默认使用 f16 GGUF（音质最接近原始权重）。

## 一、CosyVoice2 提速（GGUF + Vulkan）

- **LLM 引擎**：`cosyvoice/llm/gguf_engine.py`（服务端 `C:\AI\cosyvoice`），
  基于 Tinysoft/Cosyvoice2-0.5B-GGUF + llama.cpp PR #14711（Qwen2 bias 支持）
- 统一词表布局实测验证：文本 0..151935 + sos 151936 + task 151937 + 语音 151938+，
  第一步 logits 与 torch 相关性 0.9999、top1 一致
- 采样 1:1 复刻 `ras_sampling`（top_k=25 / top_p=0.8 / 重复惩罚）；KV cache 逐 token 解码
- **默认 f16 GGUF**（`gguf\cosyvoice_f16.gguf`，1.23GB）；环境变量 `COSYVOICE_LLM_GGUF`
  可切回 q8（`cosyvoice_q8.gguf`，657MB，更快）
- 服务端启动自动加载 + 预热 Vulkan/DML shader；GGUF 缺失/失败自动回退 torch
- 修复：`mask_to_bias` fp16 下 -1e10 溢出 -inf 导致 ONNX Softmax NaN（fp16 改用 -3e4）
- 否决项：fp16 flow estimator（误差累积，波形相关性 0.016）、LLM 单步 ONNX（链式发散）、
  bf16（EOS 失效）、flow 4 步（无稳定收益）

## 二、本版累积功能（v2.6.1–v2.6.4 随代码库一并入库）

- 语音交互打通：AI 回复后 TTS 朗读正常，不再卡"正在聆听"；首页语音角色与聊天保持一致
- 模型中心「功能绑定 → 聊天语音」卡片：可绑定 xAI / CosyVoice2 / Herdsman 并选择音色
- CosyVoice2 本地音色克隆（参考音频注册 `POST /v1/voices`）+ 7 个内置音色
- flow 解码器 ONNX + DirectML、采样步数 10→5（v2.6.4）
