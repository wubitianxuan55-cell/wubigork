## S4.5 · 微信接统一路由 + iLink 图片协议第一刀

- **微信消息走统一意图路由**：`routeIntentWithResult` 产物感知版本（原
  `routeIntent` 包装不变，语音/命令面板零行为变化）；微信回调在提醒特例之后
  先过统一路由——navigate / generate_image / status / reminder 全部命中即执行，
  回复经同一回推通道；未命中才走原轻语聊天（「微信任务入口 ~20%」补到能力面
  全量）。`IntentResult.CardPath` 为产物文件卡片留位（iLink 上传端点探明后接线，
  当前回复文本带产物去向）。
- **iLink 图片消息协议探明第一刀**：`inboundMsg` 增加 `image_item` / `file_item`
  防御性解析（file_id/url/name/md5/size 按惯例留位，未知字段不报错）；非文本
  消息转成模型可见提示行（「用户发来一条图片消息（照片.jpg），内容暂无法读取」）
  ——发图即识别入口已开，字节级内容识别待 URL/file_id 真机收敛后接 vision 管线；
  未知空项宁漏勿误（静默跳过，不喂模型）。
- 回归：`TestHandle_NonTextMessageBecomesHint`（纯图/图文/纯文本三态）+
  `TestHandle_UnknownItemSilentlyIgnored` + `TestRouteIntentWithResultWrapsRouteIntent`。

## 规范包机制化（审计 §C ③）

- `standard.Registry` + `Checker` 接口：规范包从「单个硬编码红头 lint」升级为
  **可插拔检查器注册表**；`LintDocument` 跑全量并聚合（每条 Issue 带 Spec 归属，
  Summary 按规范包分组统计）。`LintText` 保留兼容，红头改为注册表内检查器。
- **新增「造价工程表式」规范包**（审计点名的缺项）：工程/项目名称、编制单位/
  依据、单位造价口径、人材机组成、合计汇总、编制说明 六要素 + 可执行修复建议。
- GaeaDocumentLint 切到 `LintDocument`；前端 OfficePanel「规范体检」按规范包
  徽标分组展示（红头要素 / 造价工程表式）。
- 回归：`TestRegistryAndLintDocument` + `TestCostTableChecker`。

## 成本归因对标（审计 §C ④「成本知识图谱+归因对标零实现」第一刀）

- `costref.ComputeAttribution` 纯函数：项目明细逐行 vs 参考指标（P25/P75 带宽 +
  中位数基准）——差幅等级（高/正常/低，带宽退化 ±10% 兜底）、贡献金额
  （(price-refMedian)×qty）、TopDrivers 按 |贡献| 前 10、总偏离与 Summary 主因；
  无参考条目保留展示但不参与归因（不猜测），另计 Unmatched 数量/金额。
- 新绑定 **GaeaCostAttribution(projectID)**（绑定面 530→**531**）：参考池 =
  除本项目外的全部「已保存版本/已沉淀」项目（**防自对标**）；临时工作稿不参与。
- 前端：FiveCalcPanel 新增「归因对标」区（总偏离/参考基准 + 主因表：单价→参考
  中位、差幅着色、档位徽标、贡献金额）。
- 回归：`TestComputeAttribution`（带宽判定/贡献/排序/主因）+ 带宽退化兜底 +
  `TestGaeaCostAttributionExcludesSelf`。
