## 数据面盘底（刀前）

跨项目的含量分歧在库里**已有形**：导入链统一四态（ResolveQuotaCode）把「同原码不同内容」拆成 原码-N 变体行，orig_code 保留原码溯源，各变体带自己的 Source（项目导入：<文件名>）；内容全等的复用同一条（真统一）。飞轮原料=同簇内 ≥2 条含量相异且来自 ≥2 个项目源的变体。

## 机制

- **聚类键=orig_code 本身，不做文本剥尾**。原码自身的合法数字尾（WP-100）与消歧尾（WP-100-2）形状相同，首版按 `-N` 剥尾的 quotaStem 把 WP-100 误剥成 WP——组件测试当场抓获后根修为溯源字段键控（教训=形状推断 vs 关系事实，关系字段在库里就不猜形状）；
- **聚合=逐资源取各变体含量的中位数**（对离群稳健）；覆盖度（N/M 变体）与极差（min~max）如实显形，严格过半才标「多数派」；
- **宁缺勿误四闸**：≥2 变体带含量行 / 标题+单位全等 ≥2（防自然尾码误并）/ ≥2 项目源（同文件重导入不算跨项目）/ 含量相异 ≥2（全等簇无可聚合）——不成立簇带人可读原因进预览；
- **落库=ENT-<原码> 自有命名空间**（Source=企业聚合：N 项目，Note 记成员码清单），SaveQuota 按 code 整组替换——重生成=飞轮进化，绝不覆写项目/全局定额；生成的 ENT- 前缀定额不进后续聚类（无反馈回路）；
- **预览/应用双段式**（批量调价同形态）：Preview 只读扫描；Apply=作者显式点名聚类词干，后端用同一纯函数重建候选后落库（Preview 与 Apply 天然一致，前端不搬运整表）。
