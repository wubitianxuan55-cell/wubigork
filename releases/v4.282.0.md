## 落地

### ① 平台质量评审引擎（新 `internal/novelreview`，零 LLM / 零网络 / 纯函数）

15 个**可机械判定**维度，逐维给 `PASS | WARN | FAIL | SKIP` + **S1~S4 分级** + **原文证据（rune 区间 + 段落号）** + 改法：

| 维度组 | 维度 | 档位差异来源 |
|---|---|---|
| 篇幅与节奏 | 字数区间 / 段落节奏 / 对话占比 / 标点节奏 / 破折号 / 格式合规 | 各平台阈值（章长带 / 长段阈值 / 省略号密度；盐言禁用空行分段） |
| 钩子与推进 | 开篇钩子 / 章尾钩子 / 预告式收尾 / 情绪节点密度 / 爽点·升级密度 | 判定词表 + 平台线（番茄重情绪密度、起点重爽点/升级） |
| 视角与人物 | 人称视角 / 主角存在感 / 金手指提及 | 盐言第一人称；起点主角出场 + 金手指提及（主角名取自角色库 `role_type=protagonist`） |
| 细节核对 | 字数表述核对（「这五个字」vs 引号实体实际字数） | 通用 |

结论 `APPROVE / CONCERNS / REJECT` 与评审 rubric 同门槛（无 S1/S2 → 可发；有 S2 或 S3 成堆 → 有顾虑；有 S1 → 打回）。

**诚实边界**：语义维度（核心卖点 / 角色动机 / 伏笔回收）引擎**不下结论**；外部数据缺失时**显式 SKIP 并写明原因**（如「角色库未标注主角，跳过」），**不静默给 PASS**。

### ② 阈值与词表是数据资产（可覆盖）

- 默认资产：`internal/novelreview/rubric.json`（go:embed）——四档位（通用 / 番茄小说 / 起点中文网 / 知乎盐言故事）+ 判定词表（冲突 / 情绪 / 悬念 / 爽点 / 金手指 / 预告收尾）+ 逐维严重度映射。
- 覆盖：`<工作区>/.gaea/skills/novel-review/rubric.json` **整体替换**（与 `novel-deslop/words.json` 同款纪律：想增条目把默认表抄进去再改），改门槛不改代码、不发版。
- **fail-closed**：覆盖文件里出现未知维度 / 非法严重度 / 坏区间会**逐类点名报错且不换出**（不会静默降级成「什么都查不出」）。

### ③ 接线与 UI

- **绑定**：`NovelB` +2 → `NovelChapterReview(chapterNum, platform)` / `NovelReviewPlatforms()`（648 → **650**，drift OK；两方法归 `play` 空间，锁 470 → 472）。
- **创作间「平台评审」面板**（rail 入口）：档位选择器 → 结论大标 + S1~S4 计数 + 逐维结果（**按 S1→S4 排序**）+ 证据摘录 + 黄金三问（读者为什么翻页 / 本章改变了什么 / 哪条原文证据）。
