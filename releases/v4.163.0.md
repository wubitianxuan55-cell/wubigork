# v4.163.0 · gaea 长期日志机制（2026-09-08）

> 用户要求「给 gaea 建立长期日志机制」。此前状态：单文件 `whisper_data/gaea.log`（目录为历史误植）、无轮转、无上限、无保留策略；v4.162 排障时它提供了关键线索，但机制本身不可持续。

## 机制设计（internal/app/logging.go）

1. **按日分文件**：`<DataRoot>/logs/gaea-YYYYMMDD.log`——天然轮转、归档友好、单文件永不无限膨胀；当日文件 O_APPEND 追加。
2. **保留策略（长期=一年）**：启动时删除超过 365 天的按日日志（文件名日期解析失败者豁免，如 legacy）；**总量兜底**：logs 目录 >1GB 时按 mtime 从最旧删起。
3. **历史迁移**：旧 `whisper_data/gaea.log` 一次性搬入 `logs/gaea-legacy.log`（目标已存在=已迁过跳过），历史不丢。
4. **生命周期打点**：启动头 `=== gaea startup ===` 附 version + Go 版本（排障对齐发布线）；Shutdown 记 `=== gaea shutdown ===` + 运行时长，随后关闭文件句柄。
5. **前端诊断自动汇入**：GaeaLogFrontendError → slog → 同一文件（v4.104 诊断器通道不变）。

## 设置中心入口

- 新绑定 `GaeaOpenLogsDir`（explorer 打开 logs 目录，目录不存在则先建）；设置→数据面板加「打开日志目录」按钮（data-testid=settings-open-logs）。

## 附带修复：v4.162 绑定运行时不可达缺陷

- **缺陷**：v4.162 的 `GaeaReadFileB64`/`GaeaSaveFileAs` 只加了 App 方法，**漏加 bindings_office.go 的 facade 委托行**——Wails 只暴露 `Bind` 里门面结构体的方法，App 直挂方法运行时不可达（导入点完菜单后 ReadFileB64 会抛错；导出 SaveFileAs 同样会失败）。
- **根因**：`gen_bindings -names` 只扫 Go 侧 Gaea* 方法名（App+门面都算），而运行时暴露面=门面委托——两层面名字相同但可达性不同，drift 检查探测不到「App 方法漏委托」。
- **修复**：OfficeB 补三行委托（ReadFileB64/SaveFileAs/OpenLogsDir，后者本刀新增）。**接手规约：App 上新增绑定必须同文件在任一门面加委托行，且壳内实测一次调用可达。**
