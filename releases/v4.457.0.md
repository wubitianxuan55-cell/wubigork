**日期**：2026-10-07 ｜ **产物**：`releases/gaea-v4.457.0.exe` ｜ 冒烟：`/api/health` 200 ✓

## 本版是什么

用户指令「根据成本测算模版。重新设计整个造价数据库，使其适配测算模版，采用综合单价带工料机的方式结构重塑整个造价数据库」，随后明确口径「工料机或者人材机都是基本的数据，综合单价的分析表是靠工料机和消耗定额核算出来的，其实就是建立我们的工料法成本数据库」。

本版把造价库从「单价为主」重塑为**工料法三层**：工料机资源（主数据）→ 消耗定额（含量）→ 综合单价（核算输出）。**绑定面 635→654（+19，全部归 CostB 门面）**。

## 口径纠偏（本版最重要的认知修正）

实测最新产物（旺平矿业 2026-10-07 / 什邡 2026-10-06，gaea 项目空间导出）封面自述：

> 「综合单价只含人材机，管理费/利润/税金不进综合单价（在费用汇总下半单列）」

**取费不得内联进综合单价**——早期实现把取费链算进单价，已彻底分离：`ComposeUnitPrice` 只出人材机，`ComposeProjectFees` 在项目合计层跑一次。取费基数链做成可插拔 `FeePolicy`：利润基数含不含规费在实测两份产物间本身不同（百锦路=false / 市政道路=true）。

## 数据层（SchemaV25/V26/V27）

- **V25 工料机资源库**：`gf_resources`（编码/类别/名称/规格/单位/基准价/现行价/来源/期数/损耗率）+ `gf_resource_prices`（调价历史）。编码唯一 + 身份唯一（kind,title,spec,unit）。**核算取用价 = 现行价优先、为 0 回退基准价**。
- **V26 消耗定额库**：`gf_quotas` + `gf_quota_items`（定额子目 → 资源编码 + 标准含量 + 行级损耗率）。金额不入列——由含量×资源**现行价**读时重算，这正是「资源一涨、所有引用它的综合单价同步重算」的落点。
- **V27 核算缓存化**：`cost_entries.price_derived`（1=由工料机核算而来）；`cost_entry_components` 增含量/价格来源标记；`cost_estimate_items` 增规格/人材机三费/取费/定额编码/覆盖标记共 10 列；`cost_projects` 增取费参数与编制说明共 11 列。
- **`cost_entries.price` 保留列名与对外契约不变**，语义降级为「最近一次核算结果缓存」——成本库既有 20+ 消费方（PriceBand 分位/contentband 含量对标/matchindex/检索/图谱/归因对标）**零改动**。

## 三层核算

- **外委独立行类**：实测模版汇总行口径为 `材料 = SUMIF(材料)+SUMIF(外委)`（水泥窑处置/外购土/监测化验这类不在现场发生人材机的项）。已作为一等 `KindOutsourced` 落地，`Compose` 单列 `outsourcedFee` 供拆分展示。
- **零含量是合法占位**：模版保留「技术工/带班 ×0」这类工序模板列出但本项未用的行，计数进 `ZeroLines` 而**不告警**（只有负值才是真非法）——狼来了告警会让人忽略真问题。
- **项目工作簿五表解析/导出**：封面 / 费用汇总 / 综合单价 / 工料机价格 / 工程量计算。解析器识别列名差异（旺平「消耗量单位」vs 什邡「消耗单位」），导出写**活公式**（VLOOKUP 取价、SUMIF 拆三费、跨表引 P 列与取费基数链）。

## 修复与加固

- **门面分类漏规则**：`mapGaea` 只认 `GaeaCost`/`GaeaPrice` 前缀，`GaeaWorkcost*` 静默落进默认 **office** 门面（调用仍成功——前端 proxy 按方法名遍历所有门面搜索，但类型面归错域、语义脏）。已补 `GaeaWorkcost` 前缀 → 19 个方法全归 **CostB**，OfficeB 零残留。
- **生成器 CRLF 静默失配**：两个解析正则用 `$` 锚行尾，Go 的 `(?m)` 下 `$` 不匹配行尾 `\r`。症状极具欺骗性——带 `// 注释` 的行因 `.*` 顺手吞掉 `\r` 仍能匹配，**只有光秃秃无注释的行失配**，于是「新加的最后一行偏偏没被认领」（legacy 清单被吹胀、tsc 重叠锁才红）。已显式容许 `\r`，**反向验证**：CRLF 输入下仍正确认领 579。
- **组成行类别判定短路**：`normalizeKind("")` 返回「材料」（成本库空类别默认值），早期据它判断「已标注」→ 后续关键词分支全被短路，挖掘机台班被归成材料。改为空 kind 不走归一，只看强关键词。
- **`SaveRecomposed` 独立成方法**：`price_derived` 是**来源声明**，只有核算路径有资格置位；若并入 `Save` 的默认行为，任何一次普通编辑都会把条目误标成「核算价」。
- **工作区行尾统一 LF**（仓库既有口径）：PowerShell `Set-Content` 会写 CRLF，既造 diff 噪声又是上面那个生成器坑的诱因。
