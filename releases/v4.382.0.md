# v4.382.0 — 前端挂池清欠：整店订阅清零 + 交付物缓存失效接线

> 两个小欠账一并清偿：v4.349 挂池④「reducer 级整店订阅」（收口销号）+ v4.354 记录的 dirListingsCache 失效接线欠账。前端 4 文件 + 测试，绑定面 711 零变更。

## 落地（两刀）

1. **刀1 无 selector 整店订阅清零（v4.349 挂池④收口）**——
   - 全仓扫描（appStore/scheduleStore/outlineStore/previewStore 四家）：无 selector 整店订阅仅剩 2 处——`WorkspacePanel`（novelsDir/setNovelsDir）与 `FilePreviewModal`（previewFile/closeFilePreview/openFilePreview）。整店订阅 = 任意 state 键变化即整组件重渲染，全部改为逐字段 selector。
   - **审计对账**：v4.349 审计的「13 处（MainLayout:414 / HomePage:33 / AppearancePanel×8 等）」行号已过时——MainLayout/HomePage/AppearancePanel 已被中间轮次（v4.352⑦ ModelCenter ctx 拆分等）selector 化，本轮清零最后余量后全仓归零，挂池④销号。
   - gaea 控制器 `useController()` 的 `useShallow(s => s)` 整面订阅保留：App.tsx 消费近乎全量字段无法局部化，且热字段（items 流式更新）本就逐 chunk 变化——selector 化无收益，架构性拆分留待专项。
2. **刀2 交付物缓存失效接线（v4.354 记录欠账）**——
   - `deliverablesTurn.ts` 的 registryCache/dirListingsCache（本轮交付物登记 + 目录存在性探测缓存）此前只有 TTL 与测试用的 `invalidateTurnCaches()`，「轮完成后/会话切换」两个失效时机一直是预留注释。
   - 接线两处：`turn_done` 事件消费点（ensureEventsBound）+ `loadSessionData`（会话切换/恢复）。效果：新轮交付物与轮内新建文件不再被 TTL 内的旧目录探测**误标缺失**；会话切换后登记与探测随会话整包刷新。
   - invalidateTurnCaches 纯内存清空，零桥接成本；测试面用「预热 → 失效 → 重拉打桥」的调用计数断言（新增 store.invalidate.test.ts ×2）。

## 坑

1. **挂池审计的行号会过时**——「13 处」清欠前先全仓重扫：中间轮次（v4.352⑦ 等）已顺手修掉大头，按旧清单动手会重复劳动；挂池条目销号要写清「哪些是本轮修的、哪些是中间轮已修的」。
2. **恰好一次的事件绑定是模块级单例**——`ensureEventsBound` 的失效接线没有「重新绑定」的测试入口，测试从可观测面（bridge 调用计数）断言行为，不 mock 内部。
3. **缓存类欠账的失效时机在事件边界**——reducer 必须保持纯函数，失效副作用接在事件消费/装载的既存非纯区（turn_done 块本就有 ContextUsage/Balance 副作用），不顺手往 reducer 里塞。
