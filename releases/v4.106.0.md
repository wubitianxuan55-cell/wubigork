## 改动一：xlsx 条件格式预览（缺口清单 #2，零绑定）

造价/办公表格大量使用条件格式（超预算红、达标绿），此前 XlsxPreview 只还原静态样式，
条件格式的动态着色全部丢失。本轮把「CellIs 静态可判定子集」贯通到预览渲染。

### 后端（`internal/office/xlsxpreview/condfmt.go` 新增 + `xlsxpreview.go` 接线）

- 提取范围：`cellIs` 类型 + 8 种比较符（greaterThan/lessThan/greaterThanOrEqual/lessThanOrEqual/equal/notEqual/between/notBetween）+ **常量阈值** + 可解析 dxf 样式（底色/字色/加粗）。其余（expression、色阶、数据条、图标集、top10、引用单元格阈值等）**诚实跳过**并计入 `condSkipped`，绝不猜测近似。
- 数据模型：`Sheet.CondRules []CondRule`（range 单段/op/formulas/priority/fill/fontColor/bold）+ `Sheet.CondSkipped`，均 omitempty——无条件格式的文件 JSON 零变化（回归锁定）。
- 技术路径：excelize v2.11 **无公开条件格式读 API**（stylesReader/getSheetXMLPath 均私有），经公开的 `f.Pkg` 原始 zip 条目解析三层 XML：`xl/workbook.xml`（sheet 名→r:id）+ `xl/_rels/workbook.xml.rels`（→worksheet 路径）→ worksheet `conditionalFormatting/cfRule`；`xl/styles.xml` dxfs 差异样式（底色取 bgColor——dxf 与普通样式的 fgColor/bgColor 语义相反，ECMA-376 §18.8.21；theme 色不可静态解析即放弃该样式）。
- **实测坑成文**：① Go encoding/xml 对带 URL 的属性命名空间匹配不可靠（`URL:id` 匹配不到），sheet 的 r:id 按本地名 `id` 匹配（该位置无歧义）；② **excelize 写侧 SetConditionalFormat 只写 cfRule，dxfs 表不落内容**（dxfId 指向 NewStyle 内部 id）——真实 Excel/WPS 产物才有完整 dxfs，测试夹具需 zip 后处理注入真实形状 dxfs（夹具 dxfId=1 对齐注入表索引 1）。
- 提取失败/无规则一律静默（条件格式属增强层，不阻断预览主链路）；编辑回写路径（XlsxPlanResult.Preview）复用同一 Render，自动带条件格式。

### 前端（`lib/xlsxCondFmt.ts` 新增 + `components/XlsxPreview.tsx` 接线 + `lib/types.ts`）

- 纯函数判定：`parseCellRef/parseRange`（range 包含）、`parseThreshold`（数字原文或带引号文本）、`condRuleMatches`（数值比较；equal/notEqual 文本大小写不敏感；between/notBetween 上下限无序归一；空单元格不参与=Excel 语义；容忍千分位显示值）、`condStyleFor`（priority 小者=高优先级整体胜出）。
- SheetGrid 渲染：命中规则的 fill/fontColor/bold **整体覆盖**基础样式（Excel 条件格式语义），选区/冻结行等交互样式保持原有优先序。
