# v4.391.0 — 附件 URL 缓存 blob 化：base64 大字符串迁出 JS 堆 + selbar z 防御修

> 性能池⑦「base64→blob URL 会话资源管理」收口（v4.365 审计留池最后一项免拍板性能项）。侦察发现 `usePortraitUrl.ts` 的 `dataUrlCache` 是**全局无界 Map，值是 MB 级 base64 data URL 字符串**——消息内联图/缩略图/inspector/角色头像/剧照全部经此通道，长会话多图场景 JS 堆驻留可观（1MB 截图→1.37MB base64 字符串×N 张常驻）。纯前端 3 文件+2 测试（改 1 新 1），绑定面 714 零变更。

## 落地

1. **缓存值 data URL → blob: object URL**——桥（AttachmentDataURL）返回的 data URL 经 `atob`→`Uint8Array`→`Blob`→`URL.createObjectURL` 转为短句柄入缓存，原 base64 字符串即被 GC：字节迁到浏览器侧 blob 存储（脱离 JS 堆、不参与 GC 标记、不放大堆快照），Map 里只留几十字节的 `blob:` URL。转换在既有 `.then` 异步回调内，不打断交互。**消费方零改动**（Message/FileThumb/inspector/PortraitImg 拿 URL 塞 img src，接口与语义不变）。
2. **LRU 上限 96 条**——Map 迭代序即 LRU 序（命中 `delete+set` 刷新 recency），超限淘汰最旧；**淘汰延迟 120s revoke**——仍挂载的 img 在窗口期内重挂载会重拉新条目（聊天虚拟化下行卸载重挂载走缓存 miss→重桥→新 blob），直接 revoke 会裂仍持有旧 URL 的在屏图。
3. **降级回退**——环境无 `URL.createObjectURL`/`atob`（旧 jsdom 等）时原样返回 data URL，行为与旧版逐字节一致。
4. **selbar z-index 1080→990**（v4.350 池⑧防御修）——原值越过 antd 全部弹层（Modal 1000/Select 1050/Tooltip 1060），弹层内选中文本时浮条会盖在弹层之上；990=内容之上、ai-console-fab(1000) 与全部弹层之下。
5. **todos 考古**——视觉池④的 `--whisper-ink-muted` 已在中间轮次重指向 M3 secondary（chat-board.css 在案），余项仅 `--fg-faint` 升档 tertiary 的纯视觉拍板项。

## 坑

1. **jsdom 30 原生实现了 createObjectURL**（返回 `blob:nodedata:…`）——「测试环境必然走 data URL fallback」的假设不成立，钉 data: 形态的既有断言会真挂；降级路径测试要显式 `defineProperty` 摘除才能触达。
2. **淘汰即 revoke 会裂在屏图**——缓存条目被组件 state 持有（Message 的 dataUrl state），LRU 淘汰≠无人引用；延迟 revoke 给「行卸载→重挂载→缓存 miss→重拉新条目」留窗口。
3. **data URL→blob 的转换别用 fetch(dataURL)**——Chromium 支持但 jsdom 的 fetch 不支持 data: scheme，`atob` 手写循环两边都可控。
4. **后台测试命令只留 tail 会丢失败详情**——全量验证重定向完整日志再 grep，否则失败文件名不可追溯。

## 升级说明

- 长会话多图场景 JS 堆内存降低（base64 字符串迁浏览器侧 blob 存储）；图片显示行为不变（blob: 与 data: 同为合法 img src）。
- 缓存条目上限 96 张（LRU），被淘汰的旧图再次显示时自动重读一次（无感知）。
- 小说阅读页文本选区浮条层级降低：弹层（对话框/下拉/Tooltip）内选中文本时浮条不再盖在弹层之上。
