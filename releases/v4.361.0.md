# v4.361.0 — 前端优化轮：失败可见化 + 观察池清账 + 令牌卫生

> 用户口径「优化gaea前端UI」：三路并行只读审计（令牌一致性 / 交互三态覆盖 / 观察池取证）后定刀落地。纯前端 34 源文件 + 4 测试文件 + 2 新工具文件，**绑定面 706 不动（零 Go 改动）**。三主题：①失败可见化——审计撞出 6 处「失败被伪装成空态/假成功/假通过」的交互缺陷（含 1 处可能真实丢数据）；②在册观察池清账——v4.355 真机走查遗留的 file:// 头像拒载与 longtask 误报、对比度普查遗留的 schedule 弱化文字一次清完；③令牌卫生——消费侧逐字重复样式收敛单一来源。零删功能（UI 简化红线）。

## 审计结论（三路镜头）

- **镜头A 令牌一致性**：令牌体系骨架健康（appStore 单源 + App.tsx 注入 + contrast 机检契约），病灶在**消费侧**——opacity 叠加把达标色乘回低对比、同语义色多种硬编码写法、7 文件逐字重复的 softTextStyle、2 处逐字重复的情绪色 map。大工程项（字号阶梯全量替换 700+ 处、玻璃配方收敛、canvas 图表调色板）本轮不动，留待立项。
- **镜头B 交互三态**：主链路（聊天/书架/微信助手/排程/角色库）在 v4.349~v4.355 已普遍具备 loading/错误/防重；残留问题集中在**「失败被伪装」**一类——假空态（搜索失败=未找到、造价库失败=新手引导）、假成功（批量改状态无条件报成功）、假阴性（一致性检查失败=绿色全部通过）、假丢数据（设定读失败=空编辑器可覆盖保存）。
- **镜头C 观察池取证**：①file:// 头像——角色库页本体 v4.257.1 已走 AttachmentDataURL 通道，残留 4 处直连在聊天人格选择器/绘梦画室/青鸟页（走查 27 条 console 告警的真实来源，PersonaPicker popover 全量渲染为最大来源）；②longtask——PerformanceObserver 无 duration 过滤，浏览器 50ms 下限全落网；③schedule 弱化文字——真实机制是把 `--md-sys-color-outline`（0.25 alpha，边框用令牌）当文字色，亮态混色后 1.3~1.8:1，与对比度普查数字精确吻合。

## 刀线一：失败可见化（照 v4.349/v4.350 现成范式平移）

1. **NovelSettingPage 读失败防覆盖**（唯一可能真实丢数据的点）——`GetWorldview` 失败此前被吞成空编辑器，用户随手输入再 Ctrl+S 会把真实设定文件覆盖成残文。修法=loadFailed 态 + 顶部 Alert（含重试）+ 保存按钮禁用 + handleSave 入口拦截（Ctrl+S 同一入口），重试成功自动恢复。
2. **SearchModal（Ctrl+K）失败三态**——三路调用逐个 `.catch(()=>null)`，后端整体失败与「无结果」不可区分（v4.350 只修了记忆中枢，全局搜索面板漏网）。修法=区分 null（失败）与空数组（无结果），**参与的检索线全部失败**才报「检索失败，请重试」，单路失败按可得结果降级；顺手补「存为任务」失败 message.error（原静默，用户以为任务入收件箱但永不出现）。
3. **ConsistencyPanel 假「全部通过」**——规则层检查失败静默保持旧报告/初始空，首查失败渲染绿色「全部通过，未发现一致性问题」=质检假阴性。修法=ruleError 态 + warning 横幅（含重新检查）+ 空态改「检查失败，结果不可信——请重新检查」；「失败保留上次报告」的既有语义不变，但必须可见。
4. **CostLibraryView batchStatus 假成功**——逐条 Get+Save 吞错后无条件报「已把 N 条改为…」（正是 v4.350 在 batchDelete 修掉的模式，漏网同函数兄弟）。修法=照 batchDelete 计数口径（Promise.all + ok/failed 分计数，全败/部分败 warning），并补 statusBusy 闸防连点。
5. **CostLibraryPage 概览失败≠空库**——三路读取逐个吞成空数组，全失败显示 GettingStarted「造价数据库还是空的」引导去导入。修法=三路 null 化，全失败置 statsFailed 走「读取失败+重试」错误态，单路失败仍降级渲染可得部分。
6. **WeixinPage 提醒失败态 + 首拉闪空态**——loadReminders 静默吞错（失败显示「暂无提醒」误导用户去微信创建）；助手列表首拉到达前渲染「暂无青鸟助手」空态，数据到达后跳变。修法=照 loadAssistants v4.351 范式（两路全 null → failed 错误条）+ assistantsLoadedOnce 标志（首拉前显示「正在载入助手…」）。
7. **批量吞错小刀 6 处**——KnowledgePanel doReview 失败 message.error（原按钮像没反应）；MemoryPanel 三个开关失败回滚补 toast「设置失败，已还原」（原静默弹回像 UI 抽风）；ChatPage 清空会话失败恢复消息快照 + message.error（原吞错后切会话回来消息「复活」）；ModuleLauncher 语音面板打字发送失败显示错误文案（原输入被清空石沉大海）；TaskCenter 任务输出读取失败显式文案（原留白/停留旧内容）；VoiceSettingsPanel applyVoiceSettings 失败 message.error（原调了音色重进发现没保存）。

## 坑

1. **失败判定布尔方向写反两次**——「参与者全部失败」的合取式里，不参与的路（scope 外的 Promise.resolve(null)）应贡献 **true（vacuous truth）**而非 false；首版把 work 空间下 unified 单路失败判成「不报错」，定向测试当场抓出。测试红一次值回票价。
2. **回归锁断言被前缀误伤**——`not.toMatch(/color:\s*var\(--md-sys-color-outline/)` 会匹配 `border-color:` 行和 `outline-variant` 前缀；源断言要行首锚定 `^\s+color:` 并在令牌名后带标点排除前缀族。
3. **no-raw-hex 豁免按文件名**——提取色板常量到新文件后原豁免失效，eslint 门禁拦下 11 处；豁免名单要随文件迁移同步登记。
4. **react-refresh/only-export-components**——组件文件里顺手导出 hook 会触发 warning（门禁要求 0 warn）；hook 独立文件是标准解。
5. **测试定位用 option 文本而非 querySelector("select")**——页面有多个 select（语义索引面板等），裸 querySelector 拿错元素；select 的 value 赋值必须是 STATUSES 里真实存在的值，否则 jsdom 静默回落空串、onChange 拿 falsy 直接短路。
