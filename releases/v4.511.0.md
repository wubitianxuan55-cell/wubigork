# v4.511.0 · 轻语浮层列锚根修：chat-main 补 position:relative，输入岛/回底按钮对心消息列（2026-10-20）

## 病灶

`.chat-main`（轻语对话主区）自 v3.0.0 起无定位，其四个 absolute 子元素的
包含块一路锚到整板 `.chat-board`（inline relative，含左右两栏）：

- **输入岛** `.chat-composer-wrap`（absolute left:0 right:0 bottom:0）——
  横向跨满整板（含话题栏与 inspector 底下），岛体在整板宽度上居中；
- **回到底部按钮** `.chat-scroll-bottom`（absolute left:50%）——居中于
  整板而非消息列；
- **粒子层 / 声波层**（absolute inset:0）——罩到左右两栏底下。

错位量随两侧栏折叠态摆动：默认双栏展开（侧栏 240 + inspector 280）只偏
约 20px，肉眼难察觉（掩盖至今）；**侧栏折叠 52 / inspector 展开 280 时
右偏 114px，侧栏展开 240 / inspector 折叠 40 时左偏 100px**——输入岛与
消息列明显不对心。浏览器探针实证：折叠态下修复前输入岛/回底按钮对心差
114px，修复后归零。

## 修复

`.chat-main` 一行 `position: relative`——四个浮层全部受益或不受影响，
无 adverse 重锚；两栏自身的装饰性 `::after` 均锚各自 relative 父级，
不受牵连。

## 守卫（+2，`chatBoardAnchor.test.ts`）

源级断言（perf-guards / App.tokens 先例风格）：钉 `.chat-main` 列锚
不变量（浮层的包含块=消息列）+ 输入岛/回底按钮的 absolute 语义——
此类缺陷 CSS 特异度/渲染测试均不可见，只有锚本身是可守卫的不变量。

## 同族扫荡结论（守卫面收尾）

- `closest()` 全仓五处：SelectionToComposer（标准元素选择器）、
  docxOutline（DOM 内部）、Transcript `.rewind`（v4.510 已接线）——
  无选择器落空；

  均为 `ref.contains` 安全模式且 ref 接线完好；
- novel-workspace / redesign / styles 的 `position: absolute` 全部为
  组件本地装饰锚（::after 高光线、resizer、tooltip 等），逐一核对清白。
