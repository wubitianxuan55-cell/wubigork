# v4.27.4「todo 持久化改名 · .gaea/progress.md 撞名根治」

> 发布日期：2026-09-01 ｜ tag：`v4.27.4` ｜ 基线：v4.27.3 ｜ 绑定面 550 → 550（零变更）

## 勘误与根因

**勘误**：v4.26.1/v4.27.1/v4.27.2 三份发布说明里「`.gaea/progress.md` 被并行
会话覆写」的结论**错误**——用户核实并无其他会话在跑。真凶是 **gaea 自身的
`todo_write` 内置工具**（V10.6 计划进度持久化）：每次 todo_write 把 todo 清单
渲染成 markdown 写入 **`<工作区根>/.gaea/progress.md`**（todo.go
saveProgressMarkdown，walk-up 找 .gaea）。办公代理在以 wubigrok 仓库为工作区
跑任务（开工筹备计划/安全文明手册等）时，每个任务节点的 todo_write 都覆盖同
名文件——四次覆写的内容全部是任务 todo 表（时间与任务节点吻合），备份在
backups/ 的四份「外部快照」也全是 todo 表。

这是**文件名撞车**：`.gaea/progress.md` 同时是①宿主仓库的项目记忆文件
（发布进度，AGENTS/记忆约定）与②gaea 代理的运行时 todo 持久化文件。用 gaea
开发 gaea（工作区=本仓库）时必然相撞。附带发现：用户主目录
`C:\Users\wubi\.gaea\progress.md` 也留有 8 月底的代理 todo 残留（walk-up 搜索
祖先目录的设计内行为）。

## 修复

1. **写入端改名**：todo.go 持久化文件 `progress.md` → **`todos.md`**（语义
   本就是 todo 清单）。
2. **读取端兼容**：compact_util.go `readProgressFile`（compaction 时注入
   todo 状态）优先 `.gaea/todos.md`、**回退旧名 `.gaea/progress.md`**——存量
   工作区的恢复链路不断。
3. compact.go 的同文注释同步。
