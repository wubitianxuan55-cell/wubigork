## 四、门禁可信化（随刀入库，工程面）

原先 CI 对前端全量套件**无条件重试一次**：真回归会被复跑洗白，红灯因此不可信。改为
「只允许在册 flaky 文件隔离复跑」：

- `frontend/known-flaky.txt`（**当前为空**）+ `frontend/scripts/classify-vitest-failures.mjs`
  （含夹具自测）：失败集合 ⊆ 清单 → 只复跑这些文件；出现清单外失败 → 直接红，不重试。
- `vite.config.ts`：`maxWorkers` 跟机器走（逻辑核折半 ≈ 物理核，夹 [4, 8]）——原先按逻辑核开
  ~31 个 worker，超配后单 worker 墙钟可达 CPU 时间的数倍，重组件首个 `await import` 直接撞超时；
  `testTimeout` 15s→30s、`hookTimeout` 20s。
- `test/setup.ts`：`configure({ asyncUtilTimeout: 5000 })`（默认 1s 在满负载下会饿死查询）。
  **不**在 afterEach 清 `document.body`——antd message 容器是模块级单例，清空会让后续 toast 落进
  游离节点（实测一次造成 14 例假红），残留问题改由上面的 worker/预算从源头消除。
- 效果：连续 3 轮全量 2799/2799 通过，原 ContextView / TrajectoryView / MemoryPanel /
  FilePreviewModal 超时族不再需要登记。
