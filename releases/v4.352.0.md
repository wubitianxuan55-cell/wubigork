## 一、ForeshadowPanel 行组件 memo 化（数百行列表的键入隔离）

- 现状：`items.map` 全量渲染、行无 memo——行内描述编辑 `setEditing` 每键、登记表单
  `description` 每键都全列表重渲染（数百章长篇可达数百行，每行 antd Tag/Tooltip/Popconfirm）。
- 修法：抽 `ForeshadowRow = memo(...)`；`flow/remove/saveEdit/handleEditChange/cancelEdit/
  startEdit` 全 `useCallback` 化；编辑态以布尔+文本双 prop 下发（`editing`/`editDesc`），
  行数据走不可变更新——键入只重渲染受控行。
- 测试：+2 例（编辑键入仍可保存且全量写回含 3 条/取消不写回且其余行不受影响）。

## 二、ModelCenter ctx 拆分 state/actions 两通道（v4.350 辨伪项的正解）

- 回顾：v4.350 辨伪「ctx 不 memo 化」——五个 hook 返回对象字面量每渲染新引用，deps
  无法建立，强行 memo = 陈旧 ctx 真 bug。
- 本刀正解：`ModelCenterContext` 拆三——
  - `ModelCenterStateContext`：全部状态字段（内容变化才触发消费者重渲染）；
  - `ModelCenterActionsContext`：全部 setter/handler（引用波动单独承载）；
  - `ModelCenterContext`（兼容口）：两通道合并，存量 `useModelCenter()` 不破坏。
- 页面装配：stateCtx/actionsCtx 各自 `useMemo([…hook 整对象])`（hook 对象变化=其内部
  任何状态变化，语义等价于逐字段），9 个 section 逐个迁移到 `useModelCenterState()` +
  按需 `useModelCenterActions()`；`settingGlmEndpoint` 归 state 通道。
- 效果：键入 API Key（页面级 state 每键）不再全 section 重渲染——只有真正消费被改
  字段的 section 重算；此前 9 消费者全量跟着走。
- 测试：4 个 test 文件的兼容 Provider 挂载补成三连 Provider（state/actions 兼容口
  value 同对象）。
