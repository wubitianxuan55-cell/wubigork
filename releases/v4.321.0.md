## 论点

整章重写对「改一段」太重：全章重新生成会波及未选段落。partial=选区+指令+
长度模式，只重写选中片段，前后文原样拼接。**对 MuMu 的升级**：gaea partial
也走 v4.304 版本库（全文快照可回滚——MuMu 局部重写无快照无 undo，其 F5
缺陷）；全链 rune 口径（MuMu 是 Python len 字符）。**零新绑定**：
NovelChapterRewrite 的 reqJSON 契约字段（mode/start_pos/end_pos/length_mode）
早已先行，绑定面 696 不动。

## 落地

### ① 线 A · 引擎纯函数（internal/rewrite/partial.go 新文件）

- `ResolveSelection`：rune 口径选段校验与 ±50 模糊重锚（越界/倒序/文本
  不匹配三类错误文案对齐 MuMu；selected 空=只做边界校验）。
- `PartialLengthSpec` 四档区间（similar 0.8×~1.2× / expand 1.2×~2.0× /
  condense 0.5×~0.8× / custom target±20% 钳 [50,10000]，未知回 similar）+
  提示文案；`PartialMaxTokens`=max(500, min(MaxRunes×3, 8000))。
- `BuildPartialInstruction` 四段固定顺序：上下文（空→章节开头/结尾占位，
  注明仅参考）→ 选中文本（选段外一字不动）→ 用户指令（≤1000 rune 截断）→
  长度模式提示。
- NormalizeRequest partial 分支：Source 恒 custom（其余报错）、指令必填、
  lengthMode 归一、custom 需目标字数、选区形状校验；whole 行为零变化。

### ② 线 B · handler（novel_rewrite_handler.go）

- NovelChapterRewrite 加 partial 分支（whole 路径零变化）：ResolveSelection
  重锚 → ±500 rune 上下文截取 → BuildPartialInstruction → 同一
  rewrite-chapter 模板（chapter_content 只给选段；systemPrompt 代词数=
  区间上限）→ MaxTokens=PartialMaxTokens（whole 固定 8192 不动）→
  CleanRewriteOutput → newFull=前缀+新选段+后缀（拼接断言钉死前后文零
  变化）→ 版本落盘（Mode=partial+选区字段+全文快照+选段级相似度）。
- types.RewriteRequest +SelectedText（前端传 rune 偏移+选中文本做重锚）。

### ③ 线 C · 前端三件

- EditorPanel：TextArea ref 读原生 selectionStart/End，**code-unit→rune 偏移
  换算**（代理对样例钉死），「局部重写」按钮（无选区 warning 引导）。
- PartialRewriteModal 三态：选段预览+指令（必填≤1000）+长度模式四选
  （custom 出字数输入）→ 运行态禁关闭 → 结果态（新选段+统计+应用走版本库
  Apply/放弃走 Discard）。
- CreatePage 挂载（onApplied 刷新正文同 RewriteModal 口）。
