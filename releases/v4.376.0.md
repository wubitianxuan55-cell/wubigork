# v4.376.0 — Reasonix 真身蒸馏第三弹：压缩救援阶梯 + 重复调用裁决 + 技能目录预算化

> 续 v4.375 真身蒸馏留池第三弹：压缩/恢复域两把主刀 + 技能目录一把小刀，另有一批辨伪销号收口留池。全 Go，绑定面 707 零变更。

## 落地（三刀）

1. **刀1 压缩救援阶梯**（源 `agent/fold_ladder.go`/`truncate.go`/`rescueOrFail`）——
   - **1a slim 摘要档**：摘要请求=system+折叠区逐字重放+指令，当折叠区本身大到来不及重放时（正是溢出场景），这个摘要请求自己会 400，然后退到机械裸计数摘要（信息量≈0）。新增 slim 档：估算摘要请求超出 window−输出预留−5% 边际时，逐消息截头（下限 200 字符+`[…slimmed]` 标记，write_file 全文参数截 160）换有界转录——溢出场景下机械裸计数的命运换成真摘要。阶梯：fits 时逐字重放不变（缓存对齐仍是首选档）→ 全量档被 provider 真实拒绝后重试也降半预算 slim → 机械摘要兜底不变。
   - **1b 投影截断终级**（`truncateRescue`）：溢出自愈的剪枝+强制压缩无进展、**或压缩后估算仍在窗口之上**（上游 at-or-above-ceiling 语义）时，有损终级接管：保护区收窄到 target/4（上游 `truncateProtectShare=4`——planCompaction 的 ≥2000 token 尾钳在「窗口太小压不完」的困境里会把可救内容全划成圣地）→ 先抹大工具结果（老→新，KeepErrors/KeepProtected 豁免）→ 仍超再整单元（assistant+其工具结果）丢最老并装 `[earlier conversation truncated: N messages removed]` marker。改动前先归档（与 prune 同纪律；archive 目录坏=整体拒绝 fail-closed，宁可如实报错不静默毁数据）。
2. **刀2 重复调用硬阻断降级 advisory**（上游裁决：reasonix 实测硬阻断误伤多于收益，全量退役改纯 advisory；gaea 观察期 v4.375→v4.376 已满）——`repeatedSuccessBlock` 硬阻断退役：同签名写工具第 3 次成功起不再被 `blocked: [loop guard]` 替换真实结果，改为批后注入一次性合成 user 提醒（每签名每轮至多一条，确定性序；`continue` 跳过当轮压缩，与其它 nudge 同形）。计数器照记（executeOne 并发安全不变）。行为变更：turnToolErrors 不再收集 loop guard 阻断，`Success` 语义更真实。
3. **刀3 skill 目录预算化渲染**（源 skill catalog 二分压缩描述行）——目录超 `IndexMaxChars`(4000) 时不再硬截断（尾部技能被截掉=模型永远看不见它们、永远用不到），先二分收缩描述宽度让**全部条目**挤进预算，压缩态尾注「descriptions compressed…run_skill loads full details」（计入预算）；只有纯名行仍超的极端（超长技能名/技能数极多）才退回旧硬截断。fitting 目录逐字不变。

## 坑

1. **救援机制的「可达带」要先算清再写测试**——rescue 的真实可达带=「compact 尾钳（≥2000 token clamp）与 rescue 尾钳（target/4）之间的盲区」；大块 assistant 正文是 prune 永远够不到（只抹 RoleTool）、compact 尾保护又留下的内容，E2E 场景必须用这类内容构造，否则 prune/compact 先行清场、rescue 永远不被触发，测试假绿或死码。
2. **gaea 的 token 估算器是 max(bytes/4, runes/2)**——纯 ASCII 按 2 字符/token 计（保守口径），构造 fits/over 边界时按这个口径算，按 4 字符/token 直觉会算错一个数量级。
3. **-destructive-截断必须 fail-closed 于归档**——prune/compact/rescue 三级都先归档再动手，archive 目录坏=三级整体拒绝；若 rescue 在归档失败时仍继续，就是静默毁数据的最后一环。
