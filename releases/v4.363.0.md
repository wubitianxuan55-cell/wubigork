## 刀1：GaeaConvertToPdf 读侧收口（挂池设计项落地）

**取证结论**（v4.358 挂池原文「需 Pick/白名单统一设计」——本轮设计完成）：

- **现状风险**：绑定入参 `rel` 绝对路径直通（任意路径喂 LibreOffice 外部进程）；相对路径 `filepath.Join(gaeaCwd(), rel)` 会 Clean 掉 `..`（`..\..\x.docx` 可逃逸工作区）。扩展名白名单齐备但路径零约束。
- **前端调用方全量对账**（生产调用点仅 FilePreviewModal exportPdf 一处）：
  - 工作区相对路径（文件树/资料库/DAG 产物/版本基线/exports 回灌）→ 落 withinReadRoots；
  - 附件 uploads 绝对路径 → `Join(gaeaCwd(), ".gaea/uploads")` 亦在 withinReadRoots 内；
  - **唯一真·合法绝对路径场景** = 系统对话框选取的工作区外素材（useComposerAttachments handlePickFiles 存原始 `f.path`）——正是经 `GaeaPickFiles` 进来，**登记时已入表**，现成的 `isPickedFile` 天然覆盖，无需新设计。
- **收口实现**（gaea_pdf.go，对齐 GaeaReadFile 口径）：①相对路径 Clean 后拒 `..` 穿越；②统一门 `!withinReadRoots(path) && !isPickedFile(path)` → fail-closed 拒绝（「文件不在可读范围（工作区/数据根），且未经文件对话框选取」）。写侧 exports 目录与文件名全服务端拼装，无越界面。
- **影响面**：三类合法调用方全部零误伤（白名单或登记表覆盖）；内存登记表重启即清——重启后历史会话里指向工作区外的附件 chip 再导出会被拒，fail-closed 可接受。前端 exportPdf 已有 toast 错误呈现，零改动。
- **定向 +1** `TestConvertToPdfPathGuard`（四场景全零外部进程：相对穿越拒绝 / 未登记绝对路径拒绝 / 登记路径过守卫 / 工作区路径过守卫——放行断言借 .doc 扩展名拒绝分支）。**坑**：放行场景最初用 .docx，测试机装了 LibreOffice 会真转成功（err==nil）反而无法断言——借「.doc 显式拒绝」分支既证明过门又不触外部进程。

## 刀2：prompt 引擎双构造辨伪关闭（不修，证据留档）

**取证结论**（挂池原文「agent 构造捕获 eng 指针、SetPromptFS 必须先行的时序风险，毫秒级收益不抵」——复核成立且证据链完整）：

- 「双构造」实为 **New() 构造后立即被 SetPromptFS 换新**（main.go:32→34 同步单线程、Startup/httpbridge 全部之前）——第一个实例存活期内**零读者**，无正确性影响。
- 换新是**功能必需**而非疏漏：embed FS 在 main 包 go:embed，`New()` 时拿不到；prompt.Engine 显式无锁契约（override 启动装配期写一次、之后只读），不支持事后注入——换新是唯一装配手段。写作五代理捕获 `w.eng` 指针的触发点（CreateProject/OpenProject）全在 Startup 后，捕获必是换新后的实例。
- 收益 = 省一次 20 文件/92KB 解析 ≈ 个位数毫秒、进程生命周期一次；成本 = 改 New() 签名（波及全部测试/CLI）或给 Engine 加锁（违反无锁契约）+ 绑定生成面（SetPromptFS 在 bindingNames/drift/gen_bindings 三处登记）。
- **判定：风险>收益，辨伪关闭**。日后若顺手，唯一低风险形态是 New() 增可选 embed-FS 参数 + SetPromptFS 幂等短路——排池尾不单独开刀。
