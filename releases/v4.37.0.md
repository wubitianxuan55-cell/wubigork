# v4.37.0「健康巡检 + 故障转移 v0」

> 发布日期：2026-09-02 ｜ tag：`v4.37.0` ｜ 基线：v4.36.0 ｜ 绑定面 **555→557（+2：GetEngineFailover/SetEngineFailover，ModelB）**

## 背景与依据（模型中心专项调研·C 刀）

三路调研一致结论：**健康巡检/故障转移在桌面与 Web 端竞品中全部空白**（仅 LobeChat 有 Key 级轮询）——gaea 已有 EngineStatus 持久化缓存、routeSource fallback 语义与成本重排，补此刀为差异化机会点。

## 交付明细

### ① 引擎健康巡检（health_probe.go）

- `StartHealthProbe/StopHealthProbe`：goroutine 巡检，首轮延迟 1 分钟、周期 10 分钟；范围=已启用且非本地引擎（本地由保活机制管，不重复探测）。
- 轻量探测：GET `{BaseURL}/models`，8s 超时，鉴权头与 fetchModels 同链（custom 无 Key 不发 Authorization）；2xx=连通（坏 JSON 仍连通、ModelCount=0）。
- 结果写引擎 Status 并随 saveState 持久化；**Error 永不含 Key/鉴权头内容**（sanitize + 对抗回显测试锚定）；连续 ≥3 次失败加「连续 N 次探测失败」前缀（计数仅内存，成功清零）；状态相对上次变化才回调 → app 层 emit `engine-health-changed` {id, connected}。

### ② 故障转移 v0（internal/ai/client.go）

- config 布尔键 `engine_failover_enabled`（默认关=现状逐字节，回归锁锚定）；绑定 `GetEngineFailover/SetEngineFailover`（ModelB，照 GetOfflineMode 先例）。
- 转移条件：网络类错误（dial/连接拒绝/DNS/超时/tls/reset）或 HTTP 408/429/5xx；**401/403/400/404 配置类错误不转移**。
- 候选：enabled + Status.Connected + default_model 判 llm，排除失败引擎，按 m.order 取首个；用其 default_model 重试**一次**（不递归）；仍失败返回原错误。
- 流式仅在首字节前转移（doStreamRequest 错误分支）；重试请求带 failoverDone 防二次转移；转移 slog.Warn + emit `model-failover` {from_engine, to_engine, model}；统计逐笔记账（失败归失败引擎、重试按实际引擎/模型）。

### ③ 前端（模型中心）

- 「本地调度」分区第三张开关卡「故障转移」（照保活卡样式；读取失败降级「未知」禁用）。
- ModelCenterPage 订阅 `engine-health-changed`（刷新引擎状态）与 `model-failover`（info 级提示「已切换到 X 重试」）。
- 总览引擎卡：error 含「连续 N 次探测失败」时原文展示（danger）；last_checked 存在时 title 提示巡检时间。

## 收口注记（gen_bindings 门面归属）

`GetEngineFailover/SetEngineFailover` 需登记 `scripts/gen_bindings/main.go` 的 explicitOverrides（照 GetOfflineMode 先例）——后端线手写的 ModelB 委托在主代理重跑生成器时曾被前缀规则误归 OfficeB 覆盖掉，登记后重新生成归位（教训入册：**gen_bindings 新方法必须先登记 explicitOverrides 再跑生成器**）。
