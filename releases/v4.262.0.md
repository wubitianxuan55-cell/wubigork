# v4.262.0 — 原罪工具集 v1 + 过程卡（2026-09-12）

## 为什么是这一刀

用户问「原罪现在可以使用哪些工具？现在看不见调用工具的过程卡」，并拍板「A + 网络搜索工具」。
改前原罪文本链是**零工具**的：`SinStream` → `ai.ChatSimpleOptions` + `ChatStreamChunks`，
请求体里没有 tools 字段；前端 StoryStream 也不处理 `tool_dispatch`/`tool_result`。
所以过程卡不是被折叠，而是**根本没有工具调用可显示**。

## 工具集 v1（原罪域内，硬隔离口径不变）

| 工具 | 作用 | 实现 |
|---|---|---|
| `web_search` | 联网搜索公开网页（真实地名/年代风物/器物/术语） | 委托办公 builtin：`tool.LookupBuiltin("web_search")`，**schema 直接转发**，[search] 引擎扇出、SSRF/域名策略、代理一处同源 |
| `web_fetch` | 抓取指定 URL 正文（摘要不够时补细节） | 委托办公 builtin `web_fetch` |
| `sin_cast` | 查本故事已选角色卡（只读，不改设定/改名） | 角色库（跨板块共享资产层） |
| `sin_notes` | 故事便签/设定集：`list/read/write/set/delete`（≤200 条、单条 ≤2000 rune） | `%APPDATA%\gaea\sin\notes\<故事id>.json` |
| `sin_outline` | 故事大纲：`read/write`（≤4000 rune） | 同上（同文件另一键） |

注册表 `internal/app/sin_tools.go`：init 自注册、重复即 panic、顺序固定（与 image_backend /
search engine 注册表同源）。**不接**办公工作区读写、命令执行、记忆面。

## 有界工具循环

- 每轮 `ChatStreamMessages`（**新 ai 入口**，与 `ChatStreamChunks` 共用 `prepareStreamRequest`
  一处装配，两条入口零漂移；超时/模型解析/default 采样/modelhub 让位规则完全一致）；
- `Done.ToolCalls` 非空 ⇒ 发 `tool_dispatch` → 执行 → 发 `tool_result` → 追加
  `assistant(tool_calls)` + `tool` 消息继续；**上限 4 轮**，末轮不带 tools 强制收尾成正文；
- **降级**：首轮带 tools 直接失败 ⇒ 去掉 tools 重试一次 + `notice`
  「当前模型不支持工具调用，已按纯写作继续」——工具是增强不是前置条件；
- **取消**：`SinCancel` 起手即登记（改造前要等首个请求建立成功），取消覆盖流式与工具执行；
- **纪律**：未知工具如实回错并列可用清单、工具失败只记轨迹不炸整轮、工具输出 6000 rune 截断
  留可见标记、全程无正文不落空消息。

## 过程卡（前端）

（重开故事按 extra 还原）。新 `SinProcessCard`：运行中自动展开、收尾自动折叠（用户手动操作不干预）、

## 真机走查（v4.262.0 exe，图片后端 Herdsman / 故事模型 grok-4.6）

**联网工具**：先跑独立探针直调办公 builtin `web_search`——0.6s 返回 Bing 结果（1084 字）；
应用内一轮「先查证再写」里，模型真实调用 web_search，过程卡逐条显示「联网搜索 …」与耗时（500ms 级）。

**走查抓到并当场修掉的三个真问题**（都不是单测能覆盖的）：

1. **搜索狂欢**：不设闸门时模型一轮连搜 12 次，轮次封顶后正文只剩 62 字 → 加**调用预算**
   （同名 ≤3 次 / 整轮 ≤8 次，超限不执行、如实回绝并把「用已有信息收尾」写进轨迹）；
2. **收尾轮空转**：收尾轮（不带 tools）模型仍回工具调用 → 这一轮没有正文，整单报错、
   **什么都没落库**（用户只见「模型没有返回内容」）→ 加「工具阶段结束」收束令 +
   一次兜底收尾轮，把正文逼出来；
3. **前端误判超时**：静默超时原本是**一次性 90 秒**计时器（不随帧重置），工具循环的长回合
   必然踩雷（后端已落库 827 字，前端却报「请求超时」）→ 改成**每帧重置**的真沉默计时，
   并补 vitest 锁定（帧到达即重置；改前该场景在 +85s 处已判超时）。

**最终基线**：新建走查故事 → 一轮「先查证再写」→ UI 正文 **1185 字**（落库 1340 字），
过程卡展开可见 9 条工具轨迹（故事便签/故事大纲/查角色卡 + 联网搜索×3 + 预算回绝×1 +
抓取网页×2，各自带用时），零页面渲染错误、exceptionThrown=0；该走查故事已删除，
用户自己的故事未改动。
