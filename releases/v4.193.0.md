# v4.193.0 — 角色回写欠账刀：非空字段逐项确认覆盖（2026-09-10）

> v4.192.0 明确留下的欠账收口：副本→库回写此前只做安全空补（非空一律不动），
> 项目内演化后的新外貌/性格写不回角色库——「同一人设」方向句的最后一块。
> 边界照旧：**不做后台自动同步**；**RoleType/Arc/Status 任何路径都不进库**
> （关联即快照，项目内弧线以项目为准）。

## 缺口

迁移完成后（unimported=0），章节推进会让项目 characters.json 持续演化；
此时角色库头部**没有任何回写入口**（迁入横幅已消失），非空字段差异
（库内旧外貌 vs 项目新外貌）永远无法合入库——绘梦参考与章节 prompt
两边继续分叉，正是 survey 指出的「外观锚点分裂」。

## 方案：预览→逐字段确认→覆盖（两段式显式回写）

**Go（characterlib）**：

- 新增 `descFields` 描述性字段表（Gender/Age/Personality/Background/
  Appearance/Figure/Motivation/Notes，与空补字段集完全一致）：预览、
  空补、确认覆盖共用一张表，三处不会各自漂移；
- 新增只读 `PreviewImport(chars)`：逐角色对比库内 vs 副本（trim 后），
  返回 `{import, fill, conflicts[]}`——冲突=两边都非空且不同，含中文字段名
  与双方值，UI 直接渲染；不写库、不改关联、不新建；
- `ImportProjectCharacters` 签名扩展：`+overwrites map[string][]string`
  （{角色ID: [字段键,...]}）与 `+overwritten int` 返回（覆盖字段数）。
  只有**勾选过的键**才生效（键大小写/空白容错，表外键忽略）；副本值
  trim 后为空不写（**不允许清空**，清空走角色库编辑，防误触丢设定）；
  值相同不算覆盖（幂等，重复确认零覆盖）；空补语义原样（didFill/didChange
  分离，filled 只数空补角色，回执不掺水）；
- nil overwrites = v4.192 行为逐字节不变（既有单向约束测试原样绿）。

**绑定面（604→605）**：

- 新增 `CharacterImportPreview()`（只读预览）；`CharacterImportProject`
  签名扩展 `+overwritesJSON string`（空串=不覆盖任何非空字段），返回
  `{imported, filled, overwritten}` 三计数；
- 六处接线全同步：gen_bindings 门面重生成 + bindingNames.ts +
  bridge/charlib.ts（编译期双向断言）+ wailsjs 双件（手同步）+
  spaceBindings 分类表（play）+ dev mock（预览空态/导入零值）。

**前端（CharacterPage）**：

- 头部操作区新增常驻**「回写」**按钮（title 说明语义）；迁入横幅的
  「一次性迁移」按钮同走新流程；
- 两段式：点击先只读预览——**无冲突直接安全回写**（不打扰）；
  有冲突弹确认框，按角色分组逐字段列出「库内值 vs 副本值」，复选框
  **默认全不勾**（保守默认=非空一律不动），三个出口：取消 / 不覆盖仅补
  空缺 / 覆盖勾选项并回写（无勾选时禁用）；顶部说明写明空缺必补、
  定位/弧线/状态始终以本书为准；
- 回执诚实化：「新迁入 X 个，补全 Y 个角色的空缺设定，按确认覆盖
  Z 处已有设定」；零变化时诚实提示「已一致，无需回写」；
- CharacterLibraryPage「从项目导入」按钮同步修 bug：v4.192 把返回改成
  对象后回执模板没跟上（会打出 `[object Object]`），改用诚实计数文案；
  该入口保持无覆盖（不传 overwrites）。
