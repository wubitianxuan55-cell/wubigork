## 1. 数据层

- **SchemaV17**：`cost_entries` + `code`（TEXT DEFAULT ''，定额编码/清单编码，归一化存储）、
  `cost_estimate_items` + `code`（测算明细行可携带清单编码）、`idx_cost_code` 索引。
  迁移测试覆盖「新库全链 V1→V17」与「V16 终点库升级」（历史行 code 默认空串）。
- **`cost.NormalizeCode`**：全角 ASCII→半角、去全部空白（含全角空格/nbsp）、转大写——
  「ａ１－１２」「a1 12」「A1-12」同码精确命中；空串=未录入语义不变。
- Entry/Summary/Item 三结构 + Save/Get/Search/List 全字段贯通；搜索 haystack 与 BM25
  文档均含 code，关键词直接按编码命中。

## 2. 导入链（costimport + AI 解析）

- 表头新增 `fieldCode` 列映射：清单项目编码/定额编号/清单编码/项目编码/定额编码/
  定额号/清单号/编码（最长关键词胜出；「编号」仍按噪声列忽略）。
- **编码优先匹配**：带编码行命中→「编码命中，将覆盖更新」；带码未命中→直接「新增」
  （同标题不同编码=不同子目，不做标题兜底，杜绝跨子目误覆盖）；无编码行保持原
  标题/名称精确匹配语义不变。
- AI 解析 prompt 增补 code 字段提取规则；vision（OCR 报价单）路径有意不动——
  报价单鲜带定额编码，轻量启发式不加复杂度。

## 3. 匹配消费方

- **costref 归因对标**：`entryIndexes` 双索引→三索引（name/code/title），`matchEntry`
  编码精确优先（matchedBy=code|entry_name|title 边溯源），带码未命中宁漏勿误配
  （与导入链同语义，测试钉死）。
- **测算沉淀**：明细行沉淀回成本库携带 item.Code；引用条目沉淀时继承原条目编码。
