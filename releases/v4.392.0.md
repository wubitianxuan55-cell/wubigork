## 病根

指令编辑（原图 + 人话指令 → 语义改图）v4.327.0 只有云端档（OpenAI 兼容
`/images/edits`），ComfyUI 本地档诚实拒绝（「请使用云端 OpenAI 兼容引擎」）。
而用户本机全局生图后端 = comfyui——**编辑在日用后端上不可用**，与 gaea 本地优先
的基本盘直接冲突：编辑是「从重抽到修图」的范式分水岭（长期规划 §6 调研共识），
本地用户被锁在重抽世界里。

## 落地

1. **internal/ai `image_comfyui.go`**：`mode="edit"` 从诚实拒绝改为真实现——
   - `buildQwenImageEditWorkflow`：ComfyUI 官方模板
     `image_qwen_image_edit_2511.json`（comfyui-workflow-templates 0.11.62）蒸馏
     （取道不取器，API-format 构建器与 krea2/z-image 同范式）：
     `LoadImage → FluxKontextImageScale`（按原图宽高比重标，编辑不套 1024×1024）
     → ① `TextEncodeQwenImageEditPlus`×2（正/负，image1=缩放图+vae）
     → ② `VAEEncode → KSampler.latent_image`；
     `UNETLoader → ModelSamplingAuraFlow(3.1) → CFGNorm(1) → KSampler`
     （steps 20 / cfg 4.0 / euler / simple / **denoise 1.0**=语义编辑非整幅重绘，
     官方 Note「Comfy」列参数）。
   - FluxKontextMultiReferenceLatentMethod 官方明示「用 Comfy 官方权重不需要」
     不接；Lightning 4 步 LoRA 可选加速件不接（观察池）。
   - 缺原图报「指令编辑需要原图」；req.Model 在 edit 分支被忽略（请求 model 是
     生图模型名，不代表编辑引擎）。
   - **缺权重可操作提示**：gaea 从不自动下载模型；ComfyUI 回 `value_not_in_list`
     时错误追加三件文件名 + HF 链接 + 存放目录（UNET `qwen_image_edit_2511_fp8mixed`
     / 文编 `qwen_2.5_vl_7b_fp8_scaled` / VAE `qwen_image_vae` 与 krea2 共用通常
     已在）——错误即安装指引；普通错误不追加零影响。
2. **internal/app `image_handler.go`**：`GenerateMedia` 在 `edit+comfyui` 时
   `imgModel` 如实改写 `qwen-image-edit`（结果卡/台账记真实引擎，不是 krea2）。
3. **前端 `InstructionEditModal.tsx`**：底部说明改口（本地 ComfyUI 档已支持 +
   缺权重行为如实描述），零交互变更；`data-testid="instruct-edit-hint"`。
