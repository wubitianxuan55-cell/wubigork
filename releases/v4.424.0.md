## 审计结论（提示词面的三个真问题）

1. **工具教学面与注册表脱节**：`sinToolOrder` 注册表有 9 个工具
   （web_search / web_fetch / book_search / book_download / sin_cast / sin_notes /
   sin_outline / sin_illustrate / sin_export），system prompt【工具】节只教了 4 个
   ——模型每轮拿到的 tools schema 是 9 个，未教过的 5 个只剩自身 description 一层
   约束。其中 `sin_illustrate` 与【插图协议】的标记协议存在真实二义：提示词只教
   「需要画面就写标记」，模型把「用户点名画一张」也理解成写标记（绕开工具的
   caption/进度/取消语义）；书源两工具（一轮能拉整本）零提示词约束。
2. **反 AI 腔规则弱于仓内已有蒸馏判据**：原提示词只有两条示例（「总的来说」
   「这一刻，仿佛时间静止」），而小说板块 oh-story 蒸馏线（novelstyle patterns.json，
   T2 内核消费）已沉淀出两条高置信机械判据——**解释腔标记**（「她不知道的是」
   「殊不知」「多年以后」「之所以……是因为」「这意味着」）与**否定翻转句式**
   （「不是……而是……」）。原罪正文是同一类失败面的高发区，提示词层却不设防。
3. **插图协议措辞含糊**：「一次最多 2 张」的「一次」可读成每响应/每轮/每场景；
   「另起一行只写一行标记」与「标记必须独占一行、以 @@插图| 开头以 @@ 结尾」
   重复表述同一件事。

## 落地

- **【工具】节补齐 5 个工具的使用纪律**（每个一行，纪律与各自 description 同口径）：
  `sin_illustrate`（用户点名要图才调；正文配图走标记；同一张图不双路径）、
  `book_search`/`book_download`（拉桥段/文笔/情节参考才用，素材化进描写不整段照搬）、
  `sin_export`（明确要导出才调；本回合正文未落库导出拿不到）。
- **【插图协议】重写**：正文顺手配图=标记（一轮至多 2 张）；用户点名要图=
  `sin_illustrate` 工具；两者不对同一张图重复。去掉重复表述。
- **【写作规范】补两条反 AI 腔判据**（对齐 novelstyle 蒸馏，提示词劝阻 + 内核
  门禁同一套判据）：解释腔五标记点名禁用（视角钉在场景里）；否定翻转=偶尔一用
  的强调工具，不连用、不当万能句式。
- **防回归闸 ×2**：`TestSinSystemPromptCoversToolRegistry`（注册表每个工具名必须
  出现在 system prompt——将来加工具忘了教直接红）；`TestSinSystemPromptAntiAIFlavorRules`
  （解释腔/否定翻转判据在案）。既有硬边界测试（成年人/合意/真实在世人物/标记
  定界符/600～1200 字）不受影响。

## 不动清单（看着可疑，实际有约束）

- 各工具自身 description 的纪律足够（sin_export 的「本回合导出拿不到刚写内容」、
  sin_illustrate 的「两者不能对同一张图重复做」都已在 description 里）——system
  prompt 补的是**聚合视野**（模型先读 system prompt 再挑工具），不是替代。
- 截断不劈句：`truncateRunes` 自带「…」尾标（历史/角色字段/底稿预算三处共用）。
- 温度/最大 token（0.9/8192 + play 护栏钳制）：非提示词文本面，不在本批。
- 标记协议格式 `@@插图|...@@`：前端解析、Go 导出、提示词三端同源常量，不动。
