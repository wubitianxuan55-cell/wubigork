# v4.367.0 — 编辑输入性能：章节编辑 memo 化 + 设定页预览/统计防抖

> 用户口径「继续」——性能轮延续：编辑输入链路（章节多场景编辑器 / 小说设定分屏）的每击键全页重渲染与全文重解析治理。全部行为等价（最终内容/统计一致，仅中间态降频）。前端 4 源文件 + 1 新 hook，绑定面 706 不动。

## 落地三处

1. **ChapterEditor memo + updateTab useCallback**——章节编辑每击键 `onUpdate('scenes')`+`onUpdate('saved')` 两次 setTabs 使 ChapterPage 整页（959 行，含阅读模式栏/overlays/多开 tab）重渲染，ChapterEditor 未 memo 全部场景框陪跑。修=updateTab 改 useCallback（依赖 activeKey）稳定 onUpdate 引用；ChapterEditor 包 React.memo——父页其它无关 state（focus 模式/ghost 开关/其它 tab 更新）不再重渲染编辑区。
2. **ChapterPage 上报防抖**——`novel:chapter-active` 事件 effect 依赖 `[activeTab]`（每击键引用变），每次执行全文 join+countTextChars 并派发事件拖动壳层 inspector 重渲染。修=250ms 防抖（cleanup clearTimeout），输入期间不付全文遍历，停顿后上报一次最终值。
3. **NovelSettingPage 预览/字数防抖**——分屏/渲染模式每击键对全文（数万字）跑 react-markdown+KaTeX 全文重解析（10k 字约 10~30ms/键，输入明显卡顿）；wordCount 每键 trim+countTextChars 全文扫描。修=新增 `useDebouncedValue` 通用 hook（300ms），MarkdownContent 与字数统计消费防抖镜像值，编辑器本身保持逐键受控（输入零延迟）。

## 坑

1. **跨层字符串转义是转义地狱**——CDP 探针/python 补丁多层传递中 `\\n` 会被吃成真实换行写进源码（TS Unterminated string literal）；构造含反斜杠的字面量用 `chr(92)` 拼接彻底避开转义层级。
2. **防抖的正确姿势是「镜像值」而非「延迟源」**——编辑器保持逐键受控（输入零延迟），只有下游重计算（Markdown 解析/字数）消费防抖镜像；若把防抖放在 onChange 上游会造成输入回显延迟，那是 bug 不是优化。
