# v4.516.0 · 回退菜单键盘体验收官：触发钮焦点可见+自动首项+Escape 焦点归还+视口翻转（2026-10-21）

> 用户指令「继续」（前端优化迭代续轮）。v4.515 补齐 ARIA 菜单模式
> （Escape+方向键）后，回退菜单仍留四个体验缺口，本轮收官。

## 缺口与落地

1. **触发钮隐形于键盘**：`opacity-0 group-hover:opacity-100` 只有 hover
   通道——键盘 Tab 聚焦会踩到不可见按钮（对照组：助手消息操作行早有
   `focus-within` 通道）。补 `focus-visible:opacity-100` + 菜单展开期间
   常显（`aria-expanded` 与视觉态一致）。
2. **打开后焦点仍留触发钮**：方向键漫游需先 Tab 进菜单。补打开自动聚焦
   首项（键盘/鼠标打开同受益，↑↓ 立即可用）。
3. **菜单内 Escape 焦点落 body**（WCAG 2.4.3 焦点丢失）：此前统一走
   Transcript 的 document 守卫关闭，菜单卸载后焦点丢到 body。补菜单容器
   就地 Escape（preventDefault+stopPropagation 免 document 守卫重复处理）
   + 焦点归还触发钮；焦点在菜单外时 document 守卫仍兜底。
4. **菜单恒向上开被裁剪**（v4.510 时已知边角）：消息位于滚动区顶部时
   `bottom-full` 展开方向超出 scrollport 顶端。补 `useLayoutEffect` 测量
   行上方可用空间（相对 `.transcript` 滚动区），不足 200px（菜单约
   182px+余量）翻转 `top-full` 向下开。

## 测试（+4，`Transcript.interaction.test.tsx`）

- 触发钮 `focus-visible` 通道 + 开菜单常显（独立类名匹配——
  `focus-visible:opacity-100` 含子串撞 `not.toContain` 的坑用正则边界解）；
- 打开自动聚焦首项（`document.activeElement` 断言）；
- 菜单内 Escape 就地关闭 + 焦点归还触发钮（**反向变异验证**：摘
  `triggerRef.focus()` 必红）；
- 开向翻转两态：jsdom 零几何=上方不足→`top-full` 向下开；mock 充足
  空间（row 顶 500/视口顶 0）→`bottom-full` 向上开。
- 全量 vitest 452 文件 / 3926 例绿（3922 + 4）；tsc -b 0；eslint 0；
  零 Go 改动、零绑定变更（671 不动）。

## 实弹

Tab 到某条用户消息：回退钮可见出现，Enter 展开菜单且首项已聚焦；↑↓
漫游、Enter 执行、Esc 关闭并回到回退钮；消息在对话区最顶部时菜单向下
展开不再被裁掉。
