# v4.39.0「微信助手管理台 · 多微信并行 + 并发正确性两修」

> 发布日期：2026-09-02 ｜ tag：`v4.39.0` ｜ 基线：v4.38.0 ｜ 绑定面 **557 零变更**

## 定位与来源

微信助手专项调研（合成版 `docs/market-research-2026-09-02b.md`，原始稿 `docs/research-2026-09-02b/` 三份：codebase-recon / capability-recon / market-scan）。**定位经用户拍板纠偏**：微信助手 = 通过微信与 gaea 对话进行各项工作——**聊天、出图、改图、收发文件、多微信并行**。本刀为提案 C（多微信并行管理台，纯工程刀无协议风险），后续 A（对话式改图）→ B（文件收发，抓包前置）按刀序推进。

实施方式：两路并行子代理（Go 后端线 / 前端管理台线，文件所有权互斥），主代理定跨线契约（Update 空值保留语义、整对象保存、零新增绑定）并收口。

## 边界与已知限制

- 同人格多助手仍共享会话上下文/记忆（orchestrator 会话 layout 不动）；多号并行
  建议每号配独立人格（轻语预设或角色库角色）。
- PortraitURL 仅展示，无上传/生成入口（现生产方为角色库立绘，另刀）。
- 语音/文件/群聊不在本刀（欠账池挂账）。
