## 论点

v4.317 出口对账判据②欠账：「结晶技能调用 ≥5 次且成功率可见（需调用计数机制
statsFile 先例另刀）」。现状核实：技能使用计数是**前端会话级**——`useToolStats`
只统计当前会话消息里的 `run_skill` 调用，不持久、不跨会话、无成功率、且漏掉
主消费通道 `read_skill`（boot 装配的按需加载器——结晶技能被模型「翻开来用」的
时刻）。判据②的「≥5 次」是跨会话累计口径，会话级计数支撑不了。

本刀补齐：**工具级调用计数**（read_skill + run_skill 双钩子）→
`<DataRoot>/skill_stats.json` 持久化 → `GaeaSkillStats` 绑定 → 能力面板技能行
「N 次 · 成功率 X%」可见。

**诚实口径（V1 裁决）**：成功率=工具级——read_skill 找到技能并交付正文=ok、
找不得=fail（技能名漂移/删除后的如实计数，不静默）；run_skill 管线执行无错=ok、
报错=fail。回合级成功率（用户满意与否）留观察池，不在本刀虚构。「≥5 次」是
使用事实门槛（可见性支撑），不做硬闸不弹窗。

## 落地

### ① 新纯包 `internal/skillstats`（零 IO 表驱动，先例 routesuggest/taskinbox）

- `Stat{Calls,Ok,LastAt}` + `File{Version:1, Skills}`（camelCase 形状测试钉死）。
- `Record`：空名忽略；`MaxSkills=500` 新名拒收（防名字漂移长期堆积，既有名
  更新不受限）；传零值 File 自动建表。
- `View`：calls 降序 → name 升序稳定，恒非 nil。

### ② boot 双钩子（internal/gaea/boot）

- `Options.OnSkillUse func(name, ok)`（缺省 nil = 零行为变化，CLI/TUI 宿主
  不传不受影响——EmitSubagentText 同款先例）。
- `sysprompt.go` resolver 包装：read_skill 读不到名也计一次 fail。
- `boot.go` run_skill 挂装饰器 `skillUseCountTool`（新文件 skilluse.go）：
  args.name 解析失败不计（宁少勿扰）；CompactDescriptor 回退语义与注册表
  缺省一致。

### ③ App 层持久化 + 绑定

- `<DataRoot>/skill_stats.json`：route_suggestions 同款容错读（缺失/损坏/
  version≠1 回空表——计数丢得起）+ temp+rename 原子写；`skillStatsMu` 串行
  读改写（多回合并发安全）。
- `recordSkillUse` 包级回调（boot 引擎 goroutine 调用，无 App 状态依赖）；
  落盘失败只告警不阻断工具结果。
- 绑定 `GaeaSkillStats()`（**OfficeB +1，绑定面 695→696**）：只读现算视图。

### ④ 前端（能力面板技能行）

- `CapabilitiesPanel` open 态拉一次 `app.SkillStats()`（零轮询；reload 按钮
  随引擎热加载一并刷新）→ `SkillsSection` 新可选 prop `usage`。
- `SkillRow` 徽标行加灰字 `N 次 · 成功率 X%`（data-testid=skill-usage-stat）；
  usage 缺省/零调用不渲染（旧调用方与既有测试零变化）；**会话计数 chip 语义
  不变**（本会话）。
