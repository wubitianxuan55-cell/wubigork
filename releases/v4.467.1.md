# v4.467.1 · 真机崩溃根修：绑定面 nil 切片 JSON null 崩前端（清单分析弹窗）

**日期**：2026-10-07 ｜ **产物**：`releases/gaea-v4.467.1.exe`（SHA256 `dafae221ae4df1cb…` 见 SHA256SUMS）｜ 冒烟 200 ✓

用户真机反馈「点击清单，无法查看组价明细，定额库打开失败」。日志（gaea-20261007.log）实锤真因不是数据库打不开，而是 **CostLibraryPage 前端崩溃**：`TypeError: Cannot read properties of null (reading 'length')`，ErrorBoundary 拦下整块 UI（当日 12:17/12:54/16:28 三次，横跨两版构建）。

## 根因

Go 绑定结果 struct 的切片字段全部 append-only：**空定额（无含量行）** 等空态下 `Compose.Lines` / `Compose.Warnings` 为 nil，经 Wails JSON 序列化成 `null`；前端 `lines.lines.length`（QuotaAnalysisModal 空态分支）直接 TypeError——「该定额没有工料机消耗行」的空态永远渲染不出来，整页进 ErrorBoundary。同类裸消费面还有 `compose.lines/warnings`（企业定额库分析）、`res.errors`（导入/资源化回执）、`preview.candidates`（存量资源化预览）、`bundle.warnings/items`（项目导入 toast）。

## 修复（双层）

- **Go 根修**（新构建起不再产出 null）：`ComposeUnitPrice`（Lines/Warnings）、`ParseProjectWorkbook`（Resources/Items/Lines/Quantities/Skipped/Warnings 六切片）、`ApplyProjectResult.Errors`、`SeedPreview`（Candidates/Skipped）构造即非 nil。
- **前端兜底**（对旧构建 Go 产物同样免疫）：QuotaAnalysisModal、WorkcostComposeView、WorkcostResourceView、CostIndicatorsView 的全部数组消费点 `?? []`。

## 验证

- 回归钉：Go `TestComposeUnitPriceEmptyQuotaNonNullSlices`（空定额 → Lines/Warnings 非 nil、综合单价 0）；前端 WorkcostViews 新例（mock 返回 `lines: null` → 渲染「该定额没有工料机消耗行」空态不崩），25/25 绿。
- 全量 ci 绿（Go build+vet+lint 0 / tsc / eslint / vitest 全量 / knip / drift PASS@639 / 卫生守卫）。

## 教训

Wails 绑定面「Go nil 切片 = JSON null」是系统性契约：**结果 struct 的切片字段必须构造即非 nil，前端消费一律 `?? []`**——空态是合法态，不该由序列化层把它变成崩溃。
