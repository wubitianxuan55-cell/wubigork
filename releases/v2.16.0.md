# gaea v2.16.0「Herdsman 底座加固 + 工程门禁」发布说明（2026-08-14）

> 长期规划首轮（docs/superpowers/plans/2026-08-14-gaea长期规划-herdsman底座加固与工程门禁.md）落地：
> gaea 的本地能力链（聊天/视觉/embedding/rerank/OCR/文档解析/ASR/TTS/生图/翻译）
> 全部挂在 Herdsman 服务（localhost:8080）上，本轮把它变成「可探测、可探活、可告警」的受管底座；
> 同时修复前端 CI 门禁——此前 eslint 因插件缺失直接崩溃、continue-on-error 形同虚设。

## 一、Herdsman 底座加固（后端）

### H0-1 环境探测与兼容契约
- 新增 `internal/herdsman` 包（probe.go）：一次探测 config.yaml（api 段）、herdsman.exe CLI 可找到性
  （HERDSMAN_EXE 优先，其次 PATH，不执行子命令）、`/v1/models` 可达性（默认跳过真实请求，
  HERDSMAN_PROBE_LIVE=1 时开启）、四个数据契约文件（launch_records/、model_stats/events.jsonl、
  skill-operations.json、models/）的存在性与可解析性。
- 输出结构化 Probe + 中文告警清单：LAN 暴露、端口漂移（config.port ≠ 8080 而 baseURL 用默认值）、
  契约文件缺失/不可解析。herdsman 升级破坏契约时前端可第一时间看到。

### H0-2 服务健康检查
- `internal/herdsman/health.go`：端口拨测（1s）+ API 存活（GET /models，3s）+ 按能力归类已装模型
  （chat/vision/embedding/rerank/ocr/parse/asr/tts/imagegen/translation，capability 缺失时按模型 ID
  关键词归类，如 bge→embedding、sherpa/whisper→asr）。
- `App.HerdsmanHealth()`：Healthy = 端口 + API + 聊天模型齐备；Summary 给中文问题清单。

### H0-3 TTS 默认模型动态解析
- 修复：默认 `qwen3-tts-customvoice` 本机未安装（0MB），默认语音路径必然先失败再回退。
- 新增 `voice.ResolveHerdsmanTTSModel`：配置值已装则用配置值；否则按优先级（voxcpm2 第一——
  本机实测唯一可用本地 TTS）从已装列表解析；拿不到已装列表时行为等价于原逻辑。
- VoiceGetSettings 附带 ttsHerdsmanModelFallback / ttsHerdsmanModelFromInstalled 标记供前端提示。

### H0-4 LAN 暴露检测与告警
- `internal/herdsman/lancheck.go` + `App.HerdsmanSecurityCheck()`：解析 herdsman config.yaml 的
  api.lan_accessible / api.port（逐行 YAML section 解析，零新依赖），暴露时返回中文处置指引。
- 只提示、不改 herdsman 配置（config 路径：HERDSMAN_CONFIG 环境变量优先）。

### H0-5 模型用途建议 + 思考模式守护
- 模型库目录每条模型新增「用途建议」（依据 docs/2026-08-12 的 120 组受控对照测评与 08-13 TTS/OCR 实测）：
  HauhauCS 日常/识图首选、LynnStyle 可审计推理、Hermes 勿开思考模式、voxcpm2 冷启动约 50s 等；
  前端模型库卡片展示（ModelCard desc）。
- 本地引擎（herdsman/ollama）思考模式 max_tokens <4096 自动抬到 4096（bridge 与聊天流式两路径），
  杜绝测评发现的「只有推理、无正文」（Hermes T2/T7 等）。

## 二、工程门禁（E1）

### E1-1 前端 CI 修复
- eslint 配置修复：react-hooks v5 新版 flat 配置（configs['recommended-latest']）、
  补装 eslint-plugin-react-hooks / eslint-plugin-react-refresh、新增 lint script、忽略生成目录。
- 28 个硬错误清零，包括：
  - Lightbox 12 处**条件调用 Hook**（原代码在 imageSrc 缺失时 hooks 数量变化会触发 React 运行时崩溃，
    修复顺带消除该隐患）；
  - CreatePage case 块词法声明、Markdown 控制字符正则改写、no-unused-expressions 等。
- 存量高频风格规则（no-explicit-any/no-empty/no-unused-vars/ban-ts-comment/react-refresh/no-namespace）
  降为 warn 随迭代清理，不阻塞门禁。
- ci.yml：移除 continue-on-error；npm ci→npm install（仓库不提交 lockfile）；新增 vitest 全量步骤。
- 顺带修复：ComfyUI 启动位置/Python 默认路径文案反斜杠丢失（用户可见，双反斜杠修正）。

### E1-2 发布冒烟脚本
- `scripts/smoke.ps1 [-ExePath build\bin\gaea.exe] [-Port 18999]`：启动产物 → 轮询 HTTP 桥接
  /api/health → 进程存活检查 → 自动回收，把「启动即白屏/崩溃」挡在发布前。

### E1-3 版本节奏
- 本轮起转周版本：v2.15.7 后直接 v2.16.0；一周内不再发小版本，只修缺陷。

## 三、测试与验证

- Go：`internal/herdsman` 全包单测（探测/健康/LAN/能力归类）；internal/app（含 4 个新 handler 与
  目录 Hint）全量 22s 通过；bridge/ai/voice/tts 相关包全绿；go vet 干净。
- 前端：tsc -b 通过；eslint 0 errors（725 warnings 为存量风格项）；模型库卡片 vitest 5/5。
- 说明：本机沙箱环境对 `go test ./...` 的并行子进程有干扰（临时目录 fork/exec 拒绝），
  已按包级验证全部改动面；全量套件由 CI（GitHub Actions）双保险。
