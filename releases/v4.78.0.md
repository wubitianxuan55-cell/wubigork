## 变更

### Go
- `tasks.Progress.OnForceKill(fn)`：进程类任务登记强杀钩子（典型用法=闭包
  持有 `*exec.Cmd` 调 `proc.KillTree` / `KillTracked`）；钩子应在进程创建后
  尽早登记（Kill 与登记并发存在快照窗口，与 Cancel×ctx 同型，handler 仍须
  响应 ctx 兜底）；尝试结束由调度器统一清理（worker 收尾 / unregisterCancel /
  clearStaleCancel 三处同拍），旧尝试钩子不串味到重跑。
- `tasks.Manager.Kill(id)`：queued 原子取消（message=「已强制终止」，与
  Cancel/claimQueued 共用 status 条件互斥）；running 在 m.mu 内快照 cancel+
  钩子并记 cancelReq（用户取消意图终态判定与 Cancel 完全同纪律），锁外**先
  执行强杀钩子再传播 ctx 取消**（handler 可能卡在不感知 ctx 的进程等待上，
  先杀进程让它尽快退出；顺序对调只影响退出快慢）；重复 Kill 幂等；对已
  结束/不存在任务报错；未登记钩子的纯函数任务诚实降级等价 Cancel。
- `App.GaeaTaskKill` 绑定（绑定面 569→570）+ OfficeB 门面（gen_bindings
  重新生成；GaeaTask* 前缀规则自动归 office，无需 explicitOverrides）。

### 前端
- TaskCenter TaskRow：running「强制终止」两击确认——首击进入确认态（红描边
  +「再击确认终止」+title/aria 同步），3s 无再击自动回退，状态离开 running
  （如经他处取消转 stopping）复位；再击调 `GaeaTaskKill`；queued/stopping
  保持单击（取消/停止中）。
- bridge（AppBindings + camel 映射）/ spaceBindings（TaskKill→work 分面，分
  面锁 268→269）/ mock（TaskKill：立即终态 +「已强制终止」message）补接线。
- i18n 三语 +3 键：`tasks.killRequested` / `tasks.killFail` /
  `tasks.forceStopConfirm`（zh 逐字：已请求强制终止 / 强制终止失败：{msg} /
  再击确认终止）。

## 测试

- `tasks_kill_test.go` 4 用例（`-count=2` 绿）：真实子进程强杀（Windows ping
  / Unix sleep 不感知 ctx，钩子 proc.KillTree 后进程真死 + 终态 cancelled）；
  queued 强杀（原子取消、永不运行、message 区分）；无钩子降级（等价 Cancel +
  重复/未知 Kill 报错）；终态后钩子不误发。

- TaskCenter.test +2（净 7→9）：两击确认全交互（首击不调 TaskKill/再击调用/
  queued 单击直通）；3s 假计时器回退 + 状态离开 running 复位。
