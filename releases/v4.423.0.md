## 论点：底稿编辑跨故事串写 + 流生命周期三处裸奔

原罪板块「一故事=一份底稿文件 + 一个在途流」的模型下，三类真实缺陷（全部读码确证）：

1. **底稿草稿跨故事串写（P0）**：`SinSidePanel` 的编辑草稿（含 `SinNotesSave` 的
   baseline 锚）是组件内部 state、不随故事切换复位，而保存闭包绑定**当前**故事 id——
   A 故事的未保存底稿在切到 B 故事后点保存，写进的是 B 故事的底稿文件；两个故事底稿
   均为空时 baseline 相同、**冲突检测不触发，静默覆盖**。
2. **三条入口静默销毁/误投输入**：收面板、切手风琴卡、切主区页签都卸载持有草稿的
   组件（Composer 草稿、底稿编辑、书源下载进度全丢）；切故事后 Composer 的排队消息
   与残留草稿会派发到**新**故事（跨故事误投）；输入框里粘贴的长文本块（≥2000 字折叠）
   只发出占位标签「[粘贴块 1 · N 行]」——正文内容在 `submitText` 里，原罪页此前丢弃。
3. **流生命周期裸奔（Go）**：`registerSinRun` 无条件覆盖登记——双客户端（httpbridge
   网页端/双开壳）同话题连发两轮即双写同一故事，且第一个流失联不可取消；
   `run.cancel` 在流 goroutine 里迟写、`SinCancel` 无锁读（数据竞争）；切故事只解绑
   前端订阅、后端整轮照跑（10 分钟超时才停，白烧 token）；Delete/Clear 不查在途流
   （清空后收尾落库把刚清掉的内容插回来 / 删除后 FK 报「保存失败」）；中途流错误把
   已逐帧下发到前端的正文增量整段丢弃（用户屏幕上的故事重开就消失）。

## 落地

### 线1 前端（正确性 + 常驻治理）
- **底稿串写根修**：`SinSidePanel` 草稿记录归属故事 id（`draft.storyId`），保存前校验
  归属、不匹配直接丢弃；切故事即清草稿；脏状态经 `onDirtyChange` 上报页面，
  切/删故事前弹「放弃修改并继续 / 先不切」确认——脏草稿不再静默丢失。
- **常驻挂载**：主区「故事」列与右栏创作面板改 `display:none` 切换（不再条件卸载）——
  切轨迹/上下文页签不再丢输入框草稿与插图生成进度（同一插图位重复出图的根因即
  StoryStream 卸载重挂后 `autoTriedRef` 归零）；收面板不再丢底稿草稿与书源下载进度。
- **跨故事误投**：`Composer key={story.activeId}`——每个故事独立输入框（草稿/排队
  随故事切换复位），排队消息不可能派发到另一个故事。
- **粘贴块正文不再丢**：`send(display, submit?)` 双参——回显与标题建议用 display
  （用户所见），实际发给模型的是 Composer 展开后的 submitText。
- **切故事取消后端流**：`streamTopicRef` 记录在途流归属故事（发流前即登记，runID
  迟到/挂住也能取消），切故事对旧故事调 `SinCancel`——后台不再白烧整轮。
- **初始化纠偏**：故事列表读取失败不再触发「自动建新故事」（区分「读失败」与「真空」，
  瞬时故障不产生垃圾故事）；失败时保住现有架子不清空。
- **插图取消制导**：串行队列加 `cancelIllustration(token)`——排队中取消只把自己摘出
  队列（promise 以取消哨兵拒绝，卡片回空闲）；只有 token 对应的任务真的在跑才调
  `cancelImageGeneration`。历史实现无条件取消后端当前任务，排队卡点取消会误杀正在
  生成的另一张。
- **流式渲染性能**：故事流文本段改用办公同款 `MemoMarkdown`（RAF 节流 + 稳定段切分），
  数千字正文不再每个 delta 全量重跑 react-markdown 管线；智能滚动的长度跟踪从
  「整列表每帧 reduce」收敛为最后一条消息。
- **懒加载**：角色库 200 条全量列表只在面板展开/选择器打开时首拉（进板块零额外请求）。
- **可见性**：提示条移出「故事」页签条件（轨迹/上下文页签发生的失败也可见）；
  手动停止的回复渲染「已手动停止 · 内容不完整」徽标（消费后端 `extra.cancelled`，
  重开后与完整回复可区分）；故事架条目补 Space 键激活。

### 线2 Go（流生命周期 + 收尾纪律）
- **流互斥**：`registerSinRun` 命中在途即拒绝「当前故事正在生成中，请先停止再发起」
  （对齐 novel create_chapter 同款口径）；`ctx/cancel` 在登记前创建、同一锁内写入——
  `SinCancel` 读到的句柄无中间态，数据竞争根除（原「极窄竞态」注释只兜一半）。
- **Delete/Clear 在途拒绝**：「该故事正在生成中，请先停止再删除/清空」——fail-closed，
  防清空后收尾落库「复活」与删除后 FK 报错。
- **错误路径保底**：`sinStreamRound` 错误返回带上已累积的部分内容（原实现在错误分支
  提前 return，builder 尚未赋值、部分内容为空）；`runSinStream` 错误路径把已流出正文
  并入 reply 与取消同口径落库 + notice「生成中断，已保留已生成的部分」——同一板块
  「取消保留残稿、错误全丢」的双口径消除。
- **零正文取消不落空行**：只落用户消息（原实现落一条空 assistant 消息，污染历史/
  导出/轨迹）；历史装配与 Markdown 导出同步跳过空正文行（含存量数据）。
- **前情窗口化读取**：`runSinStream` 改用 `ListMessagesPage(topicID, sinHistoryTurns)`
  只取提示词窗口（千回合老故事不再整表加载）；回写定位读同样走分页。
- **上下文柱窗口折算**：`foldSinContext` 按真实请求语义折算（最近 12 条、单条 1500
  rune 截断、工具结果只计当轮）——长故事的上下文柱不再线性高估（原注释宣称
  「全量前情」与实际窗口不符）。
- **底稿块原始下标**：`sinDraftBlock` 便签序号改为 `doc.Notes` 原始下标并标注
  「序号即工具 index」——原实现按展示序重编号，空条目/预算截除会让模型 set/delete
  改错条目；`SinNotesSave` 丢弃空白便签（工具 write 本就拒绝空串）。
- **损坏留档**：便签/cast.json 损坏时先改名 `.corrupt-<ts>` 留底再按空文档继续
  （原实现直接按空读，下一次成功写把旧数据永久清零且无迹可寻）。
- **打磨**：未知工具不再扣工具预算（编造工具名不白烧 8 次配额）；附件 64KB 截断按
  rune 边界回退（不劈半个多字节字符，识图描述同步）；成书 TXT 改原子写（崩溃不留
  半截文件进成书清单）；成书节选只读头部 32KB（原整本读入内存只取 5000 rune）；
  回写定位失败补 `slog.Warn`（原静默吞掉，工具插图不回写且无迹可循）。

## 观察池

- Composer 排队项跨故事撤回提示（key 复位即丢弃，无「排队 N 条已随切换清空」提示）。
- SinMessages 无分页绑定（千回合老故事前端全量拉取；绑定面变更需随下一批绑定窗口）。
- `sinExportUniquePath` stat-then-write 并发窗口（单用户桌面端可接受）。
- `SinIllustrate` 对 `a.cfg` 的 nil 防御口径不一致（生产 cfg 恒非 nil，纯一致性）。
- 书源下载进度在「手风琴卡切换」时仍会失附（面板级已常驻，卡级未改）。
- ChatTabs 主页签无 role="tab" 语义（办公共用组件，改动波及面另批）。
- Go 余项：illustration merge 无 per-message 锁（多客户端并发丢更新，串行队列下不触发）。
