# v4.509.0 · 模型中心识图卡跟随态对齐——VisionRoute 只读生效路由（2026-10-20）

> 用户指令「优化迭代平台，本次优化前端」。识图跟随聊天模型（v4.509 前
> 93b23f2a）后端落地时留池的展示对齐项本轮清账：模型中心识图卡「当前生效」
> 行此前仍读 `routeModel`（func_vision 绑定口径），跟随时展示失真。

## 背景

2026-10-19 拍板「聊天用的本地模型本身多模态时，识图不再另找第二个识图模型」，
后端生效链重排为：**跟随聊天模型（天璇/Strata 跟当前服务档；停机 herdsman
主力兜底；herdsman 同引擎同模型）→ func_vision 独立绑定（聊天在云端时接管）
→ gaea.toml 静态注入 → 内置默认**。但识图卡的「当前生效」行读的是
`GetModelRoute("vision")`——它只反映绑定层：跟随时显示的仍是独立绑定（实际
不生效），绑定可用性也与真实链脱节。留池原文：「跟随态展示对齐待前端轮」。

## 落地

- **Go：生效链判定收敛单源 `visionRouteRO`**（跟随→独立绑定→静态），新增
  `App.VisionRoute` 绑定（挂 ModelB）返回 `{engine, model, source}`；
  source 细分 `chat-follow` / `chat-follow-fallback`（聊天引擎停机，herdsman
  主力兜底）/ `feature` / `static`（engine 不可知报空，model 报静态生效值）。
- **只读不记账（本刀关键红线）**：`visionLocalRuntime` 的 `TouchEngine`
  （解析即记账，防识图进行中被空闲收割器停机）保留在真实识图调用路径；
  展示绑定走只读解析——否则前端刷新轮询会把 `model_idle_exit_minutes`
  十分钟空闲自动停机永远喂饱。测试钉死：`VisionRoute()` 连调三次后
  `EngineLastActivity` 恒零值，`visionBoundRuntime()`（真实路径）非零。
- **vision 包导出 `StaticRuntime()`**：静态层（gaea.toml）补全默认后的只读
  快照，供 static 分支报模型名。
- **前端识图卡**（BindSection/useBindState/context）：
  - 「当前生效」行改读 `VisionRoute` 真实链——跟随态显示 `当前生效：天璇 /
    当前服务档（跟随聊天模型）`，并附「独立绑定待命（聊天回云端时接管）」；
  - chip 按真实生效态：跟随时「跟随聊天模型 · 绑定待命」（原「已绑定生效」
    在跟随时是误导——绑定此刻并不生效）；静态兜底/绑定不可用各有专属态；
  - 绑定行改名「独立绑定：」（原「当前：」在跟随时误导）；
  - 卡描述对齐三链口径（原「未绑定时用本地默认视觉模型」已过时）；
  - 通用 `modelRoutes['vision']` 行对识图不再渲染（routeModel 口径失真）。
