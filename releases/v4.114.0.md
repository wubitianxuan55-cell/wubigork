## 本刀内容

### schedule-edit 内联技能（internal/gaea/skill/builtins.go）

编制与调整纪律总纲（RunInline，office-edit 同范式；schedule_skill_test.go 锚点锁 13 条）：

- **铁律**：先读后写（schedule_get 现状）；「工具成功≠正确」（apply 回执核对总工期）；引擎裁决（fail-closed 错误原文修复重试，不手算冒充）；汇报口径（改了什么→总工期 X→Y→关键线路变化→风险）。
- **编制流程**（JGJ/T 121-2015 先分解后编网）：WBS 两级（分组 level=0 不搭接/子任务 level=1）→逻辑关系（FS 缺省/SS 流水/里程碑收口）→工期（工作日整数+依据声明+倒排校核）→日历（节假日入 calendar）→project 通道写入→analyze 质检清零→主动问调整。
- **调整流程**（ops 通道）：patch_task 压缩工期（**压缩非关键任务不缩总工期要点破**）、set_links 改逻辑、remove 级联、多调整一次 ops 数组原子下发；progress 反馈走前锋线。

### agent 写计划→板块即时回读

- store 暴露 `notifyScheduleFileChanged()`（即时刻 poll，绕过 15s 轻扫；防抖未保存/saving/error 守卫不动用户缓冲）。
- App.tsx 工具事件喂入：schedule_apply 状态跃迁至 done → 触发回读——**对话里调计划，板块秒级可见**。

### 工具卡可读化（tools.ts）

- subjectOf：schedule_* 行首=计划路径，缺省回退「当前计划」（Go 侧默认路径解析，args 常缺）。
- summarize：apply=「总工期 X 天 · 关键 Y 项 · N 处修改」；get=「总工期 X 天 · N 项工作」；analyze=「总工期 X 天 · 关键链 Y 项 · 质检 N 条」；0 值省略；extractOutputFromEnvelope 信封剥离兜底。
