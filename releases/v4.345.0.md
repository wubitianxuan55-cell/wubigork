# v4.345.0 · filewatch 关闭竞态根修：fs 通道关闭路径漏 close(out) 致消费方挂起

> 2026-09-19 发布。真机走查班后续——昨天全量 ci 撞的 filewatch 时间型 flaky
> 深挖后是**真并发缺陷**，测试加固压测定位后根修。单文件 Go 修复+测试加固。

## 论点（flaky 是缺陷的信使）

`TestCloseStopsEvents` 在全量 ci 偶发「关闭后事件通道应关闭」（2s 超时）。
先按惯例加固测试预算（2s→终态轮询 10s）压测：20 轮里仍 1 轮打满 10s 都不
终态——**不是调度慢，是 close 根本没发生**。

## 根因

`loop()` 的 select 三个退出路径：

| 路径 | 触发 | 此前行为 |
|---|---|---|
| `<-w.done` | Close() 主动关闭 | flush + close(out) ✓ |
| `fs.Errors` 通道关闭 | `fs.Close()` 连带关闭 fsnotify 内部通道 | 裸 `return` ✗ |
| `fs.Events` 通道关闭 | 同上 | 裸 `return` ✗ |

`Close()` 里 `close(w.done)` 与 `fs.Close()`（连带关闭 fsnotify 的 Events/
Errors 通道）先后发生；loop 唤醒时**两个分支都可能就绪，select 随机取胜**
——走了 fs 通道关闭分支就裸 return，`w.out` 永不关闭。消费方
`for range w.Events()`（工作区语义索引触发链）永久挂起 = 关闭竞态下的
协程泄漏。压测频率 ~1/20，全量 ci 的高负载放大了竞速窗口。

## 修复

- 新增 `outOnce sync.Once` + `closeOut()`：三条退出路径统一走幂等关闭
  （done 分支保持 flush 后关；fs 通道关闭分支补关后 return）。
- `TestCloseStopsEvents` 断言从 2s 硬超时改终态轮询（10s 预算，v4.335
  「异步链断言等终态不赌时序」纪律）——既是加固也是本缺陷的回归锁
  （压测口径：修复前 1/20 必挂，修复后 20/20 绿）。

## 坑

- **flaky 分两级**：第一级是断言预算太短（改预算就能绿，但掩盖真缺陷）；
  第二级是预算拉满仍挂（=真缺陷）。治理 flaky 必须压测到「拉满预算仍
  挂」才停，否则只是把缺陷埋深。
- select 多通道退出的关闭路径要逐条清点——「主动关闭」路径正确不代表
  「被动关闭」路径也正确（fsnotify 连带关闭是隐形触发源）。
