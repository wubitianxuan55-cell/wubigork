## 落地

### 1. 写盘断电级（fsync 三处，建议①落地）

`internal/gaea/config` 三处写盘 `AtomicWrite` → `AtomicWriteSync`
（rename 前对临时件 fsync，关闭「rename 成功但数据仍在页缓存」的断电空窗
——事故当晚 config.toml 全零的正是这个窗口）：

| 站点 | 文件 |
|---|---|
| `Save`（用户 config.toml） | `save.go` |
| `SaveTo`（项目 gaea.toml，RenderTOMLPreserving 链） | `edit.go` |
| `SaveRecentWorkspaces`（recent-workspaces.json） | `recent.go` |

配置族写盘低频（设置变更/工作区切换），单次 fsync 实测 ~2.3ms 无感。

### 2. 加载损坏自愈（不硬弹错，建议②落地）

- **`config.Load()` 用户级**：新增 `mergeUserFile`——TOML 解析失败时把损坏
  内容逐字节隔离到 `<path>.corrupt-<ts>` 后备副本 + `slog.Warn` 记账 +
  按默认继续（后续 gaea.toml 项目层照常合并）。无头 agent / boot.Build
  不再被全零 config.toml 锁死。
- **`gaeaLoadConfig()`（办公引擎）**：同款降级。此前解析失败直接返回错误，
  `GaeaInit` 永远失败=用户只能手工修文件；现在隔离+默认继续，bridge
  provider 注入链完整走完，引擎起得来。
- **边界口径**：文件缺失=跳过（原样）；读取 IO 错误=仍报错（环境问题不是
  数据损坏）；项目级 gaea.toml 损坏=仍报错（开发期可发现，降级只留给
  「断电后无法自救」的用户级）。

### 3. 单源收敛：`fileutil.BackupCorrupt`

损坏隔离助手单一源（`internal/gaea/fileutil/corrupt.go`），壳层
`config_load.go` 的 T6-9.4 内联块改调本源（行为等价，消三处重复实现）。
时间戳 CAS 严格递增——Windows 时钟粒度粗，同进程连续两次隔离可能拿到
相同纳秒互覆备份（corrupt_test 实测抓到，壳层原实现同样存在此理论缺陷，
随单源收敛一并根修）。
