## 线 A：GenUI 审计 §8-5 resume 槽位口径统一（最后一项遗留，跨层收口）

- **事实**（审计 §4 已核）：genui 交互状态 stateKey 的 slot 段=assistant 条目 id，三条生成路径原本不同——实时 `a${前端计数}`、resume `h${index}`、resync `a<日志seq>` → 跨重启状态永远 miss。
- **方案**（工作区已有半成品 + 主代理完成收尾）：
  1. 实时取号 assistantSlot：事件 payload 可选字段 logSeq（磁盘日志行 seq）可用且未占用 → `a<日志seq>`（与折叠快照同口径）；缺省（旧后端）回退本地计数器 counterSlot（跳过已占用后缀，防与日志序 id 相撞）——**旧后端行为逐字节兼容**；
  2. 装载统一 `loadItemsFoldedFirst`：GaeaResyncEvents(0) 恒返回会话全量折叠快照（id=日志序）优先，resume/回退/启动三路同 id；快照不可用（异常/形状坏 null）回退 History+rebuildHistoryItems（h<index> legacy 保底）；
  3. resumeSnapshotItems：折叠快照恢复语义收尾（running 工具卡收尾为 stopped=重启后无在跑工具；空数组=空会话短路不回退 History；形状坏 null 触发保底）；
  4. 兼容口径：localStorage 旧 key（h<index>/旧计数器）**不迁移**、任其 LRU 200 逐出（诚实降级，不串状态）。
- 测试：resumeSnapshotItems 3 例 + store 三文件 60/60 绿。
