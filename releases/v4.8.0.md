## 读屏纵深（v4.7「读一下屏幕」的欠账收口）

- **多显示器**：`screen.Monitors()`（EnumDisplayMonitors/GetMonitorInfoW 枚举）
  + `CaptureArea(x,y,w,h)` 重构（`Capture()` 变薄封装，零行为变化）；intent
  序数解析「第N(块)屏/主屏/副屏」→ `Target=screen:N/screen:primary`（仅在
  reReadScreen 已命中分支内解释，主副屏必须带动词——「主屏幕坏了」不触发）；
  越界诚实报错「这台电脑只有 N 块屏幕」。
- **OCR 摘要朗读**：OCR 文本 >300 字且 `read_screen_summary` 开（默认开）→
  本地模型压 ≤200 字口语化摘要再朗读；隐私纪律=只走本地 Herdsman（路由回退
  云端即放弃摘要退回截断，屏幕内容不出本机）；45s 超时，任何失败退回 300 字
  截断（v4.7 既有口径零回归）。
- **截图留档**：`read_screen_keep_last`（默认关——exports 会进工位检索面，
  须明示权衡）→「屏幕-最近.png」滚动覆盖 `.gaea/exports`，回复尾注路径。

## intent LLM 兜底分类器（内核留位兑现，默认关）

- 规则引擎未命中的冷路径兜底：`intent.ParseFallback` 受控校验——白名单
  navigate/status/read_screen（**生图/提醒不放行**：误触发废图+GPU 成本、需
  时间解析联动，规则引擎已有高精度位）+ **0.75 置信门** + 坏 JSON/围栏噪音
  容错，任何不合规=未命中走聊天（宁漏勿误）。
- `classifyIntentWithLLM`：routine 目标解析（常规模型绑定→默认本地 herdsman）
  + `intents_llm_timeout_ms` 硬超时（默认 2000ms，超时即弃不重试）+ navigate
  target manifest 校验（与规则引擎同口径）。
- **dryRun 恒不调用**：命令面板逐键搜索绝不打 LLM，预览-确认制口径一致；
  命中复用既有执行层，不新开执行路径。`intents_llm_fallback` 默认关。

## iLink/微信通道离线收敛（真机前最大化）

- **入站防线**：per-peer 滑动窗口限频 20 条/分（超限固定文案、不触发 LLM、
  不更新 lastPeer——防刷图=防刷模型）+ 文本 4KB rune 安全截断 + item_list
  多媒体上限 5。
- **图片→vision 管线**：`MediaRecognizer` 注入字段（nil=行为与现状逐字节一致）
  + `OCRMediaRecognizer` 适配器（url→下载→GaeaOCRText→cleanup 单注入点）；
  识别内容截 300 rune，失败保留原「内容暂无法读取」占位。
- **下载三重防线**：dial-time SSRF 拒绝私网/回环/CGNAT/IPv6 回环（较 webfetch
  更严）+ 20MiB 双保险 + png/jpeg/webp/gif 魔数终审（白名单外不落盘）。
- **协议防御**：imageItem/fileItem 自定义 UnmarshalJSON——url=数组/对象、
  file_id=数字、size=字符串、全缺字段、100KB name：多态降级不炸整批（宁漏
  勿误）；未知 type 静默跳过不变。
- **SendFileCard seam**：文本降级实现（真上传端点探明后仅换实现不动调用方）。
- `docs/ilink-non-text-protocol.md`：协议探明度表 + 真机抓包清单（原始 JSON /
  baseurl 上传域 / sendmessage 端点）。
