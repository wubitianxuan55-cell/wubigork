# v4.44.0「绘梦专项三刀：百炼模型残留修复 · 引擎枚举单源化 · 模板画幅落地」

> 发布日期：2026-09-02 ｜ tag：`v4.44.0` ｜ 基线：v4.43.0 ｜ 绑定面 **557 零变更**

## 定位

绘梦板块（ImageGenPage 及 imagegen 组件/hooks）专项摸底后收三条互不相交线，
全为真实缺陷与体验收口：百炼（dashscope）接入后残留模型导致生成 400、
引擎枚举双份漂移（meta.ts 与 ControlPanel 各一份、缺 GLM/dashscope 显示）、
模板「推荐画幅」字段整条链路无消费。**绑定面零变更、零新增绑定、零 UI 结构
重构**，与 v4.43.0 小说刀同纪律。

## 三刀

- **① 百炼模型残留修复（真 bug）**：
  - Go `GetImageBackendInfo`：backend=dashscope 时镜像 GLM 归位逻辑——空模型或
    上一后端残留（grok-imagine-* / krea2 等）一律归位 `qwen-image-edit-plus`
    （`ai.DashScopeDefaultImageModel`），手填官方编辑系模型原样保留；
    `GetImageBackendConfig` 同口径兜底。
  - Go `SetImageBackend` dashscope 分支：空 imageModel 不再保留旧 cfg.ImageModel，
    同样归位百炼默认——前端引擎列表无 dashscope（它不是引擎，是独立 Key 后端），
    拿不到官方模型名，此前残留 krea2/grok 会被带进百炼请求 → 官方报
    model 不存在。
  - 前端 `useImageGenConfig`：dashscope 后端 modelOptions 固定三档官方编辑模型
    （qwen-image-edit / -plus / -max，来自 meta 新常量 DASHSCOPE_EDIT_MODELS）；
    切后端到 dashscope 时 defaultModel 归位 `DASHSCOPE_DEFAULT_MODEL`。
  - `useImageGenQueue.handleGenerate` 提交前用 `backendSupportsMode` 拦截引擎
    固有模式残留（百炼仅改图 / GLM 仅文生图），不再点击后才被后端拒收。

- **② 引擎枚举单源化 + 补 GLM（显示/门禁一致性）**：
  - `meta.ts` 收敛为唯一引擎枚举 `BACKEND_OPTIONS`（value/label +
    img2imgOnly/txt2imgOnly 能力位）+ `backendLabel` / `isLocalBackend` /
    `backendSupportsMode` 辅助，ControlPanel / ImageGenPage 顶条状态 pill /
    useImageGenConfig 启动消息 / GenerationBar 生成门禁全部改走该单源。
  - 修复顶条状态文案：此前 xAI 显示「☁️ xAI 云端 云端」式拼接重复、dashscope/
    glm 无 label 回退裸 id；现 label 不含「云端/本地」字尾由调用方拼接。
  - **补 GLM 引擎**：ControlPanel 引擎下拉新增 GLM（txt2imgOnly，非文生图模式
    禁用 + Tooltip「GLM 仅支持文生图」），残留态（glm+img2img/t2v）显示专属
    警告；GenerationBar 按钮禁用与提示同步感知；ImageGenPage needsComfy 不
    重复拦 glm（由 queue/面板专属门禁兜底）。

- **③ 模板推荐画幅落地（功能收口）**：
  - 新纯函数 `templateSizeToPreset(ratio, mode)`：模板 size 比例标签
    （1:1/16:9/9:16/4:3/3:4/2:3/21:9）→ 绘梦实际画幅；2:3 立绘无预置档 →
    自定义 768×1152（64 倍数对齐 ComfyUI 约束）；仅 txt2img 生效（图生图随
    参考图、视频独立画幅体系）。
  - ImageGenPage `applyTemplate` 应用模板时同步画幅；TemplatePickerModal
    handleSelect 不再丢弃 size 字段（此前 onSelect 只传 label/prompt/negative）。
