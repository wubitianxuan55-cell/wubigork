# v4.421.0 · 小说板块优化批：未保存保护 + 常驻页副作用治理 + 取消防覆盖

> 用户指令「优化小说板块」（拍板 A+B 合并批：正确性修复 + 体验收口）。定刀依据=
> 三线并行只读审计（小说前端 15 项 / Go 后端 14 项 / 计划台账清账与 STALE 校正）+
> 主代理读码复核。前端 15 文件（含 3 新增）+ Go 4 文件（含 2 新增测试），

## 论点：五子页常驻挂载（隐藏 ≠ 卸载）

小说板块五个子页在 `NovelPage` 全部同挂，只用 CSS `display:none` 隐藏。由此衍生三类
真实缺陷（均由读码确证，非推测）：

1. **窗口级副作用不随页隐藏**：`ChapterPage` 与 `NovelSettingPage` 各挂一份无条件
   `Ctrl+S`（全仓仅此两处 `key === 's'`）——一次按键同时保存「设定」与阅读页那一章，
   而创作页正在手写的正文反而不保存；`F11` 在任意子页翻转不可见阅读页的专注模式并吞掉
   浏览器全屏键；阅读模式残留时 `←/→` 在书架/设定页翻章。
2. **面板上下文不随书刷新**：`ForeshadowPanel`/`ConsistencyPanel` 的 `load` 只依赖一个
   恒为 `undefined` 的 `disabled` → 切书后仍显示**上一本**的伏笔表与一致性报告；
   面板里「请先在书架打开一部小说」的引导态成了死代码，无项目时反而报红。
3. **未保存缓冲无脏保护**：创作页正文是「受控缓冲 + 显式保存钮」（无自动保存），但
   切章、切项目、开始生成、删除本章都直接 `setContent(...)` 覆盖——阅读页早有
   `needsCloseConfirm` 先例，创作页是同类缺陷的漏网点，也是本刀唯一会丢作者正文的一类。

## 落地

### 线1 创作页（未保存保护 + 体验收口）
- **三选保护**：新增共享原语 `components/novel/unsavedGuard.tsx`
  （`confirmDiscard` 两选 / `chooseUnsavedAction` 三选「先保存 / 放弃修改 / 取消」/
  `chooseAction` 并列多分支）。切章、开始生成、删除当前章、打开整章重写前一律先问，
  取消即取消；`loadedSnapshot` 与 `content` 不一致才算脏，生成完成/保存成功/取消且后端
  已落盘时刷新快照。
- **载入失败可见化**：章节载入失败此前静默清空编辑区（作者会以为该章是空的，接着保存
  就覆盖真实正文）——现如实报错并提示「编辑区已留空，请勿直接保存」（阅读页 v4.350
  已修同类缺陷，创作页此前漏修）。
- **并列分支不再绑在 Esc 上**：「覆盖下一章 / 作为分支追加」此前是
  `Modal.confirm(onOk=覆盖, onCancel=追加)`——✕/Esc（用户想退出）会触发一次 AI 生成；
  改为显式三选项，取消就是取消。
- **AI 反推大纲**：12 分钟轮询加卸载守卫（不再对已卸载组件 setState / 空跑请求）、
  按钮显示已等待秒数、回落同步路径如实提示「该路径不可取消」。
- **归因纠正**：设定读取失败不再被误报成「设定为空，请先在设定页填写」；
  文风指纹打开失败写回面板自己的 `fpMsg`（此前写进工具轨消息，面板里永远看不到）。
- **去味后刷新编辑区**：一键去味/高级去味成功后重载本章（旧实现只更新提示，作者看到的
  仍是旧文，以为没生效）；若编辑区有未保存手写内容则不刷新并如实说明。
- **创作参数持久化**：目标字数/温度/写作技能入 localStorage（此前每次进页回默认值）。
- **工具轨分组**：12 个按钮按语义分三组（质检 / 文本 / 结构）——零功能删除、零点击成本。

### 线2 常驻页快捷键门控
- `NovelPage` 向五个 pane 下发 `active`（`active?: boolean` 默认 `true`，既有测试直接
  渲染子页零回归）；`ChapterPage`/`HomePage`/`NovelSettingPage` 的 `window` keydown
  一律按 `active` 门控：非当前页既不响应也不 `preventDefault`。Ctrl+S 单一归属=
  阅读 tab 保存章节、设定 tab 保存设定、其余子页不响应。
- 目录点章改为「先切 tab、commit 后由 effect 派发 `novel:open-chapter`」——否则门控会
  把同 tick 的合法派发丢掉、点目录树失效（带时序守卫用例）。

### 线3 设定页与两常驻面板
- 两面板 `load` 依赖 `projectPath` 并由页面传 `disabled`：切书即重拉，无项目走引导态
  （不再报红）；一致性面板换书时清空上一本的 AI 深检结果。
- 导入 md/txt/json 覆盖未保存设定前先确认（此前直接覆盖）。
- 下行「伏笔 + 一致性」可折叠（localStorage 持久化，`aria-expanded` 齐备）。

### 线4 组件修复批
- 在线导入：后端在返回 jobId **之前**就已发进度/终态事件，前端却在 await 之后才订阅
  → 快速失败会让弹窗永久停在「后台下载中」。补失落兜底与诚实提示，关闭弹窗即复位。
- 章际对比加 seq 守卫（快速切换章号时迟到的响应不得覆盖新章的分数）。
- 三处裸 `EventsOff(channel)` 改走 `subscribeWailsEvent`（仓规：`EventsOff` 会清掉同通道
  别人的监听，v4.61 事故同型）。
- 提示词工坊切模板在脏时确认；新建小说空标题禁用 OK + 在途防双击；伏笔全表写回串行化
  （快速连点不再互相覆盖）。

### Go 侧同刀（后端审计并入）
- **P0 取消生成覆盖已完成章节**：取消落盘的残稿此前无条件覆盖 `chapters/NNN.md`——对
  已写完的章再生成并中途取消即整章被半截替换、无备份。改为「生成开局快照
  `existedBefore` + 取消时复查 `chapterBodyExists`」：已存在则残稿另存
  `NNN[分支].partial-<ts>.md`（`fileutil.AtomicWrite` 原子写，**绝不回落覆盖正稿**），
  事件增 `partialSaved/partialPath/notice` 可选字段，前端如实提示落点且不把残稿标成已保存。
- **P1 取消防互斥竞态**：取消路径此前提前摘除登记表而生成协程还活着，取消后立刻重开同章
  可并发出两个写者。改为条目置 nil 占位（register 见「正在取消中」如实拒绝），清理由
  `unregisterChapterGen` 独占。
- **P1 写回路径吞错 + blob/场景分叉**：收敛为 `writeBackRewritten` helper——写失败返回
  error（此前 `_ = sm.Write(sc)` 吞错仍报 `done:true`，用户看到「已改写 N 句」而磁盘未变）；
  v4 场景写回后 `syncBlobFromScenes`（此前阅读页/检索/导出读到的仍是旧文）。
