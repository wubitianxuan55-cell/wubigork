## 交付明细

### ① 引擎类型与生命周期（modelengine）

- 新类型 `EngineCustom = "custom"`（OpenAI 兼容；`IsLocal()`=false）。
- `Manager` 新增：`AddCustomEngine(name, baseURL, apiKey) (string, error)`（engineID=`custom-`+name slug，冲突追加 `-2/-3…`）、`UpdateCustomEngine`（apiKey 空串=保留原 Key）、`RemoveCustomEngine`（仅认 custom- 前缀且 Type=custom）、`SetCustomEngineKeys`/`CustomEngineKey(s)`；`fetchModels` 认证链与 401 提示加 custom 分支（空 Key 不发 Authorization 头→无鉴权本地 OpenAI 兼容服务可用）。
- 防线延伸（v4.9.1「Key 粘错框」）：baseURL 校验必须 `url.Parse` 通过且 scheme=http/https 且 host 非空——把 Key 当地址粘入会被拒绝（8 种非法输入测试覆盖）。
- `LoadState` 恢复 custom- 前缀条目（须 `type=="custom"` 且地址合法，防手改伪造）；`ClassifyModelKind` 关键词驱动天然覆盖 custom（默认 llm，测试锚定行为）。
- **Key 存储**：config 新键 `custom_engine_keys`（JSON map，engineID→`secure.EncryptString` 密文），configFile 字段 + saveSetters 登记 + 显式往返测试（该键不以 `_api_key` 结尾，现有反射守卫覆盖不到）；Key 不落 engines.json、不下发前端（GetEngines/GetEngine/saveState 三处既有清空语义不动，测试锁定）。

### ② 聊天路径（本刀价值核心）

- `internal/ai/client.go` 的 `resolveChatEndpoint`（流式/非流式两条路）经 `engineMgr.BuildChatURL` 新增 custom 分支：BaseURL + `/chat/completions`，Key 从 customKeys 取——自定义引擎真正可聊天/可设为活跃引擎/可绑定功能（功能绑定复用既有 SetFeatureModel 全链路）。

### ③ 绑定链与启动注入（app）

- 三层委托（core → App → CoreB）照抄 SaveEngine；`gen_bindings` 重跑与手写逐字节一致（TestBindingsCompleteness 锁定 555）。
- Startup 在 LoadState 前注入 `SetCustomEngineKeys(decryptCustomEngineKeys(cfg.CustomEngineKeys))`。

### ④ 前端（模型中心「引擎管理」分区）

- 「添加自定义引擎」行内表单（名称/地址/Key；前端校验与后端同口径双保险）；custom 卡：地址框可编辑（复用 handleSaveURL）、「编辑」（Key 留空=不改）、「删除」Popconfirm（提示同时移除其功能绑定能力）、「自定义」徽标。
- 地址框可见性 `is_local || isCustomEngine`——**内置云端引擎防线一字未动**（新增回归测试锁 ⑤）。
- utils：`isCustomEngine`/`isValidBaseURL`/`engineIcon` + custom 条目；`engineLabel/engineColor` 加可选 type 兜底（既有调用点零破坏）。
