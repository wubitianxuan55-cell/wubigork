**改前短板（源码级）**：

- `internal/app/novel_import_handler.go` 只有强标题正则；识别不到就退化成**单章「全文」**。

  几乎不报错，`utf8.Valid(decoded)` 这道二次校验会**静默放过误判**（MuMu 同病，规格 §3.1 点名）。

## 落地

### ① 新包 `internal/bookimport`（纯规则、零 IO、可单测）

| 函数 | 规格对应 | 要点 |
|---|---|---|
| `Decode` | §8.1-1 | 5 级链 utf-8 → utf-8-sig → gb18030 → gbk → big5 → utf-8(ignore)；**候选结果含替换符（U+FFFD）即判误判并继续下探**；额外识别 UTF-16 LE/BE BOM（记事本另存常见） |
| `Clean` | §8.1-2 | 六步顺序敏感：CR 归一 → 去 BOM → 全角空格→两个半角空格 → 行尾空白 → `\n{4,}`→`\n\n\n` → TrimSpace |
| `Split` | §8.1-3~6 | 强标题（gaea 既有全集 + markdown `#`）→ 弱标题（≤25 字/无标点/前后空行）→ 兜底窗口 → 单章「全文」 |
| `applyExtractMode` | §8.1-7 | tail 末尾 N 章；非 5 倍数向上取整；>50 或非法值降级 full（不静默乱裁） |
| `buildWarnings` | §8.1-8 | 过短 <300 字 / 过长 >12000 字 / 标题重复 / 按范围裁剪告知；消息可直接展示 |

**两处判定收紧（跑测试时实测出来的坑）**：

1. **强标题存在时不再叠加弱标题**——否则 `# 卷一\n\n内容甲\n\n## 卷二\n\n内容乙` 里的「内容甲」
   （短行+前后空行）会被当标题切碎；对齐 MuMu 的 strong-first 语义。
2. **弱标题需 ≥2 候选**才进弱模式——单候选会让整篇短文本被当成「一章标题」
   （`没有章节标记的一段文字` 这类既有无标题文本会退化），gaea 口径退回单章「全文」。

**与 MuMu 的两处有意偏离（已注释在代码处）**：

- 首标题前正文 **<200 字并入首章**而非丢弃（书名/作者/引子常在两行内，丢弃即丢信息——宁留勿删）；
  ≥200 字才成独立「前言」章（与规格一致）。
- 窗口阈值/长度判定一律 `utf8.RuneCountInString`；MuMu 用 `len()`（字节）会让中文阈值失真（规格 §3 第 14 条）。
