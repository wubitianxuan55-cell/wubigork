# v4.261.1 — 修复：原罪插图报「marshal image request: 图生图需要提供参考图」（2026-09-12）

## 用户看到的问题

原罪板块点「生成插图」→「图片生成失败：marshal image request: 图生图需要提供参考图」。
（该用户图片后端 = Herdsman，`http://localhost:8080/v1`。）

## 根因

v4.259.0 的角色参考槽门控 `sinRefPlan` 只回答「这个后端 × 模型能不能用参考槽」，一旦可用
就把 `mode=img2img` 定死；但**参考图能不能取到是另一件事**：

1. 故事没有选角色（`sinPickRefCharacters` 返回空）；
2. 角色只有远端剧照 URL（`sinRefDataURL` 明确跳过——不扩展网络面）；
3. 参考图/剧照的本地文件缺失。

以上任一时 `refImages` 为空却仍以 `mode=img2img` 发请求 → Herdsman 的 `/v1/images/img2img`
分支在 `buildImg2ImgBody`（`internal/ai/image_openai.go`）前置校验里如实拒绝
「图生图需要提供参考图」，被包成 `marshal image request: …` 上抛；而既有的自动回退只在
`refImages>0` 时触发，所以「这次用不上参考槽」被放大成**整单失败**。

## 真机取证

- `%APPDATA%\gaea\logs\gaea-20260912.log` 20:26:37 / 20:26:59 两条
  `图片生成失败 attempt=1 error="marshal image request: 图生图需要提供参考图"`，
  紧邻启动行 `图片后端: Herdsman url=http://localhost:8080/v1`；
- `%APPDATA%\gaea\sin\cast.json` **不存在** → 该故事从未选过角色 = 分支①。

## 修复

1. **解析与门控解耦**：新纯函数 `sinResolveRefImages`（`internal/app/sin_refs.go`）把候选角色
   解析成「可用参考图（data URL）+ 角色名 + 台账归属 id」；参考图优先、其次剧照，
   远端 URL 与缺失文件跳过。
2. **门控收口**（`internal/app/sin_handler.go`）：解析结果为空即 `refOK=false` 并
   **清空 `mode`/`refMethod`** 走纯文本——「参考槽用不上」不再等于「整单失败」：

   | 情形 | 行为 | 用户可见 |
   |---|---|---|
   | 没选角色 / 多角色未点名 | 纯文本 | 无徽标（不弹噪声） |
   | 选了角色但没有可用参考图 | 纯文本 | 「参考图不可用 · 已按纯文本生成」 |
   | 有可用参考图但生成失败 | 纯文本重试一次 | 同上 + `ref_fallback` |

3. **顺带修台账归属**：改前 `len(refChars)==1` 时登记 `picked[0].ID`，多角色里只有第二人
   有可用参考图会把登记记错人；现按「真正带参考图」的角色回溯。

未改：后端错误文案与 Herdsman 契约（缺参考图仍如实拒绝）、ipadapter/pulid（仍未实现）。
