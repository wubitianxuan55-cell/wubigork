> 2026-09-19 发布。观察池最后一项（v4.325 有意裁剪的「编辑器 overlay 持久
> 高亮」）的轻量落地：定位单条标注时在编辑器正文内显形高亮。纯前端
> （EditorPanel + 一条 CSS），零新绑定 705、零新依赖。

## 论点

v4.339 的「编辑器定位」把光标送到了标注位置，但 textarea 里看不见"高亮"——
选区一失焦就无感。完整 overlay（全部标注常驻高亮）v4.325 有意裁剪（镜像
背景层对字体/滚动/换行同步脆弱）。本刀取中间态：**定位伴随高亮**——只渲染
被定位的那一条 mark，编辑即失效。同步面最小的同时把"看得见"解决掉。

## 落地（EditorPanel + 一条 CSS）

1. **镜像背景层**：locate 时在 textarea 背后垫一层同排版 div（同衬线字体栈
   /`--novel-editor-font-size`/行高 1.9/字距 0.02em/20×24 padding/1px 透明
   border，box-sizing border-box），文本 `color: transparent` 仅 mark 显色
   （`--gaea-glow` 32% 混色）——textarea 切 `background: transparent` 类
   （`.novel-editor-mirror-hl`，!important 排序压过既有底色）从背后透出。
2. **换行对齐**：镜像按 textarea 的滚动条占宽（offsetWidth−clientWidth）
   补等量右内距；whiteSpace pre-wrap + overflowWrap break-word 与 textarea
   默认一致；onScroll 同步 scrollTop，聚焦滚动后 rAF 再同步一次。
3. **失效纪律**：content 或 activeNode 变化（手写编辑/流式重生成/切章）即
   清除高亮——编辑后偏移漂移的正确性问题被结构性规避；下一次 locate 覆盖。
4. pointerEvents none / aria-hidden：镜像纯装饰不拦截输入。

## 坑

- **rune 区间心算又错一次**：rune [1,3) 在 𝌆 开头的串里是「一二」不是「二三」
  （𝌆 占 rune 0）——差值/区间断言先写清"每个 rune 是谁"再写期望。
- **定位句柄里的 setState 是异步渲染**：RTL 同步 getByTestId 赶不上，须
  findBy/waitFor；setSelectionRange 则是同步 DOM 操作立即可断言——同一次
  locate 里两种时序并存。
- textarea 底色是 `!important` CSS：内联样式压不过，须追加同优先级类且排在
  源码序之后（`.novel-editor-mirror-hl`）。
