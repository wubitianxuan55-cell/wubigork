# v4.146.0 · 对话改计划回滚闭环（diff 确认卡刀A）：schedule_apply 进变更 tab + 回执卡「回滚本次」（2026-09-08）

> v4.125 落档的「对话式调整 diff 确认闭环」设计（docs/gaea-schedule-diff-confirm-design-2026-09.md）按刀序启动——**刀A「后置闭环补全」**：把「easy revert」先补齐，独立于事前确认卡成立（设计 §3 刀序建议原文「A 最小先把可回滚补齐，即使确认卡不做也独立成立」）。缺口（§1.5 读码核实）：schedule_apply 的证据卡一直在 Journal 里，但变更 tab 白名单不含它、工具卡无回滚入口——进度计划侧用户对 AI 改计划**没有任何可点的反悔入口**。纯前端，绑定面 **597 零变更**（RollbackRecord/GaeaJournalList 既有）。

## 1. 变更 tab 纳入 schedule_apply

- changes.ts：`WRITE_TOOL_NAMES` +schedule_apply；`WRITE_ONLY_TOOL_NAMES` +schedule_apply（三态层归**写入层**——整计划替换无行级 old/new；既有「WRITE⊆EDIT∪WRITE_ONLY」完备性锁同步满足）。
- `extractChangedPaths(args, tool?)` 增可选 tool 参：schedule_apply 缺省 path（Go 侧解析为当前计划）回填 `进度计划/当前计划.gsched.json`——缺省路径的整计划替换在变更聚合不漏记（与 Journal target 同口径）；其他工具与不带 tool 的旧调用行为不变。buildSessionChanges / planDiff buildChangeCalls 两处调用点同步传 tool 名。
- planDiff `buildChangeDiff`：schedule_apply 显式降级说明「整计划替换/ops 调整：无行级 diff，结果以工具回执与进度计划板块为准」——绝不伪造红绿 diff（v4.25 诚实降级纪律）。

## 2. apply 回执工具卡「回滚本次」（新组件 ScheduleApplyRollback）

- 常驻可见（对齐 TaskLiveRow 位置，不进折叠区）：schedule_apply 卡 done 后，Journal 按 **target 匹配最新一条带基线快照**的 schedule_apply 记录（与 ChangesPanel「按 target 匹配最新」同款语义），有则渲染回滚行。
- 点击调既有 `GaeaRollbackRecord`（「已被手工修改」守卫+恢复前再快照+可撤销恢复全在 Go 侧既有逻辑）；toast 反馈；无匹配记录（旧会话无快照/Journal 未就绪）**整行不渲染**，诚实无入口。
- 多次 apply 同一路径不逐卡区分（Journal 无调用级关联键，设计 §5 欠账另案）：按钮标题显式带 turn——回滚的总是该路径最近一次 apply 的写盘前基线。
- 缺省路径常量在 changes.ts / ScheduleApplyRollback 本地镜像（schedule/store DEFAULT_SCHEDULE_PATH 同款先例），不反向拉起进度计划 store 图谱。
