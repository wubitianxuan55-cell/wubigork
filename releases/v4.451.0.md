# 分支剧情 50 字压缩：分支只是方向，细节由章节计划承担（v4.451.0）

> 用户指令：「有了章节计划，现在压缩分支剧情到50字，有章节计划进行详细规划
> 后再生成文章」。**绑定面 743 零变更**（零绑定改动）。

## 背景与口径

v4.450.0 打通 分支→章节计划→生成章节 后，链路口径需要收紧：分支构思的
summary 此前约 150 字，`标题：pitch` 整段灌进 plotReq——生成提示词被长分支
剧情占据，章节计划的存在感被稀释。

本版起链路口径 = **分支（≤50 字方向）→ 章节计划（direction 展开成七字段
详细规划）→ 生成本章（计划注入正文）**。

## 落地

- **模板**：`prompts/plot-branch-browser.json` summary「约150字」→「**不超过
  50 字**」——以具体场景开头，把 触发事件→冲突→代价 各压成一笔；不展开细节
  与对白（分支只是方向，详细规划由后续章节计划承担）。must 约束同步（50 字
  内仍要触及该位置的必带项）；output description 同步；style 改一句话 logline。
- **确定性护栏**：`clampBranchPitch`（rune 口径，与模板/前端展示一致）——
  超预算时在预算内最后一个句读符（。！？；…）后截断（保留完整句子）；无句读
  才硬截 49 字+省略号，总长仍守 50。`parsePlotBranchReply` 单一收口点，
  BrainstormBranches / QuickBrainstormBranches 两条构思链同口径。
- 链路下游零改动：向导卡片展示 50 字 pitch；plotReq=`标题：pitch`（~65 字内）；
  计划卡 direction 横幅/「生成本章」/硬闸种子均为 v4.450.0 既有接线。

## 测试
