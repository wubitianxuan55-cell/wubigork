## 缺口

异常检测（adjustLevel 三档/调差建议/线性回归预测）全部是「成本条目 vs
最新询价点」的单点比对——询价库**内部**的数据质量问题（同名价格乱、
序列跳变、过期未标、长期不更新）没有任何一处会被看见，只能靠用户逐条
翻记录撞运气。

## 方案：四类体检 + 一张折叠报表

**Go（costinquiry/scan.go，只读）**——`ScanAnomalies()` 全量扫 +
内存检查，全部复用既有归一化/排序辅助（MatchTitle/sortableDate/
parsePriceDate），零新建检测基建：

1. **离散**：同归一化标题 max/min ≥1.5 关注、≥2.0 异常——同名不同规格
   混归一或录入有误；
2. **跳变**：按期数排序后相邻两点涨幅 ≥30% 关注、≥50% 异常（取最大一处）；
3. **过期未标记**：valid_until 已过而状态仍「现行」，逐条报（不依赖分组）；
4. **陈旧**：标题最新可解析期数超过一年未更新——调差与预测可信度下降。

排序：异常优先 → 类别（离散/跳变/过期/陈旧）→ 标题；每条带 severity/
detail（人话描述含关键数值）/refIds（涉及记录 id 供定位）。
Price≤0 与空标题数据点不参与；干净库诚实返回空。
