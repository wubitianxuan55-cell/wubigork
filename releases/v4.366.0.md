## 刀1：聊天组件 memo 化（四组件 + props 链梳理）

- **ChatPage props 链稳定化**：五个内联箭头回调提为 useCallback（`handleToggleSearch`/`handleToggleForceSearch`/`handleToggleThinking`/`handleOpenVoiceSettings`/`handleSwitchPersona`——后者的 `mode`/`activePersonality` 入依赖）；`quickReplies={mode !== 'plain' ? QUICK_REPLIES : []}` 的内联 `[]` 提为模块级 `EMPTY_REPLIES` 常量（内联数组是 memo 恒失效的典型来源）。
- **四组件 React.memo 包裹**：ChatModeBar（顶栏模式条，portal 常驻）/ ChatPersonaBar（人格状态条）/ ChatComposer（输入岛，含 antd TextArea）/ ChatInspector（右侧工作台，230 行子树）。声明改 `XInner` + 文件尾 `export const X = React.memo(XInner)`。
- **ChatInspector 统计单趟化**：totalChars/userCount/assistantCount 三遍全文遍历（reduce+filter+length）合并为单趟 for-of 的 useMemo。
- memo 语义安全：即使个别 props 未来引入非稳定引用，后果只是 memo 未命中（不劣化于改动前），无正确性风险——这也是本专项可以安全落地的原因。

## 刀2：StoryStream 行级 memo（原罪流式 O(消息数×分段) 根修）

审计确认：原罪流式每个 delta 到达 `setMessages` 整数组 map 替换，StoryStream 无行 memo → 对每条历史消息重跑 `parseStorySegments` 并重渲染全部 Markdown 段与插图组件（O(消息数×分段)/token），且原罪页 keepAlive 切走后照跑。

修法：抽 `SinAssistantRow = memo(...)` 行组件（storyId/m/两个插图回调为 props），`parseStorySegments` 下沉行内（memo 命中时跳过）。前提已核实：useSinStory 的流式 patch 是 `prev.map(m => m.key === asstKey ? {...m, ...} : m)`——**非流式行引用稳定**；`showNotice`/`setIllustration` 均为 useCallback 稳定引用。效果：流式期间每 delta 只重渲染流式中的那一行。
