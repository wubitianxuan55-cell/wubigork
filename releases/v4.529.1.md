# v4.529.1 · 小结标题挤压根修与亮态目检补课（2026-10-30）

> v4.529.0 UI 走查批的补完刀：v4.529.0 的 CJK 断行修复只在档案栏折叠
> （主列宽）的布局态下成立，展开栏被 flex 行挤压回四行碎句。本次根修
> 布局本身，并补齐亮色暖纸态目检。绑定面零变更，纯 CSS 一条规则。

## 1. 根因

- 协作小结头部是 flex 行：标题与状态 tag 同行，右侧另有印记预留
  （`padding-right: 72px`）。档案栏展开时主列收窄，标题被挤到约
  256px——`min(100%, 20em)` 的理想宽度从未兑现，配合 `text-wrap:
  balance` 绞回四行碎句。
- v4.529.0 的「两行验收」恰逢档案栏折叠态（主列宽），单态验过≠修复
  成立；后续复拍又只拍了无小结面板的失败态，盲区正好漏过。

## 2. 修复

- 小结头部加 `flex-wrap: wrap`，标题恒占整行（`flex: 1 1 100%`），
  状态 tag 恒换行右对齐——标题层与状态层层级更干净，不再互相挤压。
- 小结标题字号 `clamp(20px, 2vw, 27px)` → `clamp(19px, 1.7vw, 24px)`，
  与摘要正文保持层级差的同时在窄列放下完整断句。

## 3. 验收（四象限实拍）

- 亮色暖纸 × 玄墨暗态、档案栏展开 × 折叠：小结标题均为两行优雅断句
  （「导出双门：壳内走 GaeaSaveFileAs,」/「浏览器回退 a.download。」）。
- vitest 19/19；构建冒烟 `/api/health` 200，桌面副本随 build.bat 同步。
- 纪律沉淀：flex 收窄类断行 bug 的目检必须覆盖主列宽度的所有布局态
  （栏折叠/展开是两个世界）；沙箱 localStorage 跨壳存活，走查前显式重置。
