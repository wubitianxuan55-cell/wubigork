# v4.503.0 · 办公对话输出排版单源收敛+bash 卡去重（2026-10-18）

> 用户实锤三处：「字体大小不一，间距也是混乱一团，bash 类更是一长串，极度影响观感」。

## 根因：两套排版系统同树混战

同一份 markdown 同时挂着两套互相独立的排版系统，按 CSS 特异度**逐属性**打架，
胜负随选择器写法漂移——这是「字体大小不一、间距混乱」的根因：

- `styles.css` 的 `.md` 排版块（v4.337 设计的 Codex 式排版）：h1 1.45em、
  段后距 10px、表格 13px 且表头仅加粗、引用非斜体；
- `Markdown.tsx` buildComponents 里的 Tailwind 工具类：h1 18px、p my-1.5、
  th 11px、ul my-2+space-y-0.5、引用斜体。

`.md h1`（类+元素，0,1,1）压过 `.text-\[18px\]`（单类，0,1,0）→ 标题字号/边距
实际按 `.md` 渲染（h1=1.45×14≈**20.3px**，比组件里写的 18px 还大）；但 `.md th`
没写字号 → 工具类 `text-[11px]` 反而赢了 → **表头 11px vs 单元格 13px** 同表失
配；引用斜体只有工具类声明 → 混进最终渲染。表格表头失配、h4 无映射落为正文同
款（`####` 层级隐形）、标题 20px 与正文 14px 跳变过大，全部同源。

## 修复

- **单源**：Markdown.tsx 组件摘除与 `.md` 打架的全部排版工具类（h1-h4/p/ul/ol/
  blockquote/hr/th/td），只保留 Tailwind preflight 需要的 `list-disc/list-decimal`
  列表符号补偿——`.md` 排版块成为字级/间距**唯一来源**（对全部消费方一致：
  办公对话流/文件预览/知识面板同链）；
- **阶梯压平一档**（聊天场景）：h1 1.3em(≈18px) / h2 1.16em(≈16px) / h3
  1.06em(≈15px) / h4 1em 降色（--fg-dim）不降级——`####` 不再隐形；节奏同步
  收紧（标题边距 20/8→16/6，段后 10→8，hr 20→16，li 4→3px）；表格表头回归
  13px 加粗（.md 自有规则）；引用去斜体（accent 竖条+浅底保留）；
- **流式尾部对齐**：MemoMarkdown renderPending 的标题行字号近似 `.md` 新阶梯
  （h1/h2 1.25em 加粗），稳定段接管时不再从纯加粗 14px 跳到 16~20px；
- **bash 卡去重**（「一长串」）：折叠行内主体 mono 化+`$` 前缀（终端语意，可
  截断扫描）；展开后行内主体隐藏——命令由 `$ 命令块` 独占，不再折叠行摊一条
  长命令、展开后又整块复述一遍（59cc2638 已把 JSON args 换成 `$ 命令块`，本次
  消除行内/块内双份）；输出标签 9→10px 与 diff 标签同档。
