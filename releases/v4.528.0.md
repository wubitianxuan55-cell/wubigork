# v4.528.0 · 众神殿：多 Agent 圆桌、至共识讨论、实时工具轨迹与 Grok 办公工具接入（2026-10-29）

> 众神殿从“单向议事台”升级为可长期使用的多 Agent 圆桌：支持手动
> 2–20 轮或不限轮次讨论至全员明确一致，Codex / ZCode / DSH / Grok
> 共享工作空间但保留各自判断链。Codex、ZCode、DSH 的真实只读工具事件
> 统一进入实时轨迹；Grok 不再裸跑 xAI 补全，而是由 Gaea 办公
> `AgentRunner` 驱动只读办公工具。

## 1. 圆桌讨论与界面

- 新增一级板块“众神殿”，每位参与者获得共享观点窗口与独立上下文窗口；
  后续轮次分别注入个人历史发言和其他参与者的公开观点，避免共享语境
  覆盖自身判断链。
- 手动轮次支持 **2–20**；新增“不限”模式，每席必须输出结构化共识状态，
  只有所有实际参与者都明确“一致”才提前进入小结。
- “不限”模式默认安全上限 **12 轮**，达到上限后保留分歧并正常生成
  协作小结，避免无限调用；高轮次进度轨支持横向滚动。
- 讨论按用户指定顺序串行发言，轮间自动轮换首位；最终汇总只整理
  共识、分歧、开放问题与建议，不评胜负。
- 完成态先展示协作小结，再展示过程记录；支持“基于小结续议”，继承
  议题、材料、工作空间、参与者、顺序、轮次与共识模式。
- 左侧档案栏可折叠为 72px 窄轨并持久化到 `localStorage`；补全
  390 / 720 / 1440 响应式、亮暗主题与 reduced-motion。
- 讨论档案支持议题/工作空间搜索、运行/完成筛选、Markdown/JSON
  双导出。

## 2. 工具能力与实时轨迹

- Codex 保持只读 sandbox；ZCode 改走 `--output-format stream-json`；
  DSH 保持 `DSH_PERMISSION_MODE=read-only`。三席均可使用各自 Harness
  提供的只读工具。
- 真机探针通过：Codex **0.165.0**、ZCode **0.17.0**、
  DSH **0.2.1-rc.3** 均完成最小只读目录查询并返回可解析工具事件，
  工作区未修改。
- 统一解析 Codex `item.started/completed`、ZCode
  `tool_call/tool.updated`、DSH `tool_call/tool_result`；工具开始、
  完成、失败、输入摘要、结果预览和时间戳实时进入纪要。
- 前端“工具轨迹”按 Agent / 轮次展示真实工具动作。模型内部 reasoning
  不进入工具轨迹，避免把思维流误标成工具日志。

## 3. Grok 接入 Gaea 办公工具

- Grok 由每轮按众神殿工作空间新建的 Gaea 办公 `AgentRunner` 驱动，
  不再直接调用裸 xAI completion；xAI 调用仍记入 `pantheon` feature。
- 工作区文件工具重新绑定到当前讨论工作空间，并从办公注册表只复制
  `ReadOnly() == true` 的造价、知识、记忆、日程、搜索等工具。
- 明确不暴露 `write_file`、`edit_file`、`bash`、`task`、
  `install_skill` 等写类或编排类工具，也不读取/复制外部 Agent 凭证。
- `AgentRunner` 的 ToolDispatch / ToolResult 直接映射为众神殿工具轨迹；
  完整工具循环由脚本化 provider 验证。真实 xAI 工具调用未纳入本次
  发版门禁，保持这一边界如实可见。

## 4. 可靠性

- 超长材料与讨论提示词改为保留首尾并显式标记中段省略，避免截掉末尾
  的结构化共识 JSON 要求。
- 应用重启时把遗留 `running` 会话收敛为失败，保留已产生的参与者、
  部分发言和事件；第二次恢复保持幂等。
- 默认轮换、失败隔离、并发工作空间隔离、工具轨迹持久化和共识提前
  结束均有后端用例覆盖。
