# v4.41.0「微信文件收发 · 入站定稿 + 出站探针」

> 发布日期：2026-09-02 ｜ tag：`v4.41.0` ｜ 基线：v4.40.0 ｜ 绑定面 **557 零变更**

## 定位与来源

微信助手专项调研（`docs/market-research-2026-09-02b.md`）B 刀。**入站协议真机抓包
定稿**（2026-09-02 16:58 首笔 file_item 落 `wx_capture.jsonl`）：file_item 与图片完全
同构——`media{encrypt_query_param, aes_key(base64 of hex), full_url}` + `file_name`/
`md5`/`len(字符串)`，下载复用 AES-128-ECB 解密链。出站上传协议逆向文档未覆盖
（openclaw-weixin 三方印证仅确认 AES-128-ECB 五步同图片），**探针制实装**。

实施方式：两路并行子代理（通道线 / app 接线线，文件所有权互斥），主代理收口。

## 交付

- **① 入站文件收**（通道线）：fileItem 升级（media/file_name/md5/len 双容忍，旧字段
  兼容）；`resolveInboundFile`——声明大小预检 → full_url 下载（SSRF dial-time 防线
  参数化复用）→ AES 解密（aes_key 解析失败显式报错，绝不密文当明文）→ 50MiB 上限
  → MD5 比对（对上可信、对不上 Warn 保留不拒收）→ 临时文件交 FileHandler 用后即删。
- **② 内容提取接线**（接线线，`wx_file_handler.go`）：FileHandler 自持复制到
  `whisper_data/wx_files/`（FNV 防注入名 + 扩展名白名单 + 50 个/500MiB 滚动清理）；
  提取全走现有解析器零新轮子——docx/doc/xlsx/xls/pptx/ppt/pdf 走 `docmd.Convert`
  （markitdown 优先 + 纯 Go 回退），txt/md/csv/log/json 直读，其余诚实降级带自持
  路径；注入行 `[用户发来文件 X（424 KB）]` + 前 6000 字符（超限标注截断）。
- **③ 出站文件卡（探针制）**（通道线）：上传五步抽共享内核 `uploadMediaBytes`
  （getuploadurl media_type=**3** → 随机 AES-128-ECB → CDN PUT → sendmessage
  type=4 file_item{file_name, len, md5, media}）；逐节点 upload_probe capture
  （file_getuploadurl / file_cdn_upload / file_send_file_card / delivered）；图片链
  逐字节零改动；SendFileCard 按扩展名分流（图片白名单→原图链；非图片→文件卡链，
  失败逐级降级文本卡），签名不变。
- **④ 产物推送意图**（接线线）：`ActionSendLatestFile` 锚定三式保守正则（「把刚才
  的报告发我 / 发我文件 / 发送产物」，12 命中/10 不命中，产物义强名词才放行发送式，
  「提醒我把报告发给老板」正确归提醒）；`execSendLatestFile`——会话交付物登记表
  （FoldDeliverables，最近 20 会话）→ 回退 `.gaea/exports` + `.gaea/play/exports`
  mtime 最新 → 都无诚实报错；`..` 逃逸拒绝；dry-run 预览卡对齐 v4.40 模式。
- **⑤ 协议文档**：`docs/ilink-non-text-protocol.md` 新 §2「入站文件」定稿章节 +
  §3.1 出站探针标注 + 防线矩阵补文件行。
