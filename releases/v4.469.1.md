# v4.469.1 · 存量清单主定额自动转引用（SchemaV31 回填）

**日期**：2026-10-07 ｜ **产物**：`releases/gaea-v4.469.1.exe`（SHA256 `ed52081b7f8a3e8a…` 见 SHA256SUMS）｜ 冒烟 200 ✓

用户真机反馈（v4.469.0 上）：「点击所有清单都看不到定额了，**原综合单价分析表应该自动转换成定额**」。根因=V30 只建了空引用表，存量清单的引用靠「重导入双写」——用户没重导入，弹窗直查引用表为空，定额消失。

## 修复（用户零操作）

- **SchemaV31 回填迁移**：开库即把每条清单项的主定额（单值 `quota_code`）自动 INSERT..SELECT 进引用表（quantity=清单工程量、sort=1 主定额排首；NOT IN 幂等防重入）。升级一次，全部存量清单的定额自动出现在分析弹窗——正是用户期望的「自动转换」。
- **读侧兜底**：`BillQuotaLinks` 引用为空但清单项有主码时合成一条引用返回（ID=-1，不落库），盖住任何迁移前窗口期。
- V31 SQL 修正过程：首版引用了 `gf_bill_items.created_at`（该表无时间戳列）被 db 全链迁移测试当场抓获——列名以表定义为准。

## 验证

- Go `TestV31BackfillAutoConvertsQuotaCodes`（兜底合成 + 回填落表 + quantity 口径）；db 全链迁移测试绿。
- 全量 ci 绿。

## 教训

**新表+回填要同一版出**：只建表、把数据迁移寄托在「用户重导入」上的设计，对存量数据是一次功能回退（升级即丢可见性）。涉及存量数据可见性的模型变更，回填 SQL 必须随迁移链同版落地。
