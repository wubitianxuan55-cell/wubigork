## 现状盘点（侦察结论，基于代码）

### A. 统一检索：4 绑定前端拼装

- `MemoryHubPage.runSearch`（frontend/src/pages/MemoryHubPage.tsx:138-181）并行调 **4 个绑定**前端合并：
  `BrainSearch`（wails 直连）+ `WorkspaceSearch` + `SemanticSearch` + `FileSemanticSearch`。
- 后端已有 `GaeaUnifiedSearch`（internal/app/gaea_unified_search.go，T5-6）：返回 `keyword`
  （工作区全文，`workspaceSearchHits`）+ `semantic`（跨库语义，`semanticSearchHitsOnDemand`，
  含 cost/knowledge/office/file 四类）。**缺三脑命中组与文件语义组，且前端 hub 未接。**
- `WorkspaceSearchPanel` 已用 `app.UnifiedSearch`（跨库模式），扩展视图字段对它零影响（只读 keyword/semantic）。

### B. 记忆生命周期：两个真实缺口

1. **归档 tab 永远空白**：前端 `OfficeMemoryLibrary.tsx:273` 读 `view?.archives`，前端类型
   `MemoryView.archives?: MemoryArchive[]`（types.ts:540），但后端 `GaeaMemory()`（gaea_ui_meta.go:289）
   返回的 `MemoryView` 结构体**没有 archives 字段**（只有 docs/facts/scopes/storeDir/available/enabled）→
   JSON 序列化后前端永远 undefined。归档列表只有靠 `GaeaMemoryArchivedList`（分页绑定已存在，前端未用）。
2. **无恢复（Unarchive）能力**：memory 包 `Store.Archive`（软删，sqlite 置 archived=1 / file 移 .archive/）
   存在；`gaea_memory_lifecycle.go` 注释称「误归档用户仍可在 90 天内恢复」，但 **memory 包没有
   Unarchive 方法、app 层无绑定、前端无恢复按钮**——恢复路径实际不存在。唯一出口是 90 天后硬删。

### C. 可复用的既有资产（第一刀尽量零新增基建）

- 分页归档绑定 `GaeaMemoryArchivedList` / 清理绑定 `GaeaMemoryCleanupArchived`（bindings_memory.go:23-24）
- 三脑检索 `BrainStore.Search`（app/brain_store.go:66，brains 空=三脑全搜）→ 可直接被 GaeaUnifiedSearch 复用
- 文件语义 `GaeaFileSemanticSearch` 的查询段（gaea_file_index.go:89-119）→ 可抽私有实现供聚合
- 统一检索测试环境 `newUnifiedSearchEnv`（gaea_unified_search_test.go:21-73，含 mock embedding + 隔离库）
