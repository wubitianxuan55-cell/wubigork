## 2. 候选详细说明

### C1 任务实时输出面板（P1 / M）

办公长任务（价格抓取、文件索引重建、批量文档生成）一旦卡住，用户看不到「它在干什么」，只能干等或盲目取消。插件的做法值得原样借鉴：**底部单个共享输出 dock**（不是每行一个面板），选中任务行即回放该任务被读取到的输出，2s 轮询 + 终端尾自动滚动，运行中才刷新、页面不可见即暂停；结束态细分（running/stopping/completed/killed/failed），kill 按钮 3 秒武装窗口防误触。后端形态建议：`GaeaTaskOutput(taskID string) (TaskOutputView, error)`，`TaskOutputView { tail string; truncated bool }`——从任务运行期日志按任务 id 累积重放，**不消费 agent 读取游标**（插件 jobs-routes 的核心纪律：只回放、不偷读，gaea 的 Go 引擎同样适用）；`TaskStatus` 增 `stopping` 态、`TaskView` 可选增 `exit` 字段表达退出码。风险：输出量大需截断标注（插件按字节 cap + truncated 标志），避免把面板拖死。

### C2 子代理实时活动行 + 层级拓扑（P1 活动行 / P2 拓扑 / M）

gaea 的分工面板已有「谁在跑、跑了多久、几次工具调用」，但运行中的子代理卡片看不到**此刻正在干什么**——插件在运行卡片上渲染「最后文本输出 + 最后工具调用」两行实时线（从 history tail 派生、3s 轮询、页面可见才轮询），这对办公用户判断「要不要等它/要不要打断」是直接的增量价值，建议 P1 只做活动行。完整拓扑树（以主会话为根、懒加载常展开、点击跳子代理完整 transcript）价值高但依赖后端给父子关系，建议 P2 单独立项。后端形态：`SubagentRunView` 增 `parentRef?: string` 与 `origin?: "main" | "subagent"`；活动行由后端从 transcript 尾部派生 `lastText`/`lastTool` 字段（前端不做 history 拉取，保持零新增 RPC）。风险：gaea 的子代理是否真的形成父子链（task 工具派发）需要后端确认，若当前无父子记录则拓扑退化为「活动行 + 现有扁平列表」。

### C3 会话级布局持久化（P1 / S）

办公用户通常同时开多个项目/会话（造价测算、合同、资料归档），每个会话的右侧面板关注点不同（A 会话停在「成果/产物」，B 会话停在「运行/任务」）。插件把**整个布局（面板开合、宽度、打开的 Tab、展开集）按会话 id 分别持久化**，切换会话即整体换状态，并做了三道保险：结构校验、uid 重编号防碰撞、损坏回退默认。gaea 第一轮已按 cwd 持久化文件树展开集，本轮把同一模式推广到 `rightTab`（key 建议 `gaea.rightPanel.v1:<sessionPath>`，会话路径已有），尺寸层可从全局 `layoutPreferences` 平滑升级为「会话值优先、全局值兜底」。风险：仅前端、低，注意 localStorage 条目上限与损坏静默回退。可顺带评估声明式面板设置注册表（插件 `prefs.ts` + `SideCardSection.tsx`），但办公场景优先级低，**建议本轮不做**，避免堆功能。

### C4 选区转对话（P1 / M）

这是办公场景的高频刚需：读一份 docx/xlsx/markdown，选中一段文字想直接让 AI 总结、翻译、改写——现在要手动复制 → 粘贴进输入框。插件在编辑器里选中文本即浮出「add to conversation」按钮，把「来源文件路径 + 行号 + 选中文本」拼成一段带上下文的引用插入输入框草稿。gaea 的 `useComposerInsertStore`（`requestText`/`requestAt`）与现有 @ 引用机制可以直接复用，纯前端即可。实现要点：markdown/txt 预览可精确映射行号（源文检索定位，插件 `linesOfSelection` 的 best-effort 思路）；docx/xlsx 预览取 DOM 选区纯文本、不带行号；按钮按下要 preventDefault 保住选区、点击才提交；滚动/失焦隐藏。风险：预览组件（DocxPreview/XlsxPreview）需要能响应选区事件，工作量集中在把弹层挂进所有预览表面；建议第一版只做 markdown/txt/纯文本预览。

### C5 工作区文本文件内联编辑（P2 / M）

办公用户常要快速改一个 txt/笔记/markdown（如把对话摘要存成 memo、微调脚本），现在只能「外部打开」或用记忆文档的 `DocEditor`。插件的编辑体验（CodeMirror、dirty dot、Ctrl/Cmd+S、saving/saved/failed 状态机、截断提示条、markdown 预览/编辑切换）是成熟范式，但 gaea 缺**通用工作区写文件绑定**：`SaveDoc` 面向记忆文档，`DocxApplyEdit` 面向修订模式，需要一个 `GaeaWriteFile(rel string, content string) error`（或扩展 `SaveDoc` 语义）。建议 P2：先确认办公引擎是否已允许工作区写文件（权限模型），再决定绑定形态。风险：写权限与沙箱（`SetSandbox`）冲突需后端配合；`DocEditor` 是 textarea 极简实现，升级到 CodeMirror 属前端中等工作量。

### C6 运行域活动角标（P2 / S）

插件对「新子代理 / 新任务」有自动激活页面机制（0→N 或任意新 job id 触发，pref 门控），但自动切页面在办公场景容易打扰。更轻的方案是**只加角标提示**：4 主 Tab 的「运行」组上出现计数徽标（99+ 封顶），有新的 `gaea-task` 事件或子代理开始运行时点亮，用户点过去即清除。纯前端：`onTaskEvent` 已存在；子代理可用现有 `SubagentRuns` 轮询做增量检测（插件 detectNewJob/detectNewDirectSubagent 的 prev/next 快照比较思路直接可搬）。风险：低；注意「刷新页面基线不触发」的细节（避免每次加载都闪角标）。

### C7 中键关闭 + 预览队列拖拽排序（P2 / S）

办公用户一次预览多个文件（队列导航已有），中键点掉某个文件、或把常用的拖到前面是自然诉求。插件 `TabBar` 的中键关闭实现细节值得照抄：**按下记录目标、弹起仍落在同一 tab 才关闭**（VS Code 语义，防手滑），并 preventDefault 掉 Chrome 中键 autoscroll。落地位置是预览队列导航条（把 index/total 升级为可点文件条）。纯前端、独立、低风险。

### C8 树内搜索升级为宿主递归搜索（P2 / S）

第一轮按「零后端」原则做了本地过滤已加载层，但 gaea **已经有 `GaeaFileSearch(query, limit)` 绑定**（现用于 @ 引用增强的跨目录定位）。把它接到文件树搜索框即可获得插件 `fs.search` 同款能力（跨目录文件名命中），插件的关键纪律：**预算封顶 + 跳过 `.git`/symlink + 结果与已加载层去重合并**，避免大工作区拉爆。可以并入第一轮收尾或作为第二轮第一个小项。

### C9 分栏对照（P2 / L）

插件最重的交互之一：拖 tab 到 pane 边缘拆分、分栏并排、拖分隔条调宽、同会话内布局持久化。办公价值直观（docx 与 xlsx 对照、原文与译文对照），但 gaea 预览区是「单文件 + 队列」模型，改造成双 pane 涉及预览布局、状态、持久化一整条链路，工作量 L。建议排在最后（P2 尾），且只做「在侧边打开」的静态双栏（第一版不做拖拽拆分），验证办公用户真实需求后再加复杂度。

## 4. 建议的推进顺序

1. **第一轮收尾**：C8（树搜索接 `GaeaFileSearch`，预算封顶）——后端绑定已存在，S 工作量。
2. **第二轮主打**：C3（会话布局持久化，S）+ C4（选区转对话，M）——纯前端、办公高频，构成一个「会话记忆 + 阅读即引用」的完整小迭代。
3. **第三轮**：C1（任务实时输出，M，需后端 `GaeaTaskOutput`）+ C2 活动行（M，需后端字段）——任务可见性补齐，可与后端一次评估一起排期。
4. **之后**：C5 / C6 / C7（各自独立，可穿插）；C9 分栏对照留到验证真实需求后再启动。
