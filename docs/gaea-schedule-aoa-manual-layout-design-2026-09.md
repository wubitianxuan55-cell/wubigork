# gaea 进度计划双代号网络图（AOA）手动布局设计

> 状态：**草案 v1 / 待拍板**（2026-09-06）。承接 releases/v4.118.0.md 欠账池「双代号手动布局」（v4.110.0 刀1 即挂账：「节点拖动微调与手动布线待后续刀」）。本文档只做调研与设计提案，未动任何代码；拍板后按 §5 分刀实施。

## 0. 结论速览

- **定位：布局是展示层状态，引擎口径零变更**。拓扑/编号（i<j）/最早最迟/关键线路仍全部由 `buildAoa` 唯一裁决；手动坐标是纯视觉覆盖（pin），永不影响时间参数与关键性。Go 侧维持无 aoa.go 现状（AOA 自刀1 起即纯前端展示层）。
- **核心难题的裁定：混合锚定（pin 按稳定锚点键匹配）**。`buildAoa` 为每个事件产出稳定「锚点键」（`S`/`T`/`end:<taskId>`/`start:<taskId>`），手动坐标按锚点键存放；拓扑变更后——命中锚点的事件保持手动位，新事件自动落位，失配锚点清理。拒绝「一变全清」与「相对偏移跟随」两种极端（§3）。
- **数据落位：gsched.json 内嵌 `aoaLayout.pins`**（TS↔Go 镜像字段）。这不是可选项而是通道物理约束——Go `Save` 走 unmarshal→校验→重 marshal 整量重写，非镜像字段落盘即被剥掉（§4.1）。Go 只做结构校验 pass-through，不进引擎语义。
- **交互对齐 v4.118 拖拽刀纪律**：自动模式拖拽 = 自动转手动（「不骗人」先例）、纯函数吸附、Esc 取消、提交走既有 store→防抖自动保存链路。最小集 = 拖拽布点 + 半格网格吸附；箭线 waypoint 布线、对齐辅助线、框选批量均不进首轮。
- **agent 工具不暴露布局操作**（零新绑定、ops schema 零增）；通道天然保序：ops 增量改写保留 pins，project 全量回显亦保序（§4.5）。
- **刀序：刀1（锚点化+拖拽布点+持久化，中刀）→ 刀2（对齐线+整理工具，小刀，观察后拍板）→ 刀3（正交布线等，可不做）**。刀1 绑定面 588 零变更。
- 拍板问题 7 项（§6），最大风险 = 锚点代表任务被删导致的个别事件位置跳变（可降级兜底，§7）。

## 1. 上游参照（外部调研，只取交互口径）

- **专业网络计划软件（飞椽 gantt-planing 系，v4.110 刀1 调研基线同源）**：「任意自主设计网络图、节点拖动、箭线调整」，同一任务数据一键生成横道/时标/双代号/PERT 多图——即**布局与数据分离、编号与坐标解耦**的业界口径。
- **通用绘图工具（亿图/ProcessOn/Visio）**：自由布点 + 网格吸附 + 手动连线；时标刻度需自维护（即自由布局与时间轴天然解耦）。
- **专业编制软件（CCPROJECT 等）**：自动计算时间参数与关键线路 + 允许手动调整节点位置/合并节点——「引擎算数、人摆图」分工。
- **教材/规范口径**：双代号网络图（汇报/投标画法）通常**非时标**；「时标网络图」是独立图型（波形线表自由时差）。当前 AoaView 的「列=最早时间」是时标画法——手动布局模式解耦 x 与时间并不违背规范，反而是回归主流汇报画法。
- **诚实标注**：手动坐标的持久化格式与「拓扑变更后坐标失效策略」在公开资料中**未见成文方案**（各商业软件闭源，开源飞椽未文档化其坐标存储）；本节以上为能力存在性佐证，失效策略的推导见 §3，以交互设计推理为主。

## 2. 现状与缺口（逐项已核）

| 件 | 现状 | 缺口 |
|---|---|---|
| frontend/src/schedule/aoa.ts | `buildAoa` 纯函数：安全合并/虚箭线自动插入去重/一始一终/拓扑编号/正逆推/时标分层；节点 id=`n0..nN`（构造序）、`S`/`T` | 事件 id 是**构造序派生**，跨拓扑变更不稳定（手动布局的核心障碍，§3）；节点坐标直接内嵌 x/y，无外部覆盖入口 |
| frontend/src/schedule/layout.ts | `layerByTime`：列=es、行=重心两轮松弛 | 自动布局唯一来源；分支多时列内仍交叉，且**时标口径下 x 完全锁死**，用户无任何排版自由度 |
| frontend/src/schedule/AoaView.tsx | SVG 直渲：箭线两点直连（同列 bow 偏移）、节点 DOM 圆圈、统计牌 | 只读渲染，无任何鼠标直接操作；w/h 按节点坐标推画布 |
| internal/schedule/ | types/cpm/calendar/baseline/deadline/ops/project（校验+CPM fail-closed），**无 aoa.go** | 无 AOA 镜像——维持现状即可，但**schema 新字段必须镜像**（见下） |
| 持久化通道 | GaeaScheduleSave → Go unmarshal→Validate→CPM→MarshalIndent 整量重写 | **任何 TS 侧新字段不同步 Go types.go，保存一次即被静默剥掉**——数据模型设计的硬约束 |
| 交互先例 | GanttView `beginDrag`（v4.118）：window 监听三件套、预览 tip、Esc 取消、未移动不提交、纯函数换算 drag.ts | AOA 无对应件；语义与纪律可直接对齐移植 |

**用户需要手动布点的真实场景**：① 大网络交叉线——分支/搭接密集时自动重心松弛仍大量交叉，实虚箭线混织难以读图；② 汇报排版——打印/截图给甲方监理时需按楼层/专业分行、按施工段成列的「行式」排布；③ 时标挤压——自由时差大的节点被 es 列锁死，密集处标签重叠（AOA_COL_W=110 固定列距）；④ 教学口径——讲题/交底常需教材式非时标画法。

## 3. 核心语义裁定：手动坐标与 buildAoa 自动拓扑的共存

### 3.1 难题本质

`buildAoa` 的事件身份（`n0..nN`）按「任务拓扑序 × 构造顺序」派生：任务增删、搭接变更、甚至**合并判定翻转**（如给任务 B 新增一条 FF 搭接，使其不再与 A 共用完成事件）都会让事件集合重排、id 全体漂移。手动坐标若按节点 id 存，任何一次编辑后全部失配。**锚点键必须从「事件的业务身份」推导，而非构造序**。

### 3.2 锚点键设计（引擎裁决身份）

事件在 buildAoa 中天然携带成员关系：它是若干（任务, 开始/完成）对的共用体。锚点键规则（buildAoa 内产出，`AoaNode` 增 `anchor` 字段）：

- `START` → `"S"`；`END` → `"T"`（天然稳定）；
- 其余事件 → 取其全部成员键 `{end:<taskId>} | {start:<taskId>}` 中的**字典序最小者**（`end:` < `start:` 字典序，保证合并事件的代表=先构造者，与现有构造顺序天然一致；taskId 为随机 id，集合不变则最小者不变）。

稳定性分析（单测钉死，§5 测试面）：

| 变更 | 事件身份 | 手动坐标命运 |
|---|---|---|
| 改工期/进度/名称 | 不变 | **全保**（仅 es/ls 标签值刷新） |
| 改开工日期/日历 | 不变 | 全保 |
| 新增任务 | 新增事件 | 新事件无 pin → 自动落位，其余全保 |
| 删除任务 | 少数事件消失+合并回收 | 失配 pin 清理；受影响事件自动落位 |
| 改搭接（合并判定翻转） | 个别事件分裂/合并 | 代表键多存活（`end:A` 仍是 A 完成事件）；分裂出的新事件自动落位 |
| 删除「代表任务」（锚点键所指任务被删） | 该事件仍存在但换代表 | 该事件降级自动位（一次跳变），可再拖 |

### 3.3 失效策略三案对比（正面回答）

| 方案 | 做法 | 裁定 |
|---|---|---|
| A 失效重排 | 拓扑一变全清 pins | **拒绝**——任何编辑毁掉全部排版；大网络逐节点重拖正是本能力的使用场景，等于没做 |
| B 坐标跟随 | 存相对自动位的偏移量 | **拒绝**——结构变化后自动位漂移，偏移语义随之漂移，叠加不可推理；换布局算法即全体失真 |
| **C 混合锚定（推荐）** | pin 按锚点键匹配；命中→手动位，未命中/失配→自动落位；保存时清理失配键 | **采纳**——图在任何时刻都合法可读（新事件引擎自动给位），用户既有劳动局部保全，「重置布局」兜底全清 |

「AI 产建议、引擎裁决」在本能力的映射：**用户/AI 只产建议（pin），buildAoa 始终裁决（事件身份、锚点、自动落位、时间参数、关键性、循环拒绝）**。pin 通路不存在任何能让图变非法的输入。

## 4. 设计提案

### 4.1 数据模型（gsched.json 内嵌，TS↔Go 镜像）

```json
"aoaLayout": { "pins": { "end:tab1c2": { "x": 550, "y": 148 }, "S": { "x": 40, "y": 40 } } }
```

- `SchedProject.aoaLayout?: { pins: Record<string, {x:number; y:number}> }`——wrapper 包一层留演进位（未来若要 mode/网格粒度不再动顶层字段）；**mode 不入文件**：开关是视图态，useState 口径与 GanttView 前锋线/基线开关一致，默认「pins 非空→手动」。
- 坐标为**整数像素**（与 AOA_COL_W/ROW_H 同一坐标系）；半格吸附天然产出整数。TS 侧 normalize 取整，agent 手写 JSON 若带小数会被 Go int 反序列化拒绝——fail-closed，回执原文，符合既有纪律。
- **旧文件完全兼容**：无字段=自动布局；`normalizeProject` 补缺省并做结构归一（pins 非对象/坐标非有限数→丢弃该键；防御性上限 5000 键）。
- **Go 镜像（必做）**：`types.go` 增 `AoaLayout{ Pins map[string]Pt }` + `Pt{X,Y int}`（`*AoaLayout` + `omitempty`，旧文件不回写 null）；`project.go Validate` 增结构校验（坐标负值/超界拒绝、键数上限），与既有 fail-closed 风格一致。
- **语义边界诚实声明**：镜像铁律约束的是**引擎口径**（CPM/排程/校验，两侧测试互为镜像）——布局数据不属于引擎口径，Go 只做结构校验 pass-through，**锚点键的业务合法性（键是否命中当前事件）由前端渲染端裁决与清理**，Go 无从验证也不验证。Go 维持无 aoa.go。

**备选否决案**：独立 sidecar 文件（`当前计划.gaoa.json`）——需新增读写绑定（违背零绑定），且 agent schedule_apply 整计划重写时 sidecar 必然漂移；localStorage——违背「计划文件是板块与 agent 共享资产」哲学，跨机即丢。

### 4.2 交互（最小集，对齐 v4.118 纪律）

- **拖拽事件圆圈布点**：`onMouseDown` → window mousemove/mouseup/keydown 三件套（GanttView beginDrag 同构）；拖拽中节点跟随 + 网格预览线？不——只节点虚线描边 + 落点坐标 tip（先例口径：预览只动本体）。
- **吸附纯函数**：新 `aoaLayout.ts` 内 `snapPt(x, y)`——半格吸附（`AOA_COL_W/2` × `AOA_ROW_H/2` = 55×37），纯函数 + 单测；拖拽中预览即吸附位（所见即所得，杜绝拖完跳一格）。
- **自动模式拖拽 = 自动转手动**：与横道「拖移 auto=转手动是唯一不骗人的做法」同构——自动模式（时标）下拖拽，落点写 pins、视图即时切手动；工具栏与拖拽 tip 明示（「拖动即转入手动布局」）。
- **守卫**：未移动不提交；Esc 中途取消；循环依赖（`graph.ok=false`）整视图空态天然禁拖；提交走 store→防抖 800ms 自动保存→agent 回读既有链路（殊途同归）。
- **提交时机顺带清理**：commit pin 时以当前图锚点集为准剪枝失配键（pins 不无限膨胀）。
- **不做**：箭线 waypoint 布线（箭线保持两点直连+同列 bow）、对齐辅助线、框选/批量对齐、对齐到时间列提示——刀2/刀3 口（§5）。

### 4.3 渲染（双模式切换）

- 工具栏加 Segmented「布局：自动 / 手动」+ 手动态「重置布局」按钮（清 pins 回自动）。
- **自动 = 现状**：layerByTime 时标分层（列=es），零改动。
- **手动 = pins 覆盖 + 自由坐标**：`applyPins(graph, pins)` 纯函数返回覆盖后节点集（含画布 w/h 重推）；命中 pin 的事件用手动位，未命中新事件用自动位（混合共存，§3.3）。**x 与时间解耦**——时间参数（编号/最早最迟/关键性）仍全量计算并显示在节点上下，只是不再编码进 x 轴（§1 教材口径佐证）。工具栏明示「手动布局：自由坐标，时间参数不受影响」。
- 开关为视图态（useState，默认 pins 非空→手动）；切到自动不删 pins（临时看时标），「重置布局」才清。

### 4.4 TS↔Go 镜像范围（推荐 + 理由）

**推荐：schema 镜像 + 结构校验 pass-through；布局算法与锚点语义不进 Go。** 理由：① 持久化通道物理约束（§2/§4.1）——不镜像即被剥；② AOA 转换自刀1 起是展示层，Go 引擎面（CPM/校验/ops）不需要事件坐标参与任何裁决；③ 镜像面最小化=漂移面最小化——Go 只需认识 `pins: map[string]{x,y}` 两个 int，两侧测试各 3 例即可钉死，远小于移植 buildAoa 的持续成本。

### 4.5 agent 工具是否暴露布局操作（推荐 + 理由）

**推荐：v1 不暴露**（不加 ops 类型、schedule_apply 描述不提 aoaLayout）。理由：① 布局是人的视觉判断，LLM 逐点坐标决策价值低、极易制造交叉灾难；② 工具面/绑定面零增（drift PASS@588），语义面零扩；③ 通道天然安全——ops 增量改写基于 `schedule.Load` 读出的完整结构，aoaLayout 原样保留；project 全量通道若 agent 从 schedule_get 回显（Go 镜像后 get 返回含 pins）亦保序。**诚实边界**：agent 全量写一份不含 aoaLayout 的 project 会清掉手动布局——与「整计划替换」既有语义一致（baseline 同命运），不做合并魔法；若实测误伤频发，刀3 拍板「同任务集启发保留」或 set_meta 扩展（§6 问题 4）。

## 6. 拍板问题清单（每点带推荐）

| # | 决策 | 推荐 | 备选 |
|---|---|---|---|
| 1 | 手动模式坐标口径 | **自由坐标**（教材/汇报主流画法；时间参数仍全显示） | 时标锁定（x=es 只拖 y）——半自由，理线能力受限 |

## 7. 风险与对策、明确不做

**风险与对策**

| 风险 | 对策 |
|---|---|
| 锚点代表任务被删 → 个别事件位置跳变 | 降级自动位可再拖；锚点推导规则单测钉死（§3.2 全场景表）；「重置布局」兜底 |
| 拖拽帧率（每帧重渲全图） | 拖拽中只位移预览节点，不重算 buildAoa（useMemo 隔离）；现状规模（几十~几百事件）SVG 直渲可扛，性能欠账挂池 |
| agent 全量重排误伤 pins | 证据卡 Before/After 可审（既有）；欠账池挂「布局保留启发式」（刀3 口） |
| TS↔Go 口径漂移 | 两侧类型+校验+roundtrip 测试互为镜像，沿用既有纪律；drift 门禁例行 |
| 用户在手动模式误读 x 为时间 | 工具栏明示「自由坐标，时间参数不受影响」；切自动即回时标口径 |

**明确不做**：不做多人协同/布局冲突合并；v1 不做箭线 waypoint 布线、对齐辅助线、框选批量、撤销重做（壳级欠账沿用 v4.118 口径）；不做布局导入导出（PNG 走壳级截图另案）；不让 agent 决策坐标（v1）；不做 PDM/横道视图的布局持久化（本刀仅 AOA）；不动 buildAoa 拓扑/时间/编号任何口径。
