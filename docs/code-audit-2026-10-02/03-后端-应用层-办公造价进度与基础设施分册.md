**板块整体判断**

1. 七个单元的痛点高度同构，可归纳为四条主线：**① 同一事实多份实现**（截断/原子写/配置快照/路径归一/子进程/工作流/编排内核，跨单元总计数百处）；**② 全局态与无锁共享字段**（`ga`、`a.cfg`、`a.client`、`voice.Manager` 回调、`whisperSessions`、`pickedFiles`、herdsman 包级函数变量）；**③ 静默失败**（错误被吞进成功返回值、recover 只打日志、绑定面返回 nil 表示失败）；**④ 契约双源**（Go 门面 vs localhost 反射面、Go builtins vs 前端 manifests.ts、漂移闸与生成器同源）。
2. 唯一「干净」的结论是 AP8 实测的绑定面零差异（743=743）——**但正因为它干净，才暴露出 302 个方法在门面之外被本机 HTTP 面按名暴露**，即「干净的清单保护不了没进清单的东西」。
3. 最高优先级的不是体量而是**语义错误**：三套编排（AP4-01）、收件箱丢卡（AP4-02）、成本导入双写（AP4-03）、意图 handler 被覆盖导致主脑默认分支永远派发失败（AP9-03）、回调字段竞态（AP6-01）、绘梦单槽进度串台（AP7-01）。这 6 条都是「用户可见的正确性/数据损失」，且修复工作量合计仅 M 级（除编排内核为 L）。
