# gaea 图像域（绘梦）长期规划 2026

> 状态：**长期路线（v1.1 草案）**。基线：gaea v4.97.0（2026-09-05）。
> v1.1 修订（2026-09-05）：补「模型中心」职责边界——模型中心是引擎与模型目录的
> 资源管理层，图像域消费其目录、不另立模型目录（见 §2.1）。
> 本文件是「绘梦 → gaea 图像能力域」的**长期权威路线**：定义最终态、目标体系、
> 版本主题线、轮子纪律、模型档位策略与滚动复盘机制。落地细节与最新调研见：

> 用户本轮补充（2026-09-05）：绘梦应是 gaea 的「图」核心——可识图、生图、改图；
> 图既服务小说（场景、封面），也服务办公（流程图、思维导图）；其它功能模块不自己

## 0. 一页读

**最终态（18 个月口径）**：gaea 内只有一个「图」出口——**图像能力域（Image Hub）**，
对外提供五类原语：识图-读、识图-懂、生图、改图、图示。小说、角色、轻语、办公、造价、
微信、阅读全部通过同一契约消费；各板块保留自己的领域模板/资产/上下文，但不再各自
私建引擎与渲染管线。乐园的「画室」是创作前台，工位的「配图/图示/识图」是工作前台，
共享引擎，隔离资产与记忆（双空间红线不变）。**模型中心继续担任引擎与模型目录的
资源管理层（共享），图像域与各前台只消费其目录与绑定，不另立模型目录。**

**北极星**：用户无论在哪一个板块产生「图需求」，得到的是同一套可溯源、可复用、
质量分层的图资产；gaea 的「内容 → 图 → 文档/作品」成为一条自然流水线。

**版本主题线（不锁死日期，锁顺序与完成标准）**：
契约 → 画室 v1 → 一致性 → 编辑力 → 叙事成篇 → 全域嵌入/资产化 → 动态化（评估制）。

## 1. 目标体系

### 1.1 总纲（一句话）

从「绘梦 = 乐园的一个生图页面」升级为「绘梦 = 全 gaea 的图像能力域 + 乐园画室前台」，
让**所有图需求只出自一套引擎、一套契约、一套资产底座**，再经不同前台服务不同场景。

### 1.2 目标分层

| 层 | 目标 | 完成判据（长期） |
|---|---|---|
| 能力 | 识图（读/懂）、生图、改图、图示四类能力齐备且分层可用 | 每类原语 ≥1 本地档 + ≥1 云端档；能力目录稳定 |
| 一体化 | 全模块图需求走同一契约，不再新增私有管线 | 新图需求 100% 走域契约；存量 4–5 条管线收敛为「1 契约 × N 前台」 |
| 资产 | 每张图可溯源、可复用、可跨场景引用 | 溯源覆盖率 100%（模型/参数/角色/后端/成本/时间戳/许可） |
| 体验 | 从「抽卡」到「画得出、改得动、攒得下」 | 一致性一次成图可用率 ≥70%；编辑占生成行为 ≥20%；正文到可用配图步数降 ≥50% |
| 红线 | 双空间隔离不被「共享引擎」破坏 | 审计抽检 0 例：工位/乐园资产与记忆互不自动注入 |

### 1.3 术语（本文件口径）

- **图像能力域（Image Hub）**：共享家底层的图能力总称——契约、引擎路由、资产溯源、
  模型档位目录。不是导航板块。
- **画室（play 前台）**：绘梦页在乐园的沉浸式创作工作台（生图/改图/识图/资产管理）。
- **前台（consumer front）**：各板块的图入口（小说配图按钮、办公图示工具、微信发图
  识图、造价 OCR 等）。
- **模型中心（资源管理层）**：引擎注册/健康、模型目录、能力与成本元数据、
  领域与空间绑定、用量统计的**唯一事实源**（现状：模型中心板块 +
  `feature_model_handler.go` / `model_router.go` 功能域绑定）。
- **原语（primitive）**：域对外的稳定能力单位。v1 定五个：识图-读 / 识图-懂 /
  生图 / 改图 / 图示。

## 2. 目标架构（概念模型）

```
前台层（只带领域上下文，不带引擎）
  乐园：画室（生图/改图/识图/我的素材）
  小说：章节配图 · 书封 · 角色剧照
  办公：图示工具 · 文档配图 · 识图/OCR 提取
  造价：报价单 OCR · 图表生成 · 指标图
  微信/语音：发图即识 · 一句话生图/改图（触点经指令中枢）
        │  只调用
        ▼
契约层（图像能力域 · 共享）
  五原语：识图-读 | 识图-懂 | 生图 | 改图 | 图示
  规范请求/响应 · 能力元数据（空间/后端/模型/成本）
  产物溯源登记 · 素材资产索引 · 插槽模板目录 · 模型视图（只读模型中心目录）
        │  档位与绑定来自模型中心
        ▼
资源/模型管理层（模型中心 · 共享）
  引擎注册与健康 · 模型目录（能力/成本/档位）· 领域与空间绑定
  用量/成本回报 · 视模型中心既有「功能域绑定」机制演进（imagegen 域纳入评估）
        │  按档位路由
        ▼
引擎层（既有 seam，原地保留、不重写）
  生图/改图：internal/ai 图片后端（ComfyUI 本地 + OpenAI 兼容云 + GLM…）
  识图-读：OCR 引擎链（PaddleOCR / MinerU / Ovis / tesseract…）
  识图-懂：vision 大模型（本地 Qwen 系 / 云端多模态）
  图示：Mermaid/代码渲染（diagram 工具、导图交互树、图表引擎）
  资产：文件存储（.gaea/play/exports、.gaea/work/exports…）+ SQLite/JSON 索引
```

**分层纪律**：前台可以有自己的模板、提示词、领域资产引用与 UX；**不允许**复制引擎
逻辑、绕过契约直连后端、私建渲染/OCR/生图管线。跨空间引用只走用户显式动作。

### 2.1 模型中心与图像域的职责边界（v1.1 补）

| 面 | 拥有 | 不拥有 |
|---|---|---|
| 模型中心 | 引擎注册/健康、模型目录与能力/成本标签、领域与空间绑定、用量统计 | 业务原语语义（识/生/改/图示）、创作资产、插槽模板、溯源登记 |
| 图像域 | 五原语契约、按原语路由与降级、素材/溯源、插槽模板、前台模型视图 | 引擎实现、模型目录事实源（只读模型中心） |
| 各前台 | 领域模板/提示词、领域资产引用、UX | 引擎、契约、目录、渲染实现 |

**协作规则**：
1. 画室与各前台展示的「模型档位/能力徽标/成本」一律读模型中心目录（图像域只加
   创作语境视图，如「该档位是否支持角色参考/中文文字」），**不在图像域内另存一份
   模型目录事实源**；
2. 图像域发起调用时，沿用模型中心的领域绑定与空间策略（现机制：功能域 model
   绑定 + play/work 各自策略）。**T0 已裁定（2026-09-05）**：feature 功能域绑定面向
   文本 LLM，绘梦/生图不属于该语义；图像选型沿用既有四级解析（显式 model →
   portrait 等领域覆盖 → image_backend/image_model → 引擎激活默认），模型中心只做
   目录 owner，不把 imagegen 强行塞入 LLM feature 域；
3. 每次调用把 后端/模型/耗时/成本 回给模型中心用量与画室「创作记录」（同一事件，
   两个视图），避免另起一套计量。

**一句话**：模型中心管「有哪些引擎/模型、什么能力、多少钱、绑给谁」；图像域管
「识/生/改/图示怎么组织成稳定原语给全 app 用」。二者是水平切面与垂直切面的关系，
不是竞争关系。

## 3. 版本主题线（长期路线）

> 每主题是一组小版本（gaea 按天发版的节奏下，主题完成以「验收清单全绿」为准，不
> 以自然月为准）。每个主题完成后做一次复盘门：对照 §6 指标 + 更新模型档位目录 +
> 决定下一主题刀序。主题顺序允许在复盘门后微调，但「契约」必须最先完成。

### T0 图像域契约（先做 · 1–2 个小版本）

**目标**：把散落的图入口统一到同一门面，行为不变，先立根。

- 定义五原语规范请求/响应与元数据（空间标签、后端、模型、成本、产物溯源）。
- 与模型中心对齐边界：明确「模型目录事实源在模型中心，图像域只持有模型视图」；
  评估 `imagegen` 功能域纳入模型中心领域绑定口径；定调用回报（用量/成本）事件。
- app 门面层新增「图像域协调入口」（建议先薄层，不抽包；调用方 >5 后再评估
  `internal/imagehub`）。
- 产物溯源登记最小集：每张图登记 模型/参数/角色引用/后端/成本/时间戳/许可提示，
  落 play 或 work 各自空间目录。
- 绑定面纪律：每刀独立提交可回退；drift PASS；Go/vitest 全绿。

**验收**：现有 4–5 条图管线可列出「所属原语 + 消费入口 + 模型绑定来源」对照表；
画室/办公/剧照展示的模型档位同源（读模型中心目录）；新模块按对照表接口即可入域；
零行为回归。

### T1 画室 v1（接着做 · 2–4 个小版本）

**目标**：画室前台成型，模型/成本可感知，消费方开始收口。

- 画室「创作资产」面板：角色槽/模板槽/近期作品（前端为主）。
- 模型目录分层展示：能力徽标 × 档位 × 成本**全部读模型中心目录**（图像域只做
  创作语境视图）；画室侧轻量「创作记录/消耗」与模型中心用量同源（不出现积分话术）。
- 章节配图/书封/剧照入口改走域门面（行为等价，回归保护）。
- 识图「读/懂」入口在画室可试用（粘贴图片 → 识别/理解）。

**验收**：三类模型档位可在一个界面比较；角色槽可选中并带出角色数据；
小说三入口无回归；识图结果与既有模型中心/微信路径一致。

### T2 一致性（核心护城河 · 3–5 个小版本）

**目标**：角色资产从「存图」变成「确定性人设复现」。

- 一致性参考槽：参考图（角色/风格/场景多张 + 权重）入生图请求；ComfyUI 工作流按
  模型族注入（krea2/z-image 先用 img2img 近似；flux 上 IP-Adapter/PuLID）；
  不支持参考的后端诚实降级。
- 角色资产 v2：角色三视图/多姿态设定卡生成；跨图一致性评分；角色画廊化管理。
- LoRA 训练向导（实验档）：本地 kohya/Inline-Studio 类工具装配，明确显存/时长门槛；
  不做云训练。

**验收**：同一角色参考图跨 5 个场景出图人设可辨识；低分图有提示与一键补参考；
LoRA 向导可完整走通一次（12GB+ 卡）。

### T3 编辑力（补行业最大代差 · 3–5 个小版本）

**目标**：从「重抽」到「修图」。

- 指令编辑 MVP（云端先行）：图 + 人话指令 + 可选保留语义 → Qwen-Image-3.0-Pro /
  GLM-Image 编辑；原图/新图对照 + 成本。
- 本地档（B 计划）：Qwen-Image-Edit / FLUX Kontext 工作流，按显存档位默认关闭。
- 蒙版局部重绘 + 扩图 + 抠图（canvas 圈选/笔刷；透明底 PNG 导出，对齐 NovelAI V5
  原生透明卖点）。
- 编辑历史形成「变体簇」（同源图关系），支持回到任一变体继续改。

**验收**：画室 80% 的「不满意」动作可走编辑而不是重抽；局部重绘不动圈外区域；
透明底立绘可导出并回填角色库。

### T4 叙事成篇（gaea 独有闭环 · 4–6 个小版本）

**目标**：正文 → 图 → 作品的一条龙。

- 章节场景识别 → 分镜清单（角色/动作/景别/构图）→ 角色一致故事板条，可重排/换角。
- 多角色同图实验（先 2 角色，对标 NovelAI V5 定位思路）；条漫/整页版式实验。
- 整书名场面批量配图 + 图文导出（HTML/Markdown；PDF 评估）；书封多方案 + 标题文字
  渲染验证。
- 画室素材库：章节插图列表（重生成变体/替换/设为封面素材），全部带溯源。

**验收**：一部 30 章小说可在画室产出「角色一致全书插图包」；每张图可追溯回源章节与
角色；图文导出可读可交付。

### T5 全域嵌入/资产化（一体化的兑现 · 持续演进）

**目标**：工位与触点侧真正长到同一根上。

- 办公：文档配图/示意图经域生成与溯源；docx/pptx 图资产嵌入统一走登记后的文件；
  图示（流程图/导图/架构图）导出图统一登记。
- 造价：报价单 OCR、指标图/图表经域路由（复用既有 OCR 与图表链，只收口契约）。
- 微信/指令中枢：发图即识、一句话生图/改图回推图片卡片（iLink 协议成熟后）。
- 轻语（显式门）：角色表情/头像集经画室资产派生，仅用户显式允许时联动。
- 素材库资产化：个人作品集 + 版权留痕导出（AI 标记/参数/来源/许可提示）；
  可选模板/工作流文件交换（不做公共模型社区）。

**验收**：新建模块的图需求无需新增管线即可交付；交付图全部在域内可查来源；
工位与乐园资产隔离抽检 0 违规。

### T6 动态化（评估制 · 不锁承诺）

**目标**：图 → 视频/动态的延伸，只做「云端/远端先行、本地跟进」的档位。

- 图生视频（i2v/首尾帧/运镜参数）：云端 Wan/qwen 先行；本地 LTX 档跟进。
- MiniMax H3 级多模态远端档评估（参考素材多模态路由，属重档，不默认）。
- 「动态立绘/角色表情集」仅在 T5 轻语显式联动立项后评估。

**验收**：任一动态能力进入画室前先过「显存/成本/延迟/版权」四道闸，避免个人桌面
被重档模型拖垮。

## 4. 轮子纪律（不自己造轮子的制度化）

### 4.1 准入（新增图需求必须走）

1. 填**域契约申请**：原语（识读/识懂/生图/改图/图示）+ 输入输出 + 资产类型 + 空间标签；
2. 优先复用既有原语/模板/引擎档位；确需新原语时先评审「是否已有等价能力」；
3. 领域差异只允许体现在：模板、提示词、资产引用、UX、模型档位选择。

### 4.2 禁止

- 板块内私建生图/OCR/vision/渲染管线（含复制粘贴引擎代码后改参数）。
- 绕过域门面直连 `internal/ai` 后端或 OCR seam（存量逐步迁移，新代码零容忍）。
- 在模型中心之外另建模型/引擎目录事实源（图像域只允许只读视图 + 创作语境标注）。
- 把 play 角色/作品资产自动注入 work 上下文（红线，无例外）。

### 4.3 允许

- 板块保留自己的提示词库、插槽模板、领域元数据与展示形态；
- 本地引擎/云端 API 等实现层继续按各自 seam 演进，域只做契约与路由；
- 用户显式发起的跨空间产物引用（如「把画室封面放进报告」）。

## 5. 模型档位目录策略

> 本节描述的是**图像域视角的档位策略**；目录事实源在模型中心（§2.1）。T0 需与模型
> 中心对齐字段：档位/能力标签/单价/可用性/许可提示。

### 5.1 档位结构

| 档位 | 例子（2026-09 调研） | 用途 | 显示口径 |
|---|---|---|---|
| 本地免费 | ComfyUI：krea2 / z-image / flux（按模型族） | 高频、隐私、离线 | 0 元 |
| 云端旗舰 | Qwen-Image-3.0-Pro（约 0.18 元/张）、GLM-Image（0.1 元/张） | 编辑、复杂版面、中文文字 | 按张单价 |
| 免费兜底 | CogView-3-Flash 等免费档（若可用） | 试玩/降级 | 0 元 |
| 远端重档 | MiniMax H3 / 大视频（本地不可行档） | 评估制、不默认 | 明确标注 |

### 5.2 换代纪律

- 能力原语与模板**绑定档位而非绑定模型**；模型换代只换目录条目，不动契约。
- 半年一换代是常态：每次社区/GitHub 复扫更新目录，新模型先以「Beta 档位」上线，
  真机验收后再转正。
- 本地档新增能力（编辑/多参考/视频）以显存档位为闸，不做「默认全量下载」。

## 6. 跟踪与复盘机制

- **轻扫（每 2 周）**：模型新版本/社区热帖快照，只更新档位目录与事实，不改路线。
- **深扫（每 1–2 月）**：复跑外部调研主线（云端旗舰编辑能力 / 一致性方案 / 本地
  工作流生态 / 网文配图与版权），产出回填到本文 §1 调研参照与档位表。
- **主题复盘门**：每个 T 主题完成后对照 §1.2 指标 + 验收清单，决定下一主题刀序
  是否微调；重大外部拐点（如本地编辑模型成熟、某旗舰免费化）可插队评审。
- **量化口径**：一致性可用率、编辑占比、配图渗透率、溯源覆盖率、空间隔离抽检
  零违规——数据缺口的先补埋点，不拍脑袋。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 图像域成关键路径，质量/成本/排队问题被放大 | 分层档位 + 空间任务分账 + 失败降级链 + 成本可见 |
| 模型半年一换代 | 档位目录制，契约不绑模型 |
| 一体化诉求滑向大爆炸重构 | 契约先行薄层、引擎不搬、消费者渐进迁移 |
| 共享引擎破坏双空间红线 | 域 = 共享家底；资产/记忆仍按空间隔离；审计抽检 |
| 「统一」变成把稳定实现推倒重来 | 只统一入口与元数据；OCR/vision/生图引擎原地保留 |
| 版权/合规 | 参考图仅用户自有；模型许可提示；不做公共模型社区 |
| 范围蔓延（什么都想进画室） | 原语增减需评审；非图资产不进域 |

## 9. 当前待确认（进入 T0 前）

沿用上轮三点建议作为基线，仍可改口：
1. 图像域先落 app 门面薄层（不抽包、不搬引擎）；
2. 识图收编为「读/懂」两原语入口，实现链原地保留；
3. 办公思维导图保持办公原生，只登记导出图资产。
4. **模型中心继续作为引擎/模型目录唯一 owner；图像域只持模型视图（T0 落边界协议，
   T1 展示同源验证）**。T0 裁定：不把 imagegen 塞入 LLM feature 域，图像选型走既有
   四级解析 + 模型中心目录（v1.1 补，2026-09-05 T0 细化）。

另建议确认 T 线顺序：**契约 → 画室 v1 → 一致性 → 编辑力** 前四主题优先；
叙事成篇/全域嵌入随前序完成后滚动排期。
