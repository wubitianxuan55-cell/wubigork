# 市场调研：AI 办公「开工前」——文件交互与调研启动，2026-08

> 目的：前几轮调研覆盖了「解析/编辑/输出/交付/记忆」，都是任务进行中和收尾阶段。
> 本轮聚焦**开工前**：任务发出后、AI 动手前，文件怎么进入、AI 怎么建立业务上下文、
> 怎么调研/搜索/选工具。来源为 2026 年公开资料与实测报道。

## 0. 一句话结论

行业共识是「AI 项目的第一步不是下指令，而是建立业务上下文」（七步法 / 上下文工程）。
2026 年头部产品在开工前普遍做四件事：**① 工作区/文件夹授权与绑定；② @ 按需加载文件
（而非全量塞进上下文）；③ 先提交研究计划再动手（plan 可见、可确认）；④ 语义/全文搜索
定位资料（RAG）**。gaea 已有拖拽/粘贴/@引用/工作区切换/能力卡/slash 命令，缺的是
「开工前的上下文装配与可见规划」：把「要读哪些资料、用哪些工具、按什么步骤」在动手前
亮给用户确认，以及用搜索而不是翻目录来定位资料。

## 2. 可蒸馏的优点清单（映射到 gaea）

1. **开工前先交研究计划**：WorkBuddy Plan 模式与「正式调研前先提交研究计划」、千问办公
   「先拆步骤再逐项打勾」——任务发出后先把「做什么、读什么、用什么工具、按什么顺序」
   亮出来，用户确认再执行。gaea 有 SingleModelPrompt「先规划再执行」和 auto-plan 评分，
   但规划只出现在推理流里，没有「计划卡片 + 确认」的交互。
2. **@ 按需加载 + 本地文件列表**：WorkBuddy 敲 @ 唤起文件列表；Claude @filename 只加载
   该文件、可 pin 常用文件。gaea 已有 @ 解析（文件/目录/MCP/图片）与文件树选择，缺
   「跨目录搜索 + 最近使用文件 + 按扩展名过滤」的 @ 菜单。
3. **工作区授权与资料盘点**：千问办公选文件夹即授权（读/建/执行），aily 关联企业知识，
   Claude Cowork 用文件夹+文件做项目上下文。gaea 有工作空间切换，但切换后没有
   「工作区资料概览」——docx/xlsx/pdf 清单 + 一键引用。
4. **搜索定位资料，而不是翻目录**：Cursor 语义+词法索引、Cherry Studio 本地向量库、
   aily 拆关键词双检索+重排。gaea 只有 memory_search 关键词索引和 read_file/ls 手动浏览，
   无工作区全文搜索（找「哪份资料里提过 XX」要问模型或翻文件）。
5. **上下文工程（装配而非灌输）**：飞书「上下文字段」、aily 按人物/日程组织上下文、
   Claude Projects 知识库预载、Cherry 检索即上下文——开工前把「相关的」装进来，
   而不是把整个文件夹塞进 prompt。gaea 的 Compose 已装记忆/事实/作业笔记，缺
   「任务相关文件自动装配」的显式阶段。
6. **任务模板与快捷入口**：千问办公预置任务模板/定时任务、WorkBuddy 常用指令模板。
   gaea 有 slash 命令 + 欢迎页能力卡，可深化为「常用任务模板库」。

## 3. gaea 现状盘点（基于代码，2026-08-10）

### 已具备
- **文件进入**：Composer 拖拽文件（图片存 `.gaea/uploads` 并生成缩略图附件，非图片
  base64 上传保存 + `@路径` 引用）、粘贴图片、附件按钮（GaeaPickFiles 原生对话框）、
  粘贴表格即数据（本轮已落地）、@ 引用（文件/目录/MCP 资源/图片附件，ResolveRefs 解析
  后作为 Referenced context 注入）。
- **工作空间**：GaeaPickWorkspace / GaeaSwitchWorkspace 切换工作区；基础工具相对路径
  基于工作区（read/write/bash/ls）。
- **任务理解**：Welcome 6 能力卡 + 技能 chips（点击填 prompt）；slash 菜单（命令/技能）；
  ask 工具结构化澄清；SingleModelPrompt「规划 → 调研 → 执行 → 验证 → 签退」纪律；
  auto-plan 复杂度评分（不可见）。
- **调研/工具**：17 个内置工具（read_file / write_file / ls / bash / bash_output /
  kill_shell / wait / web_search / web_fetch / todo_write / complete_step /
  memory_search / knowledge_add / knowledge_search / read_skill / format_convert /
  chart_gen）+ OCR / vision / screen_capture / remember 等；CapabilitiesPanel
  （MCP 连接器 + 技能抽屉）；工具调用在聊天里以卡片呈现；推理区展示思考过程。
- **搜索**：memory_search（关键词索引，含事实/文档）、knowledge_search（知识库）、
  web_search / web_fetch（联网）；招标解析（方案编写模块）是垂直场景的「资料进来自动拆解」。

### 缺失（本轮差距）
- 无「开工前计划卡片」：规划结果不展示为可确认的步骤/资料/工具清单。
- @ 菜单无搜索/最近使用/扩展名过滤（只有目录浏览）。
- 切换工作区后无资料概览（docx/xlsx/pdf 清单 + 一键引用）。
- 无工作区全文/语义搜索（找资料靠 read_file/ls 手动翻或问模型）。
- 无「项目常用资料」固定装配（Claude Projects 知识库/aily 关联知识的本地版）。

## 5. 设计决策与强化清单（映射 gaea）

### P0 开工前上下文装配（先做）
1. **开工前计划卡片**：任务发出后（auto-plan 阶段）把规划结果渲染为「计划卡片」：
   步骤清单 + 将读资料 + 将用工具 + 待确认问题；用户可「确认开干 / 修改再开 / 改问」。
   落点：控制器把 auto-plan 输出作为结构化事件（plan 事件）发给前端，前端渲染确认卡；
   对标 WorkBuddy Plan 模式 / 千问办公任务清单。
2. **@ 文件引用增强**：@ 菜单支持跨目录搜索（工作区文件树 + 关键词过滤）、最近使用文件
   （按会话内引用/打开排序）、按扩展名分组（文档/表格/PDF/图片）；对标 WorkBuddy @
   文件列表 + Claude 按需加载。前端 FileMenu 增强，后端补 GaeaFileSearch（工作区关键词
   列出文件名匹配）。
3. **工作区资料概览**：切换/首次进入工作区时列出「资料」视图（docx/xlsx/pdf/md/csv 按
   类型分组 + 最近修改排序），每条可一键「@引用为上下文」；对标千问办公选文件夹后读资料、
   aily 关联知识。复用文件树数据，前端加过滤与分组。

### P1 深化
4. **工作区全文搜索（轻量 RAG）**：SQLite FTS5 索引工作区文本文件（标题/正文/表格），
   提供「工作区里找资料」入口，命中片段可一键引用；对标 Cursor / Cherry Studio 的本地
   索引，先做关键词/分词，向量检索按需再上。
5. **项目常用资料装配**：把常用资料「钉」为项目知识（对标 Claude pin / Projects 知识库），
   新会话自动进入上下文；knowledge 库与对话装配打通。
6. **任务模板库**：欢迎页能力卡 + slash 命令升级为「模板库」：常见任务（周报/会议纪要/
   成本测算/方案大纲）一键填入结构化指令；对标千问办公预置任务模板。

### 明确不做
- 云端知识库、团队共享上下文（个人工具定位）；
- 把整个文件夹全量塞进 prompt（坚持 @ 按需加载 + 检索装配）；
- 企业级权限/审计（同前几轮）。

## 6. 落地优先级建议

- **本轮优先（P0）**：① 开工前计划卡片（规划 → 确认 → 开干）；② @ 文件引用增强
  （搜索 + 最近使用 + 扩展名分组）；③ 工作区资料概览（一键引用）。
- **其次（P1）**：工作区全文搜索（FTS5）、项目常用资料装配、任务模板库。
- **明确不做**：云端/团队上下文、全量塞上下文。

## 7. 结论

gaea 的开工前入口（拖拽/粘贴/@/工作区/能力卡/slash）已经齐全，与 WorkBuddy、千问办公
的差距集中在「**动手前的可见与可控**」：把 AI 的调研计划亮出来让用户确认（计划卡片）、
把文件的进入从「翻目录」升级为「搜一下/最近使用」（@ 增强）、把工作区的资料变成可一键
装配的上下文（资料概览）。这三件事都复用现有 ResolveRefs、文件树、auto-plan、Compose
装配底座，本地完成、零外部依赖——做完后 gaea 就从「下完指令等结果」升级为
「先对齐计划、再让 AI 干活」，正好承接前几轮交付与记忆闭环。
