# 市场调研：AI 办公「成本库」与办公/记忆中枢打通，2026-08

> 目的：为 gaea「通用办公与记忆中枢成本库打通」提供设计依据。记忆中枢已有成本库
> （Hephaestus.db cost_entries + CostLibrary 面板），办公板块已有 cost-estimate 任务
> 模板与 xlsx 测算能力，但两者互不相通：测算时 AI 不知道成本库里有什么单价，做完的
> 测算也不会沉淀回成本库。本轮调研行业如何做「成本/单价数据」的沉淀、检索与任务内
> 引用（对标造价行业广联达、WPS/腾讯/飞书智能表格、千问办公、M365 Copilot 等）。
> 来源为 2026 年公开资料与官方文档。

## 0. 一句话结论

2026 年行业对「成本数据」的共识是**把它当成一个独立的结构化数据中枢，而不是塞在
对话或文档里**：① 造价行业标杆广联达把历史组价/材料价格沉淀为「企业数据」库，
新项目 AI 自动匹配历史组价、输入材料名即推荐相似材料、价格来源清清楚楚（组价效率
翻倍、调价从 1-2 天压缩到 2 小时）；② 通用办公侧，千问办公提出「文档知识库、AI
表格，沉淀即调用」，WPS/腾讯/飞书的智能表格把「关联字段/引用字段/业务对象检索」
做成表格的一等公民；③ 所有产品都强调**数据可溯源**（M365 内联引用、广联达载价
来源、飞书知识问答注明出处）与**可编辑**（成本库要能改、能归档，不能只增不减）。
对 gaea：成本库打通 = ① 办公 agent 原生可查成本库（测算前锚定单价）→
② 测算产出可一键沉淀回成本库（沉淀即调用）→ ③ 前端给用户可见的浏览/插入入口，
与「@ 按需加载 + 记忆自动做梦」的上下文纪律一致。

## 2. 可蒸馏的优点清单（映射到 gaea）

1. **测算前先查成本库（数据找人）**：广联达新项目自动匹配历史组价、AI 询比价锁定
   报价区间——AI 动手测算前先检索成本库锚定单价，而不是凭印象估价。gaea 现在
   cost-estimate 模板完全不提成本库，agent 也没有查询工具。
2. **沉淀即调用（办公→记忆）**：千问「沉淀即调用」、广联达「云存档让旧工程成为
   企业资产」、飞书咨询记录写回多维表格——一次测算/一次询价的单价应该回流成本库，
   供下次测算直接复用。gaea 做完测算的 xlsx 没有任何回流通道。
3. **成本库是结构化对象，可编辑可归档**：成本条目带名称/标题/分类/单位/单价/规格/
   来源/状态（现行/草案/已归档），记忆中枢 CostLibrary 已具备——但要变成办公任务
   的一等资源：可检索、可插入上下文、可被 agent 写入。
4. **来源可溯**：广联达载价来源清楚、M365 内联引用、飞书问答注明出处——成本库必须
   带来源（定额/市场询价/历史项目/本次测算文件），AI 引用时能交代依据。
5. **结构化输入纪律**：ChatGPT 表格工程先给表头+样本值、WPS/腾讯把表格作为数据
   中枢——成本库进上下文时应是紧凑的结构化行（名称/单价/单位/规格/来源），而不是
   整库灌入。
6. **相似匹配（P1）**：广联达输入材料名推荐相似材料（PE管/聚乙烯管）——成本库可按
   名称/规格模糊匹配与别名推荐，避免「换了个叫法就找不到价」。

## 3. gaea 现状盘点（基于代码，2026-08-10）

### 已具备
- **成本库（记忆中枢扩展库）**：Hephaestus.db `cost_entries` 表（SchemaV2，
  `internal/gaea/db/schema.go:67`）；`internal/gaea/cost` 提供 Save（同名 UPSERT）/
  Get/Delete/List/Search（关键字 LIKE 标题/规格/来源/正文 + 分类/状态过滤）；
  App 层绑定 GaeaCostList/Search/Get/Save/Delete（`internal/app/memory_hub.go`）。
- **成本库前端管理**：记忆中枢 CostLibrary 面板（搜索/分类/状态筛选、新建/编辑/删除
  Modal，字段含 分类/单价/单位/规格/来源/标签/状态/备注）。
- **办公测算能力**：cost-estimate 任务模板（`internal/app/gaea_templates.go`，生成
  xlsx 成本测算表：科目/单位/数量/单价/金额公式 + 原生图表）；xlsx 预览/编辑/导出
  链路（xlsxpreview/xlsxedit/XlsxEdit 等）；办公板块右侧面板已有 文件/资料/搜索/产物/
  统计 五个 Tab。
- **上下文纪律**：@ 按需引用 + summarize_file + 固定资料自动装配 + 自动做梦
  （记忆自进化）——为「成本库进上下文」提供了现成装配底座。

### 缺失（本轮差距）
- **办公 agent 无成本库工具**：工具集里没有 cost_search / cost_save，测算时模型
  无法读取成本库，也无法把结果写回——成本库与办公板块完全隔离。
- **模板未接线**：cost-estimate 模板 prompt 未引导「先查成本库、做完沉淀成本库」。
- **办公板块无成本库入口**：右侧面板没有成本库浏览/搜索/插入；用户只能在记忆中枢
  页管理，切到办公页就看不见。
- **产出→沉淀无闭环**：测算生成的 xlsx 没有一键「沉淀为成本库」的入口或指令。
- **概览未统计成本库**：MemoryHubOverview 只有 knowledge/profile/office/whisper/
  pinned 计数，无 cost 计数（记忆中枢首页看不到成本库规模）。

## 5. 设计决策与强化清单（映射 gaea）

### P0 成本库打通核心（先做）
1. **办公 agent 原生成本库工具**：内置 `cost_search`（关键字/分类/状态过滤，`name`
   读取完整条目含备注）与 `cost_save`（新建/更新成本库，字段与 CostLibrary 对齐）——
   复用 cost.Store，办公板块（gaea 聊天）测算时即可查单价、完成后可写回成本库。
   对标广联达 AI 组价匹配企业数据、千问「沉淀即调用」。
2. **cost-estimate 模板升级**：prompt 增加两步——① 先调 cost_search 以成本库单价为
   测算依据（缺失科目与用户确认或合理估价）；② 测算完成后用 cost_save 把本次采用的
   可复用单价沉淀为成本库，来源标注本次项目/文件。对标广联达云存档「让旧工程成为
   企业资产」。
3. **办公右侧「成本库」Tab（CostCardsPanel）**：与资料/搜索/产物并列——搜索/浏览
   成本库（复用 GaeaCostSearch），一键「插入上下文」（结构化行进入输入框），状态
   徽标；编辑仍留在记忆中枢（避免重复造管理 Modal）。对标 WPS 智能表格关联引用、
   飞书业务对象检索。
4. **产物面板「沉淀为成本库」**：会话产物里的 xlsx/csv 行悬停增加动作，把
   「请将 [文件](路径) 的单价明细用 cost_save 沉淀为成本库（来源标注该文件）」插入
   输入框，由 agent 执行——办公产出一键回流。对标飞书咨询记录写回多维表格。
5. **记忆中枢概览加 CostCount**：MemoryHubOverview 增加成本库计数，首页可见成本库
   规模（低成本、与 PinnedCount 同模式）。

### P1 深化
6. **成本库结构化装配**：插入上下文时输出紧凑结构化行（名称/标题/分类/单价/单位/
   规格/来源），多条合并为「成本库清单」块，避免整库灌入（对标 ChatGPT 表格输入
   纪律）。
7. **来源可溯**：cost_save 沉淀时强制要求 source（本次项目/文件），卡片展示来源；
   测算引用成本库时正文说明依据哪张卡（对标 M365 内联引用）。
8. **相似匹配与别名**：cost_search 增加名称/规格模糊匹配与 tags 别名命中
   （对标广联达 PE管/聚乙烯管相似推荐）；先在 SQL LIKE 基础上做拼音/子串，向量按需
   再上。

### 明确不做
- 企业级定额库、清单计价引擎、广联达式组价（个人工具定位，只沉淀/引用单价卡片）；
- 云端同步与团队共享成本库（本地优先）；
- 自动把测算结果无确认写入成本库（沉淀须经 agent 执行或用户一键触发，遵守
  Kimi 二问纪律：先判断是否值得沉淀，避免噪音）。

## 6. 落地优先级建议

- **本轮优先（P0）**：① cost_search / cost_save 工具（办公 agent 读写成本库）；
  ② cost-estimate 模板接线（先查后沉淀）；③ 办公右侧「成本库」Tab（浏览/插入）；
  ④ 产物面板「沉淀为成本库」；⑤ 记忆中枢概览 CostCount。
- **其次（P1）**：成本库结构化装配与来源标注；相似匹配与别名；测算表自动解析入库。
- **明确不做**：企业级组价/定额引擎、云同步、无确认自动写入。

## 7. 结论

行业把「成本数据」当作独立结构化中枢来经营：广联达靠「企业数据 + AI 匹配」把组价
从翻定额变成双击复用，千问/飞书/腾讯把「表格沉淀、关联引用」做成办公一等公民，
共同点是**双向打通**——测算任务先引用库里已有的单价（数据找人），完成后的新单价
再沉淀回库（沉淀即调用），且全程来源可溯、可编辑可归档。gaea 的成本库（cost_entries
+ CostLibrary）已经是现成的结构化中枢，缺的只是办公侧的「接口」：agent 工具
（cost_search/cost_save）、模板接线、前端入口（成本库 Tab + 产物沉淀按钮）与概览
计数。五个 P0 全部复用现有 cost.Store / xlsx / 产物面板 / 右侧 Tab 基建，本地完成、
零外部依赖——做完后，gaea 就从「每次测算都凭感觉估价」升级为「越测越准：单价沉淀
进记忆中枢，下次直接引用」，正好承接记忆自进化（自动做梦）与上下文装配（@ 按需
加载）两轮已经打好的底子。
