## 一、双市场结论（国际 PM × 国内建筑进度）

1. **AI 产建议、确定性引擎裁决的三层分工已被两个市场同时验证**。国际线：Smartsheet text-to-formula（AI 写公式→引擎求值→报错回传）是最干净的范式；国内线：广联达斑马 AI 助手（推荐逻辑关系/推荐工作包→写入计划表）是同领域对标。gaea 的对应：AI 只产结构化字段（任务/工期/搭接/日历），可行性与环检测一律由 CPM 引擎裁决，拒绝即把错误原文回传给模型修复。
2. **「AI 生成进度计划」的产品口径收敛为四要素**：任务+WBS+依赖+工期（Ingantt 最完整，NL 一句话生成后按 as-is / tweak / from scratch 三选一确认）；Microsoft Planner Copilot 只产标题骨架不排日期（反面参照：生成深度不足等于没有）。gaea 引擎已备齐搭接/日历/关键路径，生成深度可以直接做到 Ingantt 以上。
3. **对话式调整在 PM 域是安全空白**：所有 PM 竞品均无 diff 确认流；成熟范式只在编码 copilot（preview diff → confirmation gate → 一键 revert，VS Code/Copilot 口径）。Devin 的「派活-执行-PR diff 验收」三段式是组织化范本。**gaea 可在此自定义标准**（本就有的快照+证据卡+回滚底盘直接复用）。
4. **斑马 AI 助手 11 项功能 = schedule_analyze 的需求清单**：其中「AI 计划检查」（质检式：错漏+修改意见）与「AI 分析报告」（叙事式：多维风险）应做成两个独立输出模板；「推荐逻辑关系」是编制环节最高痛点，gaea 引擎已能验证推荐结果，低风险可做。
5. **反面教训**：斑马行内 AI 补全关不掉被用户痛骂——一切 AI 建议必须可一键全局关闭；Genspark 类通用 agent 只能产文档产物无结构化回流——「计划落结构化模型」正是 gaea 差异化；Devin/monday 证明「无人工干预改计划」仍不可信，人工确认不可省。

## 二、已按调研落地的刀4 口径

- **工具三件套** `schedule_get / schedule_apply / schedule_analyze`（internal/gaea/tool/builtin/schedule_tools.go）：
  - apply 按**字段/批量原语**设计（ops=upsert_task/patch_task/remove_task/set_links/set_meta），整计划生成走 project 通道——正是蒸馏点 1 的「字段级粒度」；
  - 环检测/悬空引用/非法字段 **fail-closed**，错误原文回传（引擎裁决）；
  - apply 回执带**写入后总工期与关键工作数**，工具描述强制模型核对（「成功≠正确」verify 纪律）；
  - analyze 输出=**质检 findings（规则子集）+ 关键链/近关键/里程碑叙事数据**（蒸馏点 4 的两个模板的确定性底座，LLM 润色在其上）；
  - 快照（StageBaseline）+证据卡（RecordChange tool=schedule_apply）+写根 confine，与 write_file 同纪律。
- **板块文件化**：`进度计划/当前计划.gsched.json` 板块与 agent 共读写（GaeaScheduleLoad/Save 轻量 IO 无证据卡，UI 自动保存不刷 Journal）；板块 15s 可见轻扫+focus 回读 agent 改动。
