# 通用办公板块云端/本地分工梳理与缺陷清单，2026-08

> 目的：按「云端模型负责统筹与思考，本地模型/本地软件负责常规解析、识图、
> 出图、索引」的原则，盘点通用办公板块（gaea）当前的实际分工，找出与原则
> 的偏差、缺陷和遗漏，给出落地路线。依据代码盘点（2026-08-10）。

## 0. 一句话结论

大方向已经对：**文件解析、编辑、转换、索引、OCR 基本都在本地**（excelize、
docmd、OvisOCR2 本地 llama-server、Windows OCR、BM25/TF-IDF、本地 rerank），
**云端只做 agent 统筹与生成类推理**。但存在五处系统性偏差：① 没有统一的
「常规→本地、思考→云端」路由层，办公功能模型默认绑云端，本地 35B Qwen 闲置；
② 视觉/OCR 链路云端优先（免费云竞速池跑在本地视觉前面）；③ 出图默认云端 xAI，
本地 ComfyUI/Herdsman 要手动切；④ 大文件摘要、成本导入 AI 归一化这类「常规不
思考」的活默认走云端烧 token；⑤ 本地语义索引缺一块（bge-m3 embedding 未装、
跨库统一检索无语义层）。另有调度/批处理、健康检查、敏感数据通道等结构性遗漏。

## 2. 与「本地优先」原则的偏差（缺陷）

### D1 无统一「常规→本地、思考→云端」路由层 ⭐
现状只有 per-feature 模型绑定（routeModel：功能绑定 → 全局活跃 → 兜底），
「常规」与「思考」共用同一模型选择。本地 Qwen3.6-35B 已装（Herdsman），但
docx/xlsx 编辑指令、摘要、导入归一化这些不需要深度思考的任务默认还是走云端。
缺一个 `routine` 功能域或全局「本地优先」开关：常规任务绑本地、云端兜底。

### D2 视觉/OCR 链路云端优先 ⭐
agent 侧 ds-vision-skill 的降级链是 `race(agnes, glm, glm-thinking) → custom → local`，
即免费云竞速池跑在本地视觉之前；纯 OCR 也是 `baidu-ocr → windows-ocr`。与
「常规识图本地化」相反。应调整为 `local(Herdsman Qwen3.6) → Windows OCR（纯文字）
→ MinerU（文档）→ 云竞速池兜底（复杂视觉推理）`。

### D3 出图默认云端
imagegen 默认后端是 xAI；本地 ComfyUI / Herdsman / Ollama 需要手动配置。常规
配图/封面（非精修）应「本地优先、云端兜底」。

### D4 常规生成类任务烧云端 token
- 大文件摘要：summarize_file 的 map-reduce 全程走 office 功能模型（云端），
  本地 35B 足以做分块总结。
- 成本导入 AI 归一化：GaeaCostImportAIParse 走 office 模型（云端），字段归一化
  是典型「常规不思考」任务。
- 编辑指令生成（docx/xlsx edit）也走云端——可接受，但低频简单编辑可本地化。

### D5 本地语义索引缺一块 ⭐
检索已分层（子串 → BM25 → 本地 rerank），但：
- 无本地 embedding（bge-m3 未装），跨库语义召回（记忆/知识/成本/资料一次找齐）
  目前只有 BrainSearch 关键词 + 工作区全文，没有语义层；
- FTS5 未上（数据量更大时 Go 侧线性过滤是瓶颈，规划内未做）。

### D6 调度/批处理基建薄弱 ⭐
- 只有价格源 cron；无通用任务调度器（夜间索引重建、批量 OCR、定时归档等）。
- 价格抓取是同步绑定，页面可能阻塞数秒；无任务队列 + 进度事件（bgjobs 只管
  bash 后台命令）。

### D7 无「本地优先」配置入口与成本可见性
- 没有全局开关「常规任务本地化」；
- stats 有 token 统计，但没有本地/云端分流统计与节省对比，用户无法感知切换收益。

### D8 敏感数据无策略
成本/报价这类商务敏感数据，AI 归一化、测算模板默认走云端；没有「敏感域默认
本地（Herdsman）」的通道与提示（对本地优先用户是隐私顾虑）。

### D9 本地服务健康与降级
- Herdsman 模型有 stopped/error 状态，但没有健康检查面板、自动拉起（OvisOCR2
  有拉起逻辑，视觉/rerank 没有）与云端降级编排；
- rerank 失败会静默回退，用户不可见。

## 3. 功能遗漏（常规任务本地化视角）
1. **PDF/图片报价单本地识别入表**：成本导入只支持 xlsx/csv 确定性解析；PDF/图片
   报价单要 AI 解析（且走云端）——本地 MinerU 表格结构识别 + 本地视觉归一化的
   链路未打通（调研 P1 项，未实现）。
2. **票据/截图识别即入表**（飞书式）：附件识图 → 成本条目预览 → 确认入库，未做。
3. **通用批处理队列**：长任务（批量 OCR、索引重建、批量导入）无后台任务 + 进度
   事件（对比价格抓取同步阻塞的问题）。
4. **跨库统一语义检索**：记忆/知识/成本/资料 4 库一次找齐目前是关键词级，语义级
   缺 embedding。
5. **本地服务面板**：Herdsman / Ollama / OvisOCR2 / MinerU 的运行状态、模型
   加载、失败原因一个面板可见并一键拉起。

## 4. 建议路线图

### P0（低成本高收益，先做）
1. **统一 routine 路由**：新增 `office-routine` 功能域或全局「本地优先」开关；
   摘要、导入归一化、简单编辑指令默认绑本地引擎（Herdsman Qwen3.6-35B），
   云端兜底；模型中心一键切换 + 前端可见。
2. **视觉链路本地优先**：vision-router 顺序改为 local → Windows OCR → MinerU
   → 云竞速池兜底；纯 OCR 直接 Windows OCR 优先。
3. **出图本地优先**：ComfyUI/Herdsman 可用则用，xAI 兜底。
4. **敏感数据通道**：成本/报价相关 AI 操作默认本地，可配置回云端。
5. **本地服务健康检查**：Herdsman/Ollama/OvisOCR2/MinerU 状态 + 自动拉起 +
   降级提示（rerank 失败可见）。

### P1
6. **通用调度器 + 批处理队列**：任务表 + 事件进度；价格抓取/批量 OCR/索引重建
   全部异步化。
7. **bge-m3 本地 embedding + 跨库统一语义检索**（记忆/知识/成本/资料）；数据量大
   后上 FTS5。
8. **本地/云端分流统计**：token 节省与耗时对比面板。

### P2
9. **PDF/图片报价单本地识别入表**：MinerU 表格结构 + 本地视觉归一化 → 预览确认。
   ✅ **已交付（2026-08-14 v2.23.0 T5-5）**：GaeaCostImportVisionPreview（docmd 文本提取 /
   本地 OCR（OvisOCR2→Windows OCR）+ 表格线启发式解析 + sensitive_local 本地视觉/常规模型
   归一化 → 候选预览确认入表，无确认不落库）。
10. **票据批量入表与比价工作流**（供应商维度）——比价已交付（v2.23.0 GaeaCostCompare +
   前端比价弹层）；票据批量入表（多文件队列化）仍为候选。

## 5. 结论

通用办公板块的底座已经符合「本地干活、云端思考」：解析/编辑/索引/OCR/图表/
语音全部本地，agent 统筹走云端。真正的差距不在能力而在**路由策略**——本地
模型装好了（Qwen3.6、bge-reranker、OvisOCR2、MinerU）但没有按任务性质分流，
常规任务仍在烧云端 token；加上调度、健康、语义索引三块结构性短板。P0 五项
都是配置与路由调整（新增 routine 域、视觉/出图顺序、敏感通道、健康检查），
复用现有本地服务，不改架构即可显著降低成本与隐私暴露。

## 6. 用户方向确认（2026-08-10，覆盖上文部分建议）

- **核心目标：尽量免费**。云端免费额度可用（视觉竞速池 GLM/Agnes、免费 OCR 等
  保持现状）；本地模型是零成本主力，云端付费只用于必要的思考/出图。
- **出图顺序：先 XAI，再 Herdsman**。不改为本地优先（上文的 D3/路线图③作废），
  imagegen 保持 XAI 默认、Herdsman 可配置回退。
- **不固化「常规→本地、思考→云端」路由层**（上文的 D1/路线图①作废）。由云端
  大模型在统筹时按需决定调用哪些工具；本地能力（摘要、归一化、识图、检索精排、
  语义召回）作为工具就绪、云端可选调度，不做强制分流策略。
- **bge-m3 已安装**：本地语义召回已接入（成本搜索关键词召回不足时自动补召回，
  纯本地零 token；见 `retrieval.Embedder` + `SemanticRecall`）。
- 路线图按此修订：P0 = 本地能力工具化就绪（语义召回✅、rerank✅、健康检查、
  敏感通道可选）＋ 调度/批处理异步化；P1 = bge-m3 持久化向量索引 + 跨库统一
  语义检索、本地/云端分流统计。
