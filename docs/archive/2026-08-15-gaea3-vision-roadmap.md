# gaea V3.0 愿景与路线规划

> 状态：**v2.4 定稿**（V1-V8 全部确认；r1-r7 调研全量收齐并入）｜ 日期：2026-08-15
> 定位：本文是 gaea 3.0 的**产品愿景与长期规划**；架构执行细节见 docs/2026-08-15-gaea3-architecture-design.md（插件化地基：事件日志/板块 Manifest/Provider Seam，为共识前提，纳入本文而非全部）。

## 0. 一句话愿景

**gaea V3.0：从"多功能 AI 助手"（八个互不相通的板块）升级为"个人 AI 智能体平台"——一个 agent 内核、一套会话事实源、统一记忆层，板块 = 内核之上的声明式插件，用户在本地拥有一个持续认识他、能跨域协作、可治理地自主行动的个人 AI。**

**设计初衷（不可动摇的前提）**：gaea 从第一天起就是要利用本机的配置优势 + 本地模型 + 节约 token——不是"本地优先或云端优先"的选择题，而是产品 DNA。愿景与路线的一切取舍都以此为第一约束：
- **token 节约是经济学**：能本地绝不云端（检索/嵌入/OCR/ASR/TTS/生图已全部本地化——ComfyUI 生图、herdsman OCR/ASR/TTS、OvisOCR2、cosyvoice）；
- **本地模型是能力底座**：herdsman/ollama/本地引擎是 gaea 与纯云助手的根本差异；
- **分层智能（云=大脑，本地=执行）**：云端的有些优势本地不可替代——**办公板块的统筹规划（agent 循环、任务分解、工具调度）需要云端模型**，本地小模型无法可靠承担工具调用编排（r2 实证的痛点）；正确架构 = **云端统筹规划 + 调度本地模型执行**：云做规划与编排，本地做专用能力（OCR/ASR/TTS/生图/嵌入/检索/文档处理）与数据不出本机的任务。云端只出现在"本地不可替代"处，token 成本透明可查。

三根支柱各一句话：
- **一个内核**：所有板块共享同一个 agent 内核（会话日志/工具/记忆/模型路由），板块是模式不是孤岛；
- **记忆即身份**：统一记忆层带来源与审计，人格/角色/知识跨板块连续——这是 gaea 区别于一切单域竞品的独有资产；
- **治理下自主**：子代理/目标/定时任务都在审批、沙箱、审计之下运行，把"交给 AI 自己干"变成可信的默认动作。

## 1. 市场坐标与调研依据

> 本节结论基于 7 份市场/社区调研（docs/gaea3-vision-research/r1-r7，全部收齐：r1 harness 生态 / r2 桌面中文 / r3 记忆编排 / r5 办公文档 / r6 绘梦 / r7 语音；r4 插件生态中断，H4/H6 以工程判断标注）。

### 1.1 已验证的趋势（r3 证据，2023-2026）
- **记忆即数据层是行业共识**：Letta/Mem0/Zep 三个开源项目证明"记忆作为可查询数据层"方向成立；CoALA 论文（arXiv:2309.02427）给出记忆四分类（working/episodic/semantic/procedural），生产实现共识 = 上下文核心块 + 向量/图外存 + 技能库三段式。
- **CLAUDE.md/SKILL.md 已成程序化记忆事实标准**：分层文件 + 自动加载 + hooks 自动维护——与 gaea 办公板块 skill 机制同向。
- **会话回放/分叉已成独立工具品类（2025-2026）**：agent-replay、rewind-agent、tracefork、aivcs、Agent-Git、salamander-db——共性 = 事件日志事实源 + checkpoint + 语义化 fork/merge，**与 gaea P1（事件日志）完全同构**；ChatGPT branching（2025-09）、Claude Code rewind/fork 证明用户强需求。
- **多 agent 编排四形态**：workflow / orchestrator-worker / subagent 委托 / handoff（OpenAI Swarm/Agents SDK）；Anthropic 多 agent 研究系统 fan-out 并行准确率 65.8%→78.2%；但 Anthropic 结论"最成功的 agent 最简"。
- **自主运行产品化 = 受控自主**：Dust Triggers（2025）、ChatGPT 定时任务（2025-11）、Claude Code Desktop 计划任务（2025-12）、飞书 aily（2025-12）、Gemini Spark（2026-05）——共性形态 = 睡眠期跑、醒来审（审批/通知收尾），与 gaea P4（治理下自主）完全同向。
- **本地优先隐私有真实背书**：Ente Ensu（纯本地 LLM）、Apple PCC（可验证隐私承诺）、Ink & Switch local-first 运动（网络是可选优化）；信任架构从宣传走向可验证工程（Stateful Intelligence 三支柱 2025-10、SuperLocalMemory 防记忆投毒 2026）。
### 1.2 桌面与中文市场（r2 证据，2024-2026）
- **桌面市场没有"单机单用户跨模块智能体"——这是 gaea 的定位空隙**：四个物种（聊天壳 Chatbox/Cherry Studio、本地运行器 LM Studio/Ollama、本地 RAG AnythingLLM、启动器 Enconvo）无一覆盖 gaea 的模块组合；MCP 已成桌面插件事实标准，gaea 应直接兼容（办公引擎已有 MCP 客户端，不造私有协议）；
- **中文写作 AI 处于"平台收紧、工具增多"夹缝**：晋江 2025-02 打"反 AI 创作"第一枪；彩云小梦（续写）、阅文妙笔（平台内嵌）、笔灵、Lattics（长文知识库写作）并存 → **gaea 小说板块定位"个人创作助手"（灵感/设定/润色/世界书），避开发表级代写心智**；
- **AI 陪伴：真需求、烂生意、严监管**：星野+猫箱流量与 Kimi 同量级、头部日聊 75 分钟；但 MiniMax 2025 前三季净亏 5.12 亿美元、海外收入占 73.1%；2025-12 情感陪伴新规（训练数据收紧）、AI 社交下载量暴跌 → **gaea 走"本地、私密、无广告订阅"错位竞争**（人格数据不出本机、无云端训练依赖，天然规避新规核心条款）；数字生命定位"**记忆守护/数字遗产**"而非"人形复活"（绕过伦理红线）；
- **记忆产品四条技术路线**：Mem0（向量检索，2025 获 $24M A 轮）/ Letta（上下文状态）/ Zep（时序知识图谱）/ Napkin（本地文件渐进披露）→ gaea 记忆中枢采用"**本地文件做底 + 向量检索 + 轻量关系图谱**"组合（Napkin 式可读可审计 + Mem0 式抽取 + Zep 轻量版）；
- **本地 agent 现实**：推理成熟、agent 化不成熟（小模型 tool calling 是公认痛点：流式破坏调用、幻觉 XML、卡死）→ 这**不是放弃本地优先的理由，而是"分层智能"架构的由来**：本地小模型做不了的事（统筹规划/工具编排）交给云端，本地小模型能做好的事（专用能力/低成本执行）绝不浪费——办公板块 = 云端统筹 + 调度本地模型执行（r1/r2 印证：唯一能跑通的形态就是"云端大脑 + 本地工具"）；
- **监管是 gaea 的结构性机遇**：云端拟人化陪伴成本全面上升（新规/诉讼/下架/下载暴跌），单机本地、人格数据用户自持的架构与监管方向天然一致——3.0 最可讲的差异化叙事。

### 1.4 agent harness 生态（r1 证据，2026）
- **DeepSeek Harness 是真实开源产品**：DeepSeek AI 2026-08-13/14 发布 v0.1 开发者预览（MIT），定位对标 OpenAI Codex / Anthropic Claude Cowork，公开公式"Model + Harness = Agent"；核心设计"一切皆插件"（模型/工具/技能/会话/沙箱/存储/循环/UI 全由 Cordis 插件组合，运行时级可替换），理论底座为北大+DeepSeek 论文《A Programming Paradigm for Spatiotemporal Composability》；轨迹设计（append-only 事件日志 JSONL + zstd 压缩）与主流会话转录理念一致——gaea P1 与 DSH 同构得到公开证实；
- **编码 agent 商业化爆发**：Claude Code 约 $2.5B ARR（2026-04，史上增长最快开发者产品）；OpenAI Codex、Gemini CLI、Qwen Code、OpenCode（120k+ 星）全部入场；
- **MCP 已是"必接"协议**：2026-04 活跃公共服务器 10,000+、月 SDK 下载 9,700 万、官方 Registry 12,000+ 条目、2025-12 捐赠 Linux Foundation（AAIF）；协议分层清晰：MCP（agent↔工具）+ A2A（agent↔agent）+ ACP（agent↔编辑器）；
- **Skills（SKILL.md）成第二项跨 agent 标准**：Anthropic 2025-10 发布，Claude Code/Codex/Cursor/Gemini CLI 采纳，有观点"一个 SKILL.md 可取代 CLAUDE.md/AGENTS.md/.cursorrules"——gaea 程序化记忆与技能格式应直接对齐；
- **工作台化趋势明确（H1 验证）**：腾讯 WorkBuddy、字节 TRAE Work、阿里 QoderWork 2026 年从聊天框转向"类 Office 工作台"；Claude Cowork/ChatGPT Work 让助手从"能说"变"会干"（ChatGPT Work 可连续工作数小时）；
- **对 gaea 的含义**：本机单用户与云端巨头（Cowork/ChatGPT Work/Gemini）的差异化护城河 = 本地隐私/离线/低延迟/可深度定制——与 r2 的"监管结构性机遇"互相印证。

### 1.5 旗舰板块定位：办公与绘梦（gaea 真正的竞争面）

> 补充说明：市场分析不能只覆盖会话/记忆等公共层——gaea 的核心竞争面在**办公板块**（生产力）与**绘梦板块**（创作资产）。两份专项调研 r5（中文办公文档 AI 市场）/ r6（图像生成工作台市场）进行中，以下定位基于 9 份架构评审的事实起草，待调研验证。

#### 办公板块 —— gaea 的生产力核心（"文档生产流水线"，不是"聊天型文档助手"）
- **现状资产**（评审事实）：42 注册工具；docx/xlsx/pdf 解析转换纯本地（docmd：zip+XML / excelize / PDF 文本 + OvisOCR2）；知识库/成本库/交付物/任务/技能/MCP/审批（开工计划卡）；两条模型入口（聊天 agent 统筹 + 功能直连 routeModel）；
- **市场空白已验证（r5，2026-08，265 行）**：① 四大巨头做"AI 文档"但锚定云端协作平台，且"一键生成质量不可用"是行业公论（WPS 灵犀官方批评一键 PPT、华为 OfficeClaw 总结三大痛点：版式遵从差/幻觉失真/不可编辑）→ **格式保真 + 可编辑 + 本地 = gaea 差异化**；② **2026 桌面办公 Agent 赛道已爆发（重要修正）**：腾讯 WorkBuddy（日活 1300 万+）、Kimi Work、阿里 QwenWork、字节 TRAE Work、华为 OfficeClaw 半年 20+ 款入场——但使用场景集中在 PPT（51.8%）/表格（38.2%）/批量整理（37.1%）"轻活"，**重文档生产（标书/方案/公文/成本测算）未被有效覆盖**；③ 标书 AI 痛点不在"能不能写"而在**格式合规与风险**（废标/串标嫌疑/招标系统读不到 AI 生成格式）→ "纯本地 + 格式保真 + 可溯源"价值空间；④ 私有化/数据不出域是政企硬需求（农发行/渤海财险/甘肃政务案例，Gartner 预测 2027 年 60% 大企业私有化智能体）；⑤ 市场规模：AI+办公软件 2025 约 700 亿元、AI 智能体市场 804 亿元（+123.2%）、2030 预计 6968 亿元；⑥ **结论：无产品同时覆盖"中文重文档生产 + 纯本地解析转换 + 知识库/成本库 + 交付物管理"**——gaea 差异化组合对应真实空白；
- **token 经济**：本地解析/OCR 不烧 token，仅统筹规划走云端（分层智能的直接受益者）；
- **时间窗口**（r5）：约 **12-24 个月**——巨头正在补桌面 Agent 通用能力，gaea 需以"可交付的中文文档成果 + 纯本地格式保真"建立垂直壁垒（这也是 3.0.0/3.1.0 优先强化办公板块的理由）；
- **愿景定位**：办公板块是 3.0 的产品主角——地基（事件日志/审计）让"文档生产流水线"可追溯可回放（对标标书合规的"可溯源"需求），是 3.0.0 用户价值的核心载体。

#### 绘梦板块 —— gaea 的创作资产引擎（"嵌入创作流的本地多后端工作台"，不是独立生图工具）
- **现状资产**（评审事实）：多后端（本地 ComfyUI：Flux/Z-Image-Turbo/Krea2 + LoRA/风格预设；云端 xAI 等）；生成队列/历史/灯箱（useImageGenQueue/History）；image_gen 已是办公引擎工具（板块→工具先例）；与小说（角色立绘）、办公（方案配图/图表）协作的接口已存在；
- **市场空白假设（待 r6）**：Midjourney/即梦/可灵 = 订阅式云端生图（积分/审查/排队）；本地 ComfyUI = 高技术门槛专业工具；缺的是"嵌入创作流的本地多后端工作台"；
- **token 经济**：本地 ComfyUI 生图不花钱、不排队、无审查；
- **愿景定位**：绘梦是 3.1.0「板块协作」的主角——"小说配图/方案配图"是板块协作的第一个可见闭环（3.1.0 里程碑判据已含"配封面"）。

### 1.6 其余旗舰板块定位（轻语 / 小说 / 微信助手 / 记忆中枢）

#### 轻语 —— 本地语音人格（"会说话、记得你、能干事"的本地语音链）
- **现状资产**（评审事实）：完整本地语音交互链（VAD→本地 ASR→人格 LLM→本地 TTS，barge-in 打断）；29 人格模板 + 情绪融合 + LLM 记忆管线（四步：事实抽取/退役/三元组/情节）+ 主动遗忘；TaskPlanStore 任务计划（内嵌 agent 循环执行，语音触发任务）；
- **市场空白已验证（r7，2026-08，约 100 来源）**：① 云端陪伴垄断且烧钱（豆包约 3.45 亿用户仍难盈利、星野过聆讯未盈利）→ 本地形态窗口；② 语音+人格+记忆的付费意愿已被硬件验证（Haivivi 约 20 万台、Fuzai 约 30 万台）但全是云端/儿童/潮玩 → **成人桌面陪伴空白**；③ "全本地语音链"有先例（HA Voice + Wyoming 实测零出网）但无中文人格化产品 → **gaea 空白成立**；④ 实时语音已是标配不是卖点（OpenAI Realtime/字节 Seeduplex/Character.AI 语音），级联方案（VAD→ASR→LLM→TTS）个人设备已工程化（百聆 800ms，与轻语架构同构）；
- **技术选型事实确认**（r7）：本地 ASR 中文 FunASR/Paraformer 实测优于 Whisper 系（gaea "whisper-base + funasr" 选型符合事实，纯中文建议 FunASR 优先）；本地 TTS 阶梯齐备（edge-tts → sherpa-onnx → CosyVoice，gaea 多后端分级完全可行）；
- **监管红利**（r7）：2025-12-27 网信办《人工智能拟人化互动服务管理暂行办法（征求意见稿）》首次定义"AI 情感陪伴"并收紧云端合规——本地自部署天然规避多数义务，主打"隐私原生"；
- **定位（r7 结论采纳）**："离线优先、人格驱动的中文语音陪伴 + 办公语音入口"——本地版星野 + 本地版讯飞输入法 + 本地任务 Agent 三合一；护城河在人格模板/情绪融合/记忆管线 + TaskPlanStore + barge-in 状态机（开源底座只是原料）；
- **token 经济**：ASR/TTS 全本地（herdsman/cosyvoice/edge），人格 LLM 按分层智能路由；
- **愿景定位**：轻语是"人格连续性"（3.3.0+）的载体，也是 3.2.0 受控自主的语音入口（"晚安前整理今天的记忆"这类语音任务起步）。

#### 小说 —— 世界构建创作工作台（"世界观/角色/大纲 agent + 章节流式 + 多域资产"，不是续写工具）
- **现状资产**（评审事实）：世界观/角色/大纲域 agent；章节流式创作（create-chapter-stream）；导出 TXT/MD/EPUB；角色库联动（单向引用）；绘梦配图接口；
- **定位**：r2 已证"平台收紧、工具增多"——彩云小梦是续写、阅文妙笔是平台内嵌；gaea 小说的差异 = **世界构建工作台**（设定/角色/大纲先建好，agent 按世界观生成，创作资产（立绘/封面）跨板块复用）；定位"个人创作助手"，避开发表红线。

#### 微信助手 —— 远程触达渠道（beta 服务板块）
- **现状资产**：ClawBot 桥接（微信远程对话，会话过期自愈）；无前端页面，纯服务板块；
- **定位**：把 gaea 的 agent 接进中国最大 IM——"不在电脑前也能用 gaea"（语音/文字下达任务、查看结果）；是 3.0 manifest「服务型板块」（无页面板块）的先例；beta 性质，优先级低于核心板块。

#### 记忆中枢 —— 记忆层管理面（P3 已详述）
- 8 库聚合 + 三脑 + dream 自动整理 + 轻语记忆隔离；定位 = "可查询、可审计、可演进"的事实底座（见 P3）。

#### 移动终端 —— 远程驾驶桌面（"手机是薄终端，桌面是本机大脑"）
- **定位**：gaea 桌面 = 本机大脑（模型/ComfyUI/存储/记忆/GPU 全留在桌面），手机/平板 = 远程薄终端（语音/文字交互、下达任务、查看会话与结果）——与"利用本机配置优势"完全一致：手机不跑模型，桌面资源被远程复用，token 与算力都在本机；
- **已有基础（评审事实）**：httpbridge 协议层已存在（GAEA_HTTP_PORT + 一次性 token 鉴权 + /api/rpc + /api/stream SSE，main.go 明言"浏览器页面可驱动同一个 Go 内核，与桌面端完全对齐"）；runtimePolyfill 已支持浏览器事件流（SSE 按事件名单连接 + 5s 重连）；gaea bridge 的 HTTP 代理（createAppProxy → POST /api/rpc）已存在——**协议层就绪，缺的是移动端 UI 适配层与产品级安全加固**；
- **参照（C:\AI\dsh-mobile）**：DSH 移动端 = 纯客户端 UI 适配插件（窄屏翻页器重排三栏为侧边栏+聊天两页，零核心改动）——gaea 移动端可同构：Web/PWA 复用现有 bridge 契约 + 窄屏适配，不新增核心代码；
- **与微信助手的关系**：微信助手 = 微信渠道（受限交互，ClawBot）；移动终端 = 完整远程驾驶（同构于桌面 UI，全功能）；
- **版本定位**：3.0.0 已有"手机（httpbridge）看同一会话"（事件日志多前端同步的价值点）；完整移动终端（PWA）是 3.2.0「受控自主」的配套（手机下达任务/查看结果），3.1.0 后可先行 Web 版验证。

## 2. 愿景四支柱

### P1 一个内核（One Substrate）—— 地基，共识前提
- 事件日志事实源：会话可回放/分叉/恢复（含 torn-tail 崩溃恢复）；
- 板块 Manifest：板块是声明不是代码；
- Provider Seam：换模型/后端只改配置；
- 产品意义：聊天/轻语/小说/办公都是同一内核的模式，共享会话、记忆、模型路由。
- 执行：见架构设计文档 Step 0-3（3.0.0 交付）。

### P2 板块生态（Board Ecosystem）—— 3.0 的产品层
- 首方板块迁移：知识库（最小试点）→ chat → 绘梦 → 小说 → 轻语（迁移原则见 §5.2）；
- 编程板块已恢复（2026-08-16），以 DeepSeek Harness Web 进程管理形态落地（见 §4）；完整代码工作台作为后续扩展。
- 技能/预设/提示词作为"内容"进板块（办公板块 skill 已证明可行）；插件层直接兼容 MCP（办公引擎已有 MCP 客户端，不造私有协议）；
- 远期：第三方板块（配置文件即可安装）。**生态参照（工程判断，待 r4 复核）**：Obsidian 插件社区（数千插件 + 稳定分发）证明"个人工具的配置/插件即内容"有量级；Claude Code skills/subagents 以文件形式共享成为风潮（awesome-claude-code 类仓库）——gaea 板块 manifest + skill 文件天然适配这种"配置即内容"分发；但社区冷启动成本高，3.1.0 只做首方生态 + 安装机制，不做市场。

### P3 统一记忆与身份（Unified Memory & Identity）—— 差异化支柱
- 现状：8 库 + 三脑 + 轻语管线各自为政；数字生命只是只读桥接 Herdsman（herdsman_digitallife.go，勿混淆）；
- 目标：一个记忆**数据层**（对齐 Mem0/Letta"核心记忆块 + 向量/图长期存储 + 操作 API"三段式共识），而非第 N 个库；8 个记忆库收敛为"一个数据层 + 命名空间/视图"，三脑（main/left/right）作命名空间不作物理库；带来源（事件日志出处）、分层（CoALA 四分类）、可审计；
- **会话档案化链路**：P1 事件日志 → 会话结束折叠为记忆 → 记忆可溯源（外部共识与 DSH 范式一致，P1 与 P3 必须串成一条链，不是两件事）；
- **程序化记忆直接搬事实标准**：AGENTS.md（2025 项目指令标准，gaea 已有 .gaea/AGENTS.md 实践）+ CLAUDE.md/SKILL.md（Anthropic 2025-10 发布，跨 agent 采纳）——记忆文件分层（全局/板块/项目）+ hooks 自动维护 + skill 声明式，成本低于自造格式、生态可兼容；
- **防记忆投毒提前设计**（SuperLocalMemory 2026 指出的风险）：知识库/记忆可被外部文档影响，记忆写入要审批/校验/溯源，3.0 记忆层设计时就定；
- **技术选型组合**（r2）：本地文件（Napkin 式，可读可审计）+ 向量检索（Mem0 式）+ 轻量关系图谱（Zep 式）——不追求大而全的图谱/向量基建；
- 人格连续性：轻语的"她"跨板块延续记忆与身份；角色库、知识库共享事实底座；
- 里程碑：记忆中枢从"聚合展示"升级为"可查询、可审计、可演进"的事实底座。

### P4 治理下的自主性（Autonomy with Governance）—— 完成态
- 子代理、目标循环、定时任务、工作流——全部在审批+沙箱+审计之下（对齐"受控自主"产品形态：睡眠期跑、醒来审）；
- 跨板块任务流以子代理/任务协作（"给第三章配封面"→ novel 调 imagegen），不复活单窗口编排；fan-out 并行是收益最大模式（Anthropic 研究系统准确率 65.8%→78.2%），但要等有明确用例再上；
- 前置硬约束：Windows 沙箱 fail-closed（评审证实当前 bash 无 OS 隔离）；
- 依赖项诚实声明：人格引擎在 Herdsman 手里，身份深化是 3.3+ 的独立决策。

## 4.5 与 DSH 的关系定位（三层拆解）

> 前期讨论的共识前提是"向 DSH 靠拢"——经市场调研后精确化：**向 agent harness 行业的成熟范式靠拢**，DSH 是范式最激进、最公开的实践者之一，不是依赖、不是目的地。

| 层 | 定位 | 做法 |
|---|---|---|
| 原则级 | **范式借鉴（采纳）** | 事件日志事实源 / 板块 Manifest / Provider Seam——已被市场验证（r1：轨迹是主流标配；r3：回放/分叉成工具品类），且与本地优先+分层智能互相成就（seam=本地/云端切换只改配置；事件日志=token 可审计） |
| 标准级 | **生态对齐（采纳）** | MCP（必接）/ SKILL.md / AGENTS.md / 会话格式可互操作——与 DSH 无关也要做，这是进生态不是跟项目 |
| 项目级 | **独立（不采纳）** | 不 fork、不 embed、不跟随 DSH 路线图；DSH 是 TS+Cordis、v0.1、通用 harness 坐标；gaea 是 Go + 单用户桌面 + 个人多域助理坐标 |

**三条纪律**：
1. 范式借鉴止于"接口与机制"，不移植 Cordis/TS 组件；
2. **不做全量运行期动态装配（用户已确认 2026-08-15）**：板块/能力装配只在启动期声明式完成，无热替换/HMR。**边界精确化**：工具级热增删是例外且保留（办公引擎 MCP 插件 Host 已支持 /mcp 热增删，属现状能力，不砍）；砍掉的是"板块/能力树级全量动态化"（Cordis 式 HMR + 卸载回滚），那是通用 harness 的卖点，对单用户桌面是过度工程；
3. DSH 作为定期对照对象（范式演进风向标），gaea 路线由本机配置优势、token 节约、个人多域助理三件事决定。

## 6. 护城河与风险（客观评估）

### 6.1 护城河候选（按可信度排序）
1. **多域合一 + 记忆连续性**：最可能差异化，但需 3.0 打通才成立（现状是假合一）；
2. **本地优先 + token 经济**（设计 DNA）：本地模型/本地工具/本地存储把 token 成本与延迟打下来，隐私与合规优势是副产品——这是竞品（纯云助手）无法复制的成本结构，不是"卖点"而是"体质"；
3. **陪伴人格连续性**（轻语）：依赖记忆质量与 Herdsman 关系，长期看是 gaea 的情感粘性来源；
4. **编码能力**：非护城河，补齐入口而已；编程板块已以 Harness Web 进程管理形态落地（2026-08-16）。

### 6.2 风险（专业判断）
1. 范围蔓延：硬约束 3.0.0 只做 P1+一个板块+知识库试点；
2. 架构期用户价值真空：阶段 7（v2.34-2.37 正确性）+ 3.0.0 之间要穿插可见小功能；
3. Windows 安全债：自主性之前必须 fail-closed；
4. 无反馈闭环：单用户产品无遥测，需 5+ 真实用户试用计划；
5. **"靠拢"字面化风险**：范式借鉴与生态对齐是边界，项目级耦合（fork/embed/跟路线图）会丢失 gaea 坐标——详见 §4.5 三层定位；
6. 模型依赖：本地模型质量与云端成本决定自主体验；
7. **窗口期压力**（r5）：巨头 12-24 个月内在补桌面办公 Agent 通用能力，gaea 必须在此期间以"可交付中文文档成果 + 本地格式保真"立住垂直壁垒，否则差异化窗口收窄；
8. **回退纪律**（用户要求）：每个 Step/每版独立发布、独立可回退（代码 git revert / 数据只读兼容 / 二进制保留 5 版 / 运行时开关四层保障，详见架构文档 §6.6），每 Step 验收含回退演练。
