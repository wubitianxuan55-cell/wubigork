## 1. 背景与目的

模型中心接入 Herdsman 本地服务，当前暴露 3 个大语言模型。为回答"哪个模型适合默认日常使用、哪个适合深度推理、思考模式值不值得开"这三个问题，本次对 3 个模型进行同一套任务的功能性对比测试，并专门做了**思考模式 / 非思考模式**的受控对照：

- 同一套任务、同一提示词、同一温度（0.3）、同一 token 预算；
- 唯一变量为 `thinking_enabled`（思考模式开关）；
- 三个模型在完全相同的条件下各自跑两种模式，保证横向可比。

### 3.2 双模式设计

| 参数 | 取值 |
|---|---|
| `temperature` | 0.3（两模式一致） |
| `max_tokens` | 任务原始上限与 2048 取大（两模式一致，为推理留空间） |
| `thinking_enabled` | 非思考：不传；思考：`true`（唯一变量） |
| 流式 | T17 使用 SSE，其余非流式 |

### 3.3 判定标准

- PASS：HTTP 200、回复非空、通过任务对应的自动校验；
- FAIL：请求失败、空回复、或未通过自动校验；
- 思考模式下若"仅有推理、无最终回答"，视为 PASS（推理能力已验证）但单独标注；
- 每格为单次采样（temperature=0.3），结果反映趋势而非统计显著性。

## 6. 双模式对比分析

### 6.1 速度：思考模式慢 2.7-3.4 倍

| 模型 | 非思考平均耗时 | 思考平均耗时 | 倍数 |
|---|---:|---:|---:|
| Hermes | 8.9s | 29.9s | 3.4× |
| LynnStyle | 10.7s | 28.0s | 2.6× |
| HauhauCS | 9.1s | 24.7s | 2.7× |

思考模式下复杂任务的推理链可达 5000+ 字（T5 逻辑 HauhauCS 推理 5727 字、T12 中译英 Hermes 推理 6961 字），这是耗时上升的直接原因。

### 6.2 正文长度：思考模式挤占输出预算

思考模式与正文共享 `max_tokens`，推理越长，留给正文的预算越少：

- LynnStyle：正文 615 → 418 字（-32%）；
- HauhauCS：正文 766 → 387 字（-49%）；
- Hermes：正文 679 → 682 字（几乎不变，但代价是 2 个任务"仅有推理、无最终回答"）。

### 6.3 推理链暴露：三模型差异明显

| 模型 | 思考模式下产出独立推理的任务 | 推理长度范围 |
|---|---:|---|
| LynnStyle | 20/20 | 194 - 5221 字 |
| Hermes | 18/20 | 664 - 6961 字 |
| HauhauCS | 18/20 | 947 - 5727 字 |

- **LynnStyle 是唯一稳定输出 `reasoning_content` 的模型**，思考链路完整、可审计；
- Hermes / HauhauCS 各有 2 个任务未返回独立推理通道（Hermes T1/T8、HauhauCS T1/T8），且行为有随机性（同一模型不同轮次表现不一致）；
- 极端情况：Hermes T1 在思考模式下把 4335 字"思考"直接写进正文，推理与回答混在一起。

### 6.4 失败项分析（思考模式 2 项）

| 失败项 | 现象 | 归因 |
|---|---|---|
| Hermes T1 常识 | 要求 200 字以内，输出 4335 字 | 思考模式下长度指令遵循退化，推理混入正文 |
| HauhauCS T14 长文 | 要求 800 字以上，正文仅 427 字 | 推理 5295 字耗尽 token 预算，正文被截断 |

另观察到 4 次"仅有推理、无最终回答"（Hermes T2/T7、HauhauCS T11/T15），均发生在 2048 预算被推理吃光时。若按应用默认 `max_tokens=4096` 运行，截断类现象会缓解，但 Hermes T1 这类"超字数"问题属于指令遵循缺陷，不会因预算变大而消失。

## 8. 关键发现与风险

1. **LynnStyle 是真正的思考模型**：开启思考后 20/20 任务稳定产出推理链；但 token 预算不足时会出现"只有推理、没有正文"（800 预算下实测正文为空，2048 预算下恢复正常）。应用内流式路径（小说章节/方案生成）客户端不传 `max_tokens`、交由服务端默认，非流式 `ChatCompletion` 默认 4096；若给某个任务显式传了小 `max_tokens` 再绑定该模型需留意。
2. **思考通道不稳定**：Hermes / HauhauCS 的推理暴露存在随机性，且 HauhauCS 在"非思考"模式下偶发在正文输出 `<think>...</think>` 标签（T15 实测），下游解析需兼容。
3. **思考模式收益与成本并存**：难题（逻辑/数学/多轮）的推理链质量高，但平均耗时 2.7-3.4 倍、正文缩短、并引入长度指令遵循风险（Hermes 超字数、HauhauCS 截断）。
4. **JSON 输出习惯**：三模型输出 JSON 都带 ```json 围栏和引导语，应用侧解析需按"提取代码块"方式处理（本项目测试脚本已内置兼容逻辑）。
5. **诚实性良好**：T15 知识边界任务中，三个模型均明确承认无法确认 2026 年最新 GPT 版本（Hermes：知识截止早于该年份；LynnStyle：截止 2024；HauhauCS：详细说明不确定原因），无强行编造。
6. **生成速度差异稳定**：HauhauCS（60-68 tok/s）> Hermes（54-58 tok/s）> LynnStyle（42-46 tok/s），流式首 token 热启动约 250-380ms，三模型差异不大。

## 9. 结论与选型建议

**默认日常使用：Qwen3.6 HauhauCS（Q4_K_P）**

- 速度最快（约 65 tok/s）、常规任务平均 9.1s/个；
- 非思考模式 20/20 通过、正文输出最充分（平均 766 字）；
- 识图表格理解最准确；
- 已在应用中作为 vision 默认模型，继续作为常规/识图首选合理。

**深度推理/可解释场景：Qwen3.6 LynnStyle（Q5）**

- 唯一稳定输出独立推理链的模型，思考过程可审计；
- 适合需要"先推理再作答"的复杂任务（逻辑、数学、多轮、长文改写）；
- 代价是速度最慢（42-46 tok/s）且思考模式正文变短，需给足 token 预算（建议 ≥4096）。

**输出详尽/角色化场景：Hermes3.6 Genesis**

- 非思考模式下逻辑/数学/写作输出篇幅最大、内容扎实；
- 但思考模式下推理混入正文、长度指令遵循不稳，不建议对其开思考模式。

**全局建议**

1. 应用默认保持**非思考模式**，仅对复杂任务按需开启思考；
2. 思考模式请求的 `max_tokens` 建议 ≥4096，避免"仅有推理、无正文"；
3. 下游解析 JSON 时兼容 ```json 围栏；解析正文时过滤 `<think>...</think>` 片段；
4. 识图统一用 HauhauCS（默认视觉模型）即可，其余两模型识图能力已达标可作兜底。
