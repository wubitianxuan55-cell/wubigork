# 造价数据库梳理报告（2026-08-19）

> 范围：`Hephaestus.db`（`%APPDATA%\gaea\Hephaestus.db`）成本库全量梳理。
> 触发：用户反馈「重新梳理整个造价数据库，现在一团乱」。

## 0. 一句话结论

数据本身干净（1420 条无重复、无空价、全「现行」），混乱出在**分类体系**：
SchemaV7 把旧平铺分类原样复制为 `category_path`，之后分类树又叠加演进，
导致 201 条（14%）的 `category_path` 在树上无法解析——树上看不到、统计对不上；
同时 SchemaV9 的 地区/期数 字段从未回填（1420 条全空，而来源字符串里明明带着）。

### 非法路径构成（201 = 全部可确定性修复，0 残留）

- **房建成本测算手册 49 条**（给排水10/电气9/通风7/采暖6/弱电5/土建5/单方指标7）：
  平铺在旧分类，且「通风空调」7 条被误判到 材料/安装材料（实为安装综合价子目）。
- **市政成本测算手册 26 条**：道路/交通/绿化/照明/给水/暖气/雨污/电力各章节条目
  全部误入平铺「土方」。
- **人工费数据库 7 条**：砌筑/模板/钢筋制安/混凝土浇筑/膜铺设/破拆等纯人工条目。

  树内已有同名节点（部分条目此前已迁移，形成新旧混用）。

## 2. 修复方案（已实施）

### 2.1 分类路径修复（201 条 → 合法路径，0 未解决）

规则引擎 `legacyCategoryTarget`（internal/gaea/cost/repair.go），优先级：

1. **房建成本测算手册** → `综合单价/房建工程/{给排水|电气|通风空调|采暖|弱电|土建|单方指标}工程`
2. **市政成本测算手册** → `综合单价/{道路|交通|绿化|电力|给水|暖气|雨污|照明}工程/{分部}`，
   分部按标题关键词（标线→标线、路面/碎石/沥青→机动车道、检查井→检查井及雨水口…），
   无法定分部则落专业级（如 水平定向钻穿公路 → 综合单价/交通工程）。
3. **普工/技工/特殊工种** 平铺 → `人工/{同名}`（人工类别无歧义）。
4. **人工费数据库** 纯人工条目 → `人工/技工`。
5. **玻璃及玻璃制品** → `材料/土建材料/玻璃及玻璃制品`（新增节点）。
6. **木竹材料** → `材料/土建材料/木材及竹木制品`（语义等价）。
7. **土方** 兜底 → `综合单价/土方`（中科一兵/市场复核等）。
8. **叶名唯一映射表**：水泥及水泥制品/钢材/砖瓦灰砂石/土方机械/辅助材料/燃料火工/
   土工合成材料/桩基机械/修复处置/临建设施/场外运输/脚手架/处置/运输机械/服务/
   起重机械/混凝土机械 → 树内既有同名节点。

新增分类节点 9 个（幂等创建）：
`综合单价/房建工程`（+给排水工程/电气工程/通风空调工程/采暖工程/弱电工程/土建工程/
单方指标 7 个子节点）、`材料/土建材料/玻璃及玻璃制品`。

### 2.2 地区/期数回填（从来源字符串保守提取，不臆造）

`priceMetaFromSource`：只认来源里明确写出的信息。

| 来源前缀 | 地区 | 期数 | 条数 |
|---|---|---|---|
| 重庆工程造价…（中心城区） | 重庆中心城区 | 2026年6月 | 1,184 |
| 四川省工程造价信息网…（成都市区） | 成都市区 | 2026年6月 | 24 |
| 乐山市建筑材料市场信息价…（乐山市/市中区） | 乐山市 / 乐山市中区 | 2026年7月 | 38 |
| 材料单价数据库…重庆/四川信息价 | 重庆 / 四川 | 2026年3月 | 3 |
| 人工费/机械费/材料单价数据库…2026-0X | — | 2026年X月 | 其余 |

结果：**地区回填 1,249 条，期数回填 1,284 条**；手册/市场复核/项目等无明确地区
日期的来源保持空值（不臆造）。`price_type`/`valid_until` 无可靠来源，维持空值。

### 2.3 代码自愈（防止再次漂移）

- `cost.defaultCategories` 扩展为完整树（资源库层 + 综合单价层 + 房建工程），
  与真实库 106 节点对齐——新装库播种一致，`EnsureDefaultCategories` 幂等。
- `cost.Store.Open` 现在执行 `SelfHeal()`（幂等）：`RepairCategoryPaths` +
  `BackfillPriceMeta`，日志输出修复数量；只处理「树上无法解析」的路径，用户自建
  分类不受影响。
- 修复条目同步更新 `category`（叶子名）与 `updated_at`；回填不动 `updated_at`
  （元数据富化，不当作内容变更）。
