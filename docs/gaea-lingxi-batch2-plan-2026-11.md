### B2 工具失败语义族

灵犀形态（§24.4）：每工具一组失败文案 `missing_* / parse_args_failed / partial_success / all_failed / operation_failed`，且**文案里写死后续行为**（例：「禁止重试本工具，也不要编造云文档链接」）。

- 收敛到 gaea 高频 10 类：office COM 族（open/read/edit/render/save/close）、xlsx_apply/recalc/audit、docmd/office_batch、vision/ocr。
- 三类语义必写：①**部分成功**（partial：逐文件/逐 op 报告已有哪些成了）②**全失败后续**（重试有无意义、该换什么路）③**禁编造**（失败后不得虚构路径/链接/结果——灵犀 cloud_doc_all_failed 同款）。
- 落点：各工具 Execute 的错误返回文案（参数解析失败已统一过，本批动**业务失败**文案）；不建新抽象层。
- 验收：单测断言关键字（「部分成功」「不要重试」「不要编造」按工具性质选配）；抽 10 条真实失败 case 对比模型后续行为。

## 4. 架构约束（本批起生效，零成本）

- **云能力独立成 CLI**：任何未来云能力（技能市场远端、连接器）独立二进制/子进程形态，凭据走环境变量；断网整层禁用。不进主进程（灵犀 68.9MB 主进程含四云 SDK 的反例，§20.2）。

## 5. 反例清单（后续蒸馏者防坑，引自评估报告 §7）

①复合占位符 `__BODY____OUTPUT_PATH__` 是字符串表连写假象，不是设计；②工具 schema 不在二进制里（jsonschema-go 按 struct tag 现算），「导出 schema 文件」徒劳；③流式事件名静态枚举不全（负结果，§26.4）；④逐工具 JS 归属不可得（两条路均已证伪，§25，别再试）；⑤技能包不自足（连 requests 都不预装）——「运行期 pip」等于把首启寄托于网络；⑥主进程体积陷阱——分层收益别被「全塞主进程」抵消。
