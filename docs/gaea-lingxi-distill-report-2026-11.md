## 2. 值得蒸馏的 6 项（逐项论证）

### 2.1 提示词装配顺序 —— 位置即优先级

**灵犀证据** `[观]`（§26.1）：130 节点顺序，开头是
`group_chat → skills → runtime → language → format → im_scene → agent_loop → tool_call_style → memory_system → tool_use → system_reminder`。

四条可迁移规律：
1. 场景开关（`group_chat`/`im_scene`）**排在最前**，不靠文末强调；
2. `language → format → tool_call_style` 在 `agent_loop` **之前**：先钉输出形态，再讲循环；
3. 记忆段**跟在循环之后**：先讲怎么干活，再讲能记住什么；
4. `system_reminder` 是**动态插入位**（段库统计 33 处），不是一次性段落。

**为什么值得**：纯文案，改的是 prompt 文件，可 A/B 对比；`[文档]` 我们 P0-4 只补了「清单截断/参数错误/压缩交接/渲染白名单/收尾三条」，
装配顺序这一层没动过。

**代价**：0.5 人日（改提示词 + 抽 10 条真实回复对比）。
**风险**：低。唯一注意是别把灵犀的段落**全文**搬过来——体量与语境不同，只搬顺序与位置关系。

### 2.2 交付契约的两条硬禁

**灵犀证据** `[观]`（§22.1，逐字）：
- `deliver_result.description`：**「调用前不要加 markdown 格式的有序列表或无序列表」**
- `deliver_result.success`：**「后续不再使用任何 markdown 格式输出交付物路径」**
- 配合 §14 的 `delivery_format`：协议链接直出、**禁反引号、禁代码块**（「反引号会被解析成代码片段，导致整条消息渲染错乱」）。

**为什么值得**：我们 P0-1 `[文档]` 已做「协议优先 + 禁反引号」，但缺「动作前不加列表 / 动作后不再贴路径」这一对**时序禁则**。
灵犀把渲染翻车拆成三段（之前、之中、之后），我们只覆盖了「之中」。

**代价**：0.5 人日（提示词 + 单测断言链接渲染）。
**风险**：低。注意 IM 场景与桌面场景的差异：灵犀 IM 走 `share_file`，桌面临时链接走 `file:///`。

### 2.3 工具描述写法（instructions 块 + 失败语义族）

**灵犀证据** `[观]`（§24.4、§22.1）：25 个工具的 description 都是
「一句话用途 + `<instructions>` 编号清单」；每个工具配一组失败文案（`missing_*` / `parse_args_failed` / `partial_success` / `all_failed` / `operation_failed`），
且失败文案里**直接写死后续行为**（例：`cloud_doc_all_failed`「禁止重试本工具，也不要编造云文档链接」）。

**为什么值得**：`[文档]` 我们 P0-4 只统一了「参数错误三要素」，**没有失败语义族**。
工具一旦失败，模型的行为取决于这句话，而不是我们的期望。

**代价**：2 人日（25 类工具面不全适用，按我们实际工具收敛到 10 类左右 + 文案评审）。
**风险**：中——文案改动会影响行为，需抽 10 条真实失败 case 对比。

### 2.4 技能工程质量门禁

**灵犀证据** `[观]`（§4，来自 SKILL.md 与脚本）：
公式优先 + `recalc` 后扫 `#REF!/#DIV/0!/#VALUE!/#N/A/#NAME?`；结果尺寸可变时默认动态数组（`FILTER/UNIQUE/SORT/GROUPBY/XLOOKUP`）且溢出区不得有内容；
生成 → 渲染 PNG → 复核；新建/模板复刻/局部编辑三条入口互斥；`success:false` 或 exit≠0 立即停；字体白名单 ∩ 系统字体，空集回退微软雅黑；产物目录纪律。

**为什么值得**：这是灵犀技能里**唯一带质量闭环**的部分。`[文档]` 我们 P1-2 只打算做 `xlsx_recalc`/`xlsx_audit` 两个工具，
没写「公式优先」与「动态数组默认」这两条**行为约束**；没有约束，工具就只是工具。

**代价**：P1-2 原计划 1–2 人日不变，但**提示词侧要加三条**（公式优先/零错误/动态数组），共 +0.5 人日。
**风险**：低（variance 场景需实测，灵犀也承认 `recalc` 依赖 `formulas` 包，见 §12）。

### 2.5 云能力独立成 CLI 的分层

**灵犀证据** `[观]`（§21.4、§22.3）：`kdocs-cli` 是独立 Go 二进制，形态
`kdocs-cli <service> <action> [json_params]` / `kdocs-cli call <tool>`，凭据走 `WPS_SID`，能力含 REST 与 `jsapi`（133 个 `wps.*` 动作）。

**为什么值得**：`[文档]` 我们 P2-2「技能市场/安装契约」与任何未来云能力，默认会进主进程。
灵犀证明**独立 CLI 更省**：断网可整层禁用、体积不压主包、升级独立。

**代价**：仅作为**架构约束**采纳（0 人日）；实际拆分留到真有云需求时。
**风险**：低。反面教材也在同处：灵犀有 20 个连接器 + 四云对象存储 SDK 编进 `lingxi.exe`（§20.2），主进程 68.9 MB——分层没做彻底。

### 2.6 记忆三层 + 写入门禁（新候选）

**灵犀证据** `[观]`（§26.2，72 KB 合订）：`core_memory` 常驻 + `memory_index` 检索 + `memory_recall_rules` 决定召回；
`memory_write_rules` 明确**只写**「用户偏好 / 协作规则 / 长期上下文」，其余「不干涉、不记录、不询问」；
wiki 页面有 front-matter、来源锚点、`import_rules`（哪些目录只读）。

**为什么值得**：`[文档]` 我们现有计划（P0/P1/P2）里没有记忆项，但仓里有 memory hub / wiki 相关页面存在痕迹。
灵犀这套是**可直接对照的设计说明**，不是代码。

**代价**：评估 1 人日（先比对我们现状），落地另计。
**风险**：中——记忆写入门禁一旦放宽会污染长期上下文，需先定「什么算长期上下文」。

## 3. 有条件蒸馏的 4 项

### 3.1 逃生舱形态（`script`/`script_file` + `ui`）
灵犀 `[观]`：每个脚本类工具都有 `script`（内联）与 `script_file`（路径）双入参 + `ui` 布尔（headless↔headed 同一工具）。
我们 `[文档]` P0-2 已落「A 档受控宏」（白名单 → 既有 ops），**执行面不抄**是对的。
**可抄的只剩形态**：任一高层工具缺失能力时，给一个受控的「兜底入参」而不是让模型放弃。
**前置**：先定兜底范围（宏白名单 vs 任意脚本）；不定就别动。

### 3.2 CDP 桥（本地 HTTP + 端口文件 + 插件长连 + 心跳）
灵犀 `[观]`（§21.2）：`GET /status` / `POST /cdp` 两个路由、`listen(0)` 临时端口、端口文件、`[NH-HB]` ping/pong、`plugin not connected` 硬拒。
**收益取决于我们是否有跨进程/沙箱的浏览器需求**：若无隔离沙箱，直接 CDP 直连更简单。
**判定**：先记录形态，不立项。

### 3.3 沙箱策略字段（`permission_profile` / `deny_*` / 网络 SID）
灵犀 `[观]`（§21.3）：字段集与我们 `sandbox_permissions` 同构，多出 `deny_read_paths`/`deny_write_paths` 与「按受限 SID 挂 WFP」两个维度。
**判定**：只有当我们要做本地沙箱时才需要；否则抄字段没意义。

### 3.4 MCP 单 dispatcher（`connector_exec`）
灵犀 `[观]`（§16）：工具不扁平化，统一 `connector_exec(server, tool, arguments)`；`mcp__` 前缀 0 命中。
**影响**：这正是 P2-1「office 工具 MCP 化」的**命名策略分叉**——做 `mcp__office__edit` 还是 `connector_exec(office, edit)`。
**判定**：采纳单 dispatcher 更好（工具清单不炸开、与连接器统一），但要先拍板，因为它决定对外契约。

## 7. 反例清单（看起来能抄、实际会翻车）

1. **复合占位符**：`__BODY____OUTPUT_PATH__` 不是设计，是相邻占位符在字符串表里连写（§26.3）。照抄会错位。
2. **schema 不在二进制里**：工具 schema 由 `jsonschema-go` 按 struct tag 现算（§23.1）。想「导出灵犀的 schema 文件」是徒劳的，字段名只能从 tag 表拿。
3. **事件名不可静态枚举**：`"char_delta"` 只 1 次、`content_block_*` 各 1 次（§26.4）。别指望静态还原流式协议。
4. **逐工具 JS 归属不可得**：邻近法 122/129 全吸到一个工具（§25.1），模块法只剩 `pdf_scripts`（§25.2）。已证伪，别再试。
5. **技能包不自足**：`requests` 都没预装（§11）。照抄「运行期 pip」等于把首启成功寄托于网络。
6. **主进程体积陷阱**：灵犀 68.9 MB，含四云 SDK + 20 连接器（§20.2）。分层收益被它自己的「全塞主进程」抵消了一半。
