# 市场调研：办公板块「表格 Agent 可交付」与「会话产物打包」，2026-08

> 目的：为 gaea 通用办公「表格数据工作流」与「会话产物交付闭环」提供设计依据。
> 承接此前《文件交互体验》（v3.0.7 已落地 P0-P2）与《对话内成果交付与文件交互》，
> 本轮聚焦两个此前未覆盖的角度：① **表格 Agent 的「可交付」进化**（表格不再只是
> 编辑对象，而是「选中即图表、跨表即数据、格式即清洗」的完整数据工作流）；
> ② **会话产物集中打包**（本次会话生成的文件一键 Zip 带走）。来源为 2026 年公开
> 资料、官方文档与实测报道。

## 0. 一句话结论

2026 年表格 Agent 已从「聊天式写公式」进化为**「可交付」的数据工作流**：ChatExcel
Max 2.0 宣称公式样式全支持、文件大小/数量不限制；千问表格 Agent 实测表明 AI 办公
竞赛正式进入「可交付」时代；GLM in Excel、Grok for Excel 相继入场；阿里云教程把
办公 Agent 的价值锚定在「跨表匹配、格式清洗、自动图表生成」这类**苦力活接管**。
同时，会话产物集中打包（Kimi 工作空间、WorkBuddy 会话产物）已成为桌面办公 Agent
的标配收尾体验。gaea 已有表格编辑（单元格级 + 公式重算）与 chart_gen 图表工具，
缺的是**把两者接起来的表格内入口**（选中区域 → 一键图表）与**会话产物的一键打包**。

## 1. 竞品矩阵：表格 Agent「可交付」能力

## 3. 行业趋势（本轮提炼）

1. **表格「可交付」三件套**：跨表匹配、格式清洗、自动图表——大厂教程级共识，是
   「AI 帮你干活」在表格场景最具体的落点；gaea 的 chart_gen + xlsx 编辑已具备原料，
   缺「选中区域 → 生成图表」的直连入口。
2. **会话产物 = 一包带走**：Kimi/WorkBuddy 均提供会话产物 Zip 打包；交付闭环的最后
   一步是「把本次会话所有文件装进一个包」，不是「复制一堆路径」。
3. **表格内原地完成 > 跳转外部**：GLM in Excel / Grok for Excel 证明「在表格里直接
   操作」的体验优于复制到外部工具——gaea XlsxPreview 的 AI 编辑/公式重算已是同构，
   继续往「预览内即可生成图表」演进。
4. **缩略图是产物卡片的第一印象**：豆包 PPT 卡片缩略图、AutoGPT MIME 插图——产物
   列表里「看得见内容」比「看得见图标」更接近成果。

## 4. gaea 现状盘点（基于代码，2026-08-17）

### 已具备
- 表格编辑：XlsxPreview（单元格级编辑、公式重算、行/列操作、AI 编辑选中单元格）、
  XlsxEdit/XlsxSetCell/XlsxRecalc/XlsxRowOps/XlsxColOps 绑定。
- 图表生成：chart_gen 内置工具（bar/line/pie/scatter，matplotlib，中文字体自动探测），
  chart-builder 技能；diagram_gen 流程图/时序图/甘特图。
- 会话产物：DeliverablesPanel（去重、版本徽标 vN、跳转来源消息、复制路径/全部路径、
  外部打开、定位文件、沉淀成本库入口）；DeliverableCards 对话内交付卡片。
- 文件交互（v3.0.7）：非图片附件 chip、行内文件 chip、最近文件快捷区、多文件预览队列、
  附件上下文占用透明化、产物版本时间线。

### 缺失（本轮落点）
1. **会话产物一键打包 Zip**：DeliverablesPanel 有「复制全部路径」但无「打包下载」——
   对标 Kimi 工作空间/WorkBuddy 会话产物打包。
2. **表格「选中区域 → 一键图表」**：XlsxPreview 里选中单元格后只能 AI 编辑/行列表操作，
   不能把选中区域的数据直接变成图表（chart_gen 已有，缺表格内入口与数据装配）。
3. **产物卡片缩略图增强**：FileThumb 仅图片（png/jpg/gif/webp/svg/bmp/ico）有缩略图，
   docx/xlsx/pptx 只显示类型图标——对标豆包 PPT 首屏缩略图。

## 5. 落地清单（映射到 gaea）

### P0-1 会话产物一键打包 Zip
- 后端：`GaeaZipDeliverables(paths []string) (ZipDeliverableResult, error)`——把会话产物
  文件（存在性过滤 + 相对路径清洗）打进 `.gaea/exports/gaea-会话产物-<stamp>.zip`，
  返回 zip 路径/名称/条目数/字节数；复用现有 gaeaCwd/exports 约定与隐藏子进程窗口惯例。
- 前端：DeliverablesPanel 顶栏新增「打包下载」按钮（有产物才显示），点击调绑定、
  toast 反馈 + 文件管理器定位。
- 测试：Go 单测（产物存在/缺失过滤、zip 内容校验、路径清洗防穿越）+ 前端组件测试
  （按钮显隐/点击回调）+ 绑定漂移检查通过。

### P0-2 表格「选中区域 → 一键图表」
- 后端：`GaeaXlsxChart(rel, sheet, refs, chartType, title) (XlsxChartResult, error)`——
  用 excelize 读选中区域（如 `A1:D8` 或 `B2:C20`）的行列数据，识别「标签列 + 数值列」，
  复用 chart_gen 的 Python 脚本生成 PNG 到 `.gaea/exports/`，返回图片相对路径与预览 dataURL。
- 前端：XlsxPreview 选中区域后工具栏出现「图表」按钮（可选柱状/折线/饼图），点击 →
  后端生成 → 打开图片预览（入预览队列）；与 AI 编辑按钮并列。
- 测试：Go 单测（区域解析、数据装配、图表生成 smoke 带跳过标记）+ 前端组件测试 +
  绑定漂移检查。

### P1 产物卡片缩略图增强（视进度）
- docx/xlsx/pptx 在产物面板/交付卡片显示首屏缩略图（复用 AttachmentDataURL 通道，
  后端对非图片返回首屏渲染或类型占位）。
- **实现路径确认（2026-08-17 编码调研）**：`FileThumb` 目前仅图片走
  `AttachmentDataURL`；`GaeaPreview` 对 xlsx 返回结构化单元格 JSON
  （`xlsxpreview.Render`）、对 md/txt 返回纯文本 body。因此 P1 可**纯前端**实现：
  FileThumb 对 xlsx 解析 preview body 前 3-4 行 × 前 3 列渲染「迷你表格」缩略图，
  对 md/txt 渲染首几行文本摘要，图片保持 dataURL `<img>`——零新后端绑定、
  与「预览」共用同一数据源，测试沿用现有 FileThumb 组件测试模式。

## 6. 明确不做

- 团队协作/共享产物：个人工具定位不变。
- 云端表格协作：本地优先。
- 完整表格 AI（透视表/图表引擎重写）：复用已有 chart_gen + excelize，不造新引擎。

### 8.4 结论（补充调研）

三块补充调研共同指向 gaea P2 迭代的三个候选方向：
**多智能体分工可见**（前端子代理卡片，对标 WorkSwarm/QClaw V2）、
**PPT 分阶段工作流**（大纲→逐页→排版，对标千问 AI PPT 全流程）、
**政务模板与格式校验**（对标 WorkBuddy 政务实战/LanMate）。
均与 gaea「性能 + 便捷」的个人工具定位一致，且都已有底座（子代理/pptx 技能/公文模板），
增量闭环。

## 9. 结论

本轮把 gaea 表格能力从「编辑」补齐为「编辑 + 图表」的可交付工作流，并把会话产物
收尾从「复制路径」升级为「一包带走」，两个落点都是 2026 年办公 Agent 竞品已验证、
gaea 已具备底座的增量闭环；补充调研进一步锁定 P2 三个方向（多 Agent 分工可见 /
PPT 分阶段工作流 / 政务模板与格式校验），符合「性能 + 便捷」的个人工具定位。
