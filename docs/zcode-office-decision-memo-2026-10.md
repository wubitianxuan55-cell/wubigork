## 待签第一条：F1「bash 写盘入事实链」怎么落地

**背景**：模型改 docx/xlsx/pptx 走 `bash` + Python 技能，而证据白名单把 `bash` 排除了（`internal/gaea/evidence/evidence.go:381-404`）——写出来的文件对回滚、证据、产物台账全是隐形的。

**建议：探针起步 + 技能显式兜底。**

1. 每次 `bash` 前后做工作区快照 diff，按「声明的产物路径」过滤（声明外视为噪声）；
2. 产物分三档入链：`durable`（交付物，`sha256 + 回执 id + 路径`）→ `derived`（渲染 PDF/PNG，只登「父文件 sha256 + 渲染参数」）→ `ephemeral`（中间文件，不入链，结束校验残留）；
3. 后续给技能加显式 `record_change`，作为精确通道；探针退为兜底；
4. 越界写必须 **fail-loud 回显期望路径集**（静默 deny 会被模型当工具故障，换个名字再试——本对话里双方各复现过一次）。

**成本**：探针 2~3 人日；三分分级 1 人日。
**验收**：Python 生成的 docx 能在「变更/证据」面板里回滚；中间文件不入台账；越界写有明确报错。
**风险**：探针误报（靠声明白名单压噪）；`soffice`/`pdftoppm` 产物被误当交付物（靠 derived 档隔离）。
**不签的代价**：机检与视觉验收都在给"不在台账里的文件"打分，第二周返工。

## 待签第二条：visual-judge 什么时候跑

**背景**：gaea 现在只有 before/after 像素 diff（`gaea_verify.go:66-67`，0.02/0.20），对"首次生成、没人改过"的文档恒为 0，等于没检。ZCode 的 visual-judge 补的是"这一页能不能交"，但全量跑每页一次视觉推理。

**建议：条件全量（双方共同定稿）。**

```
交付前：structure_invariants(file)      # 0 成本：页数/分页点/页码域/TOC/行距/缩进/图片比/跨页标记
  ├─ 与基线不一致 → 全量逐页视觉
  └─ 一致 → 视觉集 = 编辑触及页 ∪ 用户当前页 ∪ 机检可疑页
       └─ 超过 8 页 → 定向抽样（触及页 + 首页 + 末页）
判 fail → 每类缺陷最多修 1 轮（同一 root cause 两轮不收敛就转出）
交付元数据必须带：visual_pages_total / visual_pages_reviewed / visual_skipped_reason
```

**成本**：F2 只读渲染工具（1~2 人日）+ judge 协议与子代理（2~3 人日）。
**验收**：30 页文档默认只审 3~5 页，交付卡显示「视觉覆盖 3/12」；结构不变量被打破时自动升全量。
**风险**：大文档覆盖不全（靠 `skipped_reason` 透明化，不做静默降级）；本地视觉模型质量不足时误判（先只报 fail 不阻断，跑两周再定是否阻断）。
**不签的代价**：要么全量烧钱，要么永远不检——两端都不可接受。

## 待签第三条：锚点（A1）做到什么程度

**背景**：gaea 的"引用到对话"只把选中文字塞进输入框，模型不知道它来自第几段；ZCode 用 `<path>#<locator>` 三方共享寻址。

**建议：会话内锚点 + 编辑后重锚定；持久锚点留 v2。**

依据（ZCode 自证）：docx 的 `p:N` 是**读时位序**，插入一段就漂；它们的引用契约明写 `Locators support only page_number … Do not guess or add object, label, paragraph, table, or cell IDs`（`docx/SKILL.md:282`）。pptx 的 shape 有持久对象 id，但不在 v1 刀序。

- v1：`p:N` / `t:N/rRcC`（docx）、`Sheet!A1`（xlsx）；每次编辑后对受影响段重算文本指纹；`show_in_viewer` 时校验指纹，不匹配就重读重锚。
- v2：跨会话持久锚点（成本高一个量级，且需要稳定的段 ID）。

**成本**：v1 约 3 人日。
**验收**：用户选中第 12 段 → 模型回答里出现 `p:12`；模型 `show_in_viewer(p:12)` → 面板滚动并高亮；在 `p:3` 前插入一段后，旧的 `p:12` 不会指错。
**风险**：指纹算法要能只 hash 变更段（否则每次编辑全量重算）。
**不签的代价**：「这里改一下」永远需要一轮反问。
