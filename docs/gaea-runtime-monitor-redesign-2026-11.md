# 运行监测 UX/UI 重构与调用统计细化（2026-11-03）

> 状态：✅ 已实现，已通过桌面构建与冒烟。本文记录信息架构、统计口径、交互、验证、截图和产物身份。

## 1. 问题与目标

旧版运行监测以舰桥 HUD 和硬件遥测为视觉主轴，调用统计被放在 344px 右栏；时间范围只影响两张小图，模型明细不能搜索或排序，失败、耗时和错误原因也缺少聚合入口。此次重构把页面从“遥测展示屏”调整为可完成日常判断的运营工作台：

- 先回答运行是否正常、当前是否在生成、有多少引擎在线。
- 再回答所选时间范围内调用多少、成败如何、用了多少 Token、花费多少。
- 继续提供调用趋势、耗时分布、近期错误和模型级异常定位。
- 最后展示引擎请求日志与本机硬件资源，避免硬件指标抢占首屏。

## 2. 信息架构

页面按以下顺序组织：

1. 页面标题、更新时间、实时刷新状态和全量刷新入口。
2. 运行状态摘要：服务状态、引擎连接数、当前生成速度和上下文压力。
3. 调用统计：今日、最近 7 天、最近 30 天范围切换。
4. 调用 KPI：调用次数、成功率、Token 用量、估算费用。
5. 分析面：调用趋势、成功率拆分、近期平均耗时/P95/耗时桶、近期错误。
6. 模型调用明细：搜索、需关注/本地/云端筛选和多列排序。
7. 运行状态：当前推理、上下文、会话缓存、硬件资源和引擎卡。
8. 最近请求：全部/失败筛选，保留错误原因与缓存命中。
9. 引擎侧请求：Prompt、Prefill、Decode、缓存命中与耗时。

## 3. 调用统计口径

为避免把不同来源的数据混成一个数值，页面明确分区：

| 展示项 | 数据来源 | 口径 |
|---|---|---|
| 调用次数、成功率、Token、费用 | `getModelCallStats().trend` | 当前“今日/7 天/30 天”范围内聚合，切换范围会重算 |
| 调用量与失败趋势 | `getModelCallStats().trend` | 今日按小时桶，7 天/30 天按日桶；红点表示该桶存在失败 |
| 平均耗时、P95、耗时桶、近期错误 | `RuntimeMonitor().recent_calls` | 最近请求样本，不冒充时间范围全量 |
| 模型明细 | `getModelCallStats().per_model` | 累计口径；支持搜索、范围筛选和排序 |
| 上下文、缓存、引擎请求 | `RuntimeMonitor()` 的 Strata/Tianxuan `/metrics` | 最近一次请求或引擎会话缓存，不冒充统计总数 |

健康阈值采用“文本 + 图标/形状 + 颜色”三重表达：成功率低于 95% 显示风险态，模型存在失败或小样本低成功率时标记“需关注”，但原始失败次数和错误文案始终可读。

## 4. 交互与可访问性

- 范围切换、错误重试、刷新入口均使用原生按钮或 Ant Design 分段控件，保留键盘焦点。
- 模型搜索覆盖模型 ID 与引擎名称；筛选与排序可组合使用。
- 最近请求可切换“全部/失败”，失败行直接显示错误原因，完整错误仍保留 Tooltip。
- 图表提供 `role="img"`、可读标题和每个数据点的 Tooltip。
- 图表下方提供可展开明细表，避免只能通过颜色或悬浮读取数据。
- 加载态使用与 KPI 形状一致的骨架；统计、模型明细、页面快照分别有独立空态与错误态。
- `prefers-reduced-motion` 下停止呼吸、骨架与进度过渡。
- 375px 以下图表进入独立横向滚动容器，轴标保持可读，页面本身不产生横向溢出。

## 5. 视觉策略

- 方向：数据密集型运营仪表盘，密度 8、动效 3、布局变化 5。
- 使用现有 Gaea 主题令牌，单一强调色；绿色/红色仅表达成功/失败语义。
- 去掉扫描线、HUD 角标、多层霓虹和编号节标，降低装饰噪声。
- 数字与模型 ID 使用等宽或表格数字排版，正文控制行宽和层级。
- 面板以边界、留白和轻量表面区分层级，不堆叠同形卡片。
- 亮色与暗色共用同一结构；亮色单独降低表面混合强度。
