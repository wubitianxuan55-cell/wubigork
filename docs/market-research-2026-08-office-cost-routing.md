# 市场调研：云端牵头 + 简单任务分流（模型降本路由），2026-08

> 目的：为 gaea「主任务由云端强模型牵头，简单/常规任务交给免费云端或本地模型，
> 降低成本」的策略提供设计依据。调研同类产品如何做"模型编排/分流"——是强制路由，
> 还是只提供入口由主模型决定。来源为 2026 年公开资料与官方文档。

## 0. 一句话结论

**行业共识不是"按任务类型写死路由规则"，而是"入口 + 映射 + 由主模型/路由器决定"**：
Claude Code 用三层模型级别（Opus/Sonnet/Haiku）映射到具体模型，子 Agent 默认走最便宜
级别；Cursor 用复杂度预测器 + 任务分类器自动选模型；LiteLLM 在网关层做预算降级、缓存、
压缩与自动路由；Coze 工作流把"意图识别 → 分流 → 轻量/强模型"显式搭在流程里；
Aider/Codex 用"强模型规划 + 便宜模型执行"两段式。**对 gaea：我们只提供入口（工具 +
可配置目标模型 + 引导），由云端 agent 自行决定何时把简单活卸给本地/免费模型**，符合
用户已确认的方向，也符合行业主流。

## 1. 竞品做法矩阵

| 产品 | 路由形态 | 简单任务怎么分流 | 可蒸馏要点 |
|---|---|---|---|
| Claude Code | 三层模型级别：Opus（复杂推理）/ Sonnet（标准）/ Haiku（快速查询+子 Agent），环境变量映射到具体模型 | 内置 Explore 子 Agent 默认走 Haiku 级；`CLAUDE_CODE_SUBAGENT_MODEL` 一键把全部子 Agent 指到便宜模型 | ① 按"角色/层级"分流而非"任务类型"；② 映射可配置；③ 自定义 subagent YAML `model:` 字段可单独指定 |
| 社区 Claude Code 降本 | 主 Agent 用 DeepSeek V4-Pro，子 Agent 用 V4-Flash | 4 子 Agent 重构任务从 $22.4 降到 $0.51~$1.29（约 1/17） | ④ 子 Agent 是最先该换便宜模型的地方；⑤ 显式绑定比全局兜底可靠 |
| Cursor Router | 两段式：Compass 复杂度预测（0-1 分）→ 低于阈值走便宜模型（Grok）；高于阈值用任务分类器（domains/tasks/modifiers）选 frontier | Auto Intelligence：Fable 级满意度、成本 -68%；Auto Balance：超 Opus 4.8 满意度、成本 -41% | ⑥ 复杂度预测器决定"够不够简单"；⑦ 只有性能明显更好（75% 置信）才升级；⑧ 预算约束控制成本-质量曲线 |

## 2. 对 gaea 的设计含义

用户方向：**主任务云端强模型牵头，简单事交给免费云端/本地，我们只提供入口**。
行业验证这条路径成立，且"入口"具体有三层，gaea 的落点分别是：

1. **工具级入口（本轮）**：`routine_llm` 工具——云端 agent 按需把摘要、归一化、抽取、
   改写等一次性常规推理卸给目标模型（模型中心「常规办公」绑定，默认本地 herdsman，
   可切免费云端），可显式 `engine/model` 覆盖。等价于 Claude Code 的 Haiku 级映射 +
   LiteLLM router 的入口侧；**不强制分流，调用与否由云端 agent 决定**。
2. **子代理/技能级入口（已有，需引导）**：`task` 子代理与 `run_skill` 技能支持模型
   绑定（`subagent_model` / 技能 model 字段）。给"常规技能"（如 format-convert、
   doc-assemble 子代理）配上便宜模型目标即可复用，无需新代码。
3. **网关级（明确不做）**：LiteLLM/RouteLLM 式集中路由需要代理层与训练数据，对个人
   桌面应用过重。可借鉴的只有两点：预算降级（成本库已有价格历史基础）与成本可见性
   （stats 已有 token 统计，缺本地/云端分流对比面板，P2）。

## 3. 结论

行业不做"写死任务类型路由"，而是**内建模型级别映射 + 由主模型/路由器决定**；成本大头
在子 Agent 与机械执行，其次才是缓存/压缩/预算。gaea 按"提供入口、云端决定"落地的
最小集是：`routine_llm` 工具 + 「常规办公」目标模型绑定 + 系统提示词引导（说明该工具
何时值得用）。复杂度预测器、学习式路由器留给数据充足后再议。

## 4. 修订（2026-08-11）：从"通用兜底"到"专业小模型分工"

初版把 `routine_llm` 当"简单任务统一入口"，方向被用户纠正：**不是加一个大模型干所有
活，而是云端大模型对基础工作做二次分配与汇总，简单无脑的活分给多个本地专业小模型，
各有专长**。修订后的落地：

- **云端 agent = 调度者**：识别任务类型 → 选对应专业工具 → 汇总结果交付；不做硬编码路由。
- **本地专业工具 = 一专一能**（均为本地/免费，不消耗主模型 token）：

| 任务 | 工具 | 本地专业模型/服务 |
|---|---|---|
| 看懂图片内容（布局/对象/图表） | `vision` | Herdsman 视觉模型（Qwen3.6） |
| 提取图片/扫描件精确文字 | `ocr` | OvisOCR2 常驻服务（回退 tesseract） |
| 成本/知识/办公记忆语义检索 | `semantic_search` | bge-m3 向量 + bge-reranker 精排 |
| 文档格式转换（docx/xlsx/pdf→md） | `format_convert` | 本地解析 + OCR 回退 |
| 统计图表 / 流程图等 | `chart_gen` / `diagram` | 本地渲染（图表） |
| 截屏后理解屏幕 | `screen_capture` + `vision` | 本地 |

- `routine_llm` 降级为**通用文本兜底**：仅当任务不在任何专业工具职责内、只是纯文本处理
  （摘要/归一化/JSON 抽取/格式整理/低风险改写）才调用，走「常规办公」绑定，默认本地。
- 系统提示词新增「专业分工」引导，明确各工具职责边界与"工具优先、兜底在后"的调度顺序。
- 能力面板新增「本地专业模型」分组（vision / ocr / semantic_search），与通用办公分开展示。

这一形态与行业一致：Coze 的"意图识别→分流到专门节点"、Claude Code 的"按角色/层级映射
模型"本质都是**多专长模型协作 + 主模型调度**；gaea 的差异点是专业模型全部本地化，成本趋近于零。
