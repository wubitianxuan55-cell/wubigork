## 0. 三道闸（收益判定口径）

| 闸 | 问题 | 不过闸的例子 |
|---|---|---|
| **闸 1 · 可感知** | 用户能不能看到差别（不丢数据 / 不出错 / 更快 / 报错更准）？ | "架构更清晰"——不算 |
| **闸 2 · 可度量** | 有没有一个数字能证明改前改后不同？ | "更健壮"——不算，除非给出"崩溃后历史一致率 100%" |
| **闸 3 · 成本 ≤ 收益** | 工期是否 ≤3 天/项？（超了必须拆） | "顺手重写持久化"——不算 |

三条反例（本轮明确**不做**的类型）：
1. **为了对齐上游而改**：codex 有 daemon、有 EMA、有插件市场，gaea 单进程本地用不上 → 不排。
2. **为了"看起来专业"而加抽象**：把 4 套截断改成一个 Policy 是**修 bug**（UTF-8 非法）顺带做的事，不是为抽象而抽象。
3. **抄实现细节**：抄 `noise_relay` 的 Noise 实现、抄 `TaskTracker`——境界不同，抄了是负债。

## 2. 排期（按收益密度，不按上游编号）


## 3. Wave 1 施工卡（每项：痛点 → 改什么 → 度量 → 验收 → 回退）

### P1 · 准入与优雅关闭（B1，1.5 天）

- **改什么**：`Controller` 增加 `draining bool` + `admitted int` + `admit()/release()`；`BeginDrain(ctx, timeout)`；
  `Send/Submit` 在 drain 后返回结构化错误（不静默）；`App.Shutdown` 每步加超时 + 外部进程 stderr 尾截断 4 KiB。
- **度量**：① 关窗时"未落库回合数" = 0；② 关停总耗时可测且 ≤ 设定超时之和；③ 二次启动不重跑同一回合。
- **验收**：A1 关闸后 `Send` 返回 draining 错误且不启动回合；A2 关闸前已准入的回合跑完才返回；
  A3 超时→强制取消并落一条 `TurnDone{Err}`；A4 关停某步挂起不阻塞整体退出（DB 关闭步骤除外，必须完成）。
- **回退**：开关 `drain.enabled=false` 时行为与现状逐字节等价（事件序列快照对比）。

### P2 · 截断口径统一（B12，1 天）

- **改什么**：新增 `internal/gaea/strutil/truncate.go`（`Policy{Bytes|Tokens}`，4:1 互折，头尾 50/50，
  `WithSerializationAllowance ×1.2` 只乘一次）；四处旧实现改为薄封装；统一省略提示文案。
- **度量**：① 截断后 UTF-8 合法率 100%（现 `truncateStr` 会碎）；② 长输出**尾部保留率**（错误行/结论行不丢）；
  ③ 上下文占用可预算（同一 Policy 下字节数可预测）。
- **验收**：T1 1001B ASCII → 头 500 + marker + 尾 500（奇数尾多 1）；T2 含 emoji/中文输出合法 UTF-8；
  T3 `WithSerializationAllowance` 不重复乘；T4 dedup key 语义稳定（或一次性重建缓存）。
- **回退**：旧函数保留（行为可切换），缓存键迁移用一次性开关。

### P3 · 工具归因（B5 只取归因，0.5 天）

- **改什么**：把 `auditFunc` 的签名扩展为携带 `call_id`、`turn_id`、`model`、`parent_tool`（或改成结构体入参）；
  `taskKind` 不再固定传空串。
- **度量**：任取一次工具调用，能从审计反查到"哪个回合 / 哪个模型 / 哪次调用"，成功率 100%。
- **验收**：A5 一次带回环的工具调用，审计记录里 `turn_id` 与 `TurnStarted` 事件一致；A6 并发工具调用不串号。
- **回退**：新字段可空；审计写入失败不影响主路径。

### P4 · 出网安全 + 构造即验证（B9/B7 各取一半，0.5 天）

- **改什么**：① `provider/outbound.go`：`Policy` + `Acquire(url)` + 四态拒因（`Unavailable/Destination/Revoked/UnsupportedTransport`），
  发送前判定；跨源重定向去 `Authorization`/`Cookie`/`Proxy-Authorization` 并补 `Referer`，≤10 跳；
  ② 安全相关构造函数一律"构造即验证"，不提供"默认宽 + 后设窄"的 setter。
- **度量**：跨源 302 后敏感头泄露次数 = 0；策略缺失时默认拒绝且错误可读。
- **验收**：N1 `http://` 在 Restricted 下被拒；N2 尾点主机名归一；N3 跨源去头、同源不去；N4 11 跳终止。
- **回退**：默认 `Unrestricted`（关时行为等价）。

## 5. 明确不做清单（归档，附理由）

| 不做 | 理由（一句话） |
|---|---|
| daemon / 多传输 / socket 控制面（B2） | gaea 是 Wails 单进程桌面应用，多入口是纯成本 |
| 远程执行器（B11） | 无跨机执行需求；协议与沙箱完整性校验都是为题外场景服务 |
| 插件市场与远程分发（B7 主体） | 做市场 = 引入"下载并执行第三方资源"的攻击面；没有生态诉求时是净负债 |
| MCP 客户端 EMA/企业鉴权（B8） | 单用户本地，无企业 IdP |
| codex-mcp 服务端（把自身工具暴露成 MCP） | 无外部 MCP 客户端消费方 |
| otel 全套导出（B10 主体） | 引入 opentelemetry 依赖与 consent 复杂度；本地事实流已能回答关键问题 |
| rollout-trace bundle（B10 子项） | 只有当"可回放排障"成为明确需求时才做 |
| 抄具体实现（Noise、TaskTracker、ArcSwap） | 抄语义可以，抄实现是负债 |

## 6. 三个拍板门（不拍板就卡在 Wave 2）

1. **权限是否属于 step 快照维度？**（建议：属于。即时生效只影响下一次审批请求，不改已准入回合的审批权威）
2. **投影失败允许"滞后"吗？**（建议：允许滞后、禁止超前；断言先灰度成 warn，一版后升为 error）
3. **观测数据落盘位置与保留期？**（建议：`whisperDataRoot/telemetry`，保留 14 天，默认关闭）
