# gaea V3.0 愿景框架（独立思考草案 v0.1）

> 状态：核心论点草案 —— 基于 9 份架构评审报告与 agent 工程专业判断起草；
> 待 4 份市场/社区调研报告（r1-r4）到达后，以证据修订并合成最终《V3.0 愿景与路线规划》。
> 本文档是"思考本身"，不是最终交付物。

## 0. 一句话定位

**gaea V3.0 的愿景：从"多功能 AI 助手"（八个互不相关的板块）升级为"个人 AI 智能体平台"——
一个 agent 内核、一套会话事实源、统一记忆层，板块 = 内核之上的声明式插件。**

## 1. 事实前提（来自 9 份评审报告，全部带文件:行号证据）

1. gaea 已拥有国内同类桌面产品里罕见的完整 agent 引擎：办公板块（42 工具、规划/执行/审批/会话、MCP 客户端、技能、记忆/知识/成本库）。
2. 但八个板块是"方法直调 + 页面私有状态"的拼盘：只有办公板块接近"板块自治"，其余全是静态路由 + 直连调用。
3. 会话无事实源（整文件重写 JSONL）、事件零持久化、审计离线、provider 硬编码 39+ 处——地基欠债。
4. 轻语（人格陪伴 + LLM 记忆管线 + 语音）、记忆中枢（8 库）、角色库、绘梦、小说——这些是竞品各自单独做一类的模块，gaea 全有但互不相通。

## 2. 市场坐标（待 r1-r4 验证，先列专业判断）

- 编码 agent（Claude Code/Codex/Cursor）证明了"agent 工作台"UX 成立；但它们是单任务域。
- 本地桌面助手（Jan/Chatbox/Cherry Studio）是聊天型，没有 agentic 能力；中文写作工具是内容生成型，不是工作台。
- 记忆产品（Letta/Mem0/Zep）证明"记忆即数据层"是趋势，但脱离具体任务域。
- **空白：没有人把"个人全任务域 agent 工作台"做成本地桌面产品**——gaea 的模块集 + agent 引擎恰好是这个空白的候选者。
- DSH 的价值不在功能，在于架构范式（事件日志事实源/插件化/seam），是 gaea 3.0 地基的参照系，但 gaea 不应是"DSH 的 Go 克隆"——gaea 的产品坐标是个人多域助理，DSH 是通用 harness。

## 3. 愿景四支柱

### P1 一个内核（One Substrate）—— 插件化地基（共识前提，纳入而非全部）
- 事件日志事实源 → 会话可回放/分叉/恢复，是所有上层能力的地基。
- 板块 Manifest → 板块是声明，不是代码；加板块不动壳。
- Provider Seam → 换模型/换后端只改配置。
- 产品意义：聊天/轻语/小说/办公/编程……全部变成**同一个 agent 内核的模式**，共享会话、记忆、模型路由。

### P2 板块生态（Board Ecosystem）—— 3.0 区别于 2.x 的产品层
- 首方板块先迁移（chat/novel 先试点，编程板块作为 manifest 机制的第一个新板块）。
- 技能/提示词/预设作为"内容"进入板块（skill 已在办公板块内证明可行）。
- 远期：第三方板块 + 分发（配置文件即可安装）。

### P3 统一记忆与身份（Unified Memory & Identity）—— gaea 独有资产的重组
- 现状：8 个记忆库 + 三脑 + 数字生命各自为政；轻语有 LLM 记忆管线，办公有 memory/knowledge/cost，记忆中枢只是聚合展示。
- 目标：一个记忆层，带来源（事件日志出处）、分层（事实/画像/情境/程序化）、可审计；**人格连续性**——轻语的"她"认识你、记得你们的对话，小说角色库、办公知识库共享同一事实底座。
- 数字生命（digitallife）作为记忆层的长期演化形态：agent 拥有连续的身份与记忆，而非每次会话冷启动。

### P4 治理下的自主性（Autonomy with Governance）—— agent 化的完成态
- 子代理、目标循环、定时任务、工作流——但全部在审批/沙箱/审计之下（办公板块已具备三件套，需强化 Windows 沙箱）。
- 跨板块任务流：写小说需要绘梦封面、办公生成图片、记忆提供素材——以子代理/任务方式协作，**不复活"单窗口编排"UI**。

## 4. 初步版本路线（待调研修订）

| 版本 | 主题 | 用户可感知交付物 | 核心工程 |
|---|---|---|---|
| 3.0.0 | 地基 | 会话崩溃可恢复；板块切换更顺滑；首个 manifest 板块 | Step 0-3 + chat/novel 迁移试点 |
| 3.1.0 | 板块生态 | 编程板块（代码工作台）；技能/预设可安装；MCP 管理 UI | manifest 生态化 + run-code |
| 3.2.0 | 自主协作 | 子代理任务流（跨板块）；定时/目标任务；记忆统一带出处 | subagent UI + memory 统一 |
| 3.3.0+ | 身份 | 数字生命深化；人格连续性跨板块 | identity layer |

## 5. 专业判断的诚实声明（不奉承的部分）

1. 愿景的价值密度取决于地基质量：如果 3.0.0 只发架构不发用户价值，就是"为架构而架构"——所以 **3.0.0 必须至少让一个现有板块（chat）迁移到新地基并让用户感到"变好了"**（如会话恢复/回放）。
2. 编程板块是**验证机制**的最好试点（工具集过滤/工作区/模式预设全部首次实战），但它不该是 3.0 的核心卖点——**个人多域助理的核心卖点是"记忆+连续性"**，编程只是其中一域。
3. Windows 沙箱与包级全局注入不修，自主性愿景就是空话（评审报告已证实 bash 无 OS 隔离）。
4. 不要试图一次做完：3.0 的敌人是范围蔓延，四支柱每根都要一年以上的持续投入，先做 P1+P2 的 3.0.0-3.1.0。

## 6. 需要调研回答的问题（r1-r4）

- r1：DSH 公开定位与差距；agent 工作台的共性架构证据。
- r2：中文小说/陪伴市场是否证明"多域合一"有需求；本地桌面助手的空白是否属实。
- r3：记忆架构与多代理编排的工程共识。
- r4：插件生态量级与个人工具的商业模式事实。

## 7. 版本路线的 gaea 具体化（基于 9 份评审报告的能力清单）

### 3.0.0「地基 · 让一个板块先变好」
- 工程：Step 0-3（事件日志/Manifest/Seam）+ chat 或办公板块迁移到新地基。
- 用户可感知：办公会话断电/崩溃可恢复（torn-tail）；会话统计/成本/标题准确（日志派生）；多前端（手机经 httpbridge）看同一会话；设置/模型中心配置一处生效（seam）。
- 首个 manifest 板块候选：**恢复挂载知识库板块（KnowledgePage 现成，最小试点）**，验证"加板块只写声明"。
- 里程碑判据：chat 会话从"刷新即丢"变为"可恢复可回放"——一个用户摸得到的改变。

### 3.1.0「板块生态 · 编程板块落地」
- 工程：manifest 生态化（技能/预设/工具集过滤）；run-code 最小路径；MCP 管理 UI；grep 工具。
- 用户可感知：**编程板块**（任意文件夹工作区 + 代码对话 + 文件树/预览/变更面板 + bash 终端输出）；技能/提示词可安装；MCP 服务器可视化配置。
- 里程碑判据：用户把任意代码仓库交给 gaea 完成一个真实任务（修 bug/加功能），全流程在板块内闭环。

### 3.2.0「自主协作 · 跨板块任务流」
- 工程：子代理编排 UI（办公引擎已有 subagent 机制，补可视化）；目标/定时任务（已有 tasks/调度雏形）；记忆层统一带出处。
- 用户可感知：一句话触发跨板块任务（"给小说第三章配封面图"→ novel 调 imagegen）；夜间定时任务（"每天整理今日记忆/生成周报"——已有 dream 机制雏形）；记忆中枢从聚合展示变为可查询可审计的事实底座。
- 里程碑判据：跨板块任务流在无人工干预下完成率可度量。

### 3.3.0+「身份 · 人格连续性」
- 工程：identity 层（数字生命 digitallife 深化）；跨板块人格/记忆共享；本地模型优先的离线 agent 体验。
- 用户可感知：轻语的"她"在办公/小说/编程板块延续同一记忆与身份；离线可用（本地模型引擎已有 herdsman/ollama 支撑）。

## 8. 护城河分析（客观，不吹）

| 维度 | 现状 | 3.0 目标 | 现实评估 |
|---|---|---|---|
| 多域合一 | 8 板块但互不相通 | 一个内核多板块 | gaea 是国内少见把陪伴/写作/办公/绘梦放一桌的；但互不相通 = 假合一，3.0 打通才有真护城河 |
| 记忆连续性 | 8 库 + 三脑 + 轻语管线各自为政 | 统一记忆层带出处 | 记忆是差异化最可能的来源，但工作量与数据质量挑战大 |
| 本地/隐私 | 本地 SQLite + 本地模型支持 | 离线 agent 体验 | 隐私是卖点但"本地 agent"性能/体验受模型约束，需诚实管理预期 |
| 编码能力 | 无 | 编程板块 | 单域能力 vs Cursor/Claude Code 是劣势；**编程不是护城河，是验证机制与补齐入口** |
| 生态 | 无 | 技能/预设/板块 | Obsidian 证明了个人工具插件化有量级，但 gaea 无社区基础，生态是长期投资不是短期卖点 |

## 9. 风险清单（专业判断）

1. **范围蔓延**：四支柱都想做 = 3.0 永远发不出。硬约束：3.0.0 只做 P1 + 一个板块迁移 + 知识库试点。
2. **架构期用户价值真空**：阶段 7（v2.34-2.37）全是正确性修复（用户无感），3.0.0 若继续无感 = 近半年用户看不到进步。缓解：3.0.0 的"会话可恢复"必须做成可见卖点；阶段 7 中穿插小功能。
3. **安全债**：Windows 沙箱名存实亡（评审证实），自主性越强风险越大；3.2 的自主化之前必须补 fail-closed。
4. **无反馈闭环**：单用户产品没有遥测/用户访谈，愿景建立在假设上。缓解：调研 + 至少 5 个真实用户试用计划。
5. **DSH 对齐过度的反向风险**：地基借鉴 DSH 是对的，但产品若变成"DSH 的 Go 克隆"就失去 gaea 的身份；保持"个人多域助理"的产品坐标。
6. **模型依赖**：本地模型质量/云端成本决定自主性体验；模型中心已是优势（多引擎），继续投资。

## 11. 板块 → 内核迁移映射（工程事实，来自 9 份评审报告 + digitallife 核查）

### 11.1 现状事实修正
- **数字生命 = Herdsman 的域，gaea 只是只读观众**（herdsman_digitallife.go：只读 digital-life/life.sqlite3，注释明言"绝不修改 Herdsman 数据"）。→ P4「身份」愿景必须诚实：人格引擎在 Herdsman 手里；gaea 若要自己的"人格连续性"，需要建自己的 identity 层，或与 Herdsman 深绑。3.3.0+ 再决策（这是依赖项，不是 3.0 主线）。

### 11.2 每个板块在 3.0 内核的落点

| 板块 | 现状（证据） | 3.0 落点 | 迁移难度 |
|---|---|---|---|
| 聊天 | ChatSend 按 mode 路由 whisper（chat_service.go:27-35）；ChatPage 3 hook 编排 | 内核会话日志 + 轻工具模式（默认无工具或最小工具） | 低（先迁移，示范"会话可恢复"价值） |
| 轻语 | 独立状态机 + LLM 记忆管线（whisper 232 文件）；VoiceB 绑定 | 保留人格层与语音链，会话/记忆改接内核（评估期可保持独立存储，仅事件日志可观测化） | 中（07 报告：先可观测后改恢复） |
| 小说 | 6 lazy 子页 + 域 agent（worldview/character/outline）+ 章节流式 | 域 agent 挂到内核（novel 板块 = 内核的"小说模式"，域 agent 变成工具/子代理） | 中高（域 agent 是独立的，接入成本在会话与记忆） |
| 绘梦 | image_gen 已作为办公引擎 ExtraTool（gaea_tools.go）——**已证明"板块→工具"可行** | 保持工具形态 + 独立页面包裹；seam 化后端 | 低（先例存在） |
| 办公 | 完整 agent（42 工具/MCP/skills/memory/knowledge/cost） | 就是内核本身，3.0.0 先做地基化（事件日志） | 内核 |
| 记忆中枢 | 8 库聚合展示 | 升级为记忆层管理面（统一出处、可审计、跨板块查询） | 中 |
| 模型中心 | 多引擎管理（modelengine） | seam 注册表的管理面（换 provider 只改配置） | 低（08 报告 Step 3） |
| 角色库 | chat/novel 共享（characterlib） | 板块级共享资产，进统一身份层 | 低 |
| 微信助手 | ClawBot 长轮询 beta | 服务板块（无页面），进 manifest 作服务型板块先例 | 低 |

### 11.3 迁移原则
1. **从"用户摸得到"的板块开始**（chat），不是从最大的（办公）开始——3.0.0 的价值证明优先。
2. **先机制后全量**：知识库（最小 manifest 板块）→ chat（会话价值）→ 绘梦（工具先例）→ 小说（域 agent 接入）→ 轻语（评估后）。
3. 每迁移一个板块，保留旧实现一个版本（wailsjsCompat 先例：兼容层过渡），杜绝"大爆炸式"切换。
