# 市场调研：成本库功能深化（导入/AI 提取/管理/定时抓价）+ 规模化检索，2026-08

> 目的：为 gaea「成本库」第二轮升级提供设计依据。第一轮已打通办公 ⇄ 记忆中枢成本库
> （cost_search/cost_save 工具 + 右侧成本库 Tab + 产物沉淀）。本轮要解决：
> ① 文件导入 + AI 解析提取成本数据；② 修改/删除等管理操作；③ 定时向固定网站抓取价格
> 实时更新；④ 数据量增长后的有效检索（本地模型 rerank，如 bge-reranker-v2-m3）。
> 来源：2026 年公开资料 + 官方文档 + Herdsman 接口文档（仓库内 herdsman-api-docs-2026-08-08.md）。

## 0. 一句话结论

行业对「成本/价格数据」的运营共识是**「采集 → 提取 → 管理 → 更新 → 复用」全闭环**，且把
「导入即结构化、来源可溯、价格可更新」当作产品标配：广联达靠「供应商报价单批量导入 +
AI 组价匹配（匹配率超 80%）+ 企业材料价格库」把询价变自动化；慧讯网/造价通用「专业信息员
定期更新 + 信息价/市场价 API」维持价格时效；千问/飞书把「传文件 → AI 提取 → 入表」做成一等
公民交互；价格行情侧（水泥行情通、1688、钢联）提供日度报价与开放 API。
对 gaea：**P0 做「导入 + AI 提取 + 确认入库」与「条目管理增强」，P1 做「价格源订阅 +
手动/定时抓取 + 价格历史」，检索按数据量分级演进，最后接本地 rerank（bge-reranker-v2-m3
经 Herdsman /v1/rerank）做精排。**

## 2. 可借鉴要点（映射到 gaea）

1. **导入即结构化（办公 → 成本库）**：xlsx/csv/PDF/图片报价单 → AI 提取「名称/规格/单位/
   单价/来源/时间」→ 预览确认 → 批量入库。飞书「识图入表」、千问「传文件即解析」都是这个
   交互；且行业普遍要求**确认后才落库**（避免噪音）。
2. **价格三要素：规格 + 地区 + 时间**：慧讯网/造价通/行情通全部按这三维组织价格。gaea 成本
   条目目前只有 spec/source/updatedAt，需要补「地区」「价格时间/期数」与**价格历史**（同一
   条目多次价格快照，可回看环比）。
3. **价格时效是产品力**：慧讯网靠「定期更新数据库」、行情通靠「每日报价」。gaea 定时抓价
   的正确形态 = 订阅源配置（URL + 解析规则）→ 调度器触发 → 抓取 → 解析 → 匹配既有条目 →
   旧价入历史、新价更新 + 变更高亮 → 人工确认发布。
4. **来源与异常可溯**：广联达对百万级清单做价格异常识别并溯源；成本条目必须有 source 且
   更新时保留历史，AI 引用时能交代「依据哪一期、哪个来源」。
5. **检索分级**：数据少（<5k）LIKE 够用；中量（5k–50k）加 BM25/FTS5 与字段加权；大量或
   模糊语义（"液压振动锤 300kW" 找 hp300）加 embedding 召回 + 本地 cross-encoder 精排。
   精排候选要限流（top 50–100）、输入截断（bge-reranker-v2-m3 官方建议 ≤1024 tokens）。

## 3. gaea 现状盘点（基于代码，2026-08-10）

### 已有
- 成本库存储：Hephaestus.db `cost_entries`（SchemaV2），cost.Store 提供 Save（同名 UPSERT）/
  Get/Delete/List/Search（关键词 LIKE title/spec/source/body + category/status 过滤）。
- 代理工具：cost_search / cost_save（builtin，同名覆盖、标题自动生成稳定 name、分类概览）。
- 前端：记忆中枢 CostLibrary（搜索/筛选/新建/编辑/删除 Modal）；办公右侧成本库 Tab
  （浏览/搜索/一键引用）；产物面板「沉淀到成本库」指令。
- 文件解析基建：xlsxpreview/xlsxedit、format_convert（docx/xlsx/pdf → Markdown + OCR 回退）、
  XlsxPreview 表头+行读取——导入解析可直接复用。
- 网络基建：web_search（SearXNG/Tavily/Brave/Bing/DDG）、web_fetch（去标签、代理、重试）。
- 本地模型：Herdsman（localhost:8080/v1）已暴露 GET /v1/models、POST /v1/embeddings、
  POST /v1/rerank——**接口就绪，只差安装 bge-reranker-v2-m3 等模型**。

### 缺口（本轮差距）
- 无「导入」入口：面板不能选文件 → 解析预览 → 确认批量入库（目前只能靠产物面板指令让
  agent 逐条 cost_save）。
- 管理弱：办公侧只读；记忆中枢有 CRUD 但无批量/多选、无价格历史、无地区/价格时间字段。
- 无价格源与调度：无订阅源配置、无定时抓取、无价格变更快照；app 内无 cron/ticker 基建。
- 检索原始：Search 为单关键词 LIKE，不含 name/tags（标签是别名/相近规格的重要信号），
  无 BM25、无向量、无 rerank，数据一多会漏召+误召。

## 5. 设计决策与强化清单

### P0（核心闭环，全部复用现有基建）
1. **成本库面板「导入文件」**：选 xlsx/csv/PDF/图片 → 复用 xlsxpreview/format_convert 读表头
   与行 → 后端返回「候选条目预览」（列映射 + 名称/规格/单位/单价/来源），UI 勾选/修正 →
   确认后批量 cost_save 入库（**无确认不落库**，对齐飞书确认式入表）。
2. **AI 提取归一化**：对报价单类文件（列名不规范、含备注/起订量/含税标记）先用本地或云端
   模型把行归一化为成本条目字段；结构化 xlsx 直接按列映射（ChatGPT 纪律：表头+样本值给
   模型，计算/转换用代码）。
3. **条目管理增强**：办公侧成本库 Tab 增加编辑/删除（复用记忆中枢 Modal 逻辑）；列表支持
   多选批量删除/批量改状态；搜索补 name/tags 命中（Search SQL 增加两字段）。
4. **来源/时间必填校验**：cost_save 与导入保存时 source 建议必填、记录 updatedAt；同名
   覆盖时提示「将覆盖旧价」（面板可见），为价格历史铺路。

### P1（价格更新 + 检索精排）
5. **价格源订阅**：新增「价格源」配置（名称 + URL + 解析方式：CSS 选择器/表格列映射/API +
   频率）持久化到 Hephaestus.db 或 JSON；内置常用源模板：各市造价信息网、水泥行情通、
   1688 商品/报价接口、造价通开放平台（需令牌）。
6. **手动/定时抓取**：面板「立即抓取」按钮 + app 内 ticker 调度（每日/每周/每期，桌面临近
   进程）；抓取 → 解析 → 按「规格+名称」模糊匹配既有条目 → 价格历史表记录旧价 → 新价待
   确认列表（变更高亮 + 环比）→ 用户一键发布或忽略。
7. **价格历史**：新增 `cost_price_history`（或 cost_entries 加 price_updated_at + history
   JSON）；条目详情展示价格曲线/最近 N 期。
8. **检索升级（本地模型）**：见 §6。

### P2（可选）
- 价格异常识别（偏离历史/市场区间时高亮并溯源）、规格标准化与单位换算、成本库导出、
  供应商维度（报价单 → 供应商档案 + 比价）。

### 明确不做
- 企业级组价/定额引擎、云端团队共享、无人确认自动写入（抓价结果必须人工确认发布）、
  直接对接付费行情 API 默认采购（留开关，用户自己配令牌）。

## 6. 规模化检索方案（重点回答）

### 6.1 数据量分级与瓶颈
| 量级 | 检索手段 | 说明 |
|---|---|---|
| <5k 条 | SQL LIKE（补 name/tags）+ 分类/状态过滤 | 零模型成本，秒回；现有 Search 补字段即可 |
| 5k–50k | 加 BM25/FTS5（复用 memory.SearchIndex 的 BM25 实现或 SQLite FTS5） | 关键词召回质量显著提升，仍无模型 |
| >50k 或强语义 | 多路召回 + 本地精排 | 语义别名（"液压振动锤" ↔ hp300）靠 embedding 召回，cross-encoder 精排 |

### 6.2 推荐架构：两段式「召回 → 精排」
```
查询 → ①粗召回（并行）：
        SQL LIKE(name/title/spec/source/tags/body) + category/status 过滤
        + BM25 文本召回（memory.SearchIndex 模式）
        + （可选）bge-m3 向量召回 top 50–100
     → ②合并去重 → ③bge-reranker-v2-m3 精排 top 20–30
     → ④结构化成表返回（含价格/来源/更新时间，供 agent 直接引用）
```
- **只用 reranker 也能显著提升**：当关键词召回质量尚可（成本条目短、字段明确）时，先
  「LIKE+BM25 召回 top 100 → rerank 精排 top 20」即可解决大部分误召；向量召回（bge-m3）
  是数据量更大或别名场景再上的增强，可与 rerank 分期实施。

### 6.3 本地模型可行性（bge-reranker-v2-m3）
- **模型规格**：568M 参数（基于 BGE-M3-0.5B）；官方 max_length=8192，但微调用 1024，
  建议精排截断 ≤1024 tokens；FP16 约 2.2GB，FP32 3–4GB，Q8_0 GGUF 约 600MB 可 CPU 运行。
- **本地部署**：llama.cpp `--reranking` 即暴露 OpenAI 风格 POST /v1/rerank（query +
  documents + top_n）；HuggingFace 已有 bge-reranker-v2-m3 Q8_0 GGUF 转换。
- **Herdsman 接入**：仓库内接口文档已定义 /v1/embeddings 与 /v1/rerank，且 /v1/models 可
  探测安装状态——**装好模型后 gaea 无需新增服务，直接 HTTP 调用即可**；app 侧新增
  cost_rerank 工具（或内置在 cost_search 里做可选精排），失败时优雅回退纯 SQL。
- **延迟预算**：GPU（A10G 级）单条 45–110ms；CPU Q8_0 慢一个量级。精排候选限 50–100、
  每条 ≤512–1024 tokens，交互式搜索可接受；输入防抖 250–300ms + 结果缓存（同 query 短时
  复用）控制开销。
- **何时真正需要**：现在（<5k 条）不需要。建议先做 P0 检索补字段 + BM25，把 rerank 作为
  P1 的「开关式」能力：配置了 Herdsman rerank 模型就启用，否则 SQL/BM25 兜底——本地优先、
  无模型也可用。

## 7. 结论

成本库第二轮的本质是**把「仓库」变成「运营系统」**：导入与 AI 提取解决「数据怎么进来」，
编辑/批量/价格历史解决「数据怎么管理」，订阅源 + 定时抓取解决「价格怎么保鲜」，分级检索 +
本地 rerank 解决「数据多了怎么找」。五块全部复用现有基建（xlsxpreview/format_convert/
cost.Store/web_fetch/Herdsman /v1/rerank），无需新增外部服务；抓取结果一律人工确认发布，
遵循「本地优先 + 来源可溯 + 无确认不写」三条既有原则。
