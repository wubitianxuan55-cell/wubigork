# 市场调研：造价数据库架构——综合单价一级 / 人材机二级（重点：蜘蛛网工程成本平台），2026-08-19

> 背景：用户认为造价数据库现有架构（一级=人工/材料/机械/运输/检测/综合单价…）没有
> 调好，主张「综合单价为一级、人材机为二级」，并以《市政成本测算手册（wu整理）.xlsx》
> 为参照。本调研重点拆解「蜘蛛网工程成本平台」如何组织综合单价与人材机，再落到 gaea。

## 0. 一句话结论

蜘蛛网（陕西蜘蛛网工程管理有限公司）的整个产品线——孤影造价 / 蜘蛛造价 /
蜘蛛网工程成本平台 / 蜘蛛网工程资源平台——公开内容几乎全部是**「综合单价分析」**：
一条综合单价子目 = 人工费 + 材料费 + 机械费（人材机明细行，每行 名称/含量/单价/金额/
损耗系数）+ 管理费/利润（费率）+ 税金 → 成本价 → 不含税单价 → 含税综合单价。
这恰好就是用户要的「综合单价为一级、人材机为二级」，并且与我们《市政成本测算手册》
的结构一致。结论：**造价数据库应改为「综合单价库」：记录 = 综合单价子目（一级），
二级 = 人材机组成明细 + 费率**；人/材/机从「一级分类」降级为「综合单价内部的组成
维度」，不再当作平级分类。

## 1. 蜘蛛网工程成本平台专项调研

### 1.1 公司画像

- 主体：陕西蜘蛛网工程管理有限公司（法定代表人刘清利），专注工程成本测算与成本软件，
  拥有《房建项目（室外工程）成本测算手册》等作品著作权。
- 产品线（4 款核心软件）：**孤影造价**、**蜘蛛造价**（App Store 有上架，概算/预算/结算
  数据编制、审核、积累、分析再利用，遵循 GB50500 清单计价规范）、**蜘蛛网工程成本平台**、
  **蜘蛛网工程资源平台**（资源库：定额/材料/机械数据资源）。
- 内容运营：抖音/头条「蜘蛛网工程成本」「孤影造价」等账号，持续发布细分工程（排水沟、
  护坡、地坪、管道、屋面防水、市政道路）的**成本单价分析表**，供市场报价对比。

### 1.2 数据形态：综合单价分析（核心蒸馏对象）

公开的每一篇成本分析都是同一种结构，以「镀锌钢管成本测算」为例：

```
一、人工费：  安装                15元/m
二、材料费：  管道 66.01元/m*1.02 = 67.33元/m
             焊条、砂轮片等        3.8元/m
三、机械费：  焊机等               4.2元/m
管理费（%）：                       4.52元/m
利润（%）：                         13.55元/m
不含税单价：                        108.40元/m
税金（%）：                         9.76元/m
综合单价（含税）：                  118.15元/m
```

其它示例（浆砌片石护坡 / 喷射混凝土护坡 / 砖砌排水沟 / 透水混凝土园路 / 干挂铝板 /
防水卷材）结构一致，且材料行普遍带**损耗系数**（×1.02~×1.15）：

```
材料费：片石 80元/m³ * 1.15m³ = 92元/m³
        M7.5水泥砂浆 305元/m³ * 0.35m³ = 106.75元/m³
成本价合计：98 + 209.1 = 307.1元/m³
报价：307.1 × (1+25%) × (1+9%) = 175.46元/m³（建筑面积混凝土浇筑示例）
```

两条新核对到的细节（2026-08-19 复核公开文章确认）：

- **人材机分段并非总是三项**：部分分析（如喷射混凝土护坡）把「人工费+机械费」合并成
  一段后再列材料费。因此组成行模型应按「行」打 kind 标签（人工/材料/机械），而不是
  依赖固定三段；解析时遇到合并段可标 kind=人工机械 或按行拆分。
- **报价公式有两种写法**：分步式（管理费→利润→不含税单价→税金→含税综合单价，如
  镀锌钢管）与一步式（成本×(1+利润率)×(1+税率)，如混凝土浇筑、浆砌片石护坡）。
  两者利润率/税率口径相同（常见 25% 利润、9% 税），入库时可统一存成本价/利润率/税率，
  展示时再还原成任一种写法。

### 1.3 平台能力（宣传口径，弱于数据结构本身的证据力）

- 全维度数据分析、**动态数据资源库**、智能预测与校准；
- **政策法规联动**：与住建/造价管理部门的最新政策、计价依据、定额标准、费用调整文件
  同步，新政发布自动抓取、智能解读、即时推送；
- **工程数据智库**：让每次测算「有迹可循、有据可依」。

对 gaea 的启示：蜘蛛网的「资源库」与「成本平台」是**两个层次**——资源库存人/材/机
基础价，成本平台把资源组合成综合单价。我们现有一级分类（人工/材料/机械）更像资源库
逻辑；用户要的是成本平台逻辑。

## 2. 竞品矩阵：综合单价与人材机的组织方式

| 平台 | 综合单价的组织 | 人材机的位置 | 可蒸馏点 |
|---|---|---|---|
| 蜘蛛网工程成本平台 | 综合单价=核心条目，按专业/分部发布 | 综合单价内部分段：人工费/材料费/机械费，行级明细（名称/含量/单价/损耗/金额） | **综合单价一级 + 人材机组成二级**；损耗系数；费率（管理/利润/税） |
| 广联达云计价 | 清单项目综合单价分析表（GB50500） | 人材机明细 + 管理费/利润 + 风险，组成行与综合单价强关联 | 综合单价分析表是行业标准形态；人材机可追溯可调 |
| 市政成本测算手册（用户附件） | 专业分表（道路/给水…）→ 分部（土方工程/机动车道…）→ 子目 | 每子目 9-14 列：人工费/材料费/机械费/管理3%/利润10%/垫资3% | 与蜘蛛网同构；分区按专业/分部 |
| BOQ-AI（开源） | 对话式智能计价，SQLite 定额库 | 定额子目含人材机组成 | 本地 SQLite 存「子目+组成」可行 |
| zaojia-database | 定额库/清单库/材料设备库分库 | 材料设备独立库 + 价格快照；定额含「七项费用与人材机组成」 | 定额人材机组成面板是成熟参考 |
| 造价通/慧讯网 | 信息价/市场价按材料设备检索 | 资源价为主，不组织综合单价 | 资源库维度（对应我们的价格源） |

## 3. 蒸馏出的目标数据模型

```
综合单价子目（一级）                     ← cost_entries（改语义，不换表）
├─ 专业 / 分部 / 子目名称                  ← category_path（综合单价/道路工程/土方工程/…）
├─ 单位、项目特征及工作内容、含税单价        ← unit / spec / price
├─ 人材机二级：
│   ├─ 人工费（金额合计 + 明细行）          ← labor_fee + components(kind=人工)
│   ├─ 材料费（金额合计 + 明细行，含损耗）   ← material_fee + components(kind=材料)
│   └─ 机械费（金额合计 + 明细行）          ← machine_fee + components(kind=机械)
│      明细行 = 名称/单位/含量(数量)/单价/金额/备注
└─ 费率（可选）：管理费/利润/垫资/税金       ← 可先不入库，留展示位
```

关键点：
1. **记录语义从「资源价」改为「综合单价子目」**：入库的每条 = 一个可报价的工作项
   （挖一般土方 3.79元/m³、铸铁管铺设 638.43元/m），而不是孤立的人工/材料价。
2. **人材机是二级组成**：同一子目下多条组成行（人工 1~N 行、材料 1~N 行、机械 1~N 行），
   每行 = 资源名 + 含量 + 资源单价 + 金额（+损耗系数放备注/price 关系里）。
3. **人/材/机不再是平级分类**：若仍需要独立资源价（如材料市场价、台班价），它们属于
   「资源库」层（价格源/资源分类），与综合单价库分离——避免「综合单价里又套资源分类」。
4. 检索与测算时：搜「挖一般土方」→ 命中综合单价子目，展开可见人材机组成，报价依据
   完整可追溯（哪个专业、哪个分部、哪些人工材料机械、什么费率）。

## 4. 对 gaea 造价数据库的落地建议

（已按此方向预置 SchemaV12：`cost_entries` 增加 labor_fee/material_fee/machine_fee，
新建 `cost_entry_components` 人材机组成表。）

- 分类树默认种子改为：**综合单价 → 专业（道路/交通/绿化/电力/给水/暖气/雨污/照明/其他）
  → 分部（土方工程/机动车道/管道铺设…）**，子目作为叶子条目挂在分部下；人材机是条目
  内部组成（二级），不再单独成分类。
- 条目详情/列表展示：综合单价 + 人材机三段（人工费/材料费/机械费）+ 组成明细表；
- 导入《市政成本测算手册》时：把 人工费/材料费/机械费 三列映射为二级合计，把
  「综合单价分析」文本（如「机械费 1.挖土方(甩土)3元/m³」）解析为组成明细行；
- 管理费/利润/垫资/税金：第一阶段作为展示字段或备注保留，不参与计算（个人测算用
  综合单价直接报价即可）。

## 5. 待确认的决策点

1. 是否按上文「记录=综合单价子目、人材机=二级组成」定稿（推荐）；
2. 是否保留「资源库」层（人/材/机独立资源价分类），还是个人场景下完全由组成行承载；
3. 费率（管理/利润/垫资/税金）是否入库（影响导入映射与条目字段）。

## 6. 定稿（2026-08-19 用户确认）与实现状态

三项决策全部按推荐方案定稿，并已实现：

1. **记录=综合单价子目、人材机=二级组成**：`cost_entries` 增加
   labor_fee/material_fee/machine_fee（SchemaV12）+ management_fee/profit_fee/
   advance_fee/tax_rate（SchemaV13）；新增 `cost_entry_components` 组成行表
   （kind/title/unit/quantity/price/amount/note/sort）。`cost.Store` 的
   Save/Get/Delete/Search 与导入事务写库全链路已接新字段（组成行整组替换）。
2. **保留资源库层但不强制关联**：人/材/机独立资源价由价格源/信息价模块承载；
   综合单价库的分类树重构为 **综合单价 → 专业（道路/交通/绿化/电力/给水/暖气/
   雨污/照明/其他）→ 分部**，人材机不再平级成类。市政手册只是结构参考与首个
   蒸馏源，分类树与通用导入对任何专业开放。
3. **费率入库但仅展示追溯、不参与计算**：管理/利润/垫资存金额（元）、税存储
   百分比，前端展示可编辑，导入时从手册列原值带入。

导入器新增《市政成本测算手册》专有格式识别（任一 sheet 含「综合单价分析」+
人工费/材料费/机械费 表头即触发）：按 专业 sheet → 分部行 → 子目行 提取，
把「综合单价分析」文本解析为人材机组成行（段头切 kind、行尾金额、原始表达式
入 note，损耗系数不丢）；同名子目按项目特征片段去重（手册同一子目常因深度/
规格不同重复出现）。真实手册 8 张专业表实测 234 条全部命中。

验证基线：`go build ./...`、cost/costimport/app 相关测试、前端 `tsc -b` +
`npx vitest run`（118 文件 605 测试）、`check-bindings-drift.ps1` 全绿；
`TestGaeaDataBackup*` 两个备份测试为环境相关预置失败，与本任务无关。
